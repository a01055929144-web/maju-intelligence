## ARC-05 계산·스냅샷 계약 (검토안)

1. **편집 계산**: 새로운 가산율 경로의 단일 순수 함수는 기존 `calculatePrice`를 재사용한다. `withMargin` 같은 P1 경로는 이미 이를 사용한다. 기존 gross-margin 값은 이름만 바꿔 전달하지 않는다. 원가/마진 basis/version을 확정하기 전 기존 견적 작성기를 변경하지 않는다.
2. **금액 확정**: 알려진 판매가는 정수 원, 수량은 단위가 붙은 소수다. VAT 별도는 라인 공급가액 먼저 반올림 → 과세 라인 VAT 반올림 → 라인 합계다. 견적 `calculateQuoteTaxLine`과 ERP `calculateErpLine`은 같은 입력에서 일치함을 테스트한다. VAT 포함 계약은 총액→공급가/VAT 분리 규칙까지 03과 고정해야 하며 현재 ERP 입력 타입에는 해당 선택이 없다.
3. **주문 가격 선택은 계산과 분리**: 브라우저 원가로 재계산하지 않는다. 회사/매장/상품/정확한 판매 단위/배송 적용일에 유효한 계약, 선택된 견적 발행본, 연결 단가표 발행본을 서버가 읽어 선택한다. 대상 우선순위는 전역 계약 규칙과 7차를 결합한 계약 > 견적 품목 > 단가표 품목이다. 기존 코드에 없는 다중 발행본 선택은 C2 해소 후에만 연결한다. 시세 미정은 null이며 0원이나 최근 출고가로 대체하지 않는다.
4. **스냅샷**: 주문에는 상품명/규격/판매 단위/수량/과세/세포함 여부/단가와 `agreementId` 또는 `documentVersionId`, 선택 게시 revision, 가격 선택 시점/적용일을 고정한다. 행사는 발행 단가를 유지하고 현재 기간/판매 가능 수량/한도를 검증한다. 계약/행사 설정 변경이 과거 주문을 다시 가격화하면 안 된다.
5. **수락/수정**: 기존 견적 수락 RPC를 유일 진입점으로 유지한다. 신규 P1 pricing quote를 legacy sales_quote에 복제하거나 자동 계약 전환하는 연결은 아직 없다. 상태 전이·계약 충돌·기간·재시도 결과를 포함한 원자 경계를 먼저 확정한다. 링크 가격 전환/계약 변경과 경합한 주문은 동일 버전으로 처리하거나 409로 재확인을 요청해야 하며 다른 가격을 조용히 청구하지 않는다.

## 04 → 09 상품·확정 원가 계약

04가 제공하는 내부 읽기 결과: 회사·상품 ID, active 상태, 공개 판매명/규격/판매 단위, 명시 과세, 원가의 기준 매입 단위와 판매 단위 환산(확정 여부·근거 ID·버전·적용일), 확정 판매 단위 원가(소수 2자리), 원가 출처(전표/엑셀/직접 확정). 후보/누락/0 이하 환산/단위 불일치는 자동 가격화 불가로 표현한다. 수동 확정 원가와 환산 완료 원가를 구분하고 09는 원본 매입처/상품/환산 테이블에 쓰지 않는다.

예제(합성 값, 실제 구현 DTO가 아닌 계약안):


## 09 → 03 주문·전표·원장 계약

09의 쓰기 원천은 주문/주문 라인/가격·접근 근거이며 03의 원천인 전표/원장/재고 이동에 직접 INSERT/PATCH하지 않는다. 현행 03 진입점은 `lib/business-documents.ts`의 `saveBusinessDocument` / `confirmBusinessDocument`와 그 DB RPC다. 이 진입점이 주문 가격 출처·VAT 포함·주문 revision 멱등을 지원하는지는 아직 연결 검증 전이다. 09가 새 confirm RPC를 만들거나 기존 확정/취소 트리거를 우회하지 않는다.

## ARC-06 공개 응답·인증·활성화 계약

공개 응답 허용: 문서/회사 공개 표시명, 매장 자신의 배송 정보, 상품 공개명/규격/판매 단위, 선택된 판매가/과세/세포함 여부, 안전한 가격 출처 종류, 현재 주문 가능 상태, 자신의 주문 내역. staff 권한 해시/원가/마진/예상이익/매입처/원가 환산/기사 위치/등록증 객체 경로/암호문/출입 비밀번호는 금지한다. 기존 공개 견적과 #99 공개 DTO를 재사용하되 새 필드를 구조적으로 복사하지 않는다.

공개 토큰은 비로그인 문서 조회/임시 담기의 제한 자격이다. 주문 제출은 매장 계정 인증 및 회사/매장 membership와 첫 주문 확인을 추가해야 한다. 현재 #99 PUT은 이 8차 관문 전이므로 운영용으로 열 수 없다. 짧은 링크/카톡 미리보기는 별도 공개 읽기 모델로만 연결하고 비밀 토큰·개인 자료를 URL·OG·로그에 노출하지 않는다.

영업권 생성/연장/만료·비교 대상 회사 정보는 MAJU 운영 모듈 소유로 둔다. 고객사에는 권리가 있는 타사 이름·상태·규칙을 반환하지 않고, 허용된 리드 목록과 최초 안내 한 줄만 제공하는 별도 읽기 결과를 사용한다. 09가 고객사 링크 관리에 영업권 편집 기능을 추가하지 않는다. 실제 리드 노출 필터/보유 기간의 쓰기는 영업/플랫폼 모듈 계약을 선행한다.
