# 매장 직접 가입과 유통사 연결 — 설계 (2026-11-11, 컨트롤타워)

> 상태: 대표 결정 반영 설계. 운영 DB 변경·기능 ON 승인이 아니다. 구현은 `docs/dispatch/2026-11-11-R2-*.md`.

## 1. 대표 결정 (2026-11-11 00:11)

1. 매장은 `/store`에서 **직접 카카오로 가입**할 수 있다(링크 없이도). 매장에게도 기능(원가관리 등)을 줘서 MAJU를 쓰게 한다.
2. 로그인하면 **연결된 유통사가 만든 단가표·견적서**가 보인다: **전체 공개 단가표 + 그 매장 앞으로 만든 견적서**.
3. 연결은 **즉시**, 대신 **첫 주문은 유통사가 확인**한다.
4. **동종 업종 고객사 간 영업권을 지킨다** → 아래 2절.

## 2. 영업권 보호 원칙 (연결 방식 결정)

- 매장이 **유통사 목록을 둘러보거나 검색할 수 없다.** 어떤 유통사가 MAJU를 쓰는지 매장·다른 유통사에 드러내지 않는다.
- 연결은 **유통사가 먼저 건넨 것으로만** 생긴다:
  - (a) 유통사의 **공개 단가표 링크·QR**(이미 있음)로 들어와 가입/로그인 → 그 유통사에 연결.
  - (b) 유통사의 **매장 초대코드**(회사 설정에서 발급·회수, 6~8자) 입력 → 그 유통사에 연결.
  - (c) 매장의 사업자번호가 **정확히 한 유통사의 기존 거래처**(`normalized_customers`)와 일치하면 "○○와 거래 중이시면 연결" **제안** → 매장이 눌러야 연결. 두 곳 이상 일치하면 제안하지 않는다(어느 쪽도 노출 안 함). **리드(인허가 데이터)는 일치 근거로 쓰지 않는다** — 여러 유통사가 같은 리드를 갖기 때문.
- 한 매장이 여러 유통사와 연결될 수 있다. 유통사 A는 매장이 B와도 연결됐다는 사실을 알 수 없다.
- 매장의 원가관리 자료(다른 매입처 가격 포함)는 **매장 소유**이고 어느 유통사에도 보이지 않는다.

## 3. 데이터 구조

현재 `store_accounts`는 `company_id`·`customer_id`가 필수인 **유통사별 매장 계정**이다(직접 가입 불가). 원가관리 테이블도 `(company_id, store_account_id)` 범위다.

| 개념 | 테이블 | 변경 |
| --- | --- | --- |
| MAJU 매장(플랫폼 수준) | **신규 `store_profiles`**: id, 매장명, 사업자번호(선택, 개업 예정 허용), 기본주소·상세주소, 상태, 약관 | 직접 가입 시 생성 |
| 매장 구성원 | **신규 `store_profile_members`**(점주·관리자·직원, 카카오 auth_user_id) | 기존 `store_account_members`는 유통사 연결별로 유지 |
| 유통사 연결 | 기존 `store_accounts` + **`store_profile_id` 열 추가**(nullable→점진 필수) | 연결 시 거래처(`normalized_customers`) 없으면 `needs_review`로 생성 |
| 초대코드 | **신규 `company_store_invite_codes`**(company_id, code_hash, 만료, 회수) | 회사 설정에서 발급 |
| 원가관리 | 1단계: 기존 그대로(연결별). 2단계: `store_profile_id` 기준으로 이전 | 2단계는 별도 승인 |

기존 링크 가입 매장은 `store_profiles`를 1:1로 만들어 백필(대상 건수 보고 후 승인).

## 4. 매장이 보는 문서

- **전체 공개 단가표** = 그 유통사가 **공개 링크(공유)가 살아 있는 게시 단가표**(kind=sheet). 새 표시 칸을 만들지 않고 기존 공개 링크를 "전체 공개"로 쓴다. 회수하면 사라진다.
- **내 견적서** = 그 매장(거래처) 앞 `storefront_links`가 살아 있는 견적서.
- 가격·주문 가능 여부는 기존 규칙(유효기간, 배송 권역·요일 판정) 그대로. 원가·마진·공급처는 응답에 없다.

## 5. 첫 주문 확인

- 직접 가입·코드·제안으로 연결된 매장의 **첫 주문**은 접수(submitted)되지만 주문함에 **"첫 거래 — 거래처 확인 필요"** 표시. 유통사가 거래처 정보를 확인(또는 기존 거래처와 병합)하고 주문을 "확인"하면 이후 주문은 일반 처리.
- 거래처 확인 전에는 배송 배정·전표 생성에 쓰지 않는다(기존 `needs_review`·#460 주문 보류 경계 재사용).

## 6. 화면 흐름 (매장)

```
/store → 카카오로 시작
  ├ 처음: 매장 정보(이름·주소·사업자번호 또는 개업 예정) → MAJU 매장 생성 → 홈
  │       홈: "거래 유통사 연결" 카드 [초대코드 입력] (+ 사업자번호 일치 시 1곳 제안)
  ├ 링크·QR로 들어온 경우: 가입/로그인 후 그 유통사에 바로 연결 → 그 문서로 복귀
  └ 홈: 유통사별 [전체 공개 단가표 · 내 견적서 · 주문 내역] + 원가관리 + 구성원·주소
```
