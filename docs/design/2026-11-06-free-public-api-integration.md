# MAJU 무료 공공 API 활용 설계 (2026-11-06)

## 목적과 현재 경계

6월 HTML 5종은 아이디어 자료이며, 제공 기능·비용·권한의 근거가 아니다. MAJU의 현재 정본은 회사별 상품·가격·게시 문서·주문 링크·주문이다(`docs/backend/00_BACKEND_CONTRACT.md` 2·5·6절). 외부 데이터는 이 정본을 **자동 변경하지 않는 참고 정보**로 붙인다. 특히 매장이 별도로 올리는 원가는 매장 소유이며, 유통사 리드 생성·제3자 공유에 사용하지 않는다.

| [소진공 상가(상권)정보 API](https://www.data.go.kr/data/15012005/openapi.do) | 상가업소번호·상호·주소·업종·좌표, 반경·행정구역 조회와 수정일 조회. 무료, 개발계정 신청 가능 트래픽 10,000, 개발·운영 자동승인으로 표시 | 관리자가 자기 고객사의 영업 지역에서 동업종 **관측 점포 수**와 데이터 갱신일을 확인. 기존 리드 데이터와 중복 조회·저장 최소화 | 한 응답이 매출, 배달 건수, 실제 개폐업률, 신용위험을 직접 제공한다고 단정하지 않음. 상가 목록에서 사라진 매장을 자동 폐업 처리하지 않음 |
| [한국관광공사 국문 관광정보 API](https://www.data.go.kr/data/15101578/openapi.do) | 행사정보 포함. 무료, 개발계정 1,000, 운영계정 심의승인으로 표시. 사진은 자료별 별도 이용 조건 | 배송 권역 인근 행사명·장소·기간을 MAJU 관리자 **운영 일정**에 표시. 회사 담당자가 재고 준비에 참고 | 행사 참석자 수·매장별 주문 증가량을 예측값으로 표시하지 않음. 도로 통제·마라톤 전부를 제공한다고 가정하지 않음. 사진 원본은 1차 수집 제외 |
| [에어코리아 대기오염정보 API](https://www.data.go.kr/data/15073861/openapi.do) | 측정소별·시도별 PM2.5/PM10 등 대기질과 예보. 무료로 표시되며 운영계정 절차·이용허락 조건은 서비스별 확인 필요 | 측정소·관측 시각·원본 수치를 관리자 참고 카드에 표시. 노출 시 출처와 데이터 기준 시각 병기 | 미세먼지가 날씨보다 배달 수요와 상관관계가 높다는 문구, 배달 수요 증감 알림은 MAJU 주문 이력과 검증 전 사용하지 않음 |
| [기상청 단기예보](https://www.data.go.kr/data/15139470/openapi.do) | 격자별 단기예보, 무료. 해당 API는 기관 정책에 따라 호출량이 달라질 수 있다고 표시 | 배송·행사 일정 판단의 보조 신호 후보. AirKorea와 같은 위치·시간으로 비교할 수 있을 때만 사용 | 기상 변수만으로 자동 발주·가격 변경하지 않음 |

“무료”는 API 호출 요금 표기이지 무제한 호출·당일 운영 키 발급·제약 없는 재배포를 뜻하지 않는다. 각 기관의 운영 승인·표시 의무·응답 한도는 실제 키 신청과 파일 재배포 전에 다시 확인한다. HTML에 나온 민간 상용 서비스 가격, 비공개 리뷰 API, 자동 메시징 비용은 무료 API 계획에서 제외한다.

## 첫 구현: 관리자 참고 카드, 두 출처만

**1차는 KAMIS와 관광공사 행사**를 소규모로 시험한다. KAMIS는 현재 상품·매입가·마진 워크플로에 직접 연결되는 참고값이고, 행사는 유통사 재고 준비에 활용 가능한 운영 일정이다. 둘 다 주문 확정이나 가격 계산 경로에 넣지 않는다. 소진공은 이미 리드 보강 후보이므로 기존 리드 수집과 중복되는 별도 전체 매장 수집을 만들지 않고 반경 표본 조회로 시작한다. AirKorea·기상청은 정보 카드의 실제 사용성을 확인한 뒤 붙인다.

Next.js 모놀리스 안에 `공식 API 어댑터 → 응답 검증/단위 정규화 → 짧은 서버 캐시 → 관리자 읽기 API` 흐름을 둔다. 원천마다 인증·응답 형식·갱신 주기는 어댑터에서 처리하고, 관리자 카드에는 공통 `source`, `observedAt`, `retrievedAt`, `scope`, `quality`만 전달한다. `/admin/system`에는 출처 상태·호출량을, 향후 관리자 시장 모니터링 화면에는 검수할 참고 가격과 행사를 둔다. 유통사 화면으로의 노출은 별도 회사별 플래그로 제한한다. 배치가 시간 예산에 닿으면 남은 지역은 다음 실행으로 넘기고, 한 출처 실패가 주문·가격 화면을 지연시키지 않도록 읽기 경로를 분리한다.

1. **수집 단위:** MAJU 서버가 공식 API를 호출한다. 브라우저는 기관 키를 받지 않는다. 회사별 활성 영업 지역과 관리자가 정한 관측 품목만 조회한다. KAMIS에서는 지원 지역/품목 코드가 없으면 `미지원`으로 기록하고 빈 가격을 0원으로 바꾸지 않는다.
2. **정규화:** 가격은 `출처·원천 품목코드·품종/등급·규격·단위·도매/소매·지역·조사일·금액`을 한 묶음으로 취급한다. 행사 정보는 `원천 ID·행사명·장소·시작/종료·수정 시각·출처 URL`을 사용한다. 매장·회사 상품과의 연결은 관리자 확인을 거친 **별도 매핑**으로만 한다.
3. **캐시·호출 예산:** 각 출처별 설정에 승인된 일일 한도와 MAJU 내부 상한을 둔다. 첫 시험 내부 상한은 KAMIS 20회/일, 관광공사 20회/일, 소진공 20회/일, AirKorea 10회/일이다. 이는 공식 할당량이 아니라 MAJU의 보수적 출발값이다. 동일 쿼리 캐시를 먼저 읽고, KAMIS 가격은 조사일이 바뀔 때, 행사는 하루 1회, 상가는 주 1회, 대기질은 관리자 화면에서 필요한 지역에만 1시간 캐시로 갱신한다. 실패·한도 초과 시 마지막 정상값에 기준 시각을 표시하거나 `자료 없음`으로 닫는다.
4. **저장:** 1차 연결 확인 전에는 원문 응답 전체를 DB에 적재하지 않는다. 기존 회사별 `product_price_observations`는 고객사 업로드 원천이므로 공공 시세 저장소로 재사용하지 않는다. 지속 저장이 필요해지면 출처별 최소 칼럼·TTL·인덱스·RLS·service_role 권한의 SQL 초안과 DB 크기 예상치를 별도 승인표에 올린다. [Supabase 공식 API 보안 지침](https://supabase.com/docs/guides/api/securing-your-api)에 따라 권한과 RLS를 함께 검증한다.
5. **화면:** MAJU 관리자에서 `외부 자료 상태`(마지막 성공, 오류, 호출량)와 `시장 참고가/지역 행사`를 보고, 유통사에는 관리자가 공개 범위를 정한 **출처 있는 참고 카드**만 보여준다. 매장 주문 화면에는 우선 넣지 않는다. 주문 화면의 판매가 등락은 회사가 발행한 판매가 버전끼리 비교하는 기존 규칙을 유지한다.

## 자동 영업 아이디어의 검증 순서

- 매장별 “시세보다 15% 높음”은 단위·품종·품질·배송 조건이 맞지 않으면 오탐이다. 같은 원천코드와 환산 단위가 있는 표본에서 일치율을 측정하기 전까지 매장에 절감액을 제시하거나 유통사에 알리지 않는다.
- “대기질·날씨·행사 → 주문 증가”는 **가설**이다. 주문이 있는 회사의 지역·날짜별 이력과 신호를 최소 수 주간 대조해 방향·오차를 보고한 뒤 예측 사용 여부를 결정한다. 관측 기간과 표본이 부족하면 `모름`이다.
- “주문 감소”는 외부 API 없이 `store_orders`의 같은 매장 실제 재주문 간격으로 먼저 계산할 수 있다. 첫 단계는 내부 담당자의 확인 목록이며, 매장에 자동 메시지를 보내지 않는다.
- 매장 신뢰 점수로 미수 가능 여부를 판단하거나 여러 유통사의 견적을 자동 비교시키는 기능은 별도 동의·권한·계약이 필요한 후속 과제다.

## 구현 순서와 통과 기준

| 단계 | 작업 | 통과 기준 |
| --- | --- | --- |
| A. 공식 API 표본 | 1개 지역·5~10개 품목(KAMIS), 1개 권역·7일 행사(관광공사)를 **쓰기 없는** 요청으로 확인 | 상태 코드, 사용 가능한 지역·단위, 누락률, 응답 시간, 표시 조건과 운영 승인 상태 보고. 키·원문 개인정보는 출력하지 않음 |
| B. 관리자 읽기 카드 | 서버 어댑터·캐시·호출 예산·출처/관측일 표시, 실패 상태 | 관리자만 조회, 키 브라우저 비노출, 같은 쿼리 중복 호출 억제, 390px/PC에서 빈값·오류 안내 |
| C. 유통사 참고값 | 검수된 품목 매핑과 회사별 노출 플래그 | 다른 회사 값·매장 자체 원가 비노출, 규격/단위 불일치 시 비교 숨김, 판매가 자동 변경 없음 |
| D. 효과 평가 | 참고 카드 사용률·주문 재주기 및 예측 가설의 오차 측정 | 실측 결과와 한도/저장 비용을 보고한 뒤 매장 노출·자동 알림 여부 별도 결정 |

검증에는 **같은 품목명에 다른 규격**, **같은 규격에 다른 단위**, **자료 갱신 지연**, **기관 429/5xx**, **키 누락**, **회사 간 조회**, **매장 공개 링크 조회**를 포함한다. 회사 간 조회와 공개 링크에서는 관리자 참고 데이터 및 매장 자체 원가가 반환되지 않아야 한다. 관리자 화면에서 마지막 정상 시각과 실패 원인을 확인할 수 있어야 하며, 실패를 0원이나 정상 갱신으로 표시하지 않는다.

운영 API 키 사용, DB 스키마·데이터 변경, 고객사/매장 기능 ON은 이 설계만으로 승인되지 않는다. 현재 필요한 것은 **표본 호출 결과와 기관별 운영 이용 조건**이며, 그 결과로 구현 승인표를 작성한다.
