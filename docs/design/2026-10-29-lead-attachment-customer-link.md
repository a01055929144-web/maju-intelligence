# 리드 첨부 → 거래처 파일 탭 연결 설계

## 경계

- 이 문서는 설계만 다룬다. `lead_attachments` SQL 초안 승인·운영 적용 전에는 API나 UI를 연결하지 않는다.
- 03 거래처 파일 탭 소유 컴포넌트와 저장 로직은 이번 작업에서 수정하지 않는다.
- 파일 바이트를 다른 Storage 경로로 복사하지 않는다. 동일한 `storage_path`를 링크로 참조한다.

## 승인 후 연결 흐름

1. 리드 첨부 업로드 시 private 버킷의 `companyId/leads/leadId/...` 객체와 `lead_attachments` 메타데이터를 저장한다.
2. 리드가 거래처로 전환될 때 파일을 복사하지 않고, 전환 관계 메타데이터가 원본 `lead_attachment_id`를 참조한다.
3. 거래처 파일 탭은 고객 소유 첨부와 전환된 리드 첨부를 합쳐 표시하되, 원본 유형과 출처를 구분한다.
4. 다운로드 요청은 먼저 요청자의 `company_id`와 거래처 조회 권한을 검증한다.
5. 해당 거래처가 원본 리드의 승인된 전환 대상인지 확인한 뒤에만 원본 Storage 객체의 짧은 signed URL을 발급한다.
6. 사업자등록증 등 민감 유형은 기존 감사 로그가 성공한 뒤 URL을 반환하며, 감사 실패 시 fail-closed 한다.

## 금지 사항

- 공개 버킷 또는 영구 URL 사용
- 거래처 ID만 받고 원본 리드/회사 소유권 검증 생략
- 파일 복사로 중복 객체 생성
- `lead_attachments` 승인·적용 전에 UI 플래그 활성화

## 보완 필요

- `lead_attachments` 승인안에서 전환 관계를 별도 조인 테이블로 둘지, 기존 전환 감사 데이터로 해석할지 확정해야 한다.
- 거래처 병합 시 원본 리드 첨부 링크의 승계 규칙을 03 담당과 공동 승인해야 한다.
