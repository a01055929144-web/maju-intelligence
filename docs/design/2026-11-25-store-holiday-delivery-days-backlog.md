# 백로그: 매장 휴무일 → 배송 요일 자동 반영 (2026-11-25 대표 요청)

## 요청
매장(점주)이 자기 휴무일을 설정하면, 그 매장의 배송 요일·배송 가능 날짜가 자동으로 바뀌어야 한다(휴무일엔 배송 안 함, 달력에서 선택 불가).

## 지금 운영에 있는 것 (11/25 확인)
- `store_order_settings`(회사 기본 마감) · `store_order_territory_rules.delivery_weekdays`(권역별 배송 요일) · **`store_order_customer_rules.delivery_weekdays`(거래처별 배송 요일·마감·최소 주문)** 가 이미 있다.
- `store_order_holidays`(company_id, territory_id, kind=date/weekly/yearly, holiday_date, weekday, month, day, label) — **고객사(공급사) 휴무**, 권역 단위. 매장 단위 아님.
- `normalized_customers.business_hours`(영업시간 텍스트) — 구조화돼 있지 않아 배송 계산에 못 씀.
- 매장 배송일 달력(CX-145 1번, 진행 중)은 회사·권역 휴무와 배송 요일을 반영한다.

## 규모 판단
- **매주 쉬는 요일**(예: 매주 월요일 휴무)은 작다: 기존 `store_order_customer_rules.delivery_weekdays`에서 그 요일을 빼면 된다. 새 표 없음.
- **특정 날짜 휴무**(예: 12/31~1/2, 임시 휴무)는 중간: 거래처별 날짜 휴무 표가 새로 필요하다(`store_order_holidays`에 customer_id를 넣는 확장 또는 새 표).
- 영향 범위가 넓다: 배송 코스(route)·기사 배정·주문 마감 계산·고객사 주문 확인 화면이 모두 배송 가능일을 쓴다. 그래서 단독 큰 작업으로 분리.

## 설계 초안
1. 매장 앱 [내 정보] → **영업일 설정**: 매주 쉬는 요일(체크) + 날짜 휴무(달력, CX-145에서 만든 공통 달력 재사용) + 사유.
2. 저장 규칙
   - 매주 휴무 → 이 거래처 `store_order_customer_rules.delivery_weekdays` = (권역/회사 배송 요일) − (휴무 요일). 원래 값은 기록해 두고 휴무 해제 시 복원.
   - 날짜 휴무 → 거래처별 휴무 표(customer_id, date, label, created_by member).
3. 배송 가능일 = 회사 배송 요일 ∩ 권역 규칙 ∩ 거래처 규칙 − 회사·권역 휴무 − **매장 휴무**. 서버 한 곳(배송일 계산 함수)에서만 계산하고 화면·주문 검증·코스가 같은 함수를 쓴다.
4. 고객사 화면: 거래처 상세에 "매장 휴무" 표시, 매장이 바꾸면 고객사 알림(코스 담당이 알 수 있게). 이미 받은 주문의 배송 요청일이 휴무와 겹치면 "확인 필요" 표시(자동 취소 금지).
5. 권한: 점주·매장 관리자만 변경. 고객사도 대신 설정 가능(전화로 들은 경우).

## 결정이 필요한 것(구현 전 대표 확인)
- 매장 휴무를 고객사 승인 없이 바로 반영할지(추천: 바로 반영 + 고객사 알림).
- 휴무와 겹친 기존 주문 처리(추천: 자동 취소 없이 "확인 필요" 표시, 고객사가 배송일 변경).
- 배송 코스(route)에 바로 반영할지, 다음 코스 생성부터 반영할지.

## 순서
CX-145 1번(배송일 달력·서버 검증) 배포 후 → 매주 휴무(작은 PR) → 날짜 휴무(SQL 초안·down·PG17) → 고객사 알림·코스 반영.
