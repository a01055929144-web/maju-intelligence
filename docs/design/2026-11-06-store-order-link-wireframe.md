# 주문 링크: 기존 MAJU 매장 화면에 데이터 연결

[PC·모바일 전환 와이어프레임](2026-11-06-store-order-link-wireframe.html) · 2026-11-06 · 합성 데이터 시안

## 한 화면 틀

매장에 새 웹앱이나 주문 폼을 만들지 않는다. 현재 `/store#<token>`에서 쓰는 `components/storefront-workspace.tsx`의 **홈·주문·내역·내 정보**를 유지하고 **데이터** 탭을 더한다. 모바일 390px과 PC가 같은 응답, 필터·즐겨찾기 상태, 주문 규칙을 사용하며 배치만 달라진다. 고객사 문서 편집기의 온라인 미리보기는 매장이 보는 품목 표현을 재사용한다.

## 구현 우선순위 변경

PC에서 주문과 함께 **대분류·표형/격자형·정렬·즐겨찾기·주문 내역 표·매장 데이터**를 먼저 사용한다. 모바일은 **주문과 판매가 변동**을 가장 빠르게 확인하도록 홈의 변동 요약 → 주문 품목 연결을 앞에 둔다. 모바일의 상품 표형 전환은 우선 제공하지 않고 카드형으로 읽는다. 두 폭 모두 같은 `/api/storefront` 데이터와 주문 규칙을 쓴다.

첫 구현에서는 기존 공개 주문 데이터로만 매장 데이터의 최근 주문·판매가 변동·즐겨찾기를 계산한다. 거래처원장·매입 엑셀 업로드와 메뉴별 원가 계산은 카카오 매장 구성원 인증과 매장 전용 저장 API가 생긴 뒤 연결한다. 공개 링크 토큰만으로 매장 원가를 조회하지 않는다.

## 화면 구성

| 탭 | 같은 데이터로 보여줄 것 | 동작 |
| --- | --- | --- |
| 홈 | 다음 배송·마감, 받은 단가표·견적·행사·임박, 주문 현황, **판매가 변동** | 변동 품목 보기 → 주문 탭. 직전과 현재의 *게시 판매가*가 비교될 때만 인상·인하 표시 |
| 주문 | 해당 유통사가 이 링크에 게시한 전체 품목 | **대분류만** 탭으로 선택, 격자형·표형 전환, 상품명·판매가 오름/내림차순, 즐겨찾기, 수량·장바구니 |
| 내역 | 매장 주문의 주문일·배송일·상태·품목·합계 | PC는 표, 모바일은 같은 표의 행을 세로로 배열. 주문 상세·다시 담기 |
| 데이터 | 매장 주문·판매가 변동; 후속으로 매장 자체 원가·메뉴별 원가·외부 참고 정보 | 현재 가능한 주문 데이터부터. 원가 업로드·참고 정보는 권한과 저장 구조가 준비된 뒤 |
| 내 정보 | 매장·배송지·구성원 | 제목 오른쪽 **설정**. 알림·즐겨찾기·구성원 관리는 역할별 권한 확인 뒤 |

종합·수산·축산·주류 등은 **유통사 성격**과 **상품 대분류**를 구분한다. 상단에는 연결 유통사의 이름·성격을 표시하고, 분류 탭은 그 회사의 게시 품목에 실제 존재하는 대분류만 생성한다. 다른 회사 상품·판매가는 합치지 않는다. 선택한 분류에 품목이 없으면 빈 상태와 다른 분류 선택 안내를 보여준다.

즐겨찾기와 보기 방식은 매장 구성원에게 같은 조작을 제공한다. 저장 범위는 매장별인지 구성원별인지 구현 시 결정하되, 다른 매장으로 공유되면 안 된다. 주문 내역의 다시 담기는 현재 게시 가격과 주문 가능 여부를 다시 확인한다. 과거 주문 가격을 새 가격으로 덮어쓰지 않는다.

| 단계 | 기존 정본/입력 | 같은 매장 화면에 표시할 데이터 | 상태 |
| --- | --- | --- | --- |
| 1. 매입가·마진 | 상품 마스터, 가격 정책 | 매장에 직접 표시하지 않음 | 기존 운영 흐름 |
| 2. 문서 발행 | `pricing_documents`와 게시 버전 | 단가표·견적·행사·임박 제목, 품목, 규격·단위, 판매가, 기간 | 문서 연결은 확장 대상 |
| 3. 링크 발급 | `storefront_links`, 주문 설정 | 고객사·매장, 유효기간, 배송일·마감·휴일·최소 주문 | 기존 링크·주문 설정 재사용 |
| 4. 담기·주문 | 게시 가격과 `store_orders` | 판매가 등락, 시세 안내, 수량, 배송일, 후결제 주문 확인 | 기존 `/store` 재사용 |
| 5. 주문 후 | `store_orders`·배송 상태 | 신청·접수·배송 중·도착, 다시 담기, 마감 전 수정 | 배송 증빙 등은 후속 |
| 6. 매장 자체 원가 | 별도 매장 계정 소유 데이터 | 데이터 탭의 원장·엑셀 업로드, 열 맞추기, 메뉴별 재료 수량·중량, 원가 이력 | 카카오 구성원 인증·DB 승인 뒤 |

## 구현할 때의 최소 변경

1. `StorefrontWorkspace`에 문서 종류별로 별도 폼을 만들지 않고 `/api/storefront` 응답의 `store`와 `lines`를 확장한다. 단가표·견적·행사·임박은 같은 품목 카드에 제목·기간·뱃지만 다르게 넣는다. 게시 버전이 바뀌면 고객사가 **어느 링크를 갱신할지 명시적으로 선택**한다. 기존 주문 가격 스냅샷은 바꾸지 않는다.
2. 같은 문서 품목 표현을 온라인 미리보기와 매장 주문 화면에서 공유한다. 현재 편집기 `PricingDocumentPreview`와 `StorefrontWorkspace`의 겹치는 표시 부분만 추출한다. 전체 화면을 새로 복제하지 않는다.
3. 현재 `/store` 주문 요청은 링크 토큰 기반이다. **카카오 매장 구성원 확인은 아직 연결되지 않았다.** 이를 붙일 때 매장 자체 원가는 공개 링크 토큰만으로 조회하지 않는다. 활성 구성원만 접근하며 점주·관리자 쓰기, 직원 조회로 시작한다. 유통사의 매입가·마진·매입처는 응답에서 제외한다.
4. MAJU 관리자는 공통 화면 블록과 외부 참고 자료 품질을 관리한다. 고객사는 자기 회사 문서·링크·주문 조건을 관리한다. 관리자 설정으로 특정 고객사의 판매가를 덮어쓰지 않는다.
5. 데이터 탭의 MAJU 참고 정보는 관리자가 승인한 출처·기준일을 함께 보여준다. 행사·대기질·상권·시장 가격은 **참고 자료**이며 판매가·재고를 자동 변경하지 않는다. 매장 자체 원가, 거래처원장, 메뉴별 원가 계산은 활성 카카오 매장 구성원 인증 뒤 별도 권한으로 제공한다.

## 와이어프레임 상태 표시

시안의 주문 품목·판매가 변동·주문 내역은 **합성 예시**다. 이 파일의 분류·정렬·보기·즐겨찾기 버튼은 화면 동작만 시연하고 저장하지 않는다. 링크 발급·카카오 로그인·첫 주문 정보·결제·원가 엑셀 업로드도 실행되지 않는다. 실제 `/store`에 데이터 탭·대분류 필터·표형 보기가 구현됐다는 뜻은 아니다. 선결제·자동 발주·여러 유통사의 실제 연결은 이 범위가 아니다.
