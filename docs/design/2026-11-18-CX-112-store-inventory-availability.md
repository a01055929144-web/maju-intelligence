# CX-112 매장 재고 확인 설계

> 상태: 설계 전용. 코드·SQL·환경값·운영 DB 변경 없음  
> Owner Domain: `inventory` / Related: `order`, `product`, `pricing`  
> 목표: 매장 품목 옆에 재고 상태를 보여 주고, 확실한 품절만 담기를 막으며 대체 품목을 안내한다.

## 1. 전제와 범위

- 재고의 단일 원장은 기존 `inventory_movements`다. 원장을 매장 요청마다 직접 합산하지 않는다.
- 매장 조회는 원장과 같은 트랜잭션에서 갱신되는 `inventory_balances`의 `on_hand_quantity`, `updated_at`을 읽는다.
- 상품별 추적 여부와 적음 기준은 `product_inventory_settings.tracking_enabled`, `safety_stock_quantity`를 사용한다.
- 수량 비교 전 `product_unit_conversions`로 매장 판매 단위를 기본 단위로 환산한다. 환산이 확인되지 않으면 품절로 단정하지 않는다.
- 현재 설계에는 `inventory_reservations`가 없다. 따라서 여러 매장의 동시 주문을 반영한 **가용재고**와 강제 차단은 예약 원자성 계약이 준비된 뒤에만 활성화한다.
- 다중 창고, 로트, 소비기한, 자동 대체, 자동 발주는 범위 밖이다.

## 2. 매장 표시 계약

| 상태 | 판정 | 매장 표시 | 담기 |
|---|---|---|---|
| `in_stock` | 추적 상품이며 기본 단위 현재고가 안전재고보다 큼 | `재고 있음` | 허용 |
| `low_stock` | 현재고가 0보다 크고 안전재고 이하 | `재고 적음` | 허용, 주문 중 변동 가능 안내 |
| `out_of_stock` | 최신이고 신뢰 가능한 현재고가 0 이하 | `재고 없음` | 예약 원자성 적용 후 차단 |
| `unknown` | 미추적, balance 없음, 단위 환산 미확인, 지연/대조 오류 | `재고 확인 필요` | 기존 주문 정책 유지, 확인 필요 안내 |

수량 원문, 원가, 평균원가, 재고가치, 매입처, 안전재고 숫자는 매장 응답에 포함하지 않는다. 화면에는 상태와 기준 시각만 반환한다.

`out_of_stock`은 아래 3절의 예약 원자성까지 켜진 회사에서만 매장 차단 상태로 반환한다. 그 전에는 현재고가 0 이하라도 `unknown`으로 내려 `재고 확인 필요`를 표시하고 기존 주문 흐름을 유지한다. 화면이 품절처럼 보이지만 서버는 주문을 받는 중간 상태를 만들지 않는다.

## 3. 담기 차단과 주문 시점 재검증

화면 표시만으로 주문을 막지 않는다. 아래 조건이 모두 충족될 때 서버가 같은 회사·상품을 다시 검증하고 `out_of_stock`이면 해당 줄 추가를 거절한다.

1. 회사 기능이 기본 OFF에서 회사 allowlist로 켜져 있다.
2. 상품이 재고 추적 대상이고 판매 단위 환산이 확인됐다.
3. 재고 투영이 최신이며 원장 대조 오류가 없다.
4. `inventory_reservations` 또는 동등한 원자적 예약이 주문 RPC와 같은 트랜잭션에서 생성된다.
5. `가용재고 = 현재고 - 활성 예약수량`이 요청 기본 단위 수량보다 작다.

예약 계약 전에는 0 이하 현재고도 `unknown`으로 전달한다. 부분 성공이나 클라이언트 계산으로 재고를 차감하지 않는다. 차단이 켜진 뒤 장바구니 추가와 주문 제출은 같은 서버 판정 규칙을 쓰되, 주문 RPC가 마지막으로 잠그고 재검증한 결과를 정본으로 삼는다.

## 4. 대체 품목 제안

품절 품목에는 최대 3개 후보만 제안한다. 후보는 모두 다음 조건을 만족해야 한다.

- 같은 `company_id`이고 해당 매장 링크/게시 문서에서 볼 수 있는 활성 상품
- 원래 품목과 같은 상품 분류이며 판매 단위 환산이 확인됨
- `out_of_stock` 또는 `unknown`이 아님
- 매장별 숨김·주문 안 함 설정에 해당하지 않음

정렬은 같은 규격·단위, 매장 즐겨찾기, 재고 상태(`있음` 우선), 기존 게시 순서 순이다. 가격은 기존 매장 가격 해석 함수를 다시 호출하며 재고 응답이 가격을 만들지 않는다. 후보를 자동으로 장바구니에 넣거나 원래 줄을 바꾸지 않고 매장이 직접 선택해야 한다.

후보가 없으면 `대체 가능한 품목이 없습니다. 유통사에 문의해 주세요.`를 표시한다.

## 5. 회사·매장 권한 경계

- 공개 링크 주문은 기존 서명 토큰의 `company_id`, `customer_id`, 문서 버전과 만료·회수 상태를 먼저 검증한다.
- 회원 매장은 기존 `store_account_id`와 연결된 `customer_id` 범위만 사용한다.
- 재고 수량 캐시와 조인은 `company_id + product_catalog_id`를 사용한다. 노출 품목·대체 후보 응답 캐시는 `company_id + store_account_id/customer_id + 링크 또는 게시 버전 + product_catalog_id` 범위를 포함해 같은 회사의 다른 매장 결과도 섞이지 않게 한다. 요청의 회사·매장 ID를 권한 근거로 신뢰하지 않는다.
- 노출 상품은 기존 매장 링크/게시 문서의 품목 집합과 교집합으로 제한한다. 다른 회사·다른 매장 전용 품목을 후보로 섞지 않는다.
- 브라우저가 `inventory_movements`나 `inventory_balances`를 직접 읽지 않는다. 기존 서버 권한 경계와 service role 전용 DB 권한을 유지한다.
- 응답에는 원가·재고가치·평균원가·매입처·원장 사유·담당자 이름을 포함하지 않는다.

## 6. 지연·오류 안내

구현 시 회사별 허용 지연시간을 하나의 서버 상수로 두며 초기 제안은 15분이다. 다음 중 하나면 `unknown`으로 내린다.

- `inventory_balances.updated_at`이 허용 지연시간보다 오래됨
- 상품 balance가 없거나 단위 환산이 미확인
- 원장 합계와 balance 대조 오류가 감지됨
- 재고 서비스 조회가 시간 초과 또는 실패

매장 문구는 `재고 정보가 늦게 반영되고 있습니다. 주문하면 유통사 확인 후 안내드립니다.`로 통일하고 마지막 확인 시각을 함께 표시한다. 오류를 `재고 없음`으로 바꾸거나 장바구니 전체를 막지 않는다. 운영자 화면에는 회사·상품 키와 지연 원인을 남기되 매장에는 내부 오류를 노출하지 않는다.

목록 전체에 신뢰 가능한 재고가 하나도 없어도 상품 목록을 빈 화면으로 바꾸지 않는다. 상품과 기존 담기 동작은 그대로 두고 목록 위에 위 지연 안내를 한 번 표시하며, 각 품목은 `재고 확인 필요`로 표시한다. 실제 노출 상품이 0개인 기존 빈 상태와 재고 조회 실패를 같은 문구로 합치지 않는다.

## 7. 읽기 흐름

1. 기존 매장 인증/링크 검증으로 회사·매장·노출 품목을 확정한다.
2. 노출 품목 ID를 회사 범위로 묶어 `inventory_balances`, 재고 설정, 확인된 단위 환산을 한 번에 읽는다.
3. 순수 판정 함수가 `있음/적음/없음/확인 필요`와 기준 시각을 만든다.
4. 품절 품목만 같은 노출 범위에서 대체 후보를 계산한다.
5. 주문 제출 시 서버가 재검증하고, 예약 계약이 켜진 회사에서만 원자적으로 차단/예약한다.

## 8. 구현 선행 조건

- E 재고 원장과 `inventory_balances`가 대상 회사에서 적용·대조 완료
- 판매 상품의 재고 추적 설정과 기본/판매 단위 환산 확인
- 예약 테이블과 주문 RPC의 잠금 순서·멱등성·취소 해제 계약 승인
- 기존 매장 링크/회원 권한 경계 재사용 확인
- 기본 OFF + 회사 allowlist, 대표 승인 전 활성화 금지

## 9. 필수 검증

- 있음/적음/없음/확인 필요 경계값과 판매 단위 환산
- 다른 회사 및 다른 매장 비노출 품목·대체 후보 차단
- 지연·balance 없음·대조 오류를 품절로 오판하지 않음
- 원가·재고가치·매입처 canary 비노출
- 두 매장의 마지막 수량 동시 주문에서 한 건만 예약 성공
- 주문 취소/실패/멱등 재호출 시 예약 정확히 해제 또는 재사용
- 품절 후보 자동 선택 없음, 매장 명시 선택만 허용
- PC 1440px/모바일 390px에서 상태·지연 안내와 담기 차단 사유가 잘리고 넘치지 않음

## 10. 이번 문서에서 결정하지 않는 것

- 재고 수량 자체를 매장에 공개할지 여부
- 회사별 허용 지연시간을 15분과 다르게 둘지 여부
- 대체 상품의 세부 유사도 점수
- 창고별 재고·배송 권역 배정

이 네 항목은 실제 사용 회사의 재고 정확도와 예약 운영을 확인한 뒤 별도 승인한다.
