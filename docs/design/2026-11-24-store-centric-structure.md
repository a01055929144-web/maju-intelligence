# 매장 중심 구조 설계 (2026-11-24 대표 요구 정리 · 컨트롤타워)

> 이 문서 하나가 기준이다. 작업 지시서(CX-140~)는 여기서 쪼갠다. 새로 만들기보다 있는 것을 다시 쓴다.

## 0. 원칙
- **버그 0:** 판매가 계산은 한 곳(`self_order_price_v2` 순서: 약속가 → 매장 카탈로그 → 기본가)만 쓴다. 화면·API가 가격을 따로 계산하지 않는다. 모든 표는 `company_id`로 나뉜다. 새 기능은 플래그 OFF + 회사 allowlist. 운영 DB 변경은 대표 승인 후.
- **토큰·개발비 최소:** 이 문서로 먼저 확정 → 단계별 PR 묶음. 한 PR = 한 고객 행동. 큰 파일(`lib/store.ts`, 지도)은 새 파일로 빼서 붙인다. 감시 스크립트 1개.
- **링크는 입구일 뿐:** 매장이 무엇을 보는지는 "링크"가 아니라 **매장-고객사 관계**가 정한다.

## 1. 용어
| 용어 | 뜻 | 지금 데이터 |
|---|---|---|
| 고객사 | MAJU를 쓰는 식자재 공급사(예: 제이에스리테일) | `companies` |
| 매장 | 음식점. 여러 고객사와 거래할 수 있음 | `store_profiles`(매장 1개) ↔ `store_accounts`(고객사별 연결, `company_id`+`store_profile_id`+`customer_id`) |
| 기존 매장 | MAJU 전부터 그 고객사와 거래하던 매장 | `normalized_customers`(거래처) + 매출 원장 |
| 신규 매장 | 마주가 리스트업·영업한 매장 | 리드(`business_permit_leads`) → 가입 |
| 마주 관리자 | 대표(플랫폼 운영자) | `/admin` |
| 우리 품목 | 그 매장이 쓰는 품목 목록 | `store_product_preferences`(매장 즐겨찾기) — "회사 지정" 표시 없음 |

## 2. 매장 종류별 규칙
### 2-1. 기존 매장 (고객사가 먼저 준비)
1. 고객사가 **매출 원장 업로드**(11월분 또는 2026-01-01~11-24) → 거래처·품목·최근 단가가 쌓임. (화면 `/revenue/transactions` "매출 원장", 표 `sales_transactions` 있음 · 운영 0행. 품목이 이름 문자열이라 **상품 연결 단계 필요**)
2. 원장에서 매장별 **우리 품목 + 최근 거래 단가** 자동 세팅 → 고객사가 확인·수정. 원장에 없는 품목도 추가 가능(영업용).
3. 매입가가 있으니 품목별 **이익률 자동 계산**.
4. 고객사가 매장 **연락처로 초대 준비**(이름·대표·주소·전화). 매장이 카카오로 가입하면 **준비된 매장 정보에 자동 연결** → 바로 주문. (`store_owner_activation_requests`의 `prepared_by_company_member_id`·`phone` = **S-3d 개업 준비 가입 게이트, 묶음 2, 운영 미적용** — 이것을 기존 매장 초대에도 쓴다)
5. 매장 화면 기본은 **우리 품목**. 그리고 **전체 상품**을 같이 보여 매출 증대("이것도 취급하네", 행사·추천 표시).

### 2-2. 신규 매장 (마주가 영업)
1. 입구: 오프라인(단가표·견적서·전단지 QR) / 온라인(인스타·톡톡·카페 링크). **입구마다 출처 코드**(짧은 주소 재사용).
2. QR → 카카오 가입 → 매장 등록 → 링크로 온 매장은 **자동 외식업 확인**(CX-139 A).
3. 가격은 **마주 관리자가 허용한 고객사만** 보인다(신규 매장은 마주 관리 대상).
4. 받는 것: 단가표 · 견적서 · 약속가(매장 앞 고정가) · 전체 상품.

### 2-3. 공통 — 다른 고객사 보기
- 한 매장이 **다른 업종 고객사**(예: 식자재 매장이 정육·주류 고객사)의 단가표·견적서도 본다.
- **신규 매장:** 마주 관리자가 허용한 고객사만.
- **기존 매장:** 그 매장의 원래 고객사와 **협의(동의) 후**에만 다른 고객사 노출.
- 주문·장바구니는 **고객사별로 분리**(배송·마감·결제가 고객사마다 다름).

## 3. 공동 영업
| 영업 주체 | 비용 | 기록 |
|---|---|---|
| 배송기사(가는 길) | 없음 | 현장 기록(CX-135) · 배송 위치 |
| 고객사 영업자·대표 | 없음 | 현장 기록 · 영업 위치(파랑) |
| 알바(마주 고용) | 있음 · 14~18시 · 방문 1건당 | 현장 기록 사진 필수 · 배정(CX-137) · 출처 코드 |
| 마주 관리자 직접 | 있음 | 오프라인·온라인 · 즉시 사용성 확인 |
- 마주 관리자가 고객사 매입가를 보고 제안 단가를 정하는 것은 **고객사 동의(약관·계약)** 가 먼저다. 동의한 고객사만, 매입가는 관리자 화면에서만, 매장에는 절대 노출 금지.

## 4. 데이터 — 있는 것 재사용 / 새로 필요한 것
| 필요 | 있는 것 | 새로 |
|---|---|---|
| 매장 가격 | `self_order_price_v2`, 카탈로그 템플릿(양식·일식)·매장 연결, 약속가 `customer_price_agreements`(0행) | 없음 |
| 우리 품목 | `store_product_preferences`(매장 즐겨찾기) | `assigned_by_company`·`source`(원장/회사/매장)·`last_price` 열 |
| 원장 → 우리 품목 | `sales_transactions`, 매출 원장 화면, 매칭 함수 `lib/store/08-sales-transaction-*` | 원장 품목명 → 상품 연결 + 매장별 우리 품목 생성 |
| 매장 초대 | S-3d(운영 미적용), `store_owner_activation_requests` | S-3d 운영 적용 + 고객사 초대 화면 |
| 링크 없는 매장 화면 | 매장 구성원 세션(`STORE_MEMBER_SESSION`), `store_member_catalog_v2`(여러 고객사 묶음) | 매장 홈을 링크 대신 관계로 구성 |
| 신규 매장 고객사 허용 | `/admin/stores` | `admin_store_company_access`(매장×고객사, 관리자 허용) |
| 기존 매장 타 고객사 동의 | 없음 | 동의 기록(원 고객사 동의 → 노출) |
| 출처 코드 | 짧은 주소·`pricing_document_share_links` | 출처 이름(전단지 A·인스타·톡톡) |

## 5. 화면
- **고객사 · 매장 목록 → 매장 상세(한 화면):** 기본 정보·초대 상태 / 적용 카탈로그 / 우리 품목(원장에서 채우기·추가·단가·이익률) / 받은 문서(단가표·견적서·약속가) / 주문 이력.
- **매장 앱 홈:** [우리 품목] [받은 단가표·견적서] [전체 상품] + 거래 고객사 전환. 링크 없어도 보임.
- **마주 관리자:** 신규 매장 목록 → 고객사 허용 / 알바 배정 / 출처별 성과.
- **링크 관리:** 공개 단가표 링크·QR만. MAJU 공통 틀(왼쪽 메뉴·가격 탭) 적용.

## 6. 단계 (의존 순서 · PR 묶음)
| 단계 | 목표 | 작업 | DB 승인 |
|---|---|---|---|
| **1** 기존 매장 주문 | 이번 주 | ① 링크 관리 공통 틀 ② 매장 홈을 관계 기준 3칸으로(링크 불필요) ③ 매장 상세 + 우리 품목(회사 지정 열 추가) ④ S-3d 적용 + 기존 매장 초대 | ③ 열 추가, ④ S-3d |
| **2** 원장 → 자동 세팅 | 다음 주 | 매출 원장 업로드 → 상품 연결 → 매장별 우리 품목·최근 단가·이익률 | 필요 시 |
| **3** 신규 매장 | 알바 시작 전 | CX-139 A·C·D(자동 확인·안내·알림), 관리자 고객사 허용, CX-137 알바 배정·출처 코드 | 허용 표 |
| **4** 다른 고객사 보기 | 이후 | 신규: 관리자 허용 노출 / 기존: 원 고객사 동의 흐름, 고객사별 장바구니 | 동의 표 |
- 보류: CX-139 B(매장마다 링크 자동 발급) → **불필요**(2단계 매장 홈이 관계 기준이 되면 사라짐). CX-134(부가세 포함가) → ERP 전.

## 7. 각 단계 공통 시험(버그 0 체크)
다른 고객사 매장·가격이 절대 안 섞임 / 확인 전 매장은 가격 0 / 우리 품목 외 상품도 같은 가격 함수 / 기존 링크로 들어온 매장도 그대로 동작 / 모바일 390·PC 1440 / 플래그 OFF면 지금과 100% 동일.

## 8. 결정 필요
1. 기존 매장: "우리 품목만 주문"인가, "전체 상품도 주문 가능(기본 화면만 우리 품목)"인가.
2. "다른 업종" 기준: 고객사 업종 분류(식자재·정육·농산·주류·공산 …)를 관리자가 지정?
3. 마주 관리자의 고객사 매입가 열람·제안 단가: 고객사 동의를 약관에 넣을지, 고객사별 동의 버튼으로 할지.
4. 1단계 우리 품목의 첫 채움: 원장(2단계) 전까지는 회사가 직접 고르기로 시작해도 되는지.
