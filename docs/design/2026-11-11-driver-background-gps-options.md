# 기사 백그라운드 실시간 위치 — 방법 정리 (2026-11-11 · 컨트롤타워)

> 상태: **기록용(결정 보류)**. 대표 결정(23:13): 이 방법들은 문서로만 남기고, 지금은 D차수 **웹 기본 최적화 먼저**. 실행은 웹 최적화 후 다시 결정.

## 왜 웹으로는 안 되나
- 브라우저는 **화면에 보이는 페이지만 위치를 받는다**(개인정보·배터리 정책). 화면이 꺼지거나 내비 앱으로 넘어가면 `watchPosition`이 멈춘다.
- 확인한 우회(모두 불가): 다른 앱 위 버블·뱃지(앱 권한 필요) · 화면 속 화면(PiP, 안드로이드는 동영상만이고 위치 멈춤) · 무음 재생으로 페이지 유지(위치는 화면 보일 때만, 배터리·불안정) · 서비스 워커/푸시/백그라운드 동기화(위치 API 사용 불가).
- 웹에서 할 수 있는 최대: 운행 중 화면 꺼짐 방지(Screen Wake Lock), 도착·완료 순간 위치 측정, 화면 복귀 시 즉시 측정 → D-3에 포함.

### ① 공개 위치 앱 (앱 개발 없이 가능한 1순위 우회)
- [Traccar Client](https://www.traccar.org/client-configuration/)(안드로이드·아이폰, 무료·오픈소스): 거리/시간 간격, 정지 감지, 끊김 시 모아 보내기, 안드로이드 깨우기 옵션, 설정 비밀번호.
- [OwnTracks](https://owntracks.org/booklet/tech/http/)(안드로이드·아이폰, 무료·오픈소스): HTTP POST JSON, Basic 인증·`X-Limit-U/D` 헤더, 서버 못 닿으면 쌓아 두고 재전송.
- MAJU 할 일: 위치 수신 API(기사별 비밀 토큰, 회사 격리, **운행 중 위치만 저장**) · 한글 설정 안내 화면([복사] 버튼·캡처) · 관제 지도에 "위치 앱 연결됨 · N분 전/꺼짐".
- 약점: 앱 UI 영문(한국어 번역 여부 미확인), 앱 2개, 배터리 최적화 제외 설정 필요(삼성 등), MAJU 이름 안 보임. QR/링크 설정 지원 여부 미확인.
- 권장 운용: 처음 설정은 관리자가 대신, 기사는 매일 켜기/끄기만. **기사 1~2명 시험 → 불편하면 ④로**(수신 API 재사용).

### ② 텔레그램
- 기사가 MAJU 봇에게 "실시간 위치 공유" → 봇 API가 갱신 수신. 간격·공유 시간은 텔레그램 정책을 따름(세부 확인 필요). 저장소에 보류된 텔레그램 모듈 있음.

### ③ 차량 GPS 단말기
- 회사 소유 차량일 때 가장 안정적. 기사 교체·폰 꺼짐과 무관. 도착·완료·사진은 MAJU 웹/앱과 병행.

### ④ MAJU 기사 앱
- 웹을 감싼 앱(Capacitor) + 백그라운드 위치(움직일 때 5~15초, 끊김 시 모아 보내기), 안드로이드 상단 "배송 중" 알림(필요하면 운행 버블). **안드로이드 먼저**(기사 대다수), 아이폰 나중.
- 배포: 설치 파일 직접 배포/내부 테스트 → Google Play(개인 계정은 출시 전 테스터 20명·14일 비공개 테스트, 조직 계정은 D-U-N-S) · Apple(테스트플라이트 → 심사). 백그라운드 위치 사유 심사. 서명 키는 대표 보관.
- 관제 지도는 실시간 구독(D-4)과 같은 수신 구조.

## 공통 (어떤 방법이든)
- **위치정보법**: 기사 위치를 고객사에 보여 주는 서비스 → 위치기반서비스사업 신고·개인위치정보 동의가 필요할 가능성이 높다(법률 확인 필요). 기사 동의 화면, **근무(운행) 중에만** 기록, 보관 기간 안내.
- 저장: 최신 위치 1행 즉시 갱신 + 경로(`staff_location_events`) — 핑이 잦아지면 묶어서 저장(기사 10명·5초·10시간 ≈ 하루 7만 행).
