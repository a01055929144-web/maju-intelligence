# 견적·상품 매핑·가격 자동화 설계 (2026-10-15)

> 상태: 설계 승인 대기. 구현·운영 마이그레이션 금지. SQL 초안은 `docs/sql-drafts/quote-pricing-automation-phases-2-4.sql`에 있다.

## 0. 확정된 선행 작업

- 견적 임시저장·수정은 커밋 `7f74e97`에서 구현됐다.
- 발행 견적 수정 방식은 **동일 견적 갱신**이다. 견적 ID와 공개 토큰은 유지하고 품목·금액·유효기간 스냅샷을 교체한다.
- 공개 견적의 원가·마진 비공개 규칙과 만료 안내 화면은 변경하지 않는다.

## 1. 기존 `product_catalog` 처리 결정

`product_catalog`를 폐기하지 않고 **표준 품목 원장으로 승격**한다. `sales_quote_items.product_catalog_id`가 이미 이 테이블을 참조하므로 FK 교체와 견적 회귀를 피할 수 있다. 운영 데이터가 현재 0건이라 의미 전환 비용도 낮다.

- 기존 판매 필드는 전환기 표시 폴백으로 유지한다.
- 정규 필드(이름, 브랜드, 원산지, 규격 수치/단위, 입수량, 판매 단위, 분류)를 추가한다.
- 기존 `purchase_price`는 전환기 캐시로만 유지한다. 최종 원가는 기본 공급 상품 또는 활성 공급 상품 최저가에서 읽는다.
- 유통사 원본은 새 `supplier_products`, 매핑은 새 `supplier_product_matches`에 분리한다.
- 발행된 견적은 `sales_quote_items`의 품목명·원가·판매가 스냅샷을 계속 사용한다.

## 2. 1-B — 업로드와 상품 매핑

### 데이터 모델

- `product_suppliers`: 회사별 유통사. 엑셀 열 매핑은 기존 `excel_mapping_presets`에 `upload_type='product-catalog'`, `preset_name='supplier:<id>'`로 저장하므로 스키마 변경이 없다.
- `product_brand_dictionary`: 회사가 편집하는 브랜드 표준명과 별칭 사전.
- `product_catalog`: 고객 견적서에 표시되는 표준 품목. 이름·브랜드·원산지·규격·입수량·판매 단위·카테고리·용도·대표 메뉴를 가진다. 빈 값은 `18L`/`통` 같은 placeholder 대신 `규격 미정`/`단위 미정`으로 표시한다.
- `supplier_products`: 유통사 원문과 파싱 결과, 최신 원가·관측일. 식별 순서는 유통사 상품코드 → 바코드 → 정규화 이름+규격+단위 fingerprint다.
- `supplier_product_cost_history`: 업로드별 원가와 참고 판매가 최저·중앙값.
- `supplier_product_matches`: 유통사 상품 → 표준 품목 다대일 연결. 후보 3개와 속성별 일치 여부를 저장하고 `auto`/`confirmed`는 유통사 상품당 하나만 허용한다.
- `product_supplier_defaults`: 표준 품목의 기본 공급 상품. 없으면 활성·원가확정 공급 상품 중 최저가를 내부 추천하되 사용자가 바꿀 수 있다.
- `product_catalog_imports`: 파일·열 매핑 스냅샷·신규/갱신/제외/경고·실행자 감사 기록.
- `customer_product_prices`: 거래처·유통사 상품·표준 품목(매핑 전 null 가능)·판매 단가·일자·수량·출처 파일. 업종 추천과 실제 단가 근거다.

### 파일 처리

- `.xls`, `.xlsx`, `.csv` 지원. 구형 BIFF는 구현 시 SheetJS 공식 배포 0.20.3을 업로드 시점에 동적 로딩한다. 실제 파일 읽기 검증은 통과했지만 승인 전 의존성은 커밋하지 않았다.
- 헤더 공백·괄호·구두점을 제거해 자동 추천하되 원가 열은 사용자가 반드시 확정한다.
- `[합 계]`, 빈 상품명, 수량 음수는 가격 산출에서 제외한다. 반품은 원본 건수에만 남긴다.
- 동일 상품은 최신 일자 원가, 판매가 최저·중앙값을 미리보기에 표시한다.
- 미리보기: 신규/갱신/제외, 원가>판매가, 원가==판매가 과다, 원가 미확정.

### 파서 (`domains/product` 순수 함수)

1. `*`, `**`, `★`, `先`, `■` 같은 내부 표시를 제거하되 원문은 보존한다.
2. 괄호와 `/` 토큰을 브랜드·원산지·용도·공급처 메모로 분류한다.
3. 국내산/국산/수입산 및 국가명+`산` 사전. 국산과 국내산은 비교 시 같은 코드다.
4. 회사 편집형 브랜드/별칭 사전(씨제이=CJ). 미일치는 자동 확정하지 않는다.
5. `1.4kg→1400g`, `1.8L→1800ml`; `b/10`, `*4개`, `350g*30봉`; 범위·±는 별도 메모.
6. 결과마다 원본 token과 confidence를 보관한다.

### 매칭

1. 유일 바코드 일치가 최고 우선이다.
2. 확정된 `(회사, 유통사, 상품코드)`는 다음 업로드부터 재사용한다.
3. 이름·브랜드·원산지·규격·단위 5개가 모두 일치할 때만 `auto`다.
4. 일부 일치는 상위 후보 3개. 권장 가중치는 이름 35, 규격 20, 브랜드 15, 원산지 15, 단위 15다. 사람이 확정 전 견적 원가로 사용하지 않는다.
5. 화면에서 후보별 ✓/✗, 일괄 확정, 새 표준 품목, 표준 품목 편집을 제공한다.

초기 표준 품목이 0건이므로 첫 업로드의 실제 자동 매칭률은 0%다. 바코드 보유 8.3%는 표준 바코드가 생긴 뒤 가능한 상한 후보일 뿐이다. 5항목 일치율은 현재 산출할 수 없다. 확정 후 같은 유통사 코드의 재업로드는 100% 재연결 가능하다.

### 화면

- `/revenue/products`: 표준 품목 / 유통사 상품 / 상품 매핑 탭
- 업로드 드로어: 유통사 → 파일 → 열 매핑 → 미리보기 → 저장
- 상품 매핑: 미매칭/후보/확정, 속성별 ✓/✗, 후보 3개, 일괄 확정
- 견적 편집기: 내부 공급처별 원가 비교. 고객 출력에는 판매가만 표시

## 3. 1-C — 식자재 용도 추론

용도는 동일 상품 판정에 쓰지 않고 후보 순위·대체재·템플릿 추천에만 쓴다.

- 조리 태그: 구이, 찌개·국, 조림, 튀김, 볶음, 무침, 찜, 전골·탕, 육수, 생식·회
- 전처리 태그: 손질, 다짐, 채, 슬라이스, 대패
- 메뉴 태그: 김밥, 볶음밥, 냉면, 샤브, 초밥 등
- `product_usage_evidence`: source(`rule|purchase|ai|manual`), confidence, 근거, 확정 여부. manual이 최우선이며 AI는 확인 전 `추정` 배지다.
- 순서: 상품명 규칙 → 구매 거래처 업종 통계 → 못 정한 품목만 AI(호출 상한·별도 승인).
- 활용: 같은 용도 대체재/원가 비교, 업종·메뉴별 단가표 초안, 리드 메뉴·리뷰 기반 견적 초안.

## 4. 실제 샘플 분석

`배동바지 매입가.xls`(BIFF, Sheet1): 66열, 데이터 1,253행(거래 1,252 + 합계 1), 거래처 97곳, 상품코드 1,090종. 반품 152행 제외 후 가격 산출 대상은 1,100행이다. 매입가=단가는 1,040행(83.0%), 매입가>단가는 171행, 매입가 빈값은 0행이다.

| 항목 | 상품 수 | 후보율 | 의미 |
|---|---:|---:|---|
| 이름 | 1,090 | 100.0% | 내부 기호 제거 후 확보 가능 |
| 브랜드 사전 후보 | 91 | 8.3% | 초기 사전 기준 하한, 사람 확인 필요 |
| 원산지 | 656 | 60.2% | 상품명/규격 명시분 |
| 중량·용량 규격 | 893 | 81.9% | kg/g/L/ml 기준 |
| 판매 단위 | 1,069 | 98.1% | ERP 단위 열 기준 |
| 입수량 | 349 | 32.0% | `b/N`, `*N개`, `중량*N봉` 초안 규칙 |
| 바코드 | 91 | 8.3% | 유효 길이 기준 |
| 용도 규칙 태그 | 54 | 5.0% | 보수적 키워드 기준 |

브랜드/입수량은 정답 라벨이 없어 성공률이 아니라 **추출 후보율**이다. 승인 후 100개 층화 표본을 사람이 판정해 precision을 측정한다.

샘플에는 업종이 없어 업종별 상위 구매 품목은 아직 산출할 수 없다. 거래처 수 기준 참고 품목은 무우(3곳), 쌀·대파·오이·두부·부추·콩나물(각 2곳)이다. 업종 예시는 `customer_product_prices` 적재 후 거래처 업종을 조인한다.

## 5. 2단계 — 업종별 영업 단가표

- `price_list_templates`, `price_list_template_items`; 업종별 기본 하나는 `price_list_industry_defaults(company_id, industry)` PK로 강제한다.
- 가격: `fixed ?? 원가 × (1 + (품목마진 ?? 템플릿마진)/100)`.
- 원가 변경은 미발행 초안에만 재계산 가능하고 발행 견적은 고정한다.
- 구매 이력·용도 기반 템플릿은 초안만 만들고 사람이 확정한다.

## 6. 3단계 — 자동 견적 초안

`domains/quote/createQuoteDraftFromTemplate`: 리드 업종+메뉴 → 기본 템플릿 → `draft`, 공개 비활성. 같은 리드의 미발행 draft는 중복 생성하지 않는다. 원가 0/미확정/비활성/미매핑 품목은 제외 사유와 건수를 표시하고 회사 마진 하한을 지킨다. 리드 버튼과 `견적 요청` 상태 전환에서 호출하되 자동 발행은 금지한다.

## 7. 4단계 — 브랜드 우대가

`customer_brands`와 거래처/리드의 테넌트 안전 복합 FK를 둔다. 지점 접미 제거는 후보 제시만 하고 사용자가 확정한다. 최근 accepted/sent 브랜드 견적 → 브랜드 마진 → 업종 템플릿 순으로 적용한다. 공개 문서는 `○○ 가맹점 우대가`만 표시하고 원가·마진은 숨긴다.

회사에는 `min_quote_margin_percent`, 견적에는 발행 당시 문구를 고정하는 `pricing_label`을 추가한다.

## 8. 가격 예시

| 유형 | 원가 | 규칙 | 판매가 |
|---|---:|---|---:|
| 일반 | 10,000원 | 템플릿 12% | 11,200원 |
| 품목 마진 | 10,000원 | 품목 15% 우선 | 11,500원 |
| 브랜드 | 10,000원 | 우대 10%, 회사 하한 8% | 11,000원 |

브랜드 마진이 6%면 회사 하한 8%를 적용해 10,800원이다.

## 9. 구현 순서

설계/SQL 승인 → 운영 마이그레이션·RLS 검증 → 파서/업로드/매핑 → 규칙·구매 이력 용도 추론 → 업종 단가표 → 자동 draft → 브랜드 우대가. 각 DB 적용 전에 멈추며 기존 상품/견적 데이터는 삭제·자동 변환하지 않는다.
