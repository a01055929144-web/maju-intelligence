# 역할별 권한 계약

기준: [백엔드 계약서](00_BACKEND_CONTRACT.md) 9절. 현재 API는 `manage_sales` 등 capability를 사용한다. 이 표는 목표 권한이며 운영에서 역할 변환 전까지는 기존 권한 판정을 유지한다.

| 자원·API | 대표 | 경리 | 직원 | 기사 | 매장 링크 |
|---|---|---|---|---|---|
| 가격·견적·단가표 | 읽기·쓰기 | 읽기 | 담당 범위 읽기·작성 | 없음 | 게시된 가격만 |
| 매장 주문 | 읽기·쓰기 | 읽기 | 접수·수정·마감 | 배송 범위 읽기 | 자기 매장 주문·내역 |
| 매출·매입 전표 | 읽기·확정·취소 | 읽기·확정·취소 | 업무 범위 작성, 돈 읽기 | 없음 | 없음 |
| `partner_ledger_entries`·예치금 | 읽기·지급 | 읽기·지급 | 허용된 요약 읽기 | 없음 | 자기 주문 결제 안내만 |
| 상품·공급처·가져오기 | 읽기·쓰기 | 읽기 | 업무 범위 읽기·쓰기 | 없음 | 공개 품목명·판매가만 |
| 재고·출고·발주 | 읽기·쓰기 | 읽기 | 준비·발주·입고 | 배송 범위 읽기 | 노출 설정된 재고 안내만 |
| 직원·회사 설정 | 읽기·쓰기 | 없음 | 없음 | 없음 | 없음 |

API는 매 요청마다 회사·역할·capability를 확인한다. 매장 링크는 직원 세션과 분리하며, 토큰으로 확인한 `customer_id` 밖의 주문을 읽지 않는다. DB의 service role은 브라우저에 공개하지 않고, 회사 범위와 복합 FK로 다른 회사 행 참조를 차단한다.
