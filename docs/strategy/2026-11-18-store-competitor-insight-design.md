# CX-113 매장 PC 상권·경쟁 분석 설계

## 1. 문서 상태와 범위

- 상태: 설계 완료, 구현 보류
- 대상: 매장 PC의 `상권` 탭
- 전제: CC-45 지도 공통화와 CC-46-A 전국 영업 인허가 데이터가 먼저 준비되어야 한다.
- 공개 방식: 기본 OFF, 회사별 허용 목록으로만 연다.
- 이번 작업에는 코드, 키, 스크래핑, 외부 API 호출, 운영 DB 변경, 배포가 없다.
- CX-102 및 CX-112 문서와 구현 범위를 섞지 않는다.

첫 화면은 자사 매장을 중심으로 반경 500m 또는 1km의 동종 업소를 보여준다. 사용자는 전체/동종 업종, 최근 30일/90일 신규 개업, 영업/폐업 상태를 바꿔 볼 수 있다. 표시 대상은 공식 인허가 사실, 업소명, 업종, 인허가일·폐업일, 공개 주소, 거리, 블로그 언급 수와 외부 링크로 제한한다.

자동 수집 대상에서 영업시간, 메뉴·가격, 리뷰 본문, 블로그 본문, 대표자 연락처는 제외한다. 신규 경쟁점 알림, 지역 생존율, 유통사 히트맵은 후속 단계로 미룬다.

## 2. 지도 재사용 범위

| 구분 | 재사용 대상 | 원칙 |
| --- | --- | --- |
| 직접 재사용 | `KakaoAddressMap`, `KakaoMapMarker`, `KakaoRadiusOverlay` | 기존 SDK 로더, 중심 이동, 마커, 반경 표시를 그대로 쓴다. 상권 탭에서 SDK를 다시 로드하지 않는다. |
| 조건부 재사용 | `MapListRow` | 리드 행동이나 단계 변경 없이 공개 경쟁점 정보만 받도록 사용할 수 있을 때만 쓴다. |
| 모양만 참고 | 지도 필터 칩, 좌우 패널 배치 | 경쟁 분석 전용 상태를 두고 리드 상태와 연결하지 않는다. |
| 재사용 금지 | `MapLeadFilterStrip`, `LeadListPanel`, `StoreManagementPanel`, `StageChipSelect` 및 리드·고객 API | 영업 리드, 고객 관계, 담당자 메모가 매장 화면으로 새지 않게 도메인을 분리한다. |

구현 시에도 이 문서 때문에 기존 지도 파일을 먼저 쪼개지 않는다. 실제 중복이 생길 때에만 지도 껍데기나 범용 목록 행을 최소 단위로 추출한다. 좌표가 이미 있는 업소는 추가 지오코딩 없이 표시하고, 화면 범위 밖 결과는 클러스터 또는 개수 요약으로 처리한다.

## 3. 무료·공식 데이터 출처

| 데이터 | 출처와 사용법 | 저장·표시 범위 | 제한 |
| --- | --- | --- | --- |
| 개업·폐업·업종·주소 | [지방행정 인허가 데이터개방(LOCALDATA)](https://www.localdata.go.kr/)의 최신/이력 인허가 정보 | 공식 원본 식별자, 상태, 인허가일·폐업일, 업종, 공개 사업장 주소, 원본 갱신 시각 | 주기 서버 동기화만 허용한다. 이용 조건과 호출 한도는 신청한 서비스·키의 현재 메타데이터를 따른다. |
| 서울 지역 보완·검증 | [서울 열린데이터광장](https://data.seoul.go.kr/)의 해당 인허가 데이터셋 | LOCALDATA와 같은 공개 필드 및 출처 표시 | API는 한 요청 최대 1,000건이다. 데이터셋별 이용허락과 제한을 확인하고, 화면 요청마다 호출하지 않는다. |
| 블로그 관심도 | [네이버 검색 API - 블로그](https://developers.naver.com/docs/serviceapi/search/blog/blog.md) | 검색 결과 총수, 최근 제목·링크, 집계 시각만 사용한다. 본문은 수집하지 않는다. | 공식 일 한도는 25,000회다. 아래 내부 예산과 캐시를 우선한다. |
| 지도 표시·장소 이동 | 기존 Kakao Maps JavaScript SDK와 카카오 장소 링크 | 지도, 좌표, 사용자가 누르는 외부 링크 | 현재 공식 무료 쿼터는 Web SDK 300,000회/일, 주소·좌표·키워드·카테고리 REST API 각각 100,000회/일이며 전체 API 월 3,000,000회다. 쿼터는 변경될 수 있으므로 운영 시 [공식 쿼터 문서](https://developers.kakao.com/docs/latest/ko/getting-started/quota)를 기준으로 한다. |

LOCALDATA를 전국 기준 원본으로 삼고 서울 데이터는 누락 확인과 보완에만 쓴다. 동일 업소는 출처 원본 식별자를 우선하고, 없을 때만 정규화한 업소명·주소·업종·인허가일 조합으로 후보를 만든다. 서로 다른 출처 값을 덮어쓰지 않고 출처와 기준 시각을 함께 남긴다.

무료 공식 API가 없는 메뉴·가격과 경쟁점 리뷰 본문은 자동 수집하지 않는다. 유료 Google Places 기반 영업시간·평점도 1차 범위에서 제외한다. 검색 결과나 지도 웹페이지를 긁어 빈칸을 채우지 않는다.

## 4. 개인정보와 회사 격리

1. 사용자의 `company_id`와 연결 매장 ID는 로그인 세션에서 서버가 정한다. 요청 본문의 회사·매장 ID를 권한 근거로 믿지 않는다.
2. 매장은 자기 회사에 연결된 매장 중심의 결과만 요청할 수 있다. 응답은 공개 인허가 필드와 집계치만 명시적으로 골라 반환한다.
3. 유통사의 리드 단계, 고객 관계, 담당자, 메모, 주문·매출 정보는 조회·조인·응답하지 않는다. 매장 화면이 영업 리드 테이블을 직접 읽는 구조도 금지한다.
4. 공개 원본에 포함되어도 대표자 개인 전화번호·이메일과 주거지로 볼 수 있는 상세 주소는 표시하지 않는다. 블로그 본문과 리뷰 작성자 정보도 저장하지 않는다.
5. 캐시 키에는 `company_id + store_id + 반경 + 업종 + 기간`을 포함한다. 다른 회사 결과를 공유 응답으로 재사용하지 않는다.
6. 검색어와 외부 응답을 로그에 그대로 남기지 않는다. 운영 로그에는 출처, 호출 수, 상태, 지연 시간, 캐시 여부만 기록한다.
7. 지역 통계는 5개 미만 업소 집단을 순위나 비율로 노출하지 않는다. 상세 원본 접근과 집계 접근은 서버에서 분리한다.

서비스 권한 키는 서버에만 두며 브라우저 응답, 오류 메시지, 분석 로그에 넣지 않는다. 운영 데이터 저장소의 관리자 권한으로 매장 화면을 직접 조회하게 하지 않고, 회사 범위가 강제된 읽기 경로만 둔다.

## 5. 캐시와 호출 한도

| 대상 | 갱신·캐시 | 내부 안전 한도와 실패 처리 |
| --- | --- | --- |
| LOCALDATA·서울 인허가 | 공식 갱신 이후 하루 1회 증분 동기화, 원본 기준 시각 표시 | 화면에서는 외부 호출하지 않는다. 재시도는 지수 백오프하고 마지막 정상 자료를 최대 72시간 `자료 갱신 지연`과 함께 보여준다. |
| 거리·밀도 | 기존 좌표와 전국 업소 자료로 서버 내부 계산, 결과 24시간 캐시 | 사용자 조작마다 외부 지오코딩하지 않는다. 좌표가 없는 건은 배치 보완 대상으로 보내고 그 화면에서는 제외한다. |
| 네이버 블로그 | `정규화 업소명 + 행정동 + 업종`별 24시간 캐시. 탭에서 상세 행을 펼치거나 사용자가 새로고침할 때만 갱신 | 회사당 신규 검색 100회/일, 매장·업소 조합당 1회/일, 전체 20,000회/일을 기본값으로 둔다. 공식 일 한도의 80%에 도달하면 신규 호출을 멈추고 캐시와 외부 검색 링크만 제공한다. |
| Kakao 지도 | 기존 SDK 로더와 좌표 캐시 재사용 | 공식 일·월 쿼터의 80%에서 경고하고, 한도 근접 시 장소 검색·지오코딩 보완부터 끈다. 기본 지도와 이미 저장된 좌표는 유지한다. |

내부 한도는 환경별 설정값이며 공식 한도보다 낮게 유지한다. 한도 초과나 제공자 장애는 상권 탭 전체 장애로 만들지 않는다. 부가 정보만 `업데이트 지연`으로 표시하고 인허가 기반 마커·목록은 마지막 정상 자료로 제공한다.

이번 설계에서는 새 캐시 테이블이나 운영 DB 변경을 만들지 않는다. 구현 단계에서는 기존 전국 업소 자료와 좌표 캐시를 우선 사용하고, 영속 캐시가 더 필요하면 별도 DB 변경안으로 검토한다.

## 6. 구현 계약과 완료 조건

구현 API는 매장 세션, 반경, 업종, 기간만 받아 공개 필드와 집계치만 반환한다. 외부 제공자 키와 원본 응답은 반환하지 않는다. 목록에는 자료 출처와 `기준 시각`을 표시하고, 블로그·장소는 명확한 외부 링크로 연다.

구현 완료 조건은 다음과 같다.

- 기능이 기본 OFF이며 허용된 회사에서만 상권 탭이 보인다.
- 다른 회사 매장 ID를 넣어도 결과가 반환되지 않는다.
- 유통사 리드·고객·메모·주문·매출 필드가 응답과 화면에 없다.
- 인허가 자료만으로 마커·목록·거리·밀도가 동작하고, 네이버·카카오 부가 호출이 실패해도 기본 화면은 유지된다.
- 1440px와 390px에서 지도와 목록을 사용할 수 있고, 키보드로 필터와 목록을 이동할 수 있다.
- 외부 호출 수, 캐시 적중률, 한도 사용률, 마지막 정상 동기화 시각을 운영 지표로 확인할 수 있다.
- 회사 격리, 캐시 키 분리, 한도 차단, 오래된 자료 표시를 자동 검증한다.

## 7. 후속 순서

1. CC-45 지도 공통화와 CC-46-A 전국 업소 자료의 실제 필드·권한 경계를 확인한다.
2. 읽기 전용 응답 계약과 회사 격리 검증을 먼저 구현한다.
3. 인허가 기반 지도·목록을 연 뒤 네이버 언급 수를 선택적 보강으로 붙인다.
4. 실제 사용량을 본 뒤 신규 경쟁점 알림, 지역 추이, 유통사 집계를 각각 별도 과제로 검토한다.
