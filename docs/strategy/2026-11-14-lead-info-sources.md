# 리드 정보 최대 확보 방법 — 네이버·카카오·공공데이터 (2026-11-14 11:39 대표: "어떠한 방법으로든 네이버·카카오 정보를 다 가져오는 방법 강구")

> 결론: **"다 가져오기"는 가능한 만큼 최대로 하되, 공식 경로로만.** 화면 긁기(스크래핑)·자동 브라우저 수집은 각 서비스 약관 위반이고 계정·API 키 차단·법적 위험이 있어 하지 않는다(기존 원칙). 대신 아래 조합이면 영업에 필요한 정보 대부분을 **보이게** 할 수 있다.

## 0. 먼저 알아야 할 약관 사실 (11/14 확인)

- **카카오 로컬 API 결과는 저장 제한**: 카카오 데브톡 공식 답변 — "좌표와 주소 정보를 저장하여 활용하는 형태는 허용하지 않습니다." **저장 가능한 것은 장소 ID와 URL**, 나머지(주소·전화·카테고리·좌표)는 **화면에서 실시간 호출**로 보여 주는 구조만 허용.
- ⚠️ **지금 코드는 카카오에서 받은 카테고리(`kakao_category_name`)와 전화(`phone`)를 리드에 저장함**(`lib/store.ts` 11696·11809·11813). → **약관 위반 소지 — 고쳐야 함(아래 1번).**
- 네이버 검색 API(지역·블로그): 결과 저장·캐시 범위는 네이버 개발자 약관 확인 필요 → 확인 전까지 **링크만 저장**, 나머지는 실시간 표시.
- 공공데이터(인허가·소상공인 상가정보)는 이용허락 범위 제한 없음(출처 표시) → **저장·가공 가능**. 저장해야 하는 값(업종·좌표·면적·개폐업)은 공공데이터로 채우는 게 정답.

## 1. 바로 고칠 것 — 카카오 저장 범위 (P1, 약관)

1. 리드에 저장: **카카오 장소 ID·URL만**. 카테고리·전화·주소·좌표는 저장하지 않음.
2. 리드 상세·지도 미리보기를 열 때 **카카오 JS SDK `services.Places`로 실시간 조회**해 주소·전화·카테고리 표시("카카오 정보 · 실시간").
3. 이미 저장된 카카오 출처 값 정리: `lead_contact_field_sources`로 출처가 카카오인 전화·카테고리를 찾아 비우는 dry-run → 대표 승인 → 실행(업종 보정에 쓴 값은 우리 분류 결과만 남기고 원문 카테고리는 지움).
4. 업종 보정은 카카오 카테고리 대신 **공공데이터 업종**(아래 2번)으로.

## 2. 저장할 정보는 공공데이터로 최대한 (무료)

| 데이터 | 주는 것 | 상태 |
| --- | --- | --- |
| 행안부·서울 인허가 | 상호·주소·좌표·업종(위생업태)·개업/폐업·**면적**·인허가 전화 | 있음(리드 86%). 면적 스위치 켬(다음 배포) → 재조회 |
| **소상공인시장진흥공단 상가(상권)정보** | 전국 영업 중 상가: 상호·지점명·**업종 대/중/소분류**·도로명주소·**좌표**·층 | **새로 추가** — 업종 '기타' 23%(JS)·63.7%(비브)를 공식 분류로 채우고, 좌표 없는 28%를 채우는 데 가장 효과적. 파일(분기 갱신)·API 둘 다 무료 |
| 국세청 휴·폐업 | 사업자번호 있는 곳의 계속/휴업/폐업 | 있음(사업자번호 있는 리드만) |

→ 공통 리드(전체 매장 DB, CC-46-A)에 **인허가 + 상가정보를 합쳐** 저장 → 모든 고객사가 같은 품질로 받음.

## 3. 카카오·네이버는 "연결 + 실시간 표시"로 최대한

| 항목 | 방법 | 저장 |
| --- | --- | --- |
| 카카오 장소 | 매칭 성공률부터 올림(93% 실패 원인 재현 → 좌표 반경 검색·음식점/카페 카테고리 필터·상호 정규화) → 장소 ID·URL | ID·URL만 |
| 카카오 상세(전화·카테고리·주소) | 상세 열 때 JS SDK 실시간 | 안 함 |
| 네이버 플레이스 | 지역 검색 링크 | 링크만 |
| 네이버 블로그 언급 | 블로그 검색 결과 수·최근 글 링크(마케팅 활발도) | 숫자·링크(약관 확인 후) |
| 영업시간·메뉴·가격·리뷰 | 공식 무료 API 없음 → **장소 링크 한 번 눌러 보기** + 아래 4번 | — |

## 4. 사람이 보태는 정보 (회사 전용, 공유 안 함)

- 영업 담당이 방문·통화·카톡 때 알게 된 **영업시간·주력 메뉴·주문 품목·담당자**를 리드에 빠르게 적는 칸(맞춤 견적 서랍 1단계와 같은 칸 재사용).
- 매장이 가입하면 매장이 **직접** 영업시간·메뉴를 입력(자기 정보) → 정확도 최고.

## 5. 비용 드는 선택지 (보류 — 대표 결정 시)

| 선택지 | 주는 것 | 비고 |
| --- | --- | --- |
| 구글 Places | 영업시간·평점·리뷰 수 | 유료, place_id 외 장기 저장 제한 |
| 상권·매출 데이터 업체(민간) | 추정 매출·메뉴·유동 인구 등 | 계약·비용 |
| 카카오·네이버 정식 제휴 | 장소 데이터 대량 이용 | 사업 제휴 필요 |

## 6. 순서 (CC-46에 반영)

1. **카카오 저장 범위 고치기(1번)** — 새 저장 중단은 바로, 기존 값 정리는 dry-run → 승인.
2. 46-2⓪ 매칭 실패 원인 → 성공률 올리기(ID·URL만 저장).
3. **소상공인 상가정보 연동**(파일/API) → 업종·좌표 채우기 — dry-run → 승인.
4. 면적(인허가 재조회) → 폐업 정리 → 공통 리드(46-A·B·C).
5. 리드 상세 "외부 정보(실시간)" 카드: 카카오 실시간 조회 + 네이버·카카오 링크 + 블로그 언급 수.
