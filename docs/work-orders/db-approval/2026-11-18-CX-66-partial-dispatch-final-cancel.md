# CX-66 부분 출고 후 잔량 취소 DB 승인표

상태: **승인 전 초안 — 운영 적용 금지**

검증 기준: CX-62 접수 경계와 CX-66 전체 출고 #1095, CX-75 운영 적용 기록 #1115가 포함된 최신 `main` (`d235827`)

대표 결정: 부분 출고 뒤 남은 수량은 취소한다. 추가로 필요하면 새 주문을 만든다.

## 적용 묶음
- 선행: CX-62 `receive_store_order_with_sale_document` 주문 접수 + CX-66 #1095 전체 출고 1차 SQL
- 연계: CX-62가 만든 `draft` 매출 전표의 줄을 원 주문 스냅샷으로 유일하게 확인한 뒤 실제 출고량으로 줄이고, CX-66의 기존 확정 함수를 한 번만 호출한다.
- `docs/sql-drafts/2026-11-18-CX-66-partial-dispatch-final-cancel.sql`
- `docs/sql-drafts/2026-11-18-CX-66-partial-dispatch-final-cancel.down.sql`
- `docs/sql-drafts/2026-11-18-CX-66-partial-dispatch-final-cancel.pg17.test.sql`

## 보존·대사 계약
- 원 주문 줄 수량·가격·세금 스냅샷과 주문 `known_total`은 바꾸지 않는다.
- 줄마다 실제 출고 수량과 최종 취소 수량을 기록하고 합이 원수량을 넘지 못하게 한다.
- 원 주문 줄과 접수 전표 줄은 전체 스냅샷으로 유일하게 대응될 때만 연결한다. 스냅샷이 완전히 같은 중복 줄은 임의 순번으로 연결하지 않고 부분 출고를 거절한다.
- 작성중 전표에는 실제 출고 수량만 남기며 기존 확정 함수를 한 번 호출한다.
- 확정 전표 합계 = 원장 sale = 실제 출고 줄 금액 + 기존 배송비. 재고는 실제 출고량만 차감한다.
- 출고량이 전부 0이면 주문과 작성중 전표만 취소하고 원장·재고는 만들지 않는다.
- 일부 출고 뒤 같은 주문의 추가 출고는 거절한다. 필요 수량은 새 주문으로 접수한다.
- 묶음 중 한 주문이라도 실패하면 모든 주문·전표·원장·재고·수량을 롤백한다.
- 실제 두 연결의 같은 키·같은 내용은 동일 결과와 요청·원장·재고 1세트로 수렴한다. 같은 주문의 서로 다른 키 동시 경합은 정확히 한쪽만 성공하고 효과를 중복하지 않는다.
- down은 이력이 있으면 거절하고 빈 일회용 검증 DB에서만 복구한다.

## 돈·재고 안전 점검표
| 항목 | 기대 결과 |
|---|---|
| 원 주문 수량·단가·세금·합계 | 변경 없음 |
| 실제 출고 수량 | 출고 줄에 별도 기록 |
| 미출고 잔량 | 같은 거래에서 최종 취소 |
| 과세 공급가 | 실제 출고 수량으로 재계산 |
| 면세 공급가 | 실제 출고 수량으로 재계산 |
| 부가세 반올림 | 전표 줄 생성식 그대로 적용 |
| 배송비 | 부분 출고가 있으면 기존 배송비 유지 |
| 전량 취소 | 전표·원장·재고 생성 없음 |
| 0원 출고 | 거절 |
| 원장 금액 | 확정 전표 총액과 일치 |
| 재고 이동 | 실제 출고 상품 줄만 1회 차감 |
| 재시도 | 같은 결과 반환, 중복 기록 없음 |
| 같은 주문 추가 출고 | 거절, 새 주문 필요 |
| 묶음 중간 실패 | 전체 롤백 |
| 다른 회사 접근 | 거절 |

## 알려진 제한과 다음 경계
- 전체 스냅샷이 같은 중복 주문 줄은 어느 줄을 출고했는지 증명할 수 없어 부분 출고를 거절한다.
- 이 경우까지 지원하려면 CX-62 접수 전표를 만들 때 `source_order_line_id`를 직접 저장하는 별도 변경이 먼저 필요하다. 이 초안은 UUID나 줄 순번으로 추정하지 않는다.
