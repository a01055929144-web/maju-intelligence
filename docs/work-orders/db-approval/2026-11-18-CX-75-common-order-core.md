# CX-75 주문 공용 경계 SQL 승인·적용 기록

상태: 승인된 CX-75 SQL 1회 운영 적용·읽기 검증 완료. 회사 설정은 OFF이며 배포·실제 주문 검증은 별도다.

## 변경과 보존

`2026-11-18-CX-75-common-order-core.sql`은 기존 공개 함수의 이름·인자·기본값·OID를 유지하고 `place_store_order_core_v2`로 연결한다. 기존 구현은 서비스 역할도 직접 실행할 수 없는 `cx75_*_impl` 함수로 보존한다. 문서 발행 가격과 카탈로그·자체 주문 가격의 계약이 다르므로 해당 계산을 임의로 통일하지 않는다. 공용 경계가 주체·회사·상품·수량·품목 마감과 저장된 금액을 확인하고 기존 계산 및 멱등 검사를 호출한다.

회사별 `store_order_settings.unified_order_core_enabled` 기본값은 false다. OFF에서는 기존 함수 계약을 그대로 실행한다. ON에서만 추가 공통 검사가 작동한다. 기존 멱등 요청은 원래 구현이 동일 내용인지 확인하고 원래 결과를 돌려준다. 주문 수정·상품 비활성화 이후의 정상 재시도를 새 주문처럼 검사하지 않는다.

| 공개 진입점 | 공용 경계를 거친 실제 검사 경로 |
| --- | --- |
| `place_store_order` | 공용 검사 → 문서 토큰·스냅샷 가격·회사/권역/거래처 마감·휴무/요일·행사 잠금·요청 지문 → 저장 금액 대사 |
| `place_store_member_order` | 위 경로 + 동일 회사·거래처의 활성 매장·구성원·사용자 검사 |
| `place_store_catalog_order_core_v1` | 공용 검사 → 카탈로그 토큰·협의가/등급가/기본가·배송 정책·행사 잠금·요청 지문 → 대사 |
| `place_store_catalog_order_v1` | 공용 경계 → 기존 공개 카탈로그 어댑터 → 위 카탈로그 core 경계 |
| `place_store_catalog_member_order_v1` | 공용 경계 + 구성원 검사 → 기존 회원 카탈로그 어댑터 → 위 카탈로그 core 경계 |
| `place_store_account_order` | 공용 검사 → 계정 잠금·자체 주문 자격·가격·배송 정책·정렬된 행사 잠금·요청 원문 비교 → 주문/줄/알림/요청 저장 → 대사 |
| `place_store_account_orders` | 기존 배치 앵커·공용 프로필·중복 회사/키 검사 → 회사순 반복 → **각 항목에서 공개 `place_store_account_order` 호출** → 항목별 예외 하위 트랜잭션. 성공 항목 유지, 실패 항목 전부 취소 |
| `place_store_order_with_delivery_snapshot_09` | 설치되어 있을 때만 감싼다. 기존 배송 스냅샷 구현이 문서/회원 주문 공개 함수로 재진입. 해당 운영 정의의 별도 확인 필요 |

폐기된 `place_store_pending_delivery_order`는 적용하거나 감싸지 않는다. 신규 주문 알림은 S-2a의 `company_notifications`를 그대로 사용한다. `notification_type='new_order'`, `idempotency_key=주문 요청 UUID 문자열`이다.

최대 잠금 대기 3초, 문장 30초이며 설치 전체가 한 트랜잭션이다. 원복은 활성 회사를 먼저 OFF로 바꾼 뒤 `.down.sql`을 사용한다. ON인 회사가 하나라도 있으면 원복을 거절한다. 주문·줄·알림·장바구니·요청 이력은 삭제하지 않는다. 원복은 기존 공개 OID와 원래 함수 정의·실행 권한을 복원한다.

## 검증과 제한

`tests/sql/store-order-core-cx75.pg17.test.sql`을 실제 P0/P1/P2·회원·S-2b·S-2a SQL 시험 뒤 실행한다. 새 배치 부분 성공, 같은 키의 수량/메모/배송일 충돌, 편집/비활성화 이후 재시도, 두 연결의 배치 직렬화, 서로 다른 링크의 행사 재고/매장 한도 경합, 시가 미확정, 품목 마감 1분 전후, 1원 오차의 주문·줄·알림·요청 전체 롤백, 원복을 검증한다.

화면·API 코드는 바꾸지 않는다. 1440/390 화면 회귀와 tsc/lint/build는 기존 CI 결과로 기록한다. 배송 스냅샷 함수는 기존 통합시험과 같은 커밋 `220b9c1011368570873f61be467e651cf22a6cec`의 실제 SQL을 CI가 별도 체크아웃하여 실행한다. 8개 진입점의 주문·재시도·회사 격리·원복을 확인한다. 운영 적용 전에는 여전히 실제 설치된 정의와 고정본을 대조해야 한다.

가상 상품 5,000개를 회사 3곳에 나눈 PG17 시험에서 실제 공용 주문은 0.024947초, 계정 카탈로그 1,766행 조회는 0.503897초였다. 시험 기준은 각각 5초·10초이며 운영 성능 보장은 아니다. 접수·전표 확정·원장·재고는 CX-62/CX-66 범위이며 이 초안으로 운영 사용을 승인하지 않는다.

### 운영 정의 읽기 대조 (2026-11-18)

운영 프로젝트에서 `pg_proc`의 정의·인자·소유자·실행 권한만 SELECT했다. 고객·주문·계좌 행은 조회하지 않았다. 필수 함수 7개 모두 소유자 postgres, SECURITY INVOKER, 실행 권한 postgres/service_role이며 anon/authenticated 실행 권한이 없다. 선택 배송 함수는 미설치여서 실제 적용 시 건너뛴다. 아래 정의를 외부 연결 없는 일회용 PG17에 복제한 뒤 CX-75 전체 시험도 통과했다(주문 0.012964초, 카탈로그 0.162265초). 운영 쓰기·기능 ON은 없었다.

## 운영 적용 결과 (2026-11-18)

- 적용 시각: 15:07 KST. 적용 대상은 이 문서의 CX-75 SQL 한 건이며 다른 승인 대기 SQL은 실행하지 않았다.
- 적용 전: 필수 공개 주문 함수의 정의·권한이 승인표와 일치하고 신규 공용 경계가 없는 것을 읽기로 확인했다. PG17 적용·원복 시험과 CI가 통과했다.
- 적용 후: 회사별 설정의 기본값 OFF, 새 공용 경계와 공개 주문 함수 연결, RLS·실행 권한을 읽기로 확인했다. 기존 주문 데이터는 바뀌지 않았다.

- 실제 주문·출고·전표 처리와 회사별 기능 ON은 이번 검증 범위에 포함되지 않았다. 같은 SQL을 재실행하지 않는다.
