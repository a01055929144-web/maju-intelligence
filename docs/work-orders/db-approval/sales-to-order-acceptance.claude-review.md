# Claude 검토 — S-2 영업 → 주문 수락 DB 승인 초안 (PR #180) · 2026-11-02 18:05

**결론: 설계 방향은 승인한다.** 다만 아래 6개를 반영하고, **실제 SQL · down · PG17 테스트를 먼저 작성**해서 다시 올린다. 대표 승인은 SQL을 받는 것이다(지금 문서는 설계만 있고 SQL이 없다).

## 좋은 점 (그대로 유지)
- 게시 version 기준 수락, 회사 복합 FK, RPC 하나 + idempotency, 공용 단가표와 매장 전용 문서 구분
- P2 주문 · 링크 재사용(새 주문 정본 없음), 레거시 `sales_quotes` 보존
- 빈 칸만 보완, 주문 줄 가격 스냅샷, 파괴적 down 금지, 03 / 07 / 09 책임 분리

## 반영할 것
1. **매장 쪽 수락에서 리드 매칭이 애매할 때 전체를 실패시키지 않는다.**
   - 지금 초안은 `Lead match ambiguous`로 전체를 되돌린다. 매장 입장에서는 주문을 못 하게 된다.
   - 바꿀 것: 수락 · 주문은 진행한다. 리드 연결만 `needs_review`로 두고, 담당자 "확인 필요" 목록에 올린다.
   - 직원 화면 수락(대신 수락)에서는 지금처럼 후보를 고르게 한다.
2. **수락은 ⓪-2 흐름의 ④ "카카오로 시작"에서 호출한다**(1556 A-0b).
   - 매장 식별(카카오 계정 → 매장 계정)을 `accepted_by_key`와 거래처 연결에 쓴다.
   - 매장 계정 테이블이 필요하면 이 묶음에 포함한다(역할 = 매장, 자기 주문만, 직원 계정과 분리).
3. **`pricing_document_sends`에 `template_id` · `layout`을 추가한다**(대표 지시: 템플릿 여러 개 중 골라서 보냄). 거래처(매장)에게 보낸 기록도 같은 테이블에 담을 수 있게 `lead_id` / `customer_id` 중 하나를 필수로 한다.
4. **견적 수락이 상품 미연결 · 과세 미확정으로 실패하지 않게, 게시할 때 막는다.**
   - 게시 검증에 추가: 모든 품목이 상품에 연결 · 단위 · 과세 확정.
   - 수락 RPC의 검증은 그대로 두되, 매장이 실패를 보는 일은 없어야 한다.
5. **공개(로그인 없는) 경로의 남용 방지**: 공용 단가표 수락 · 새 리드 생성에 요청 한도(같은 기기 · 같은 전화번호)와 입력 형식 검증을 둔다. 결과 기록은 남긴다.
6. **A-2 범위**: 사업자등록증 사진 · 출입 비밀번호 · 놓을 곳 사진은 이 묶음에서 뺀다(그대로 OK). 새 칸 3개(`delivery_recipient_name`, `delivery_contact_phone`, `preferred_delivery_time`)에 **놓을 곳(문 앞 / 매장 안)** `delivery_drop_location`을 추가한다.
