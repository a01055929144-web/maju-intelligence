# S-2a 매장 자체 주문 SQL 검토안

이 문서는 적용 승인 전 검토 자료다. 적용 SQL과 되돌리기 SQL은 `docs/sql-drafts`에 둔다. 회사별 `store_order_settings.self_order_enabled` 기본값은 false다. 앱을 연결할 때에도 `STORE_SELF_ORDER` 기본 OFF와 회사 허용 목록을 검사한다.

| 적용 전 운영 읽기 확인 | 필요한 이유 |
| --- | --- |
| 매장 계정의 사업자 확인·약관·거래처 확인·공용 프로필 열, 구성원과 사용자 상태 | 주문 주체를 검증 |
| 운영 거래처의 배송 기본주소 및 활성 권역, 배송 요일과 마감, 주문 설정 | 기존 운영 배송 정보를 사용 |
| P0 판매가, CC-29c 등급 가격 함수, CC-36b/37 주문·품목 스키마 | 서버가 가격과 주문 합계를 계산 |
| CX-13 거래처 확인 함수와 상태 전이 트리거 | 자동 확인은 기존 확인 함수로 감사 기록을 남김 |
| #915 및 #925 적용된 `company_notifications`의 열·고유 키·서비스 역할 권한 | 새 주문과 함께 회사 알림 생성 |

새 주문의 `notification_type`은 `new_order`이고 `idempotency_key`는 같은 주문 요청 UUID의 문자열이다. 한 회사 내 키가 충돌하면 해당 주문 전체가 실패한다. 주문 요청 기록에 주문한 구성원과 결과가 남는다. 일괄 주문은 유통사별로 1건을 처리하고 실패한 유통사는 오류를 반환한다.

유효하고 발행된 매장 대상 단가표의 품목 가격, 등급 가격, 회사 기본 판매가 순으로 계산한다. 유효성과 배송지의 등록 권역은 기존 운영 데이터로 판정한다. 외상 한도는 설정값만 저장하며 E단계의 미수 잔액 연결까지 한도 판정은 비활성이다.

DB 검증은 격리 PG17에서 기존 매장 주문·알림 시험을 바탕으로 실행한다. 운영 화면과 실제 시험 매장 전체 흐름 확인은 앱 연결 이후 승인된 환경에서 진행한다. 운영 적용은 대표 승인 후 컨트롤타워가 수행한다. 되돌리기는 신규 설정, 주문, 저장 장바구니 또는 즐겨찾기가 생기면 중단한다. 사용 이후에는 회사별 스위치를 끄고 주문 이력을 보존한다.

## 후속 검토

- 기존 링크 주문 RPC 본문은 보존했다. 새 경로는 CC-36b의 주문 검증을 바탕으로 작성했다. 두 경로의 공용 검증 추출은 별도 호환성 검증이 필요하다.
- 리드 전환·동일 사업자 기존 거래처 연결과 동종 업종 신규 연결 차단은 가입·연결 RPC에서 검토한다. 이 초안에서 가입 함수는 바꾸지 않았다.
- 화면에서 장바구니 가격 변동 안내를 구현하려면 주문 전 표시 가격을 최신 카탈로그 응답과 비교하는 앱 연동이 필요하다.

## 승인 기준

| 판단 | 조건 |
| --- | --- |
| Draft SQL의 main 병합 | SQL이 `docs/sql-drafts`에 있고 PG17·전체 CI를 통과한다. 이 병합은 운영 DB 승인과 별개다. |
| 운영 적용 전 주문 입력 필수 검증 | 기존 링크 주문과 동일하게 1~100개 품목 줄만 허용한다. PG17에서 0·101줄 거절과 주문·알림 미생성, 1·100줄 정상 저장을 확인한다. |
| 대표의 운영 SQL 적용 승인 | 2-3 ① 리드 전환·동일 사업자 거래처 재사용 및 ② 동종 업종 차단을 담당하는 관리형 연결 경로의 적용·검증 근거를 첨부한다. 근거가 없으면 승인표를 열어 둔다. |
| 공용 검증 추출 | S-2 명세의 코드 작업이다. 기존·신규 RPC의 동작 동등성을 시험하고, 미완료 상태로 적용하려면 컨트롤타워 검토에서 명시적으로 남겨야 한다. OFF 상태의 초안 병합을 막는 조건은 아니다. |
| 실제 회사 활성화 | 운영 적용에 대한 대표 승인 이후, 회사 허용 목록에 있는 승인된 시험 매장에서 가입 → 주문 → 주문 내역의 전 구간을 확인한다. |

## 2026-11-17 운영 승인 선행 증거

상태는 **운영 적용 대기**다. 운영 확인에는 함수 정의와 스키마 메타데이터만 사용했다. 주문·거래처·구성원 행의 값은 조회하지 않았다.

| 선행 기준 | 확인한 근거 | 승인 판단 |
| --- | --- | --- |
| 2-3 ① 리드 전환·기존 거래처 재사용 | 운영 `record_pricing_document_acceptance`에 리드 및 사업자번호 매칭 분기가 있다. 격리 PG17의 [기존 수락 시험](../../sql-drafts/20261102-S2-sales-to-order-acceptance.pg17.test.sql)에서 리드의 거래처 전환, 단일 기존 거래처 재사용, 모호한 후보의 검토 보류를 통과했다. 운영 `activate_store_owner_v1`에도 사업자번호 참조가 있다. 초대코드 연결의 [CX-12 초안](../../sql-drafts/20261111-CX-12-store-connect-by-code.sql)은 이미 연결된 동일 회사·프로필은 반환하고 신규 연결에는 별도 거래처 행을 만든다. | **부분 확인**. 기존 수락 경로의 근거는 확보했다. 가입·초대 전체에 적용되는 재사용 규칙은 CX-58의 종사업장 식별 및 03방 CX-59 중복 규칙과 함께 확인해야 한다. |
| 2-3 ② 동종 업종 신규 연결 차단 | 운영의 `connect_store_profile_by_invite_code_v1`, `activate_store_owner_v1`, `activate_public_store_owner_with_delivery_v1` 본문에서 업종 판정을 확인하지 못했다. 격리 PG17의 [CX-12 시험](../../../tests/sql/store-connect-cx12.pg17.test.sql)은 소유자·코드·동일 연결 재시도를 확인한다. | **미충족**. 가입·연결 담당 경로에서 동일 업종 거절, 다른 업종 허용, 업종 미설정 확인 필요와 경쟁사 정보 비노출을 검증해야 한다. |
| ③ 기존 링크 주문과 자체 주문의 필수 검증 동등성 | [S-2a PG17 비교](../../../tests/sql/store-account-order-s2a.pg17.test.sql)를 서비스 역할로 실행했다. 같은 회사·매장·품목에서 발행 단가와 합계 일치, 각 경로별 같은 키 재시도 응답 일치, 지난 배송 마감과 0·101줄 거절을 확인했다. 자체 주문의 100줄 저장과 거절 시 주문·알림 미생성도 기존 시험에서 확인했다. | **부분 확인**. 두 경로의 공용 검증 추출은 대기다. 휴일·요일, 최소 금액 정책, 행사 재고 경합, 시가 및 수정·취소의 동등성은 이 비교로 입증되지 않았다. 자체 주문의 새 자격·결제 조건과 가격 우선순위는 명세에 따른 차이다. |

①·②의 가입·연결 경로 근거와 ③의 남은 동등성 판단을 기록하기 전까지 운영 승인 요청은 대기한다. 이 보완은 승인표와 격리 시험에 한정한다.
