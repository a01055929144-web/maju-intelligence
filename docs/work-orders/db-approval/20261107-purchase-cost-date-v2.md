# 매입일자 저장 v2 SQL 검토 요청 (Phase 1)

상태: **검토 전용 / 기능 OFF / 운영 미적용**

## 최소 범위

- 이미 `product_catalog`에 존재하고 업로드 전에 매핑이 확정된 품목만 처리합니다.
- 파일의 매입일자가 있으면 그 날짜를, 없으면 사용자가 고른 업로드 날짜를 `price_date`와 `receipt_date`에 동일하게 기록합니다.
- 과거 날짜는 이력과 매입 기록에 남기되 현재 매입가를 덮어쓰지 않습니다.
- 거래 원문 행은 모두 보관합니다. 품목·날짜별로 `priceSelected=true`인 한 행을 현재가 후보로 고르거나, `priceHeld=true` 한 행으로 명시 보류해 현재가를 유지합니다.
- 같은 품목의 파일 최신일이 보류되면 그보다 오래된 선택 단가는 이력에만 남고 현재가 후보가 되지 않습니다.
- `purchase_price=0`이고 날짜가 없는 신규 미가격 상품은 최초 날짜·원가 반영을 허용합니다. 비영가 기존 매입가에 날짜가 없으면 기본 보호하며, 사용자가 `replaceUndatedCurrent=true`로 이번 적용일 교체를 명시하고 `expectedPurchasePrice`가 DB 현재값과 일치할 때만 반영합니다.
- 상품 현재가는 품목 전체의 파일 최신일로 선정하고, 공급처 최신 원가는 각 `supplierProductId`의 파일 최신일과 `last_seen_date`를 독립 비교합니다.
- 원가만 바꾸고 날짜를 함께 갱신하지 않는 기존 쓰기는 트리거가 `purchase_price_date=null`로 전환합니다. 이후 날짜 업로드는 그 값을 덮지 않고 명시 확인을 기다립니다.
- 배치 ID와 요청 본문으로 재시도 중복을 막고, 한 행이라도 실패하면 전체를 되돌립니다.
- 선택 원가 저장과 `pricing_p0_command(...recalculate)`를 같은 DB 트랜잭션에서 실행하고 `recalc_run_id`를 배치에 기록합니다.
- 가장 최근 완료 배치만, 이후 현재가 변경이 없을 때 복구할 수 있습니다.
- 복구는 연결된 가격 재계산 run과 매입가·이력·receipt를 같은 트랜잭션에서 되돌립니다.

## 명시적 제외

- 표준 품목이 0개인 파일에서 신규 품목 생성, 원문 정규화, 자동 매칭까지 한 번에 끝내지 않습니다.
- 따라서 “3,417행 전체 원자 저장”은 **745개 품목의 생성·매핑이 먼저 완료된 뒤**에만 성립합니다.
- 신규 품목 생성과 원문 매칭은 별도 Phase 2 승인 대상입니다.
- 기존 v1 SQL, 운영 DB, 앱/API, 가격 재계산 함수 자체는 변경하지 않습니다.

## 현재 원가 쓰기 경로 점검

- `docs/sql-drafts/20261107-purchase-cost-batch.sql`: v1 저장·복구가 `purchase_price`만 갱신합니다.
- `lib/pricing/purchase-cost-repository.ts`: 기존 직접 수정·실패 복구가 `purchase_price`만 갱신합니다.
- v2 저장·복구는 가격과 날짜를 함께 갱신합니다.

따라서 기존 경로를 모두 즉시 개편하는 대신, 날짜를 동반하지 않은 가격 변경은 기준일 미확정으로 만드는 DB 경계를 둡니다. 향후 v1/API가 명시 날짜를 받게 되면 가격과 날짜를 함께 쓰도록 별도 전환할 수 있습니다.

## 전체 사용 경로의 단계별 선행조건

1. **Phase 2 필요:** 표준 품목이 없는 원문에서 신규 상품을 만들고 745개 품목 매핑을 사용자에게 확정받습니다.
2. **이 초안의 Phase 1:** 매핑 완료된 거래 3,417행을 날짜별 receipt/history로 저장하고 선택 원가만 현재 매입가에 반영합니다.
3. **이 초안 내부:** 같은 RPC·트랜잭션에서 `pricing_p0_command`를 실행해 마진 기반 판매가를 갱신하며, 실패하면 날짜 저장도 전부 롤백합니다.
4. 단가표·주문 링크가 `pricing_items`를 읽는 기존 계약인지 09 검토로 확인하고, 승인 전에는 기능 플래그를 켜지 않습니다.

현재 초안만으로는 1번이 없어 표준 품목 0개인 실제 파일의 전체 사용자 경로를 완료할 수 없습니다.

## 제안 기능 플래그

`PURCHASE_COST_DATE_V2_ENABLED=false`

이 문서는 플래그 이름만 제안하며 앱 설정은 바꾸지 않습니다. 승인 전에는 RPC를 호출하는 API/UI가 없어야 합니다.
