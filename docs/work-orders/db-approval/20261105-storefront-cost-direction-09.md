## 공개 계약

- `STORE_PURCHASE_COST_DIRECTION_ENABLED`가 켜지고 회사가 명시적으로 동의한 경우만 서버 조회.
- RPC 결과는 `product_id`, `sales_unit`, `direction(up/down)`뿐이다. 공개 DTO에는 기존 상품·단위와 검증한 enum만 연결한다.
- 금액·차액·변동률·마진·매입처·매입일은 공개하지 않는다. 판매가·매장 자체 원가와 분리해 '유통사 매입가 상승/하락'으로 표시한다.
- 동일 상품·단위의 최근 유효 매입일 두 개를 비교한다. 이전 값 없음·보합·같은 날 서로 다른 가격은 숨긴다. 미래 날짜·수량/원가 0·과세 미확정도 제외한다.

## 유효 출처 판정의 연동 경계

현재 매입 기록에는 반품·오류·취소 상태가 없다. 양수 원가만 보고 유효하다고 추측하지 않는다. 06의 인증된 owner/manager 흐름에서 반품·오류·정정 취소를 제외한 기록에만 `check_storefront_cost_source`를 호출해야 한다. 이 RPC는 현재 `purchase_receipt_effective` 스냅샷과 일치하는지 원본 행 잠금 아래 확인하고 확인자·사유·정정 이벤트 수를 기록한다. 공개 토큰 API나 09 설정 UI에서는 이 함수를 호출하지 않는다.

연동 호출자는 회사·권한·확인자 식별자를 서버 세션에서 정한다. 클라이언트가 보낸 회사·확인자 이름을 권한 판단에 사용하지 않는다.

로컬 TCP 바인딩이 거부돼 별도의 새 데이터 디렉터리에서 PostgreSQL 17 단일 사용자 모드로 SQL을 실행했다. 운영/기존 테스트 클러스터는 사용하지 않았다. 이 모드는 실제 다중 접속·일반 세션 실행을 대체하지 않으므로 service_role 실행과 브라우저 최종 결과는 CI를 기준으로 한다.

다시 올려 원본 값이 달라지거나 정정 이벤트가 추가되면 기존 확인이 무효다. 정정을 취소해 원래 값으로 돌아와도 이전 확인을 되살리지 않는다. 명시적으로 재확인할 때까지 숨긴다. 유효 판정 연동이 준비되지 않으면 결과가 비어 있으며, 기능을 켜기 위해 이 확인을 생략하지 않는다.

원본의 `storefront_cost_revision`은 내용이 실제로 달라질 때만 증가하며, 같은 내용 재시도에는 유지된다. 원본이 A→B→A로 재업로드돼도 갱신 번호가 달라 과거 확인을 복원하지 않는다. 갱신 번호만 직접 덮어써도 트리거가 기존 번호를 유지한다. SQL 적용 후에는 공개 플래그와 무관하게 기존 원본 수정 시 이 메타데이터를 추적하며 원가·품목 값은 바꾸지 않는다. 이 원본 테이블 메타 변경도 별도 운영 승인·06 검토 범위다.

## 후속과 위험

- 실제 동작 활성화에는 새 DB 승인·적용과 06의 유효 출처 판정 연동이 필요하다. 기본 OFF 상태의 UI/API·회귀 검사는 준비한다.
- 03 매장 자체 원가 API와 07 활성 구성원 helper 기반 UI는 별도 PR. 공개 토큰만 가진 방문자에게 원가관리 탭/API를 열지 않는다.
- 1.8L·18L·500ml SKU 혼용은 표시 규격 보완과 별개의 상품 매칭 위험이다. 이 기능은 SKU를 합치거나 단위를 환산하지 않고 같은 상품 ID·단위만 비교한다.
- 03/04/07 소유 파일은 수정하지 않는다. 외부 피드백의 세부 내용·개인정보를 복제하지 않는다.
