# 리드 외부 정보 보강 DB 승인 초안

> 상태: **승인 전 · 운영 실행 금지**  
> 운영 프로젝트: `fcmdvveqmcgtioelzqun`  
> API 키 값은 코드·로그·PR·문서에 기록하지 않는다.

## 목적

공식 API만 사용해 대표 회사 리드의 활성도·규모·업종·영업 상태를 보강한다.

- 네이버 검색광고 키워드 도구의 월간 PC·모바일 검색수 → 활성도
- 국민연금 가입 사업장 가입자 수 → 규모 보조
- 건축물대장 연면적 → 인허가 면적이 없을 때만 규모 참고
- 소상공인 상가(상권)정보 → 업종 보강·폐업 교차 확인

스크래핑은 하지 않는다. 값이 없거나 매칭 신뢰도가 부족하면 `0`이나 폐업으로 추정하지 않고 **모름**으로 둔다.

## 기존 칸 재사용

| 결과 | 저장 위치 | 규칙 |
|---|---|---|
| 월간 검색수 | `business_permit_leads.keyword_volume` | PC+모바일 절대 검색수. 기존 데이터랩 상대값을 새 절대값으로 바꾸기 전 출처를 감사 이벤트에 기록 |
| 업종 | `business_permit_leads.industry_primary`, `industry_tags` | 공식 상가정보와 기존 분류가 일치하거나 신뢰도 기준을 통과할 때만 빈값 보강. 운영자 입력은 덮어쓰지 않음 |
| 폐업 확인 | 기존 `permit_status`, `is_active`, `exclude_reason` | 상가정보 한 소스만으로 자동 폐업 처리하지 않음. 교차 확인 결과만 감사 이벤트에 남기고 자동 제외는 별도 승인 |
| 호출·매칭 이력 | `lead_enrichment_events` | 공급자, 조회 시각, 상태, 매칭 신뢰도, 재시도 가능 시각, 값 존재 여부를 `metadata`에 기록 |

## 신규 칸 승인 요청

`business_permit_leads`에 아래 nullable 칸만 추가한다.

| 칸 | 형식·제약 | 용도 |
|---|---|---|
| `employee_count` | `integer`, `NULL or 0 <= value <= 100000` | 국민연금 가입자 수. 미조회·미매칭은 NULL |
| `employee_count_checked_at` | `timestamptz` | 해당 값의 공식 조회 시각 |
| `building_floor_area_sqm` | `numeric(14,2)`, `NULL or 0 < value <= 10000000` | 건축물대장 건물 단위 연면적. 매장 면적과 구분 |
| `building_floor_area_checked_at` | `timestamptz` | 해당 값의 공식 조회 시각 |

출처·원문·매칭 신뢰도는 중복 칸을 만들지 않고 `lead_enrichment_events.metadata`에 둔다. API 원문 전체, 인증값, 개인 식별 정보는 저장하지 않는다.

## 호출 계약

1. 기존 `/api/cron/recommend-refresh` 야간 배치와 리드 상세 보강 진입점만 재사용한다.
2. 같은 리드·공급자의 최근 성공 또는 `not_found` 이벤트가 30일 이내면 외부 API를 다시 호출하지 않는다.
3. 상세 열기 호출은 캐시가 만료된 경우에만 실행하고 화면 응답을 장시간 막지 않는다.
4. 회사별·공급자별 일일 상한과 실행당 처리 상한을 둔다. `429`, `5xx`, 공공데이터 활용 승인 직후 오류는 지수형 대기 후 제한 횟수만 재시도한다.
5. 인증 오류와 잘못된 요청은 재시도하지 않는다. 비밀값이나 외부 원문을 오류 메시지에 넣지 않는다.
6. 매칭은 정규화 상호+주소를 기본으로 하고, 국민연금의 사업자번호 앞 6자리는 단독 식별자로 사용하지 않는다.
7. 건축물대장은 주소가 한 건으로 확정될 때만 저장한다. 연면적은 `store_area_sqm`을 덮어쓰거나 매장 면적으로 표시하지 않는다.
8. 상가정보의 폐업 표시는 참고 신호다. 다른 공식 상태와 충돌하면 `모름/확인 필요`로 둔다.

## 점수 반영 경계

- `keyword_volume`은 값이 있을 때만 활성도 근거로 사용한다.
- `employee_count`, `store_area_sqm`, `building_floor_area_sqm`은 존재하는 신호만 규모 근거로 사용한다.
- 값 없음은 0점이 아니며 등급을 낮추지 않는다.
- 이 승인 묶음은 기존 리드 점수·등급을 운영에서 일괄 재계산하지 않는다. 별도 dry-run으로 전후 분포를 보고한 뒤 승인한다.

## 권한·회사 격리

- 모든 조회·갱신·감사 이벤트는 `company_id`와 `lead_id`를 함께 검증한다.
- 외부 API 호출과 DB 쓰기는 서버 전용 경로에서만 수행한다.
- `public`, `anon`, `authenticated`에 신규 칸 갱신 권한을 추가하지 않는다.
- 대표 회사 외 회사에는 기능을 켜거나 백필하지 않는다.

## 대표 회사 채움 비율 보고

운영 쓰기 전 읽기 전용 집계로 아래 기준의 분모·분자를 고정한다.

| 항목 | 전 | 후 | 채움 기준 |
|---|---:|---:|---|
| 월간 검색수 | 측정 대기 | 측정 대기 | `keyword_volume is not null` |
| 직원 수 | 컬럼 승인 전 | 측정 대기 | `employee_count is not null` |
| 인허가 매장 면적 | 기존 집계 재사용 | 측정 대기 | `store_area_sqm is not null` |
| 건물 연면적 | 컬럼 승인 전 | 측정 대기 | `building_floor_area_sqm is not null` |
| 표준 업종 | 측정 대기 | 측정 대기 | `industry_primary`가 비어 있지 않고 `미분류`가 아님 |
| 영업 상태 교차 확인 | 측정 대기 | 측정 대기 | 최근 30일 상가정보 성공 이벤트 존재 |

분모는 대표 회사의 병합되지 않은 활성 리드로 고정하고, 회사 ID·상호·주소·원문은 보고서에 출력하지 않는다. 외부 API 연결 전/후 같은 분모를 사용한다.

## 승인 후 검증

- [ ] 폐기 가능한 PostgreSQL 17에서 컬럼 제약·회사 격리 검증
- [ ] 30일 성공·없음 캐시와 만료 후 재조회 검증
- [ ] `429`·`5xx` 제한 재시도, 인증 오류 무재시도 검증
- [ ] 동일 리드 동시 요청에도 공급자별 호출·이벤트 중복 방지
- [ ] 국민연금 동명이인·복수 주소를 모름 처리
- [ ] 건물 연면적이 매장 면적을 덮어쓰지 않음
- [ ] 상가정보 단독 신호로 자동 폐업·자동 제외하지 않음
- [ ] 값 없음이 점수 감점으로 바뀌지 않음
- [ ] 비밀값과 외부 원문이 로그·응답·감사 이벤트에 남지 않음
- [ ] 대표 회사 dry-run 채움 비율 전/후와 호출 건수·실패율 보고

## 운영 적용 전 승인 문구

아래 문구가 없으면 SQL·운영 데이터 변경·대표 회사 기능 활성화를 하지 않는다.

```text
DB-APPROVED: fcmdvveqmcgtioelzqun / 리드 보강 employee_count·building_floor_area_sqm 및 조회시각 칸 추가
```

## 현재 승인 상태

- Claude 검토: 대기
- 대표 승인: 대기
- `DB-APPROVED:` **없음**
