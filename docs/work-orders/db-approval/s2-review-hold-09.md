## 재현한 결함

적용된 `record_pricing_document_acceptance`를 별도 새 로컬 PG17 DB에서 실행했다. 리드의 기존 거래처와 다른 거래처에 quote 수락을 요청하고 주문 링크 ID까지 전달하면:

| 결과 | 적용 SQL | 보완 초안 |
|---|---|---|
| needsReview | true | true |
| 협의 단가 생성 | true | false |
| 문서 매장 연결 생성 | true | false |
| 링크 주문 가능 | true | false |

보완 후 기존 777원 활성 협의 단가가 바뀌지 않는 것도 검증했다. 운영에는 시험 행을 만들지 않았다.

## 변경 객체와 범위

- 초안: `docs/sql-drafts/20261102-S2-review-hold.sql`
- down: `docs/sql-drafts/20261102-S2-review-hold.down.sql` (기능 OFF 상태에서 원문 복원; 결함 동작도 돌아오므로 운영 재활성화 금지)
- `CREATE OR REPLACE FUNCTION public.record_pricing_document_acceptance` 하나만 교체한다. 서명·권한·기존 객체는 유지한다.
- 기존 매칭 로직이 검토 필요를 결정하면 거래처 기본정보 갱신·문서 가격 연결·협의 단가 종료/생성·주문 링크 활성화 전에 수락 요청만 저장하고 반환한다.
- 반환값은 `needsReview=true`, `orderEnabled=false`, 가격 연결/주문 링크 ID null이다.
- 정상 수락과 기존 멱등 unique 경합 처리는 변경하지 않는다.
- 앞 단계에서 생성된 후보 거래처나 기존 리드 연결 로직 전체를 재설계하지 않는다. 이번 보완은 검토 필요 상태의 가격·주문 부작용 차단이다.

## 적용 전 확인·복구

1. 현재 함수 원문·권한과 관련 테이블 건수/스키마를 저장소 밖에 백업한다. 이 보완은 기존 행을 갱신하는 migration이 아니다.
2. 이미 `needs_review=true`로 저장된 요청과 연결·협의 단가·주문 링크가 있는지 회사 범위로 확인한다. 기존 멱등 결과는 자동 재작성하지 않는다. 과거 부작용 정리는 별도 데이터 검토 대상이다.
3. Claude 검토와 새 대표 승인 후 단일 트랜잭션으로 함수만 교체하고 읽기 검증한다. 09는 운영 실행하지 않는다.
4. 실패 시 DDL 트랜잭션 롤백. 적용 후 복구는 수락 플래그 OFF 상태에서 저장한 원문으로 복원한다. 결함 동작을 다시 운영에 열지 않는다.
5. 매장 카카오 계정·첫 주문 전체 경로 완료 전 기능 ON/운영 E2E 완료로 보고하지 않는다.
