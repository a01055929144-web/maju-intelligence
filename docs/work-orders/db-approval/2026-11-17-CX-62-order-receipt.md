# CX-62 주문 접수와 작성중 매출 전표 적용 승인표

**운영 적용 대기 · CX-62 활성화 전 SQL 승인 선행.** 대표 결정은 접수 시 작성중 전표, 출고 확정 시 전표 확정과 원장·재고 이동이다. 이 제품 결정은 운영 SQL 적용 승인이 아니다.

| 운영 읽기로 확인한 선행 조건 | 결과 |
| --- | --- |
| CX-38 주문 전표 및 ERP 저장 구조 | 운영에 주문·전표·원장·재고 구조와 기존 CX-38 함수가 있다. 이 초안은 `order_sale_document_lines`, `save_business_document`를 작성중 경로로 재사용한다. |
| 주문 접수 검토 트리거 | 운영에 `store_orders_review_guard`가 있다. 이 단계에서 거절되면 작성중 전표 저장도 같은 트랜잭션에서 롤백된다. |
| CX-62 접수 RPC | 기존 운영 읽기에서 새 함수가 없었다. 적용 직전 함수·의존 권한과 주문 전표 초안 존재 여부를 다시 읽는다. |
| 기능 스위치 | `FEATURE_ERP_ORDER_DOCUMENTS_COMPANY_IDS`에 제이에스리테일이 이미 포함돼 있다. CX-62는 새 회사 허용 목록 `FEATURE_ORDER_RECEIPT_DRAFT_COMPANY_IDS`에서만 열린다. 기존 ERP 허용 목록만으로는 새 접수 RPC를 부르지 않는다. |

## 거래와 금액 경계

- 접수 RPC는 회사·주문 행을 잠그고 revision을 확인한다. 서버 주문 줄로 작성중 매출 전표를 저장하고 회사·거래처·원본 연결을 확인한 뒤 같은 트랜잭션에서 `received`로 바꾼다. 중복 요청은 같은 결과를 반환한다.
- 확정 단가 주문의 금액이 작성중 전표와 원 단위까지 맞아야 접수한다. 기존 매퍼의 세금 포함 단가 내림·반올림 또는 배송비 환산 때문에 불일치가 있으면 주문과 전표를 그대로 두고 오류를 반환한다. 모든 단가·배송비 반올림 조합의 실데이터 호환성은 적용 전 추가 확인이 필요하다.
- 시가 제안 단가는 작성중에만 둔다. 시가 확정 및 부분취소 이후 최종 금액 확인은 CX-66/CX-67 계약 범위다. 출고 확정 전에는 작성중 전표 수정, 출고 확정 뒤에는 역분개 경로를 사용한다.
- 공용 전표 저장 함수 뒤에 등록증 상호와 사업자번호, 사업장 주소 스냅샷을 같은 트랜잭션에서 확정한다. 등록증 상호가 비면 관리 상호로 표시하고, 사업장 주소가 없으면 빈값을 저장한다. 종사업장번호의 전표 스냅샷 칸은 CX-61 후속으로 남긴다.
- 접수 상태에서 주문이 취소되면 같은 회사·주문·거래처의 작성중 매출 전표와 줄만 같은 트랜잭션에서 삭제한다. 확정된 전표는 기존 취소·역분개 계약이 담당한다.
- 접수 SQL은 일반 확정 차단을 설치하지 않는다. [출고 차단 조각](../../sql-drafts/2026-11-17-CX-62-dispatch-guard.handoff.sql)과 [되돌리기 조각](../../sql-drafts/2026-11-17-CX-62-dispatch-guard.handoff.down.sql)은 CX-66 승인 SQL의 같은 트랜잭션에 넣는다. CX-66에서 회사·주문·전표 및 최종 금액 확인을 끝낸 뒤, 주문 ID를 거래 로컬 설정 `maju.dispatch_confirm_order`에 지정해 전표를 확정하고 즉시 지운다.

[PG17 합성 시험](../../sql-drafts/2026-11-17-CX-62-order-receipt.pg17.test.sql)은 낡은 접수·두 연결의 중복 접수, 타사 거절, 트리거 실패와 금액 불일치 롤백, 과세·면세·배송비 혼합 대사, 거래처 스냅샷, 접수 후 취소, 분리된 출고 차단과 되돌리기를 확인한다. 실제 CX-66 출고 확정의 원장·재고 이동은 승인된 출고 함수와 함께 다시 검증한다.

## 병합 전 확인 순서

1. CX-58 사업자 칸, 기존 CX-38 저장 함수·권한, CX-62 새 RPC 존재 여부와 기존 작성중 전표를 운영에서 읽기로 다시 확인한다.
2. CX-66 출고 확정 함수와 분리한 차단 조각을 하나의 적용·되돌리기 묶음으로 검토한다. CX-62 접수·취소와 연결한 PG17 시험에서 미확정 시가·출고 금액·원장·재고 이동까지 확인한다.
3. 새 목록이 빈 상태로 코드 병합을 검토한다. 기존 ERP 스위치의 저장·접수 흐름을 유지하고 새 RPC를 호출하지 않는다. main 병합은 별도 운영 시간 및 현황판 승인 뒤 진행한다.
4. 대표의 SQL 적용 승인을 받은 컨트롤타워가 현황판 잠금을 확보해 SQL을 적용하고 함수·권한·트리거를 읽기로 확인한다. 기존 경로에서 이미 확정 전표가 생긴 미접수 주문을 대사해 안전하게 처리한 뒤, 승인된 회사만 새 목록에 넣는다.

[되돌리기](../../sql-drafts/2026-11-17-CX-62-order-receipt.down.sql)는 주문 출처의 작성중 전표가 남아 있으면 차단 장치를 보존하고 거절한다. 작성중 전표가 없고 앱 호출도 중단된 상태에서만 추가 함수와 트리거를 제거한다. 주문·전표·원장·재고 행은 삭제하지 않는다.
