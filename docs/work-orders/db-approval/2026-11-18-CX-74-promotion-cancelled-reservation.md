# CX-74 부분 취소와 행사 예약량 — 승인 전 SQL 초안

운영 적용 승인 없음. #1117은 기능 OFF Draft 유지. 운영 DB 쓰기·데이터 보정·기능 ON·배포를 하지 않는다.

## 원인과 계약

`2026-11-18-CX-66-partial-dispatch-final-cancel.sql`은 원래 `quantity`를 유지하고 출고한 수량을 `shipped_quantity`, 나머지 최종 취소 수량을 `cancelled_quantity`에 기록한다. 각 수량은 음수가 아니며 출고+취소 ≤ 원래 수량이다. 일부 출고는 `in_delivery`, 전량 취소는 `cancelled` 상태다.

D4 `promotion_remaining_v1`과 카탈로그·계정 주문 엔진은 취소되지 않은 주문의 원래 수량 전체를 예약량으로 합산한다. 따라서 부분 취소한 수량도 계속 소비한 것으로 계산한다. 문서 주문·회원 문서 주문·배송 미확정 주문 엔진은 `submitted`만 합산하므로 접수/출고 후 소비량이 누락되는 반대 문제도 있다.

공통 계약: **취소되지 않은 주문에서 `quantity - cancelled_quantity`를 합산**한다. 출고한 수량은 이미 소비했으므로 계속 포함한다. 전량 취소 주문은 제외한다. 전체 행사 재고와 같은 매장 한도에 같은 계산을 적용한다. 현재 수정 중인 주문을 제외하는 기존 조건·행사 행 잠금·멱등 키·권한·가격·세금·원장·재고 전표는 유지한다.

예: 원래 3.125, 출고 1.630, 최종 취소 1.495이면 소비량은 1.630이다. 행사 재고/매장 한도가 4이면 새 주문 2.370까지만 허용하며 추가 0.001은 거절한다. 수량·원래 금액·주문 이력의 자동 변경은 없다.

## 검증 범위

`tests/sql/promotion-cancelled-reservation-cx74.pg17.test.sql`을 기존 CX-75 실제 SQL 체인에 포함한다. PostgreSQL 17·정확한 폐기 DB 이름 가드가 있다. 실제 주문 엔진·공통 경계를 사용하며 CX-66의 최종 취소 행 모양만 합성한다. 이번 시험이 실제 부분 출고 RPC부터의 통합 검증을 대체하지는 않는다.

- 문서/회원 문서/카탈로그 core·일반·회원/계정/배송 스냅샷 7개 진입점 × 전체 재고·매장 한도 2종.
- 3.125 → 최종 취소 1.495 → 잔량 2.370 → 추가 주문 성공 → 같은 키 재시도 무효과 → 0.001 초과 거절.
- 실패 후 전체 주문·알림·멱등·전표/원장/재고 스냅샷 불변. 출고 소비량을 두 번 해제하지 않음.
- up/down 전후 전체 이력 불변, 함수 정의·OID·소유자·ACL 원복.
- 별도 기존 D4 PG17 시험의 회사 격리·무제한·품절·실제 service_role 호출·ACL 유지.

최종 실행 결과는 #1117의 최신 head CI에 기록한다. SQL이 준비되어도 운영 적용·실제 부분 출고 연결·기능 활성화가 완료됐다고 보고하지 않는다.
