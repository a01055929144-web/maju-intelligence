# CX-132 ① 공개 문서 공유 주소·미리보기

Ponytail: 사용함

- Owner: pricing. Related: organization(기존 회사 공개 허용). 07 가입·05 링크 관리 API/화면은 수정하지 않는다.
- 기존 `preview_id/preview_title/preview_description`을 재사용한다. 새 테이블·컬럼·RPC·운영 쓰기 없음.
- 기존 CX-44의 10자리 `/s/코드`는 매장 링크이며 SQL의 문서 코드는 `/d/`용이다. 이를 중복 발급하지 않고, 이미 존재하는 공유 행 UUID를 하이픈 없는 32자리 ID + 128비트 HMAC 표식(총 55자)으로 표현한다. 문서 코드는 매장 코드와 길이·문자 규칙이 구분된다. 과거 미리보기 ID는 메타데이터 전용이므로 ID만 알아서는 새 문서 접근 권한을 얻을 수 없도록 기존 링크 비밀키의 별도 HMAC 용도 문자열로 서명하고 DB 조회 전에 검사한다. 추가 키나 스키마는 없다.
- `DOCUMENT_SHARE_BRANDING_COMPANY_IDS`에 명시된 회사의 일반 공개 문서 준비/재시도에서 `/s/<55자리>`를 기본 반환한다. 빈 목록=OFF. 기존 공유 기능·공개 문서 회사 허용도 함께 필요하다. 환경 설정은 이번 PR에서 등록·활성화하지 않는다.
- 일반 공개 발급 시 서버가 발행본의 회사명·문서명으로 `MAJU · {유통사} {문서명}`와 매장 혜택 설명을 기존 미리보기 칸에 저장한다. 리드 영업용 미리보기 문구는 유지한다.
- 미리보기 칸이 비어 있는 기존 행도 공유 행 ID로 별칭을 만들고, 서버에서 게시 문서의 안전한 제목·설명을 투영한다. ID/미리보기 ID 조회가 모호하면 메타데이터는 반환하지 않는다. 기존 행을 보정하거나 새 공유 행을 만들지 않고 원래 fragment 링크도 계속 검증한다.
- 짧은 주소는 같은 공유 행·게시 버전을 가리킨다. 기존 `/pricing-document#토큰`, `/q/ID#토큰`, 저장된 QR, 발행본 가격·내용은 수정하지 않는다. 발급 재시도는 같은 행·코드다.
- 일반 브라우저는 기존 검증된 fragment 문서 경로로 302 이동한다. 카카오·트위터 등 기존 판정의 미리보기 봇은 토큰 없는 `/q/ID`만 받는다. 미리보기 응답은 제목·설명만 화이트리스트로 반환하고 토큰·고객·담당·연락처·가격·임의 하단 정보를 포함하지 않는다.
- 회수·열람기간 만료·회사 허용 해제·보관 문서·키 변경·요청 제한은 기존 서명/공개 문서 경계에서 차단한다. 미리보기 역시 활성 회사·게시 문서·회수·만료를 확인한다. 미리보기 페이지는 동적 응답, noindex/nofollow/no-referrer. 짧은 주소는 no-store/no-referrer다.

## 작은 화면 흐름

기존 발행 버전 → 공개 링크·QR 생성 → 짧은 주소 복사/QR → 기존 공개 단가표.
카카오 미리보기: MAJU · 회사명 + 문서명 / 가입 전 확인·단가 비교·간편 주문 설명.

## 파일 소유·검증 문턱

- 05방 #1264가 main `2e2bb97`에 병합됐고 담당 방의 QR 파일 소유 해제를 확인했다. 그 결과 위에서 발급 화면과 로컬 QR 렌더러가 같은 공개 주소 검증을 재사용한다. 해시 없는 서명 별칭·기존 fragment 주소는 허용하고, 다른 출처·검색 매개변수·자격증명·별칭의 fragment는 거절한다.
- 단위/실제 API 핸들러 합성 DB 시험: 발급 멱등·원본 내용 불변·기존 fragment·봇 토큰 비노출·회수/만료/회사/키/보관/요청 제한·기본 OFF.
- 1440/390: 기존 공개 QR 입구·복사·열기·오류/회수 경로에서 새 주소를 시험한다. 실제 로컬 QR PNG를 만들고 새 별칭의 fragment 오염·외부 출처 거절, QR 렌더 실패 시 링크 복사 유지, 공개 읽기·가입 입구·만료/회수를 확인한다. 원격 증거는 `readonly-pg17/cx132/cx132-{qr|public}-{sheet|quote}-{1440|390}.png`. 기존 리드 fragment 경로 회귀도 유지한다.
- 원격 CI의 단위 시험·lint·Next 타입/빌드·공개 문서·반응형·Stage A 결과를 PR에 기록한다. 로컬 npm 작업 없음.
- 실제 카카오톡 발송·실계정 캐시 갱신은 수행하지 않는다. 합성 Kakao scraper UA의 토큰 없는 이동/OG 메타와 캐시 헤더까지 검증하고 실제 캐시 반영은 총괄방 운영 관문 뒤 확인한다. 외부 서비스에 남은 과거 카드의 즉시 삭제를 보장하지 않는다.

## 원격 검사 실패와 수정
