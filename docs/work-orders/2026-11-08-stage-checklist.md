## 우선순위와 충돌 방지

1. 09: 기존 문서 게시 버전과 테스트 매장 링크로 `/store` PC/390px 표시를 확인한다. 운영 데이터 쓰기는 승인 범위에서만 한다.
2. 09·07: 기존 7인자 주문 RPC는 유지하고 새 회원 주문 RPC를 **다른 이름**으로 추가한다. SQL 승인·적용→코드 배포(회원 플래그 OFF)→대상 회사 ON 순서로 전환한다. 주문 API는 09, 인증 helper는 07이 소유한다.
3. 09: 기존 `StorefrontWorkspace`를 재사용해 링크 주문과 카카오 매장 세션의 진입·원가관리를 연결한다. 회사/매장 일치는 서버에서 검증한다.
4. 03·05·09: 수락→거래처 연결→주문 링크→첫 주문→내역/작성자 기록을 한 매장으로 통합 검증한다.
5. 02→03/04→06/08: 주문 DTO 계약 이후 배송, ERP, 지표 순으로 연결한다.

Draft #345와 #349는 같은 주문 화면/API에 닿는다. #345를 먼저 최신 main 기준으로 정리하고 후속 주문 브랜치를 재배치한다. #349의 기존 RPC 제거안은 그대로 운영 적용하지 않는다. 신규 SQL과 운영 쓰기 검증은 별도 승인 및 PG17/CI 뒤에 진행한다.
