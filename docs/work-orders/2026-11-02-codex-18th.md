## 1. 로그인 · 권한 (WO-21 변경)

- **카카오 로그인은 대표 · 직원 누구나** 쓸 수 있다(배송기사 전용이 아니다).
  - 아이디 계정이 있는 사람도 카카오를 연결할 수 있다. 로그인 방법은 사람마다 아이디 / 카카오 / 둘 다 중 하나다.
  - 연결 방법: 초대 링크로 한 번 연결 → 그다음부터 카카오 버튼으로 로그인. 연결되지 않은 카카오는 거부한다.
  - `/login` 화면 문구는 "대표 · 직원 모두 · 아이디 또는 카카오"로 하고, 모바일 링크로 들어와도 같은 화면을 쓴다.
- **'알바'라는 이름은 쓰지 않는다. 권한 묶음으로 관리한다.** 고객사 대표와 MAJU 관리자가 설정한다.
  - 기본 묶음: 대표 · 관리자 · 영업 · 배송 · **필드 영업(모바일만)** · 정산. 묶음을 복사해서 새 묶음을 만들 수 있다.
  - 권한 항목:
    - PC 화면 접근
    - 영업 · 리드 · 지도
    - 견적서 · 단가표 작성
    - 단가 · 매입가 보기
    - 주문관리 · 출고 준비
    - 배송 앱
    - 매입 · 매출 · 입출금
    - 거래처 연락처 전체 보기
    - 직원 · 권한 변경
    - 엑셀 내려받기
  - 필드 영업(모바일만): PC 정보는 볼 수 없다. 매장 링크 · 리드 · 방문 기록 · 가격 비교만 쓸 수 있다.
- 권한은 **서버(API)에서 확인한다.** 메뉴를 숨기는 것만으로 처리하지 않는다. `role_permissions(company_id, role_key, permission_key, allowed)`.
- 화면: 설정 › 직원 · 권한 (RoleSettings). MAJU 관리자도 고객사 상세 › 직원 · 권한 탭에서 같은 화면을 쓴다.

## 2. 고객사 서비스 켜기 · 구분 · 가져오기 이력 (WO-22 변경 · AdminServices)

- 고객사마다 **서비스를 켜야 그 메뉴와 화면이 보인다.**
  - 서비스: 영업관리 · 견적서·단가표 · 링크 주문 · 물류 TMS · ERP · 영업권 확대 · 필드 영업 전용 모드.
  - `company_services(company_id, service_key, enabled)`.
  - 메뉴 · 페이지 · API 모두 이 값을 확인한다(꺼진 서비스 API는 403).
- **고객사 구분**을 고르면 서비스가 자동으로 켜진다(켠 뒤 직접 바꿀 수 있다).
  - 종합 식자재(전체)
  - 주류 유통 · 영업만(자체 앱 있음)
  - 축산 · 수산(주문 + TMS)
- **가져오기 이력**은 고객사 상세의 탭으로 둔다. 고객사가 직접 올린 것과 관리자가 대신 올린 것을 함께 보여준다.
- **기초 등록 데이터는 하나로 쓴다.** 고객사가 고치면 관리자 화면에도 바로 반영된다(같은 테이블).
- 담당자 로그인에 카카오 연결(초대 링크)을 넣는다.

## 3. 관리자 고객사 지도 (WO-23 변경)

- 고객사 지도 탭과 같은 **카카오 지도**를 쓴다. SVG 타일은 쓰지 않는다. 구 단위로 묶는 규칙은 그대로다.
- 필터에 **고객사 구분**을 추가한다(영업만 쓰는 고객사 구분).

## 4. 요금제 · 성사 수수료 (AdminPricing)

- 과금 항목을 설계한다. 금액은 대표가 나중에 정한다.
  - 기본(회사/월)
  - 신규 리드 노출(100건/월)
  - 영업권 확대(구 · 기간)
  - 링크 주문 구좌(매장 구좌/월, 자동 영업)
  - TMS(차량/월)
  - ERP(사용자/월)
  - 요금제 = 항목 묶음이고, 서비스 켜기와 연결한다.
  - 테이블: `billing_items` · `billing_plans` · `company_usage_monthly`.
- **MAJU 영업 성사 수수료 2%(부가세 별도)**:
  - 적용 대상: MAJU가 연결한 매장(필드 영업 또는 MAJU 리드에서 시작해 첫 주문까지 간 매장)의 거래액.
  - 기간: 정할 것(안: 첫 주문부터 12개월).
  - 귀속 근거: 리드 → 첫 견적·링크 → 60일 안 첫 주문. 이 과정을 `deal_attributions`에 남기고 화면에 근거로 보여준다.
  - **돈 받는 방법(중요)**:
    - 매장 결제 · 예치금을 MAJU 통장으로 받았다가 고객사에 넘기는 방식은 **구현하지 않는다**(전자금융업 등록 대상).
    - 등록된 PG의 분할 정산으로 2%만 MAJU가 받거나, 월 정산서 + 자동이체로 받는다. 대표가 법률 확인 후 정한다.
    - 지금은 귀속 기록과 월 수수료 계산까지만 구현한다.

## 5. 단가 우선순위 (PriceRules · 신규)

- 매장 × 상품 단가는 서버의 한 함수로 결정한다.
  - **0 협의 고정가 > 1 견적서 > 2 단가표 > 3 기본가(매입가 × 기본 마진)**
  - 행사가 · 임박가는 별도로 계산하고, 기간 · 수량 안에서 더 싼 값을 우선한다.
- **매장에는 견적서 또는 단가표 중 하나만 연결한다.** 둘 다 연결하는 것은 금지다(DB 제약 + 화면 검증).
- **유효기간이 끝나면 다음 순위로 자동 전환한다.** 만료 7일 전에 알림을 보낸다.
  - 테스트 필수:
    - 견적 만료 → 단가표 값
    - 단가표 만료 → 기본가
    - 협의 고정가가 있으면 항상 협의 고정가
- 협의 고정가: `customer_fixed_prices(customer_id, product_id, price)`. 거래처 상세에서 관리한다.
- 같은 품목인데 매장 요청 때문에 값이 다른 경우(대파 2,000 / 2,200) → 그 매장의 협의 고정가로 처리한다(새 상품 코드를 만들지 않는다).
- 매입가가 바뀌면 기본가만 다시 계산한다. 협의 고정가 · 견적은 그대로 두고, 역마진이면 표시만 한다.

## 6. 출고 준비 (OrderSummary 이름 변경 · WO-10 변경)

- 메뉴 이름은 **출고 준비**로 바꾼다(기존 '배송분 집계 · 사입 주문표').
- 단계: ① 주문 확정 → ② 주문 마감 → ③ 품목 집계 → ④ **발주(사입)** → ⑤ 입고 · 매입 등록 → ⑥ 매출 등록 → ⑦ 피킹 · 패킹 · 상차.
- **매장별 수량을 보여준다**: 대파 10단 = [A]1 · [C]1 · [D]1 · [H]2 · [K]5. 요청이나 단가가 다른 매장은 강조한다(K: 굵은 것 · 2,200).
  - 카톡용 복사도 매장별로 나눠서 적는다.
- **재고 확보 구매**: 재고가 충분해도 더 살 수 있다. 줄마다 "재고 확보" 수량을 더한다.
  - 발주할 양 = 주문 합 − 가능 재고 + 재고 확보.
- 회차(야간 · 주간 · 추가 발주) · 매입처 바꾸기 · 주간으로 넘기기는 17차 그대로다.

## 7. 발주 → 매입전표 (BuyVoucher 다시)

- 줄 단위 입력: 발주 수량 · **받은 수량** · **매입 단위** · 전일 단가 · **오늘 단가** · **단위 환산** · 금액 · 메모.
- **단위 환산**: 상품에 `purchase_unit`, `sale_unit`, `conversion_factor`를 저장한다.
  - 예: 청양고추 1박스 = 9.5kg(실중량 기준). 박스로 사도 재고는 kg로 늘고, 매입가도 kg당(60,000 ÷ 9.5 = 6,316)으로 반영한다.
  - 한 번 정하면 다음부터 자동이다.
- 계근 상품은 받은 수량에 실측 중량을 넣는다.
- **매입가 반영 규칙**: 매장 요청 때문에 달라진 매출 단가(2,200)는 매입가에 반영하지 않는다. 매입가는 그 품목의 실제 매입 단가(기본)로 갱신한다.
- 저장하면:
  - 매입전표를 만든다(원본 = 발주).
  - 재고를 늘린다(환산 단위 기준).
  - 단가가 바뀐 품목은 매입가 반영 후보로 올린다(자동 반영 설정이 켜져 있으면 바로 반영).
  - 덜 온 수량은 다음 회차로 넘긴다.
  - 영수증 사진을 첨부할 수 있다.

## 8. 상품 등록 (ProductForm 다시)

- 폭은 약 920px. 3개 섹션(기본 / 분류·매입처·보관 / 가격), 4칸 격자로 촘촘하게 배치한다.
- **규격 · 단위 · 원산지 · 창고 위치는 드롭다운**으로 한다. 목록은 회사 설정에서 관리하고 "+ 새 값"으로 바로 추가할 수 있다.
- 중량·용량 칸은 빼고, **매입 단위 환산** 칸으로 바꾼다.
- 가격:
  - 처음 매입가와 기본 마진을 넣으면 기본가가 자동 계산된다.
  - 옆에 **우선순위 표**(협의 고정가 매장 수 / 견적 / 단가표 / 기본가)를 보여준다.
  - **매입전표가 들어오면 매입가가 자동으로 바뀐다**(최근 매입가).

## 9. 매입가 반영 (WO-04 변경)

- 입력 표는 매입 · 매출 전표와 **같은 공통 입력 표**를 쓴다(엑셀형 · 단축키 · 품목 찾기). 변동 · 쓰는 곳 · 영향받는 문서 표시는 유지한다.
- 품목을 자유롭게 추가 · 삭제할 수 있다.
- ERP를 쓰는 회사: 매입전표 단가로 자동 갱신한다.
- ERP를 안 쓰는 회사: 매입가 칸을 직접 고치거나 **엑셀 업로드**로 갱신한다(별도 ERP 연동은 만들지 않는다).

## 10. 템플릿 · 행사 · 임박 · 단가표 만들기 · 인쇄

- 매장 화면:
  - 행사 · 임박 상품은 **카테고리 맨 위에 필터처럼** 둔다. 예: "행사 3 · 임박 5". 누르면 전부 보인다.
  - 행사 · 임박 상품은 **남은 수량을 항상 표시**한다. 주문 확정 · 마감 때 줄어든다(재고 원장과 연결).
  - 전체 목록에서는 "행사 상품 + n개 · 임박 + n개"로 접어서 보여준다.
- **단가표 만들기**:
  - 이름을 정할 수 있다.
  - **단가표 / 견적서를 토글로 선택**한다(같은 화면).
  - 입력은 매입 · 매출과 같은 공통 입력 표를 쓴다.
- 온 · 오프라인 인쇄(전단): 행사 상품도 **행마다** 표시한다.

## 11. 오늘 코스 사용 조건 (WO-24 보완)

- 링크 주문을 쓰거나 매출 원장 · 매출처(상호만이라도)를 올린 고객사는 오늘 코스를 쓸 수 있다.
- 지도에 필요한 값: 상호 · 사업자번호 · 연락처 · **주소 · 상세주소**. 엑셀 가져오기와 같은 칸을 쓴다.
- 주소를 좌표로 바꾸지 못한 거래처는 따로 모아 보여주고 다시 시도할 수 있게 한다.

## 12. 엑셀 가져오기 · 미리보기 (WO-25 변경)

- 표준 칸 편집 화면에서 **키(내부 이름)는 보이지 않게** 한다.
- **여분 칸 5개**(`extra_1`~`extra_5`)를 기본으로 둔다. 회사가 이름을 붙여 바로 적재한다. 더 필요하면 `extra_attributes`에 둔다.
- 이번에 보완할 것:
  - 거래처: 주소 · 상세주소 · 결제 조건 · 담당. 중복 기준은 사업자번호 → 상호+전화.
  - 거래처 원장: 협의 고정가 여부.
  - 상품: 매입 단위 환산 · 창고 위치 · 공통 카테고리.
  - 재고: 위치 · 기준일.
  - 좌표 변환에 실패한 줄을 따로 보여준다.
- **미리보기에서 반영할 결과를 고른다**: 새로 / 같은 상품 / 의심 / 오류를 체크박스로 고른다. 예를 들어 오류 · 의심 · 같은 상품을 빼고 **새로만 반영**할 수 있다. 빠진 줄은 남겨 두고 나중에 따로 처리한다.

## 순서 · 플래그

- **5 단가 우선순위**: 묶음 E(매장 링크) 전에 먼저 한다. 매장 가격이 이 함수에 달려 있다.
- **6 · 7**: 묶음 F에 넣는다(17차 C 재고 원장 다음).
- **8 · 12**: 묶음 B에 넣는다.
- **9 · 10**: 묶음 G(가격)에 넣는다. 단, 매장 화면의 행사 · 임박은 묶음 E에 넣는다.
- 새 플래그(기본 OFF):
