# 공개 단가표 첫 주문 배송 자격 — 2026-11-10 정정

Owner: order. Related: pricing(서명 링크·조회), delivery(기존 권역 읽기), 07(주소 등록), 03(기존 거래처 권역 연결).

가입은 사업자번호·권역 설정 없이 가능하다. 주문은 서버 저장 기본주소로 같은 회사의 활성 권역 정확히 1건과 실제 배송 가능 요일을 확인해야 한다. 개업준비 매장도 같은 규칙이다. 07 가입·활성화 파일, 03 거래처 원장 및 중앙 체크표는 수정하지 않는다.

## 구현 범위

- `domains/order/delivery-eligibility.ts`: 기본주소의 시·도/시·군·구/일반구만 판정. 상세주소·기존 합친 주소를 위치 판정에 사용하지 않는다.
- `lib/pricing/store-delivery-eligibility.ts`: 서명 링크에서 확인한 회사/거래처 범위로 저장된 분리 주소, 활성 권역/실제 지역 키, 고객→권역 요일을 읽는 공통 판정. 조회와 주문 제출 직전에 재사용한다. 페이지 끝까지 읽어 서버 행 제한이 중복 권역을 숨기지 않도록 한다.
- 시 전체와 일반구가 서로 다른 활성 권역에 걸리면 중복으로 차단한다. 구만 등록된 권역에서 기본주소의 구를 알 수 없으면 허용하지 않는다. 잘못된 지역 키/알 수 없는 단위도 차단한다. 자동 우선순위·주소 추측·권역 자동 생성 없음.
- 일치 권역이 있어도 거래처의 기존 `delivery_territory_id`가 null/다르면 담당자에게 연결을 요청한다. 원장 쓰기 없음.
- 기존 고객→권역→회사 마감/휴일/최소금액 정책 및 `place_store_order`/`place_store_member_order`와 스냅샷 생산자를 유지한다. 선택 날짜는 기존 서버 정책과 native RPC가 다시 검증한다.
- 새 검증 ON에서는 고객 입력 스냅샷 대신 서버의 분리 주소로 생산한다. OFF에서는 기존 쿼리·RPC·스냅샷 계약을 유지한다.
- 날짜 없는 pending 제출은 새 플래그 상태와 관계없이 400. #458 런타임 우회 경로 제거. 과거 NULL 날짜 주문 표시는 보존. #461은 취소/종료되어 재사용하지 않는다.

## 적용 의존성 및 기본 OFF

`STORE_ORDER_ADDRESS_VERIFICATION_ENABLED=true`와 `FEATURE_STORE_ORDER_ADDRESS_VERIFICATION_COMPANY_IDS` 해당 회사 허용이 모두 필요하다. 기본 OFF는 새 주소 컬럼을 조회하지 않는다. ON인데 #463 SQL 미적용/분리주소 null/조회 실패면 안전하게 주문 차단한다. 기존 합친 주소를 임의 분해하지 않는다.

1. 07 #463 분리주소 SQL/가입·활성화 계약 적용과 관련 플래그 확인.
2. 기존 public owner delivery SQL 및 `STORE_PUBLIC_OWNER_DELIVERY_ENABLED`/회사 allowlist 확인. 현재 운영 플래그 OFF이므로 새 매장 권역 자동 연결을 가정할 수 없다. 기존 매장은 03 담당자가 권역 연결 확인.
3. 위 의존성 확인 후 별도 승인으로 09 새 검증을 대표 회사에만 ON.
4. 대표가 실제 화면에서 주소 안/밖·요일·가입 후 첫 주문을 확인. 외부 카카오 인증과 실주문은 CI 합성 테스트로 증명하지 않는다.

이번 PR은 신규 SQL 없음. 운영 DB 쓰기·플래그 변경·환경변수 변경·배포·실가입·실주문 없음. 기존 pending SQL은 역사적 격리 CI 회귀 전용이며 운영 적용 금지.
