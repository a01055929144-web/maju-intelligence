# 02 Stage D 주문→배송 대기 계약과 합성 테스트 계획

Ponytail: 사용함

상태: **09 주문 DTO 대기**. #350은 단계 체크 문서이며 주문 DTO 구현이 아니다. 09가 아래 계약을 제공하고 병합하기 전에는 02가 TMS 런타임, API, DB, 화면을 변경하지 않는다.

## 시작 조건

09가 배송 후보마다 다음 값을 제공해야 한다.

- `companyId`
- `orderId`
- `customerId`
- `deliveryDate`
- `orderRevision`
- 배송지 스냅샷: `customerName`, `address`, `addressDetail?`, `recipientPhone?`, `loadingPosition?`

추가 전제:

- 09가 취소 주문을 배송 후보에서 제외하는 기준과 `orderRevision` 증가 규칙을 소유한다.
- 02는 `companyId`가 다른 후보를 섞지 않고, 동일 `orderId`의 상충 데이터와 낮아진 revision을 오류로 처리한다.
- 고객·기사 배정은 기존 TMS 자료를 사용한다. 주문 DTO만으로 미배정 주문을 임의 배정하지 않는다.

## 보존해야 할 수동 코스

- 주문 후보가 0건이어도 기존 수동 코스와 수동 거래처 순서를 그대로 유지한다.
- 주문이 연결되지 않은 수동 정차지는 `orderIds: []`로 남긴다.
- 취소로 주문 후보가 사라져도 해당 거래처가 수동 코스에 있으면 삭제하지 않는다.
- 주문 연결 과정은 `route_plan_confirmations`와 기존 완료 이력을 수정하지 않는다.

## 합성 데이터

기본 fixture는 회사 A, 배송일 D, 수동 정차지 M, 기사 배정 거래처 C1, 미배정 거래처 U1로 구성한다. 주문 A1·A2는 C1의 같은 배송지, A3는 C1의 다른 배송일, U1은 기사·코스 배정이 없는 상태로 둔다. 취소 주문 X1은 09 결과에서 빠진 상태로 입력한다.

## 합성 테스트 시나리오

| 시나리오 | 입력 | 기대 결과 |
| --- | --- | --- |
| 기존 수동 코스 유지 | 주문 후보 없음, 수동 정차지 M 존재 | M과 순서 유지, `orderIds: []`, 완료·확정 자료 무변경 |
| 취소 주문 | X1 제외, X1 거래처가 수동 코스에 존재 | 수동 정차지는 유지하고 X1 참조만 없음 |
| 취소 후 자동 후보 없음 | X1 제외, 거래처가 수동 코스에 없음 | 새 정차지를 만들지 않고 다른 코스도 변경하지 않음 |
| 일부 주문 취소 | 같은 거래처 A1 유지, A2 취소로 제외 | 정차지 1개 유지, `orderIds`에는 A1만 존재 |
| 복수 주문 | C1·D에 A1과 A2 | 정차지 1개, 안정 정렬된 `orderIds`, 주문별 revision 보존 |
| 다른 배송일 | C1의 A3가 D가 아님 | D 코스에서 제외 |
| 배송지 충돌 | 같은 거래처·날짜 주문의 스냅샷이 다름 | 자동 병합하지 않고 충돌 오류 반환 |
| 미배정 주문 | U1 주문, 기존 기사·코스 배정 없음 | 자동 배정·누락 금지, 미배정 결과로 분리 |
| 회사 경계 | 회사 B 후보가 회사 A 요청에 포함 | 전체 요청 실패 또는 명시적 오류, 회사 A 코스 무변경 |
| 주문 충돌 | 같은 `orderId`에 다른 거래처 또는 배송지 | 오류 반환, 부분 반영 없음 |
| revision 역행 | 저장 기준보다 낮은 `orderRevision` | 오래된 후보로 거절, 기존 연결 유지 |

## 구현 후 테스트 위치

1. 순수 변환 계약은 `tests/order-route-consumer.test.ts`에 추가한다.
2. 09 DTO를 읽고 기존 TMS 배정과 합치는 런타임 통합 테스트는 09 계약 병합 뒤 02 소유의 별도 테스트 파일에 추가한다.
3. 미배정 결과는 “누락도 자동 배정도 아님”을 API 응답과 화면에서 확인한다.
4. 런타임 연결 전에는 PC/390px 운영 완료로 표시하지 않는다. 연결 뒤 수동 정차지 유지, 미배정 표시, 충돌 오류를 각각 확인한다.

## 완료 기준

- 09 DTO가 위 필드와 취소·revision 규칙을 포함해 main에 병합됨.
- 네 핵심 합성 흐름(수동 코스, 취소, 복수 주문, 미배정)이 통과함.
- 실패 시 부분 반영이 없고 기존 코스·확정·완료 이력이 보존됨.
- 운영 DB 쓰기와 배포는 별도 승인 뒤 진행함.
