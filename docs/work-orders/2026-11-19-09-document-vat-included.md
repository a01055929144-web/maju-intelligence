## 사용자 행동과 호환

새 기능이 허용된 회사에서 새 빈 문서/추천 문서만 부가세 포함으로 시작한다. `DEFAULT_DISPLAY`의 기존 false를 바꾸지 않는다. 기존 문서의 복사/연장은 원래 방식과 단가를 그대로 보존한다.

새 문서의 일반 과세1000원 기준단가는 포함 표시1100원, 행사1100원은1100원, 임박60원은60원으로 유지한다. 행사 고정가를1.1로 다시 가산하거나 입력값을 역산해 원본으로 바꾸지 않는다. 포함/별도 표시를 전환해도 고정 행사 가격은 그대로이며 과세 포함/면세 고정가를 안내한다. 원상품 세금 정정은 기존 #1149·#1151의 명시적 동작을 사용한다.

`priceContract: promotion-gross-v1`와 행별 `priceIncludesTax`로 저장된 단가의 기준을 명시한다. 일반 단가 계산/일반 MoneyInput의 기존 기준은 유지한다. 서버 clean이 같은 회사 행사 원본의 가격/세금을 확정하고 포함 여부를 행 종류에서 정한다. 구형 화면이 새 계약을 누락해도 outer P1이 저장된 방식을 보존하며, 기존 문서를 새 방식으로 바꾸는 요청은 거부한다. 이전 발행본에 새 해석을 소급하지 않는다.

`PRICING_DOCUMENT_VAT_ENABLED=true`와 `PRICING_DOCUMENT_VAT_COMPANY_IDS`의 인증된 회사가 일치해야 새 기능을 사용할 수 있다. API도 동일 회사 기준으로 새 방식 저장을 검사한다. OFF 상태에서는 새 방식 편집을 잠그고 다음 행동을 안내하지만 기존 발행본의 의미는 보존한다. 운영 환경변수 등록/ON 없음.

## 소유/선행

09는 문서 UI/도메인/P1 저장 SQL만 수정한다. 06의 공개/회원/계정 주문 함수,04의 전표/부분출고 파일은 수정하지 않는다. 승인표는 #1150 → #1155 →09 저장 선행과 소비자/producer 순서 **CX-38b → CX-66 →06 주문 VAT SQL**을 구분한다. 금액 스냅샷을 역산하지 않고 주문 공급가/세액/합계를 전표·부분출고까지 전달해야 한다.
