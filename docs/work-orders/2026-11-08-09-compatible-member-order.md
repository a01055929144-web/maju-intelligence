## 호환과 회원 경계
- 기존 `place_store_order(text,date,jsonb,uuid,uuid,integer,text)`는 삭제/교체/권한 변경하지 않는다. 새 `place_store_member_order`만 추가하고, down도 새 함수만 제거한다.
- `STORE_MEMBER_SESSION_ENABLED`와 서버가 확인한 회사 허용 목록을 모두 만족하는 회사만 07 helper와 새 RPC를 사용한다. 둘 중 하나라도 OFF이면 기존 7인자 주문을 유지한다. 요청 JSON의 회사/회원/사용자/전환 여부로 이 분기를 정하지 않는다.
- 회원 전환 ON 회사는 활성 회원이 없으면 403이며, 새 RPC 장애/권한 변경 시 구 RPC로 재시도하지 않는다. 회원 ON 전제에서만 공개 토큰 단독 주문을 거부한다고 표현한다.
- DB는 새 주문 저장 전 같은 회사/거래처의 활성 계정·영업 상태·회원 역할·로그인 사용자를 잠금 아래 재검증하고, 신규 주문의 store_account_id/ordered_by_member_id를 기록한다. 기존 행 백필 없음.
- 기존 P2의 행사/가격/세금/규격/단위/배송/재고 계산을 재사용한다. 회사/매장 격리, 같은 회원·동일 키 1건, 다른 회원 같은 키 거부, 탈퇴 후 재생 차단, 작성자 보존을 검증한다.

## 검증과 승인
- PG17은 실제 P0/P1/P2/S2/manager-role migration과 주변 합성 fixture만 사용한다. 기존 7인자 함수 본문 해시·OID·실행 권한을 up/down 전후 비교하고 기존 7인자 호출의 정상 주문도 확인한다.
- 새 함수의 다른 회사/매장/위조 사용자/초대·탈퇴·정지 거부, 작성자/스냅샷/멱등 및 두 연결의 탈퇴 경합·동시 동일 요청을 확인한다. 회원 주문이 있으면 down 거부, 기존 RPC 보존도 확인한다.
- 새 SQL 승인표: `docs/work-orders/db-approval/store-member-order-09.md`. 운영 적용은 별도 승인 전 금지. SQL 적용·읽기 확인 → 코드 배포(회원 전환 OFF) → 기존 주문 확인 → 승인 회사만 회원 전환 ON 순서다. 기존 함수 제거는 별도 후속 승인 범위다.
- 이번 작업은 운영 DB·실주문·기능 ON·환경변수·배포·병합을 수행하지 않는다. 실제 브라우저→API→DB 첫 주문 E2E와 운영 완료 판정은 별도다. 최종 검사 건수/CI 링크는 PR 본문에 기록한다.
