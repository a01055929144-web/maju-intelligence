# 매입이력 정정과 매장 원가관리

Owner: pricing(매입이력), store(매장 원가). Related: product, quote, order.

## 확인한 현 상태

- `purchase_receipt_lines`는 날짜·매입처·품목별 엑셀 기록을 보관하지만 같은 키 재업로드는 원본 행을 덮어쓴다. 기존 화면은 최근 90일·최대 5,000행을 먼저 가져와 품목별로 묶고, 정정 기능이 없다.
- 단가표·견적서의 `pricing_p1('catalog')`는 `sales_spec`만 반환한다. 판매 규격이 비어 있고 `spec_value/spec_unit`이 있는 상품은 규격이 빠진다. 출력 부품은 이미 `spec`을 표시한다.
- 주문 링크는 현재 판매가와 품목 규격을 공개한다. 유통사의 매입가·마진은 공개 응답에 없다. `store_accounts`/`store_account_members`는 있으나 매장 자체 매입 원가 데이터는 없다.
- [제이에스리테일 피드백](https://app.notion.com/p/40f9433515838187834febdf1a98741b)은 매입 오입력 정정, 용량·등급별 SKU, A4 QR, 단가 등락 정보의 선택 공개를 요구한다. 등락률 공개는 그 기록에서 **검토 중**이며 자동 공개 결정은 아니다.

## 구현 순서

1. 매입이력: 서버 날짜 범위·검색·100행 페이지 조회, 품목 행을 누르면 날짜별 내역. `id`를 포함해 개별 기록을 식별한다. 정정은 원본을 덮지 않고 별도 override와 정정 이벤트를 한 트랜잭션에 기록한다. 정정 이유를 필수로 하고, 상품 연결과 원가를 바꿀 수 있게 한다. 재업로드해도 override는 남는다. 원본 공급가액·부가세·합계는 정정하지 않으며 청구 금액 정정은 전표 흐름으로 보낸다. 정정한 원가를 현재 판매가에 반영할 때는 기존 매입가 반영·재계산을 별도로 실행한다.
2. 규격: `sales_spec` 우선, 비어 있으면 `spec_value + spec_unit` 표시. 출력 모델이 이미 규격을 전달하므로 카탈로그 조회 두 경로만 보완한다. 규격값도 없으면 빈 칸을 유지하고 상품관리에서 직접 수정한다.
3. 주문 링크 단가 등락: 기본 비공개. 유통사가 공개 설정을 켠 경우에만 직전 유효 매입가 대비 **상승/하락/보합** 중 상승·하락 방향만 공개한다. 원가 금액, 변동 원 수치, 마진, 공급처, 매입일은 공개하지 않는다. 반품·오류·정정 취소 건은 기준에서 제외하고, 비교할 이전 값이 없으면 표시하지 않는다. 공급처 원가와 매장 자체 원가를 섞지 않는다.
4. 매장 원가관리: 같은 Next.js 모놀리스의 `store` 도메인 안에 `주문 | 주문 내역 | 원가관리` 탭을 둔다. 기존 고객사 폼의 버튼·표·열 맞추기·미리보기 부품을 재사용한다. 매장은 자신이 가진 매입 엑셀을 올려 상품명·규격·단위·매입처·일자·수량·단가를 확인하고 저장한다. 매장별 원가는 `store_account_id` 소유이며 유통사의 `product_catalog.purchase_price`와 분리한다. 링크 토큰만으로 원가를 조회하지 않고 카카오로 가입한 활성 매장 구성원 확인 후 접근시킨다. 점주/관리자만 업로드·정정, 직원은 조회만. 주문 가격과 매장 자체 원가를 비교할 수 있지만 유통사 원가·마진은 응답에 포함하지 않는다.

## DB 승인 대기

- `purchase_receipt_line_overrides` + `purchase_receipt_correction_events` + 단일 정정 RPC. 회사 복합 FK, service_role 전용, 정정 전/후·사유·작성자 기록. 원본 `purchase_receipt_lines`는 유지한다. 재업로드 시 같은 행 ID의 override를 계속 적용한다.
- 매장 원가 `store_cost_imports`, `store_cost_lines`, `store_cost_corrections`: `(company_id, store_account_id)`로 격리, 날짜·상품·원천 파일·단가·단위 스냅샷, 중복 업로드 키, 정정 이력. 매장 구성원 권한은 API와 DB 양쪽에서 확인한다. 매장 계정 하나가 여러 유통사에 연결될 때 소유권을 다시 설계해야 하므로 현재의 유통사별 계정 경계를 명시한다.
- 등락 공개 설정은 회사별 기본 OFF. 운영 적용 전 승인표와 PG17 검증을 별도로 낸다. 이 문서로 운영 DB를 변경하지 않는다.

## 안전 기준

- 공개 견적·주문 응답에 유통사 원가·마진·공급처를 넣지 않는다.
- 엑셀 원본과 정정 이력을 구분한다. 고객사가 수정한 매입이력은 원본 전표나 판매가를 조용히 변경하지 않는다.
- 기존 고객사 폼을 유지하고 빈 상태·오류·권한 안내 및 모바일 390px를 검증한다.
