# 주문 돈 안전 점검표 (2026-11-17 · 대표 지시)

> 대표 11/17 16:06: "지금 처음에 설계를 잘 만들어 놔야 다수의 고객사가 들어올 때 버그나 오류가 없다. 주문은 그만큼 중요하다. 돈이 걸린 거라서."

이 점검표는 **매장 주문 · 매출 전표 · 원장 · 재고**에 닿는 PR과 스위치 켜기에 모두 적용합니다.
- 해당 PR(Codex · Claude Code)은 본문에 이 표를 붙이고, 칸마다 시험 이름이나 캡처를 적습니다.
- 컨트롤타워는 표가 비어 있으면 병합 · 배포 · 스위치 켜기를 하지 않습니다.

## 1. 설계 원칙 (바꾸려면 대표 승인)
1. **금액은 서버가 한 곳에서만 계산합니다.**
   - 주문 줄 단가 · 공급가 · 세액은 DB 함수(`place_store_account_order` · 링크 주문 RPC)와 `store_order_lines` 계산 칸이 유일한 출처입니다.
   - 화면 가격은 "보여 주기"일 뿐입니다. 화면과 서버가 다르면 주문 전에 알립니다.
2. **접수에는 작성중 전표, 출고 확정에는 전표 확정**으로 처리합니다(CX-62 · CX-66).
   - 주문 저장 · 수정 · 매장 취소는 원장 · 재고를 움직이지 않습니다.
   - 접수와 작성중 전표 연결은 한 트랜잭션에서 끝납니다. 접수만으로 원장·재고가 움직이지 않습니다.
   - 시가 단가와 부분취소는 출고 확정 전 작성중 전표를 수정합니다. 출고 확정 뒤에는 수정·취소를 정해진 역분개 경로로 처리합니다.
3. **같은 요청은 몇 번 와도 결과가 한 번입니다.** 주문 · 취소 · 접수 · 전표 확정 · 수금은 모두 멱등 키나 revision 조건을 둡니다.
4. **회사가 섞이지 않습니다.**
   - 모든 테이블 · 키 · 조회에 `company_id`를 넣습니다.
   - 브라우저 역할은 주문 함수를 실행할 수 없고, 서버가 세션으로 확인한 사용자만 넘깁니다.
5. **지우지 않고 되돌립니다.** 확정 전표 · 주문은 행을 지우지 않고 취소 · 역분개합니다(CX-64 "삭제" = 취소 + 숨김). 누가 · 언제 · 왜를 남깁니다.
6. **새 기능은 회사별 스위치 기본 OFF**입니다. 스위치 이름은 하나만 둡니다(`isFeatureEnabled`). 옛 env 이중 스위치는 CX-62에서 없앱니다.

## 2. 켜기 전 필수 시험 (PG17 + 앱 시험 · PR마다 해당 칸)

| 2 | 같은 키에 다른 내용 | 거절(Idempotency conflict) |

| 8 | 행사가 · 재고 한도 · 매장별 한도 | 초과 거절 · 동시 주문에서도 초과 0 |
| 9 | 마감 시각 · 휴무일 · 배송 요일 · 최소 금액(block/fee/notice) | 경계값(마감 1분 전 · 후) 시험 |
| 10 | 다른 회사 매장 · 다른 회사 상품 · 다른 회사 주문 ID 섞어 보내기 | 전부 거절 |
| 11 | 여러 유통사 한 번에 주문 | 유통사별 성공 · 실패가 서로 영향 없음 |

| 13 | 확정 전표 "삭제" | 원장 · 재고 되돌림 · 수금 연결이면 막힘 |
| 14 | 단가표 만료 · 회수 · 새 버전 발행 직후 주문 | 서버가 최신 유효 단가로 계산 · 화면과 다르면 알림 |

## 3. 회사별로 켜기 전 운영 확인 (컨트롤타워 + 대표)
1. 회사 설정을 확인합니다: 후불 · 결제 기한 · 마감 · 배송 요일 · 최소 금액 · 배송 권역 · 새 매장 자동 승인 여부.
2. 시험 매장 1곳에서 실주문 1건 → 접수·작성중 전표 → 출고 확정·전표 확정 → 원장 · 재고 → 취소(역분개)까지 돌리고, **금액 대조표**(주문 · 전표 · 원장)를 기록에 남깁니다.
3. 첫 주 동안 매일 "주문 합계 = 전표 합계 = 원장 증가" 대조 쿼리를 돌립니다(컨트롤타워 예약 작업).
4. 이상이 있으면 그 회사 스위치만 끄고, 원인을 정의한 뒤 다시 켭니다.
