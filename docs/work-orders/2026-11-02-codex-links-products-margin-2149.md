## 1. 링크 관리 — ⑤ 와이어프레임대로 다시 구성 (매장별 링크 관리의 중심)

**머리**
- 연결 문서 이름(‹ 한식 기본 단가표 v4)
- 범위 탭: 전체 매장 · 선택한 매장 N · 특정 매장
- [+ 매장 추가]

**필터 줄**
- 매장명 · 전화 · 주소 검색
- 묶어 보기(배송 권역 · 담당자 · 없음)
- 결제(전체 · 후결제 · 선결제)
- 주문 받기(전체 · 켬 · 끔)
- 정렬

**선택 막대**: 선택 N곳 → 링크 복사 · 결제 방식 바꾸기 · 주문 끄기 · **보내기**(공통 SendDocumentDialog, A-0b)

**매장 표**(권역별 묶음 머리: 권역명 · 배송 요일 · N곳 · 열람 · 주문)
- 열: ☐ · 매장(계약 단가 N품목 표시) · 담당자 · **매장 링크**(가린 주소 + [복사]) · 열람 · 주문 · 결제(선택) · 주문 받기(토글) · **구성원**(점주 · 직원 수, A-0c) · 기록 ›
- 합계 줄
- 매장 링크는 **매장 고유 링크**(O-1)다. 문서를 바꿔도 주소는 그대로다.
- 결제 선택에서 **선결제는 비활성**(PG 보류) + 안내 한 줄.

**아래 표: 보낸 링크 · 열람 기록**
- 기간 7 · 15 · 30일 · 기간 지정, 관심(높음 · 주문 중 · 미열람)
- 열: 매장(리드면 "리드" 표시) · 보낸 문서 · 보낸 날짜 · 보낸 사람 · 처음 열람 · 최근 열람 · 열람 · 주문 · 관심
- 줄 버튼: [오늘 할 일] [바로 클로징] [다시 보내기]
  - 관심 "높음" = 열람 3회 이상 · 주문 0 → 담당자 오늘 할 일에 자동으로 올린다.
- 데이터: `pricing_document_sends` · `storefront_links` · `storefront_link_events` · `store_orders`(S-2 승인 묶음).

**매장 상세(기록 ›)**: 링크 재발급 · 끄기 · QR · 구성원 목록 · 보낸 문서 이력 · 주문 이력.

## 2. 상품관리 → ERP 묶음으로 옮기고 "전체 상품"으로

**위치**
- 와이어프레임대로 사이드바 **ERP 묶음 첫 메뉴 "상품관리"**로 옮긴다.
- **ERP를 쓰지 않는 회사도 이 메뉴는 항상 보인다**(전체 상품이 있어야 단가표 · 견적서 · 행사 · 임박을 쓸 수 있다).
- 주문 · 단가 쪽 화면에서 상품이 0건이면 빈 화면에 "먼저 전체 상품을 등록해 주세요 → [상품관리로]"를 보여준다.

**탭 · 이름 정리**

| 지금 | 바꿀 것 |
|---|---|
| 마스터 상품 | **전체 상품** |
| 매입가(매입 단가표) 업로드 | **전체 상품 업로드**로 바꾼다 |
| 매입처 상품 업로드 | **탭을 없앤다** |
| 표준 품목 연결 | **탭을 없앤다** |

- **전체 상품 업로드**
  - 상품 마스터를 올린다. 열: ERP 코드 · 품목 · 브랜드 · 규격 · 단위 · 구분(카테고리) · 매입처 · 과세 · 재고 방식 · (선택) 매입가.
  - WO-25 표준 칸 · 열 맞추기 · 미리보기 · 같은 상품 처리를 재사용한다.
  - 매입가 칸이 있으면 첫 등록 값으로만 쓴다. **매입가를 바꾸는 업로드는 "매입가 반영" 화면에만 있다**(#171).
- **매입처 상품 업로드 탭을 없앤다**
  - 매입처는 전체 상품의 "매입처" 칸으로 관리한다.
  - 매입처가 보낸 매입가 파일은 "매입가 반영 › 엑셀 올리기"에서 매입처를 골라 올린다.
  - 내부 테이블(`supplier_products` · 원가 이력)은 그대로 쓰되, 화면에서 따로 다루지 않는다.
- **표준 품목 연결 탭을 없앤다**
  - 이 탭은 "매입처 파일의 품목 = 우리 전체 상품 중 어느 것"을 맞추는 기능이다. **마진 그룹과는 관계없다.**
  - 이 맞추기는 업로드 미리보기의 "같은 상품 · 의심" 처리와 매입가 반영의 "신규" 탭에서 한다. 따로 탭을 두지 않는다.
- 남는 탭: **전체 상품 | 전체 상품 업로드 | 업로드 이력**

## 3. 마진 설정 — 누구나 이해하게 다시 구성

**문제**: 지금은 "마진 그룹 → 카테고리 연결 → 기본 마진 → 품목 마진 · 직접가"가 따로 놀고 있다. 어디서 무엇을 정해야 판매가가 나오는지 보이지 않는다.

**판매가가 정해지는 순서(위가 우선)** — 화면 맨 위에 그림으로 보여준다
1. 품목 직접 판매가(고정)
2. 품목 마진 %
3. **구분(카테고리) 마진 %**
4. 회사 기본 마진 %

계산식: 판매가 = 매입가 × (1 + 마진%) → 올림 단위

**화면 구성(`/revenue/pricing/margins`)**
- **맨 위**
  - 회사 기본 마진 % · 올림 단위(1 · 10 · 100원)
  - 계산 예시: "매입가 10,000원 → 판매가 11,500원"
- **가운데 = 구분별 마진 표**
  - 왼쪽: 전체 상품의 구분 트리(대 · 소분류)
  - 열: 구분 · 상품 수 · 마진 %(입력, 비우면 "회사 기본 따름") · 올림 · 예시 판매가
  - 하위 구분은 상위 값을 따른다.
- **"마진 그룹" = 같은 마진을 여러 구분에 한 번에 적용하는 묶음(선택 기능)**
  - 예: "채소류 15%"를 채소 · 쌈채소 · 고추류에 적용.
  - 그룹을 쓰지 않아도 구분별로 바로 정할 수 있다.
- **아래 = 예외 품목 표**: 품목 마진이나 직접 판매가를 정한 품목만 모아 보여준다(품목 · 구분 · 매입가 · 적용 규칙 · 판매가 · [규칙 지우기]).
- **[저장] 전 미리보기**: 바뀌는 품목 수 · 판매가 변화(전/후)와 영향받는 단가표 · 견적서 수 → [저장 + 다시 계산].
- 빈 상태: "전체 상품이 없어요 → [상품관리]"

**데이터 정리**(중복 출처 금지)
- P0의 `margin_group_categories`는 **구분 이름 문자열**로 연결한다. 전체 상품의 구분은 `product_categories`(id)다.
- 구분 마진의 정본을 하나로 정한다. 기본안: **P0 margin_groups를 정본으로 두고, 구분 연결을 `category_id`로 바꾼다.**
  - 구분 하나에 마진을 직접 정하면 내부적으로 그 구분 전용 그룹을 쓴다.
  - `product_categories.margin_bp`(WO-03 초안)는 쓰지 않는다.
- DB 변경이 필요하면 `db-approval/pricing-margin-category.md`로 승인 표를 올린다.
  - 승인 전에는 화면 구성 · 미리보기 · 문구만 먼저 바꾼다(지금 데이터 그대로).
