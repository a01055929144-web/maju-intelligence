## 게시 버전과 출력
- productId·상품 노출명·규격·단위·과세·판매가와 표시 옵션은 게시된 content로 고정한다. 다른 버전/문서 또는 변경된 content를 출력 직전 응답으로 받아들이지 않는다.
- 실시간 갱신 대상은 기존 계약대로 행사 가능 여부와 남은 수량뿐이다. 현재 상품 원장/초안을 과거 게시물에 덧붙이지 않는다.
- 인쇄·PNG·게시 미리보기 XLSX는 선택 버전의 같은 출력 모델을 사용한다. 유효기간 만료나 가격 숨김이면 가격을 내보내지 않는다. 게시 XLSX에는 스냅샷에 없는 최신 ERP 코드를 추정해 넣지 않는다. 초안 품목 내보내기는 기존 ERP 코드 흐름을 유지한다.
- 자동 인쇄도 수동 인쇄와 같은 재확인을 거치며 실패하면 인쇄하지 않고 다음 행동을 안내한다. 열린 미리보기의 KST 문서 만료도 가격을 숨긴다.
- 문서 가격 만료: 상품은 남고 가격은 숨김. 공유 링크 하드 만료/회수: 공개 문서 전체를 차단. 다운로드·인쇄된 사본의 소급 삭제는 약속하지 않는다.

## 05 전달 기록 연동 계약 — 구현 중복 금지
- 게시/미리보기/인쇄/PNG/XLSX/링크 준비/복사는 실제 전달을 뜻하지 않으며 연락 이력을 만들지 않는다.
- 명시적인 실제 전달 완료에만 기존 `record-send` 계약을 사용한다. 준비된 shareLinkId, 검증된 documentVersionId, 전달 대상 하나, templateId/channel, delivered=true 및 같은 idempotencyKey를 재사용한다.
- documentId/companyId·가격·publicUrl·작성자 이름을 클라이언트의 신뢰 입력으로 추가하지 않는다. 회사/행위자·URL·문서 종류는 기존 서버 계약이 결정한다.
- 응답의 sendId와 leadActionId가 같은 한 건을 05가 재사용한다. 09는 `lead_actions`를 별도 INSERT하지 않는다. 응답 유실은 같은 요청으로 재시도하며 409는 다른 내용의 키 재사용으로 다룬다.
- 05 소유 원자 RPC `record_pricing_lead_share_delivery`와 Draft #285의 별도 승인/운영 적용, 비밀키·회사 허용 목록·IP 제한이 운영 차단점이다. 합성 화면 테스트가 실제 발송/연락 기록 완료를 대신하지 않는다.
