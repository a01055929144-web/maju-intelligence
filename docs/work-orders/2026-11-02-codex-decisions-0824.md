  - ☐ · 품목 · 판매 단위 · 기본 매입 단위(작은 선택)

- 중앙값 대상:
  - 박스 실중량: 최근 5회 입고. 기록이 없으면 고정값을 쓴다.
  - 섞인 재고의 매입가: 남은 재고와 이번 입고들의 단가.

### 2-3 매장 링크 · 매장 주문 (WO-07 · WO-08) — 순서를 앞당김
- **Owner Domain**: order
- **Related Domain**: customer, pricing, catalog
- **Use Case**: `CreateStoreLink`, `ResolveStoreItems`, `PlaceStoreOrder`
- 링크를 만들면 그 거래처의 거래처 원장 품목(`customer_items`)이 자동으로 보이는 품목이 된다. 여기에 견적 · 단가표 · 행사·임박 품목을 더한다. 출처 배지를 달고, 품목마다 켜고 끌 수 있다.
- 매장에 보이는 정보(주문 내역 · 거래원장(기본 꺼짐) · 예치금 잔액 · 거래명세표)는 고객사가 정한다. 회사 기본값을 두고 매장마다 바꿀 수 있다. **서버에서 확인한다.**
- 매장 가격: 우선순위 0 협의 고정가 > 1 견적서 > 2 단가표 > 3 기본가(= 그날 기준 매출가). 행사 · 임박은 따로 표시한다.
  - 견적서와 단가표 중 하나만 매장에 붙는다. 기간이 끝나면 자동으로 다음 우선순위를 쓴다.
- 매장 주문 화면: 품목 · 수량 · 단위 · 품목별 요청(비고). 요청은 출고 준비 비고로 이어진다.

### 2-4 출고 준비 · 발주서 이미지 (WO-10 · WO-11)
- **Owner Domain**: purchasing
- **Related Domain**: order, inventory
- **Use Case**: `CloseOrders`, `AggregateForPurchase`, `PlacePurchaseOrder`
- 흐름 표시줄:
  1. 주문 확정
  2. 주문 마감
  3. 품목 집계
  4. 발주(사입)
  5. 입고·매입 등록
  6. 매출 등록
  7. 피킹·패킹·상차
- 진행 막대: 매입전표 N / 전체 곳. 끝난 매입처는 ✓ 완료 카드로 접는다.
- **매입처마다 카드**를 만든다.
  - 카드 머리줄(진한 배경): 이름 · 상태 · 품목 수 · 매출처 줄 수 · 비고 수 · [발주서 이미지] [카톡용 복사] [발주하기].
  - 그 아래 표 머리.
- 표 열(기본 순서): **품목 · 수량 · 단위 · 전일가 · 매출처 · 비고 · 삭제(−)**. 체크박스 칸은 없다.
- 품목 칸:
  - 이름 + 둥근 `+`(추가 발주 · 매출처 줄 더하기). "재고 확보" 버튼은 없다.
  - 품목 비고는 이름 아래 작은 글씨로 보여준다.
- 매출처 줄:
  - 매장별 수량을 나눠서 보여준다(예: 대파 1 + 1 + 1 + 2 + 5).
  - 오른쪽 빨간 `−`는 이번 발주에서만 뺀다. 매장 주문 수량은 그대로이고, 5초 동안 되돌릴 수 있다. 뺀 기록은 `excluded_at/by`에 남긴다.
- 합계 줄: `합계 · N곳`. 품목 이름은 반복하지 않는다. 수량은 수량 칸, 단위는 단위 칸. 단위가 섞이면 줄을 나눈다.
- 비고:
  - 종류: 매장 요청 · 품목 비고 · 이번 비고.
  - 비고가 없으면 점선 `+ 비고`, 있으면 굵은 글씨 + 고치기.
  - **화면에서는 노란 강조를 하지 않는다.**
- 회차: 야간(기본) / 주간 / 추가. [주간으로 넘기기]. 매입처는 줄마다 바꿀 수 있다.
- **발주서 이미지**(PNG · 인쇄 · 카톡 글):
  - 같은 구조, **전일가는 뺀다**: 품목 · 수량 · 단위 · 매출처 · 비고.
  - 굵은 합계 줄. **비고 칸만 노란 강조**. 품목 비고는 첫 줄 비고 칸에 넣는다.
  - 꼬리: "★ 노란 칸은 꼭 지켜 주세요". [매출처별 / 합계만] 전환.
  - 카톡 글에서는 비고를 ★로 표시한다.

- 전표 입력(15 · 16차):
  - 왼쪽: 오늘 전표 목록. 품목 입력은 크게, 견적 · 단가표 · 최근 출고 하이라이트.
  - 줄마다 기준 단가(회색) + 실제 단가.
- **매출전표에도 "등록하면서 입금"**을 넣는다(2-5의 지급과 같은 방식, 방향만 입금).
- 모든 돈 기록은 `ledger_entries` 하나에 남긴다. 예치금은 거래처별로만 둔다(잔액보다 많이 뺄 수 없다).
- 전표를 삭제하거나 취소하면 연결된 입출금을 함께 처리할지 확인 창으로 묻는다. 자동 삭제는 하지 않는다.

### 2-8 재고 원장 (WO-14 앞부분)
- **Owner Domain**: inventory
- 17차 C 표 그대로다: 매입 + · 주문 확정 = 예약 · 마감·출고 − · 주문에서 만든 매출전표는 변동 없음 · 직접 매출 − · 반품 + · 맞추기 ±.
- 같은 원본 문서로 두 번 차감되지 않게 한다(문서 id + 종류 unique).
