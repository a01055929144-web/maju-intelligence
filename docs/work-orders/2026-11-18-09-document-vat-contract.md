## 추천 계약 — 대표의 포함 고정가 기준 유지

1. 새 문서만 부가세 표시 기본값 ‘포함’. 설정 없는 기존 초안/발행본의 fallback false는 유지한다. 복사/연장도 기존 의미를 자동 변경하지 않는다.
2. 행사·임박의 판매가는 고객에게 제시한 최종 포함가로 유지한다. 포함/별도 표시 선택으로 실제 지급 총액이 늘어나면 안 된다. 일반 품목과 구분한 행별 price_includes_tax를 서버가 결정한다.
3. 추천 표시는 행사 고정가를 그대로 두고 ‘부가세 포함 행사’로 명시하는 방식이다. 일반 품목의 별도 표시와 섞이면 행사 포함가임을 행 또는 묶음에 알린다. 별도 표시를 위해 공급가를 보여줘야 한다면 서버가 정수 원 공급가·세액·최종가를 함께 반환하도록 계약한다. 브라우저가 역산한 값을 새 원본으로 쓰지 않는다.
4. 기존 발행본/주문/전표의 가격·세금 의미는 불변. 새 의미를 적용할 때 새 문서/새 발행의 명시적 snapshot 구분이 필요하다. 기존 값 부재를 새 의미로 해석하거나 기존 행사 원본을 일괄 보정하지 않는다.
5. R16 가격 순서(유효 약속가→카탈로그→기본가), 단위·시가·행사 가용성·멱등성은 기존 서버 함수 한 곳을 사용한다. 새 가격/주문 엔진을 만들지 않는다.

## 서버 소유 계약에서 확인할 결과

인증된 회사/매장·문서/발행본·배송일 문맥에 대해 기존 가격 결과에 다음 의미를 고정해야 한다. 필드명은 기존 서버 API에 맞춘다.
- unit_price와 tax_type, price_includes_tax가 무엇의 금액인지 명확해야 한다.
- source·promise_until과 원본 행사/일반 품목 여부, 표시한 최종가와 실제 주문 줄 계산이 같아야 한다.
- 새/기존 snapshot을 구분하여 기존 발행본 계산을 보존한다.
- 문서 일반/행사, 공개 링크/회원/여러 유통사 주문의 기존 진입점이 같은 계약을 쓴다.
- 클라이언트가 보낸 포함 여부/회사/금액을 신뢰하지 않고 기존 서버 검증 문맥에서 정한다.

06방의 가격 계약과 09의 문서/주문 읽기 연결에서 이 의미를 확인한 뒤 앱·SQL을 구현한다. 채팅 전달 승인은 별도이며 이 문서를 만들었다고 다른 방으로 전송하지 않았다.

## 11/19 주문→전표 대사 보완

04 독립 검토에서 포함가를 원 단위 공급 단가로 역산한 뒤 수량/VAT를 다시 계산하면 주문과 전표가 달라질 수 있는 경로를 확인했다. 합성 예: 포함 고정가60원×1.5=최종90원인데, 단가를 round(60/1.1)=55원으로 바꿔 수량을 곱하면 공급가83원+세액8원=91원이 될 수 있다. 실제 DB/고객 금액 재현과 구분한다.

추천은 서버가 확정한 줄별 공급가·세액·최종 금액을 모두 스냅샷으로 고정하고 주문→작성중 전표→출고 확정으로 같은 값을 전달하는 것이다. 포함가를 순단가로 바꿔 별도 계산 엔진에서 다시 세액을 산출하지 않는다. 실제 기존 필드명·함수 경계와 부분 처리의 잔액 배분은 04/06 및 전표 소유 계약에 맞춘다.

추가 검증: 과세/면세/행사/임박 각각 수량0.001·0.005·0.125·0.333·1.5, 포함/별도 표시, 접수 재시도, 부분 주문·부분 출고·부분 취소, 잔여 수량 처리. 부분별 공급가/세액/합계의 합이 원 주문 스냅샷과 일치해야 한다. 마지막 부분에 잔액을 배분하는 등 하나의 서버 규칙을 정하며 UI가 임의로 고치지 않는다. 기존 발행본/주문/확정 전표는 새 규칙으로 소급 재계산하지 않는다. 이 계약/통합 시험 전에는 새 VAT 동작을 운영에서 켜거나 완료로 보고하지 않는다.
