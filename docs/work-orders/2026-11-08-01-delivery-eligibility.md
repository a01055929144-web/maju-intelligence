# 01 신규 거래처 배송 후보 기본 제외 설계

상태: **설계·SQL 초안만 / 운영 적용·백필·기능 ON 금지**

## 문제

`getTodayRoutePlan()`은 현재 `normalized_customers`의 모든 거래처를 배송 후보로 바꾼다. 담당자·차량·주소가 없어도 `미배정` 그룹과 `지역 + 거래처명` 임시 주소로 지도에 나타난다. 따라서 주문이나 수동 배송 결정이 없는 신규 거래처도 배송 대상처럼 보일 수 있다.

`business_status`, `relationship_status`, 담당자·차량 값은 배송 의사를 뜻하지 않는다. 이름이나 메모의 `TEST_ONLY` 같은 문자열도 제품 규칙으로 사용하지 않는다.

## 최소 제품 규칙

`normalized_customers.delivery_eligibility` 하나만 추가한다.

| 값 | 의미 | 코스·지도 |
| --- | --- | --- |
| `eligible` | 사용자가 배송 후보로 승인한 거래처 | 기존 규칙대로 후보에 포함 |
| `not_ready` | 아직 배송 후보로 승인하지 않은 거래처 | 배송 코스·지도 그룹에서 제외 |

- 기존 행은 승인된 백필에서만 `eligible`로 바꿔 현재 코스·순서·기사·차량을 보존한다.
- 스키마 적용 뒤 생성되는 신규 행은 출처와 관계없이 기본 `not_ready`다.
- 향후 UI는 권한 있는 사용자의 명시적 “배송 후보에 포함” 동작만 `eligible`로 바꾼다.
- `relationship_status`와 `business_status`는 영업·사업자 상태로 계속 독립 관리한다.
- 기능 플래그 `DELIVERY_ELIGIBILITY_ENABLED`는 기본 OFF다. OFF에서는 현재 동작을 유지한다.
- 02 주문 소비 계약의 신규 주문 거래처는 계속 `unassigned`다. 주문이 있다는 이유만으로 이 필드를 바꾸거나 자동 배차하지 않는다.

## 기존 코스 보존 조건

1. 기능 ON 직전 기존 행 수와 `eligible` 행 수가 같아야 한다.
2. 기존 `route_plan_confirmations.customer_ids`, 순서, 기사, 차량은 수정하지 않는다.
3. 기존 수동 정류장은 주문 후보가 없거나 취소돼도 유지한다.
4. 담당자·차량 미배정인 기존 거래처도 백필 대상이며 기존 `미배정` 그룹에 남는다.
5. 회사·직원 배정 범위 필터를 우회하지 않는다.
6. 배송 완료는 02의 명시적 완료 이벤트만 사용하며 상태·메모로 추정하지 않는다.

## 후속 제품 연결 범위

초안 승인과 운영 적용 확인 뒤 별도 PR에서만 진행한다.

1. 거래처 읽기 모델에 `deliveryEligibility`를 추가한다.
2. 기능 플래그 ON 회사에서 `getTodayRoutePlan()` 입력을 `eligible`로 제한한다.
3. 거래처 상세에 권한이 있는 사용자의 명시적 포함·제외 동작을 추가한다.
4. 지도에는 `not_ready` 거래처를 배송 마커·미배정 배송 그룹으로 만들지 않는다.
5. 02의 `unassigned` 주문 묶음은 별도 확인 영역으로 유지하고 자동 코스에 합치지 않는다.

## 테스트 범위

### SQL·데이터

- 빈 테이블과 기존 행이 있는 테이블 모두에서 초안 적용 성공.
- 기존 행은 모두 `eligible`, 적용 뒤 신규 행은 `not_ready`.
- 허용하지 않은 문자열과 NULL 저장 거부.
- 회사, 거래처 ID, 기존 RLS·FK·UNIQUE 계약 불변.
- down 초안은 열만 제거하며 운영 적용 대상으로 취급하지 않음.

### 애플리케이션

- 플래그 OFF: 현재 후보 수·순서·기사·차량이 바뀌지 않음.
- 플래그 ON: `eligible`만 코스와 지도에 포함.
- 신규 `not_ready`: 거래처·영업 화면에는 보이지만 배송 마커와 미배정 배송차 그룹에는 없음.
- 기존 미배정 `eligible`: 계속 미배정 그룹에 포함.
- 확정 코스의 기존 정류장 순서와 수동 정류장 유지.
- 다른 회사·직원 배정 범위의 거래처가 섞이지 않음.
- `거래중/거래종료`, 사업자 상태, 상호·메모 문자열로 배송 후보 여부가 바뀌지 않음.

### 02 계약·화면

- 주문이 있는 `not_ready` 신규 거래처는 02 결과에서 `unassigned`이며 지도 자동 추가 없음.
- 주문 취소 뒤에도 기존 수동 정류장 유지.
- 명시적 완료 이벤트 없는 거래처는 완료로 표시하지 않음.
- `/dashboard?routeMode=map` 1440px·390px에서 기존 코스가 유지되고 신규 `not_ready` 마커가 없으며 가로 넘침이 없음.

## 승인 게이트

1. 이 설계와 SQL 초안 검토.
2. 폐기 가능한 PostgreSQL 17에서 up/down·백필·동시 삽입 검증.
3. 대상 회사별 기존 행 수, 백업, 롤백 계획 보고.
4. 명시적 운영 SQL 승인 후 스키마 적용과 읽기 확인.
5. 코드 배포는 기능 OFF.
6. 대표 회사에서 기존 코스 diff가 0임을 확인한 뒤 별도 기능 ON 승인.
