# CX-60 매장 사업자 정보 RPC 계약 검토안

2026-11-17 운영 스키마 읽기에서 `store_profiles.business_name`, `sub_business_number`, `business_entity_type`을 확인했다. 가입·초대 연결·S-2b 수정·알림 반영의 현행 RPC에는 이 필드의 처리 분기가 없다. 이 문서는 07방과 맞출 계약 초안이다.

## 쓰기와 소유 경계

| 경로 | 계약 |
| --- | --- |
| 가입 | 검증된 카카오 세션의 사용자로 프로필과 점주를 만드는 기존 트랜잭션에서 선택 입력 3칸을 저장한다. 기존 호출이 새 입력을 생략하면 같은 동작과 응답을 유지한다. 개업 예정 흐름도 사업자번호 검증 규칙을 유지한다. |
| 초대 연결 | 기존 초대코드·활성 점주 검증과 동일 회사·프로필 멱등 응답을 유지한다. 신규로 연결한 고객사 거래처에만 적용한다. 거래처 후보를 선택할 때 CX-59 사업자번호+종사업장번호와 중복 허용 정책을 따르며 임의 후보로 연결하지 않는다. |
| 최초 거래처 확인 | S-2b `confirm_new_store_account_v1`의 회사·계정·거래처 범위에서 사업자 정보의 빈 칸만 매장 값으로 채운다. 이미 등록한 거래처 값과 매장 상호는 보존한다. |
| 매장 설정 | S-2b `update_store_profile_v1`의 점주 검증, 프로필 잠금, 요청 키, 변경 이력 및 회사별 알림을 재사용한다. 변경 요청의 필드 생략은 유지, 빈 값은 명시적 삭제로 구분한다. 회사별 거래처에는 이 단계에서 쓰지 않는다. |
| 유통사의 알림 반영 | S-2b `apply_store_profile_notification_v1`의 회사·계정·현재 거래처와 최신 알림 검증을 따르며 선택한 회사에만 적용한다. 사업자 상호는 `business_name`에 쓰고 `customer_name`의 변경은 기존 별도 선택에만 맡긴다. 미반영 사업자 변경 뒤 배송 정보 알림이 들어온 경우에도 최신 알림에서 미반영 값을 검토할 수 있어야 한다. |
| 앱 | 09가 가입·설정 화면과 페이로드를 연결한다. 07과 기존 가입·연결·변경 알림 RPC 및 알림 표시 필드 계약을 먼저 맞춘다. 03의 CX-58 기존 DDL, CX-59 키 계산, `lib/store.ts` 및 고객 API 파일은 소유 범위 그대로 둔다. |

검증 규칙은 CX-58/CX-59와 같이 선택 항목인 사업자 상호, 문자열 숫자 4자리 종사업장번호(앞자리 0 보존), `individual`/`corporation`이다. 법인등록번호는 매장 3칸의 범위에 포함하지 않는다. 신고된 매장 상호와 유통사가 부르는 거래처명은 각각 기존 칸을 사용한다.

## 합성 검증

| 사례 | 기대 및 현재 근거 |
| --- | --- |
| 종사업장 0001·0002를 같은 사업자번호로 저장, 3자리와 허용되지 않은 개인/법인 코드 거절, down | 기존 CX-58 PG17 기준선에서 확인. |
| 점주 아닌 사용자 거절, 변경 키 재시도, 회사별 알림, 타사 반영 거절, 거래처 기존 값 보존 | 기존 S-2b PG17 기준선에서 확인. 새 3칸을 통과시키는 연결 시험은 계약 확정 뒤 추가한다. |
| 가입의 한 트랜잭션 저장, 새 입력 생략, 계약에 맞는 매출처 최초 반영, 다음 설정의 생략/삭제 구분 | CX-60 RPC 및 합성 API 시험 대기. |
| 여러 유통사 연결 중 선택 회사만 반영, 앞선 미반영 사업자 변경+뒤따른 배송 변경, 오래된 알림·연결 변경 거절 | CX-60 통합 PG17 시험 대기. |

격리 PG17에서 CX-58·S-2b 기준선이 통과했다. [현행 계약 재현 시험](../../tests/sql/store-cx60-current-contract.pg17.sql)은 새 필드를 현행 RPC가 거절하는 것과, 대표자 변경 후 출입 방법만 다시 변경하면 마지막 알림만 반영되고 앞선 변경이 처리 완료되는 것을 재현했다. 이 시험은 결함을 기록하는 수동 실행이다. 계약 구현 뒤에는 두 변경이 모두 유통사 검토에 남는지 확인하는 회귀 시험으로 교체한다.

기능 기본 OFF 및 회사별 허용 목록을 사용한다. 가입 전 회사가 정해지지 않는 직접 가입에는 신뢰할 수 있는 회사 범위를 정하기 전까지 기본 동작을 사용한다. 운영 쓰기·설정 변경·배포는 승인 범위 밖이다.


## 설정·알림 SQL 초안

- [적용 초안](../sql-drafts/20261117-CX-60-store-business-identity-settings.sql)과 [되돌리기](../sql-drafts/20261117-CX-60-store-business-identity-settings.down.sql)는 이미 있는 CX-58 칸과 S-2b 함수 세 개를 재사용한다. 대상 함수 본문이 검토한 형태와 다르면 트랜잭션 전체를 중단한다.
- 되돌리기 전에 CX-60 회사별 허용을 끈다. 처리되지 않은 사업자 정보 변경 알림이 있으면 되돌리기가 중단된다. 유통사가 알림을 처리한 뒤 다시 실행한다. 이미 저장된 프로필·거래처 값은 보존한다.
- [설정·알림 합성 시험](../../tests/sql/store-cx60-identity-settings.pg17.test.sql)은 점주 권한, 4자리 번호와 앞자리 0, 멱등 요청, 최초 확인 시 빈 칸 채우기, 회사별 알림, 명시적 초기화, 되돌리기를 다룬다.
- 가입·초대 연결과 유통사 화면의 새 필드 표시는 07과 계약을 맞춘 뒤 이어간다. 현재 앱의 회사별 스위치는 설정 화면에 적용된다. 운영 SQL 적용은 컨트롤타워 승인 절차를 따른다.
