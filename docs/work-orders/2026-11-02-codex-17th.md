## A. 엑셀 가져오기 · 데이터 옮기기 (WO-25 변경)

- **가져올 대상** (4가지): 상품 마스터 · 매출처/매입처 · **거래처 원장(거래처별 품목·단가)** · **재고**.
  - 단가표와 과거 전표는 다음 단계로 미룬다.
- **MAJU 표준 칸 편집**: 회사마다 따로 편집한다.
  - 할 수 있는 것: 칸 이름 바꾸기 · 보이기/숨기기 · 순서 바꾸기 · 회사 칸 추가.
  - 필수 칸(ERP 코드 · 노출명 · 규격 · 단위 · 매입가)은 끄거나 지울 수 없다.
  - 편집한 칸 설정은 상품 등록 팝업 · 표 · 엑셀 내려받기에 똑같이 적용한다.
  - 테이블: `company_field_definitions(company_id, entity, key, label, group, required, visible, sort, is_custom)`. 회사 칸의 값은 `extra_attributes`에 저장한다.
- **흐름**: 파일 → 열 맞추기 → **등록 전 미리보기 · 수정** → 중복 · 반영.
- **미리보기 화면**(ImportPreview):
  - 결과 분류(새로 / 같은 상품 / 의심 / 오류)와 줄 단위 처리(추가 · 빈 칸만 채우기 · 덮어쓰기 · 건너뛰기).
  - **칸을 바로 고칠 수 있다**(엑셀처럼). 고친 칸은 노란색으로 표시한다.
  - 찾아 바꾸기, 오류 줄 내려받기.
  - 바뀌는 값을 미리 보여준다(예: 매입가 10,500 → 10,800, 판매가 다시 계산).
  - `import_rows`에 원본 값과 수정한 값을 따로 저장하고, 반영한 뒤에도 되돌릴 수 있다.
- **재고 가져오기**: 엑셀로 재고를 수정한다. 차이만큼 맞추기 기록으로 남긴다(아래 C 재고 원장).
- **거래처 원장(거래처별 품목)**: `customer_items(company_id, customer_id, product_id, last_price, last_date, source)`.
  - **매장 링크를 만들면 그 거래처의 품목이 자동으로 보인다**(F 참고).

## B. 상품관리 (WO-03 변경)

- 상품 등록은 **크게 뜨는 팝업**(약 1120px)으로 바꾼다. 오른쪽 패널 방식은 쓰지 않는다.
  - 왼쪽 열: 기본 · 분류·매입처 · 가격
  - 오른쪽 열: 보관·재고 · 사진 · 추가 정보
  - 입력 칸 높이는 42px, 글자는 15px.
  - 버튼: [저장하고 새로] [저장]. 단축키 Ctrl+Enter.
  - ERP 코드나 비슷한 상품이 이미 있으면 경고한다.
- 왼쪽 필터 탭을 3개로: **구분 / 매입처 / 마주 공통 카테고리**. 재고관리에도 같은 필터를 쓴다.
- **마주 공통 카테고리 맞추기**(CategoryMatch):
  - 회사 구분을 MAJU 공통 카테고리에 연결한다. 상품명 · 규격으로 자동 추천하고 맞춤 정도(%)를 보여준다.
  - 데이터가 없는 회사(온보딩): 업종 선택 → 공통 카테고리를 그대로 회사 구분으로 만들기 → 구분별 기본 마진 → 공통 품목 골라 담기.
  - 테이블:
    - `maju_categories`: 플랫폼 공통, 관리자만 편집
    - `product_categories.maju_category_id`
  - 상품 등록 팝업에 "마주 공통 카테고리(자동 추천)" 칸을 둔다.

## C. 재고관리 (WO-14 변경) — 모든 전표와 연결

- 화면:
  - 왼쪽 필터(B와 동일), 카드(재고 상품 · 가능 수량 마이너스 · 안전 재고 아래 · 오늘 출고 예정)
  - 표 열: ERP 코드 · 상품명 · 규격 · 재고 방식 · **현재 · 출고 예정 · 가능** · 안전 · 위치 · 최근 출고
  - 줄마다 [맞추기]
  - 엑셀 올리기(수정)와 내려받기
- **최근 출고 팝업**(InventoryHistory):
  - 재고 기록(입고 · 출고 · 반품 · 맞추기 · 주문 확정)
  - 최근 출고된 매장 목록(30일 출고량 · 마지막 날짜). 매장을 누르면 그 매장의 상품 히스토리로 간다.
- **재고 변동 규칙** — 재고 방식이 `재고` 또는 `재고+사입`인 상품만 적용한다. 사입 · 시세 · 일배 상품은 수량을 세지 않는다.

| 사건 | 현재 재고 | 출고 예정 |
|---|---|---|
| 매입전표 등록 (사입 주문표에서 만든 전표 포함) | + | |
| 주문 확정 | | + (예약) |
| 주문 마감 · 출고 확정 | − | − (예약 해제) |
| 주문 취소 · 수량 변경 | | ± |
| 주문에서 만든 매출전표 | **변동 없음** (출고 때 이미 뺌) | |
| 매출전표 직접 입력 (주문 없음) | − | |
| 반품 (매출 수량 −) | + (폐기를 고르면 그대로) | |
| 매입 반품 | − | |
| 맞추기 · 엑셀 재고 수정 | ± 차이만큼 | |

- 구현 방식:
  - `inventory_movements`(재고 원장)에 모든 변동을 한 줄씩 남긴다. 칸: 사건 종류 · 원본 문서 id · 수량 · 이전 · 이후 · 입력자.
  - 현재 재고는 원장 합계로 계산한다.
  - **같은 원본 문서로 두 번 차감되지 않게 한다**(문서 id + 종류 unique).
  - 주문에서 매출전표를 만들 때는 `order_id`로 연결하고, 차감은 하지 않는다.
- **가능 = 현재 − 출고 예정.** 가능 수량이 마이너스면 사입 주문표의 "사입할 양"에 자동으로 넣는다.
- 테스트 시나리오(PG) — 아래 연속 흐름에서 각 단계 결과가 표와 같아야 한다. 위 사건 표의 모든 사건을 이 흐름에 포함한다.
  1. 매입 20 → 현재 20
  2. 주문 확정 4 → 출고 예정 4, 가능 16
  3. 마감 · 출고 → 현재 16, 예정 0
  4. 그 주문으로 매출전표 생성 → 변동 없음
  5. 반품 1 → 현재 17
  6. 직접 매출 2 → 현재 15
  7. 맞추기 −1 → 현재 14
  8. 같은 출고를 재시도 → 중복 차감 없음

## D. 배송분 집계 + 사입 주문표 = 한 화면 (WO-10 · WO-11 변경, 사입 주문표 화면은 따로 만들지 않음)

- 흐름 표시줄: ① 주문 확정 → ② 주문 마감 → ③ 집계 → ④ 매입처별 사입 주문 → ⑤ 매입전표 등록 → ⑥ 피킹·상차(인쇄).
- 표는 **매입처별로 묶는다**.
  - 묶음 머리줄: 매입처 · 상태(주문 전/주문함 · 시각) · 품목 수 · 총수량 · 예상 금액 · [카톡용 복사] [캡처] [매입전표로 만들기].
  - 열: ✓ · 품목 · 규격·단위 · **주문 합 · 재고(가능) · 사입할 양 (= 주문 합 − 가능)** · 회차 · 매입처(줄마다 바꿀 수 있음) · 전일 단가 · 메모.
- **회차**: 야간(기본) / 주간 / 선주문 추가.
  - 재고가 모자라도 야간에 산다.
  - 야간에 물건이 없으면 [주간으로 넘기기]. 같은 품목이 주간 회차로 옮겨간다.
  - 선주문을 못 넣어 고객사에 문의가 오면 [+ 추가 사입]. 추가 회차가 하나 생긴다(매장 · 시각 기록).
  - **매입처는 주 매입처가 기본이고 줄마다 바꿀 수 있다.** 바꾸면 해당 매입처 묶음으로 옮겨간다.
- 카톡용 복사 형식:

  ```
  [매입처] MM/DD 주문
  품목 규격 수량단위
  …
  — 회사 · 담당
  ```

- 테이블:
  - `purchase_orders(company_id, delivery_date, supplier_id, round[night|day|extra], status[draft|ordered|received|voucher_created], ordered_at)`
  - `purchase_order_items(order_qty, received_qty, prev_price, price, carried_to_round)`
  - 집계는 마감된 주문의 합계 − 가능 재고로 만든다.

## E. 사입 주문 → 매입전표 (BuyVoucher 팝업)

- 팝업 위쪽에 요약을 보여준다: 매입처 · 회차 · **주문 품목 수 · 주문 총수량 · 받은 총수량 · 전일 단가 기준 금액 · 전표 합계**.
- 줄마다:
  - 받은 수량을 입력한다. 주문과 다르면 노란색으로 표시한다.
  - 오늘 단가(영수증 기준)를 입력한다. 기본값은 전일 단가다.
  - 금액 · 메모.
- 영수증 첨부: 카톡 사진 올리기 또는 찍기. 영수증 숫자를 읽어 단가 칸을 채우는 기능은 다음 단계로 미루고, 이번에는 칸만 둔다.
- 저장하면:
  - 매입전표가 생긴다(원본 = 사입 주문). 재고 상품은 재고가 늘어난다(C).
  - 단가가 바뀐 품목은 매입가 반영 후보로 올린다(WO-04).
  - 덜 온 수량은 [주간 사입으로 넘기기]를 체크하면 다음 회차로 넘어간다.
  - 사입 주문 상태는 `voucher_created`가 된다.
- 한 사입 주문에서 매입전표는 하나만 만들 수 있다. 다시 만들려면 기존 전표를 수정한다.

## F. 매장 링크 · 보이는 품목 · 거래원장 노출 (WO-07 · WO-08 변경)

- 매장 링크를 만들면 그 거래처의 **거래처 원장 품목(customer_items)이 자동으로 보이는 품목**이 된다. 여기에 견적 · 단가표 · 행사·임박 품목을 더한다.
  - 출처 배지를 붙인다. 품목마다 보이기를 켜고 끌 수 있고, [+ 품목 더하기]가 있다.
- **매장에 보이는 정보는 고객사가 정한다.** 회사 기본값은 주문 설정에서 정하고, 매장마다 바꿀 수 있다.
  - 주문 내역
  - **거래원장** (거래 내역 · 미수 · 입금) — 기본 꺼짐
  - 예치금 잔액
  - 거래명세표 내려받기
- 매장 화면은 이 설정을 서버에서 확인한 뒤 보여준다. 화면에서 숨기기만 하는 방식은 금지한다.
