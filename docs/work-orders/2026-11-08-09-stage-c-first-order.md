# 단계 C — 기존 매장 링크에서 첫 주문

Ponytail: 사용함

기준 main `69fec03`(#341, #343, #344 포함). pricing/order 출력 소비자 보완이며 운영 DB 변경·배포·기능 활성화·실제 메시지 발송은 포함하지 않는다.

## 이번 변경
- 기존 링크 화면이 발급 직전 회사 주문 설정을 읽고 확인 결과와 설정 화면 입구를 제공한다. 조회 실패면 발급 요청을 보내지 않고 재시도한다. 저장 설정이 없는 경우 기존 서버 기본값 사용을 알린다. 회사 설정 요약은 권역/거래처의 최종 배송 정책을 대신하지 않는다.
- 문서 변경 중 이전 versions 응답을 무시해 잘못된 게시 버전을 선택하지 않도록 한다.
- 기존 `/store`의 fragment 링크가 바뀌면 화면 세션을 새로 생성하여 장바구니·내역·메모·수정 주문·재시도 키를 초기화한다. 회수/권한 거부 응답 뒤 이전 매장 데이터는 제거한다.
- 주문 중복 클릭을 막고, 응답 유실은 기존 같은 idempotencyKey로 재시도한다. 주문 변경 시 기존 키 초기화 정책은 그대로다.
- 주문 API가 RPC로 넘기는 품목 입력은 productId/promotionId/quantity뿐이다. 회사·매장·가격은 토큰과 기존 서버/RPC에서 결정한다.
- 내역은 store_order_lines의 주문 당시 이름·규격·단위·과세·단가를 표시한다. 현재 상품 원장으로 과거 주문을 다시 계산하지 않는다. 원가/마진 필드는 추가하지 않는다.

## 소비 계약과 차단점
- 03 Draft #342의 acceptPricingDocument/PricingAcceptanceResult는 아직 미병합·SQL 미적용이다. 이번 코드는 이를 import하거나 RPC를 호출하지 않는다. 검증된 서버 수락 컨텍스트만 미래 소비 입력이며 브라우저 company/customer/lead/가격은 신뢰하지 않는다.
- needsReview=true 또는 orderEnabled=false이면 주문 링크가 없다. storefrontLinkId/token은 서버가 성공한 저장 결과에서만 소비한다. 같은 수락 키의 회수·만료·설정 없음 결과를 재시도로 새 링크 발급으로 바꾸지 않는다. 기존 서명 모듈/fragment URL 계약을 사용하고 토큰을 로그·연락 메타데이터·브라우저 저장소에 쓰지 않는다.
- 07 구성원 경계 PR은 별도 승인 대기다. 이번 변경은 기존 bearer 주문 링크의 회사/customer 경계만 사용하며, 매장 로그인이나 costAccess를 주문 권한으로 승격하지 않는다. 07 인증/구성원 파일과 03 RPC/SQL은 수정하지 않는다.
- #342 및 07의 기능 OFF를 유지한다. 승인·적용·인증 어댑터 확정 후 서버 수락→서명 URL→기존 /store 통합 검증이 별도로 필요하다. 이번 PR의 합성 검증은 단계 C 운영 완료 증거가 아니다.
