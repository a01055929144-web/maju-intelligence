# 공개 문서 점주 가입·첫 주문 — 격리 시험 준비

기본 OFF. 코드 준비 문서이며 시험 DB 생성·데이터 입력·환경 변경·배포·운영 SQL 실행 승인이 아니다.

## 허용 조건

다음이 모두 맞아야 시험 사업자 확인을 사용할 수 있다.

- `STORE_PUBLIC_TEST_MODE_ENABLED=true`
- `VERCEL_ENV=preview`인 전용 배포
- `STORE_PUBLIC_TEST_DATABASE_PROJECT_ID`: 별도로 준비한 Supabase 시험 프로젝트 참조
- `SUPABASE_URL`: 그 시험 프로젝트의 HTTPS 기본 주소
- `NEXT_PUBLIC_SUPABASE_URL`: 등록했다면 같은 시험 프로젝트 주소
- `STORE_PUBLIC_TEST_COMPANY_ID`: 승인된 대표 회사 UUID 하나
- `STORE_PUBLIC_TEST_BUSINESS_NUMBER`: 서버 Sensitive 환경에만 저장한 정확한 시험번호
- `STORE_ORDER_DELIVERY_SNAPSHOT_ENABLED`는 OFF

운영 프로젝트 `fcmdvveqmcgtioelzqun`, Production/Development, DB 주소 불일치, 누락·잘못된 설정은 DB 요청 전에 거부한다. 시험 모드 OFF는 기존 운영 NTS 검증을 유지한다. 다른 회사와 다른 번호는 시험 확인을 받을 수 없다. 시험번호는 화면·응답·로그·커밋에 출력하지 않는다. 입력을 생략하면 인증 증명과 서버 요청의 회사를 확인한 뒤 서버 설정 번호를 사용한다.

기존 가격표·문서 공유·주문·공개 가입·회원 세션 스위치와 회사별 허용목록도 그대로 필요하다. 전역 PRICING/STORE_ORDERING 우회로 시험 회사 범위를 넓히지 않는다. Kakao 인증·약관·회사/회원 권한·유효 문서·배송일·마감·판매가·주문 중복 검증은 우회하지 않는다.

## 데이터와 표시

공개 문서·가입·주문 화면에 시험 배너를 표시한다. 가입 폼은 합성 매장·대표·배송지·연락처를 사용하며 현재 Kakao 연락처도 시험 폼에 재사용하지 않는다. 시험 확인의 `verification_request_id`는 `test-only:`로 구분한다. 일반 테이블과 RPC를 재사용하되 **별도 DB만 사용**한다. 이 접두사는 격리의 대체물이 아니다.

개통은 시험 DB의 거래처·매장·회원·개통 기록을, 주문은 시험 DB의 주문·품목·열람/행사 예약 기록을 만든다. 시험 개통 확인 접두사가 있는 새 시험 매장만 서버에서 조회하고, 그 거래처에 시험용 배송 요일을 준비한다. 기존 규칙은 덮어쓰지 않고 가격·마감·최소금액은 회사의 기존 검증을 따른다. 운영에 남은 미완료 요청·실제 개인정보·고객 목록은 복사하거나 재사용하지 않는다. 시험 DB를 나중에 운영 DB로 전환하거나 시험 데이터를 운영으로 옮기지 않는다.

### 별도 미해결: 일반 신규 매장의 배송 권역

일반 거래처 등록은 `assignCustomerByTerritory`를 사용하지만 공개 점주 개통 SQL은 이 경로를 거치지 않고 권역 없는 거래처를 만들 수 있다. 주문 RPC는 거래처 또는 권역의 배송 요일을 요구한다. 회사 주문 설정에는 기본 요일이 없다. 따라서 일반 신규 매장의 즉시 첫 주문은 별도 결함이며, 시험 요일 준비로 해결됐다고 판단하지 않는다. 서버 주소 기반 권역 추천·회사 내 유효 권역/주문 규칙 검증·미매칭 안내 및 개통과의 원자 연결을 별도 설계/검증해야 한다. 필요한 SQL은 초안·승인표까지만 준비하고 운영 적용은 별도 승인한다.

## 별도 환경 준비 단계

1. 승인된 별도 시험 DB를 준비한다. 프로젝트/브랜치 생성에 비용이 있으면 별도 비용 승인을 받는다. 이번 코드 작업은 프로젝트를 생성하지 않는다.
2. 기존 선행 P0/P1/P2/S2·회원·점주 개통·공개 공유 SQL의 적용 목록을 시험 DB용으로 검토한다. 운영 SQL 원문을 운영에 재실행하지 않는다. 시험 데이터는 합성 회사·상품·게시 문서·배송 조건만 준비한다.
3. Preview 전용 DB 키·서명키·공개 기본 주소를 등록한다. 운영 주소/키를 상속하지 않는다. 발송·결제·배송 생산자·자동 작업·운영 ERP 연결은 연결하지 않는다.
4. 승인된 Kakao 시험 계정과 전용 앱/허용 콜백을 준비한다. 사용자 로그인·동의·추가 인증은 사용자가 직접 수행한다.
5. 합성 공개 문서 → Kakao → 시험 매장 정보·약관 → 첫 주문 → 같은 키 재시도·내역을 확인한다. 다른 회사·잘못된 설정·운영 DB 주소에서 차단되는지도 확인한다.
6. 끝나면 Preview 접근과 시험 스위치를 OFF로 되돌리고 시험 기록을 보존하거나 별도 승인된 시험 DB 정리 절차를 따른다. 운영 계정/주문/개통 요청은 정리 대상으로 삼지 않는다.

현재 시험 DB와 실제 Kakao 연결은 이 작업에서 생성·확인하지 않았다. CI는 합성 API 경계, 설정 차단, 실제 PG17 개통·주문 RPC와 멱등성을 검증한다. 실제 외부 인증부터 끝까지 완료한 결과로 해석하지 않는다.
