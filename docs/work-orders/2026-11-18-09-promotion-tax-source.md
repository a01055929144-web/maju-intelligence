# 원상품 세금 구분 → 신규/기존 행사

main c7ab679 기준 독립 수정. #1109 연장 기능 및 05 인쇄 작업을 선행 조건으로 두지 않는다.

확정 원인: 새 행사 서랍은 taxable 고정, 담기 화면은 unknown도 taxable로 추정했다. 기존 행사 수정에는 과세/면세를 고치는 입력이 없었다. 상품 변경만으로 기존 행사·문서 스냅샷은 바뀌지 않는다.

수정: 새 행사 서랍은 선택 상품을 기존 회사 catalog API로 조회해 상속하고 unknown이면 저장하지 않는다. 담기 경로도 unknown을 보존하고 확인/다시 담기 안내. 서버 저장 경계는 모든 신규 save-promotion에서 인증된 회사+활성 상품의 tax_type을 읽어 클라이언트 값을 대체한다. 다른 회사/누락/미확정/조회 실패 시 쓰지 않는다.

기존 행사에는 과세·면세 입력과 원상품 불일치 안내/명시적 반영 버튼을 제공한다. 조회만으로 쓰지 않는다. 사용자가 저장해야 기존 revision 검사를 거쳐 바뀐다. 현재 원상품 값 읽기와 행사 쓰기는 기존 REST 조회/RPC의 두 단계이며 상품이 동시에 변경될 때의 원자적 일치까지 보장하지 않는다. 엄격한 동시성 강제가 필요하면 별도 SQL 초안/down/PG17 검토가 필요하다.

새 DB 칸이나 RPC 교체는 필요하지 않다. 기존 P1 RPC가 행사 taxType 수정을 지원한다. 기존 행사 원본 자동 보정·실데이터 쓰기·기능 ON·배포 없음. 기존 기능 스위치/권한 범위 안의 버그 수정이다.

회귀: 서버 유래 값/회사 범위/unknown·조회 실패 차단, 기존 행사 명시적 수정·revision 보존의 앱 시험. 기존 CI 실행 document-actions E2E에 1440/390 신규 상속·기존 불일치 확인/수정·unknown 차단·버튼44·넘침 검증. 독립 PG17은 실제 기존 RPC로 세금 수정/충돌·가격/초안/발행본 보존을 확인한다. CI 결과 전에는 완료로 간주하지 않는다.

다음 별도 동작: 문서 초안의 ‘현재 세금 구분 확인/반영’과 행사 행의 저장 불가능한 직접 선택 안내. 발행본을 수정하지 않는다. VAT 포함 기본값·행사 고정가 해석은 이 PR에서 바꾸지 않는다.
