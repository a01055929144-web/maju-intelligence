# 영업 지역 행정경계 선택 1단계 조사·설계

작성일: 2026-10-20  
범위: 조사·설계만. 경계 파일 추가, 화면/API 구현, 운영 데이터 변경은 승인 전 금지.

## 결론

- 원천은 **국가데이터처 SGIS 2025 센서스용 행정구역 경계(SHP)**를 사용한다.
- 런타임 SGIS API 호출 대신, 원본을 한 번 가공해 **WGS84 정적 GeoJSON을 시·도별로 분할**해 배포한다.
- 기존 `시·도 + 첫 시·군·구` 키는 시 전체 선택으로 유지하고, 일반구 도시는 `administrative_subarea` 구 단위 키를 함께 지원한다. 경계는 일반구별로 유지한다.
- 카카오 지도에는 현재 시·도 한 곳의 단순화 경계만 lazy-load한다. 확대 수준과 무관하게 전국 경계를 한 번에 올리지 않는다.
- 구현 전에 2025 원본을 내려받아 아래 용량·형상 검증 게이트를 통과해야 한다.

## 1. 데이터 출처와 이용 조건

### 채택: 국가데이터처 SGIS

- 공공데이터포털의 `국가데이터처_SGIS 행정구역 통계 및 경계_20250630`은 2024년 통계와 **2025년 기준 행정구역 경계**, 전국 SHP를 제공한다.
- 포털 표기는 무료이며 `이용허락범위 제한 없음`이다. 상업 서비스용 정적 가공물의 원천으로 가장 안전하다.
- SGIS 자료제공 안내는 센서스용 행정구역 경계를 2001~2025년, 전국, 공개, 무료로 제공하고 기준시점을 매년 6월 30일로 설명한다. 원본 좌표계는 EPSG:5179다.
- 공식 경계 OpenAPI도 2000~2025년 경계와 2자리 시·도/5자리 시·군·구/8자리 읍면동 코드를 제공하지만 access token과 호출 의존성이 생긴다. 이번 용도는 정적 파일이 더 안정적이다.

출처:

- [공공데이터포털 SGIS 행정구역 통계 및 경계](https://www.data.go.kr/data/15129688/fileData.do)
- [SGIS 자료제공 목록](https://sgis.mods.go.kr/view/pss/openDataIntrcn)
- [SGIS OpenAPI 정의서](https://sgis.mods.go.kr/developer/upload/doc/SGIS_OpenAPI_%EC%A0%95%EC%9D%98%EC%84%9C.pdf)

배포 화면에는 법적 의무 여부와 별개로 데이터 계보를 명확히 하기 위해 `행정경계: 국가데이터처 SGIS (2025.06.30 기준)`을 표시한다.

### 제외 후보

- 국토교통부 센서스 경계 자료는 공공누리 제4유형(출처표시·비상업·변경금지)으로 표시된 자료가 있어 상업 서비스와 dissolve/단순화에 부적합하다.
- GitHub 등 비공식 변환본은 용량 벤치마크와 가공 절차 참고로만 사용하고 제품 원본으로 쓰지 않는다.

## 2. 파일 크기와 배포 예산

공식 2025 자료의 다운로드 파일 크기는 공개 메타데이터에 표시되지 않고 자료신청 후 내려받는 구조다. 따라서 아래에서 `실측`과 `예산`을 구분한다.

### 공개 벤치마크

- 과거 KOSTAT 시·군·구 GeoJSON은 전국 약 **52 MB**, 1% 단순화본은 약 **0.364 MB**로 공개된 사례가 있다.
- 최근 SGIS 파생 사례는 시·군·구 256개를 8% 단순화해 약 **604 KB**로 제공한다.
- 둘 다 2025 공식 원본의 실측값은 아니지만, 시·군·구 수준에서 수백 KB 목표가 현실적임을 보여준다.

참고:

- [southkorea-maps 크기 비교](https://github.com/southkorea/southkorea-maps)
- [SGIS 파생 경계 단순화 사례](https://github.com/DevMinGeonPark/mapcn-kr)

### 구현 전 실측 게이트

| 산출물 | 목표 |
| --- | ---: |
| 2025 전국 원본 SHP 묶음 | 다운로드 후 원본 ZIP/SHP 각각 기록 |
| WGS84 미단순화 전국 GeoJSON | 실측 기록, 브라우저 배포 금지 |
| dissolve + 단순화 전국 GeoJSON | gzip 기준 1 MB 이하 |
| 시·도별 분할 파일 | 각 gzip 기준 250 KB 이하, 목표 50~150 KB |
| 초기 화면에서 실제 로드 | 현재 시·도 1개만, 250 KB 이하 |

가공은 `EPSG:5179 → EPSG:4326`, 읍면동을 일반구 또는 시·군·구 단위로 dissolve, topology-preserving simplification, 좌표 정밀도 5자리 순으로 한다. 섬이 사라지거나 자기교차가 생기지 않는지 `makevalid/clean`과 육안 검수를 함께 수행한다. 목표를 넘는 시·도는 단순화 비율만 높이지 않고 외곽 섬 링 분리, TopoJSON 검토 순으로 대응한다.

## 3. 지역 단위 결정

### 확정안: 시 전체와 일반구를 병행

현재 `extractLeadAdministrativeArea`는 주소의 `시·도 + 첫 시·군·구`를 저장한다.

- `서울특별시 강남구` → 구 단위
- `경기도 성남시 분당구` → `경기도 성남시`
- `충청북도 청주시 흥덕구` → `충청북도 청주시`

기존 `administrative_area`는 그대로 두고 `administrative_subarea`를 추가한다. 성남시 분당구 리드는 `경기도 성남시`와 `경기도 성남시 분당구` 두 키를 함께 가진다. 저장값이 어느 컬럼과 일치해도 포함하므로 기존 시 전체 값은 변환 없이 계속 동작한다.

지원 도시는 고양·부천·성남·수원·안산·안양·용인·청주·천안·전주·포항·창원이다. 일반구가 없는 지역은 기존 단일 키만 쓴다.

### 예외

세종특별자치시는 현재 추출 규칙이 하위 `시·군·구` 토큰을 요구해 자동 매칭 대상이 아니다. 기존 결정대로 이번 경계 기능에서 별도 규칙을 만들지 않고 선택 비활성/안내 처리한다.

## 4. 카카오 Polygon 성능 설계

카카오 지도 Web API의 Polygon은 다중 path와 `setOptions`, `setPath`, `setMap`을 지원하며 click/mouseover/mouseout/mousemove 이벤트를 제공한다. 공식 샘플도 여러 polygon에 hover와 click을 연결한다.

- [Kakao 지도 Polygon 문서](https://apis.map.kakao.com/web/documentation/)
- [Kakao 다각형 이벤트 샘플](https://apis.map.kakao.com/web/sample/addPolygonMouseEvent2/)

권장 렌더링:

1. 지도 중심 또는 bounds로 시·도를 판정하고 해당 파일만 `fetch`한다.
2. `idle` 이벤트 뒤 시·도가 바뀐 경우에만 다음 파일을 가져온다. 빠른 이동 중 요청은 취소한다.
3. 한 시·도당 제품 단위 polygon 약 5~31개만 유지한다. 전국 polygon을 동시에 만들지 않는다.
4. 선택/hover/색칠 전환은 polygon 재생성이 아니라 `setOptions`로 색만 변경한다.
5. 툴팁은 polygon마다 DOM을 만들지 않고 CustomOverlay 하나를 재사용한다.
6. 지역 집계는 polygon별 N회 호출하지 않고 `province + metric` 한 번에 모두 받는다.
7. 정적 파일에는 장기 immutable cache를 적용하고, 집계 API는 짧은 서버 캐시를 둔다.

확대 단계:

- 전국 수준: 경계 선택 레이어 숨김 또는 시·도 외곽만 표시
- 시·도 수준: 제품 영업 지역 단위 polygon과 색칠 표시
- 상세 수준: 같은 polygon 유지, 선 두께만 조정

대안인 Canvas/WebGL/vector tile은 전국 수천 개 도형에는 유리하지만, 현재 시·도별 최대 수십 polygon에는 복잡도 대비 이점이 작다. 1차는 카카오 기본 Polygon이 적합하다.

## 5. 2단계 구현 구조 제안

- 정적 파일: `public/maps/sales-areas/2025/{provinceCode}.geojson`
- manifest: 기준일, 출처, 파일 해시, bbox, feature 수, 원본/압축 크기
- 각 feature 속성: `administrativeArea`, `parentAdministrativeArea`, `province`, `district`, `centroid`, `bbox`
- 집계 API: 시·도별 `customerCount`, `recentLeadCount`, `totalLeadCount` 일괄 반환
- UI: 기존 `SalesAreaSelector`의 추천 칩·select·지도 중심 추가를 그대로 두고, 지도 경계 선택을 점진적으로 추가
- 권한 없음: hover/집계 열람만 허용하고 click 저장 이벤트는 차단
- 접근성/모바일: 지도에만 의존하지 않고 기존 select와 추천 칩을 동일 저장소의 대체 입력으로 유지

## 6. 승인 후 검증 기준

- 경계 클릭 추가/해제와 설정 페이지 값이 동일하다.
- 분당구 선택은 수정구 리드를 포함하지 않고, 성남시 전체 선택은 세 구를 모두 포함한다.
- 기존 성남시 전체 저장값은 변경 없이 동일하게 동작한다.
- 색칠 기준 전환이 polygon 수를 늘리거나 추가 API N회 호출을 만들지 않는다.
- 권한 없는 직원은 저장 요청을 만들 수 없다.
- 모바일에서 지도 조작과 하단 대체 선택 UI가 겹치지 않는다.
- 시·도 파일 첫 로드 p95 500 ms 이하(운영 icn1, 캐시 miss), 재방문은 브라우저 캐시 hit.
- 현재 시·도 파일 gzip 250 KB 이하. 초과 시 구현 승인을 다시 받는다.

## 7. 첫 06시 크론 측정 상태

행정구역 백필은 완료됐지만 검증용 `서울특별시 강남구` 지정은 원래 상태로 되돌렸다. 현재 본사에는 인식 불가 값 `인천`, 시범사에는 직접 지정값이 없어 유효 영업 지역이 비어 있다. 따라서 다음 06시 크론에서도 지역 적재·적재 직후 카카오 보강의 비교 수치가 생성되지 않는다.

유효한 영업 지역을 사용자가 지정한 다음 정상 06시 크론에서 다음을 읽기 전용으로 집계한다.

- 회사별·출처별 `지역 안 적재 / 지역 밖 제외`
- 강남구 최근 30일 835건의 정부·서울 중복, 폐업, 대상 외 업종, 기존 거래처, 실제 영업 대상
- ingest 보강의 지역 일치, 상호명 단독, 미매칭, 전화 자동 확보/제안

크론을 임의 실행하거나 측정을 위해 영업 지역을 다시 설정하지 않는다.

## 8. 재생성 절차와 2단계 실측

- 재생성 스크립트: `scripts/build-sales-area-boundaries.mjs`
- 실행: `npm run maps:build-sales-areas -- --input <원본을 GeoJSON으로 내보낸 경로>`
- 원본은 저장소에 포함하지 않는다. 스크립트가 EPSG:5179 좌표를 감지하면 EPSG:4326으로 변환하고, 읍면동을 일반구 또는 시·군·구 경계로 병합한 뒤 8% 단순화·정리·시·도별 분할·manifest 생성을 한 번에 수행한다.
- 산출물은 `public/maps/sales-areas/2025`에 저장한다. 각 파일의 gzip 크기가 250KB를 넘으면 스크립트가 실패 종료하므로 초과 산출물은 배포될 수 없다.
- 최초 생성에는 SGIS 2025 경계를 WGS84 GeoJSON으로 교정한 공개 파생본을 사용했다. 기준 및 라이선스의 원천은 위 1절의 SGIS 공식 자료이며, 행정구역 개편 시에는 공식 원본을 다시 내려받아 `--input`으로 생성한다.
- 일반구 반영 후 최종 17개 시·도 파일은 총 252개 경계이며, 최대 파일은 전라남도 35,105 bytes(gzip)다. 모든 파일이 250KB 게이트를 통과했다.
