## 권한 경계 판정

1. `product_catalog`와 `supplier_products`는 회사 데이터다. 서버는 인증된 회사 ID를 고정하고 모든 읽기·쓰기에 `company_id`를 포함해야 한다.
2. `platform_products`는 회사 상품을 대체하지 않는 플랫폼 내부 식별 계층이다. 회사 화면에는 공개 가능한 설명과 자기 회사 연결만 반환한다.
3. 플랫폼 운영자의 service role 사용 가능성은 권한 그 자체가 아니다. 플랫폼 상품 API는 관리자 세션과 활성 역할을 각각 확인하고, `catalog_operator`에게 원가·동의·감사·역제안 접근을 허용하지 않는다.
4. 플랫폼 연결 판단에는 이름·브랜드·원산지·규격·단위·바코드만 사용한다. 다른 회사의 원가·판매가·계약단가와 가격 통계는 응답·화면·로그에서 제외한다.

## ARC-10 지표·감사 원천 기준

| 지표 | 현재 원천 | 재계산 기준 | 현재 한계 |
| --- | --- | --- | --- |
| 사용 중 고객사 | 관리자 대시보드의 회사/활동 집계 | 기준 시각, 활성 판정 조건, 회사 ID 집합 또는 건수 해시 | UI에 산식과 기준 ID가 없음 |
| 주간 활동 직원 | 직원 활동 집계 | 주 시작·종료 시각, 고유 사용자 ID, 활성 회사 필터 | 기간·중복 제거 규칙이 응답에 없음 |
| 주간 연락·방문 | 활동 원장 집계 | action 종류, 발생 시각, 회사·사용자·대상 ID | 어떤 action이 포함되는지 UI에서 확인 불가 |
| 월간 견적·계약 | 견적·계약 집계 | 월 경계(Asia/Seoul), 상태 필터, 문서 ID | 견적과 계약의 합산 규칙이 응답에 없음 |
| 업로드 점검 | 업로드 이력과 분석 작업 | 업로드 ID, 상태, 품질점수, 중복 건수, report ID | 화면 필터 결과와 전체 원천 건수 구분 필요 |
| 감사 요약 | `admin_audit_logs` 최근 50건 | 로그 ID, 서버측 기간·필터·총건수 | 현재는 최근 50건을 클라이언트가 재분류한 표본 |

같은 지표는 관리자 화면·API·향후 리포트에서 동일한 `metricKey`, 기간 경계, 필터와 원천 정의를 공유해야 한다. 숫자만 복사해 별도 통계로 만들지 않는다.

## PR #106과의 충돌·드리프트

- PR #106은 아직 미병합이므로 이 문서는 그 경계를 운영 점검 기준으로만 사용했다. 병합 전 main의 공식 상태로 간주하지 않는다.
- `docs/02_DOMAIN_MAP.md`는 `product_catalog`를 quote 테이블로 적고 있으나 실제 코드는 product 파서, purchasing 공급상품, pricing 접근이 함께 사용한다. PR #106의 분리 방향과 현재 문서 소유권이 충돌한다.
- `docs/pages/admin.md`는 `admin_audit_logs`를 일반 감사 원천으로 설명하지만, 현재 화면은 최근 50건만 조회한다. 전체 감사 지표처럼 해석하면 ARC-10과 충돌한다.
- 플랫폼 표준 품목 1단계는 과거 문서에서 “진행 승인”으로 표현되지만 실제 main에는 설계·SQL 초안만 있다. 운영 상태는 `초안 / 미적용`으로 고정한다.
- 기존 정기결제는 운영 중이지만 WO8 요금제 정책은 별도 플래그 OFF다. “결제 운영”을 신규 결제·선결제·수수료 승인으로 확대 해석하면 안 된다.

## 남은 승인 사항

1. 플랫폼 표준 품목 1단계 SQL 최종본과 운영 적용 여부
