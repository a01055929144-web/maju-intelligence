- 수집·가져오기·병합 시 연락 금지 재적용 및 owner/manager 전용 해제 API.
- 대표·관리자 첫 PC 사용, 직원 첫 모바일 로그인 수칙 확인 화면과 확인 기록.
- 설정에서 다시 보기, 플랫폼 관리자에서 회사별 확인 여부 표시.
- 이용약관의 연락 주체·책임 조항은 대표의 법률 검토 후 별도 반영.

현재 PR은 기존 `lead_actions` 출처 안내 감사와 `sales_outreach_policy_acknowledgements`
수칙 확인을 기록한다. `company_do_not_contact` 신규 등록과 `lead_contact_field_sources`
쓰기, 연락 거부+리드 제외 원자 처리는 전용 RPC 승인 전까지 구현·호출하지 않는다.
수칙 확인 SQL 초안은 `app_users.id`가 없는 기존 대표 세션도 회사별 `legacy_owner`
주체로 기록할 수 있게 설계했으며, C6 계정 전환 시 이관 또는 재확인 정책 확정이 필요하다.

## 10:00 묶음 전 남은 활성화 범위

- `docs/sql-drafts/lead-do-not-contact-rpc.sql`은 DNC 등록·리드 제외·감사 로그를 한 트랜잭션으로 처리하는 Claude 검토용 초안이다. 운영 미적용이며 `LEAD_DNC_WRITE_ENABLED` 기본 OFF다.
- 운영 `lead_actions`에는 `actor_user_id` 컬럼이 없음을 대조했다. RPC 감사 행은 표준 `action_type='exclude'`, `result='제외'`를 사용하고 actor ID는 `metadata` JSONB에만 남긴다.
- 칸별 출처 조회는 회사+리드 범위의 서버 API로 연결했다. 쓰기 경계도 준비했지만 `LEAD_FIELD_SOURCE_WRITE_ENABLED` 기본 OFF이며 수집·수동 수정 호출부는 검토 후 연결해야 한다.
- 따라서 현재 화면은 기존/향후 적재된 칸별 출처를 표시할 수 있지만, 이 PR만으로 과거 리드의 칸별 출처가 자동 생성되지는 않는다.
