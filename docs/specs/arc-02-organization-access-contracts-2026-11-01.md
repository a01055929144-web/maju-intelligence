# ARC-02 회사·직원·공개 링크 접근 계약

> 상태: 현재 코드 계약과 회귀 기준. 운영 DB 변경, 기능 플래그 활성화, 공개 주문 링크 구현을 승인하지 않는다.
> Owner Domain: `organization`
> Related Domain: 공개 링크를 소비하는 `pricing/order/customer` 경계
> 작업지시 기준: PR #106의 `docs/specs/modular-monolith-reorganization-work-orders-2026-11-01.md` (아직 `main` 미병합)

## 1. 서명된 회사 문맥

- 고객사 요청의 `company_id`는 서명된 `maju_customer_session`의 `companyId`가 유일한 원천이다.
- 쿼리·본문의 `companyId`는 고객사 세션의 회사를 바꾸지 못한다. `getRequestAuthScope()`는 고객사 세션이 있으면 요청값보다 먼저 세션의 회사를 반환한다.
- MAJU 관리자 세션만 진단·대행을 위해 요청의 회사 ID를 사용할 수 있으며, 회사 ID가 없으면 `missing_company_id`로 실패한다.
- 서명만 유효해도 충분하지 않다. `userId`가 있는 세션은 매 요청에서 같은 `(company_id, user_id)`의 활성 멤버십, 사용자·회사 상태, 임시 권한 만료를 다시 확인한다.

## 2. 회사별 직원 참조와 표시 이름

- 직원의 안정 식별자는 전역 사용자 ID가 아니라 `(company_id, company_members.id)`다. 같은 사용자가 여러 회사에 소속되어도 직원 참조가 섞이지 않아야 한다.
- `companyMemberId`는 서명 쿠키의 과거 값을 신뢰하지 않고 `getActiveCustomerMembership()`이 현재 회사·사용자로 다시 조회한 값을 세션 문맥에 덮어쓴다.
- 회사 표시 이름은 `resolveCompanyStaffDisplayName()` 한 곳에서 결정한다. 해당 회사의 수락된 초대 이름을 소셜 프로필 이름보다 우선하고, 일반 placeholder는 식별 이름으로 쓰지 않는다.
- 담당 거래처 호환 키는 `companyMemberId`를 우선한다. 사용자 ID·이메일·이름·차량 문자열은 기존 데이터 호환용이며 모든 조회는 별도로 `company_id`를 함께 제한해야 한다.

## 3. 공개 매장 링크와 직원 권한 분리

- 공개 매장 링크 주체는 직원 세션이 아니다. 공개 링크로 `workspaceRole`, `companyMemberId`, 직원 capability, 회사 전체 조회 권한을 만들지 않는다.
- 향후 매장 주문 링크는 불투명 토큰으로 서버 저장 행을 찾고, 그 행의 `company_id`와 `customer_id`를 읽기 범위로 사용한다. 요청 본문의 회사·거래처 ID로 범위를 넓히지 않는다.
- 공개 응답은 판매용 문서·품목·가격·배송/주문에 필요한 화이트리스트만 반환한다. 매입가, 마진, 공급처, 직원 목록·권한, 기사 개인 위치, 내부 메모와 출입 비밀정보는 제외한다.
- 현재 `main`에는 공개 매장 주문 링크가 없다. 구현된 공개 견적 링크가 가장 가까운 사례이며, 토큰 형식·게시/만료 확인 후 서버에서 회사 ID를 얻고 품목을 `(company_id, quote_id)`로 제한하며 원가·마진을 SELECT하지 않는다.
- 주문 링크 구현은 ARC-06의 SQL·본인확인·결제 선행조건 승인 전까지 기능 OFF를 유지한다.

## 4. 회귀 기준

1. 고객사 세션 회사 A와 요청 회사 B가 다르면 결과 회사는 항상 A다.
2. 관리자 세션은 명시적 회사 ID 없이는 회사 범위 작업을 시작하지 않는다.
3. 멤버십 조회는 `company_id`와 `user_id`를 함께 사용하고 최신 `company_members.id`와 회사 표시 이름을 반환한다.
4. owner/manager는 회사 전체 capability를 유지하고 staff/temporary는 담당 범위 키를 사용한다.
5. 공개 링크 라우트는 고객사/관리자 세션의 직원 권한 헬퍼를 호출하지 않는다.
6. 공개 링크의 하위 품목 조회는 토큰으로 찾은 서버 행의 회사·문서 ID를 함께 제한한다.
7. 공개 응답과 쿼리에는 매입가·원가·마진·공급처·직원 권한 필드가 없다.

## 5. 충돌과 보류

- PR #106 문서는 아직 `main`에 없으므로 이 문서는 해당 PR의 ARC-02 범위만 참조한다. PR #106이 변경되거나 병합될 때 용어와 선행조건을 다시 대조한다.
- 과거 주문 방향 문서는 매장 전용 인증·`customer_id` 범위 모델이 없다고 기록하고, 최신 와이어프레임은 매장별 링크를 요구한다. 실제 링크 인증 방식은 ARC-06에서 확정하며 이번 작업에서 추정 구현하지 않는다.
- 운영 DB 스키마·데이터·RLS는 변경하지 않는다. 공개 주문 링크, 알림, 자동 차단, 세션 관찰 플래그도 활성화하지 않는다.
