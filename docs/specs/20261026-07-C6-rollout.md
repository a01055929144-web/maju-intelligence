# C6 권한·업무 분리 적용 순서

운영 스키마를 2026-10-26 읽기 전용으로 확인한 결과 `company_members.role`과 `staff_invitations.role`에 CHECK 제약은 없었습니다. 다른 환경에 제한 제약이 추가되면 C6 SQL의 사전 점검이 중단하므로 기존 사용자 정의 직책을 보존한 채 제약을 검토해야 합니다.

1. 대표가 [`20261026-07-C6.sql`](../sql-drafts/20261026-07-C6.sql)을 검토·승인한다. 운영 적용은 06:00~07:30 KST를 피한다.
2. 스키마·RPC·RLS·권한을 확인한다. 직원 관리자(manager)가 대표(owner)를 바꾸는 요청은 RPC에서도 `owner_target_forbidden`으로 거부되는지 테스트 DB에서 검증한다.
3. [`20261026-07-C6-legacy-dry-run.sql`](../sql-drafts/20261026-07-C6-legacy-dry-run.sql)을 SELECT로 실행해 회사별 driver→배송, sales→영업, owner·manager→둘 다와 미분류 값을 확인한다. 실제 백필 UPDATE는 별도 SQL·승인을 거친다.
4. 서버 코드 배포 후 `STAFF_ACCESS_V2_ENABLED=true`를 설정한다. 그 전에는 기존 직원 화면과 세션 동작을 유지한다.
5. 대표·관리자·알바 계정으로 초대, 복수 업무, 만료일, 차량 미배정, 대표 계정 보호를 확인한다. 배송 업무에서 차량이 없으면 지도는 사람 아이콘을 사용한다.

이번 SQL 초안은 기존 직원 데이터를 수정하지 않습니다. 운영 적용과 실제 백필은 각각 대표 승인 대상입니다.
