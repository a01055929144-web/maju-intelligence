# 04-A2 전체 매장 DB: 쓰기 없는 시범 측정 준비

상태: **측정 준비, 수집 전환 미승인**. 이 문서의 운영 조회는 `SELECT`만 실행했다. 원천 데이터 다운로드·운영 DB 적재·수집 코드 전환은 하지 않았다.

## 대상과 확인된 기준값

- 운영 고객사 영업 지역: 본사는 서울 강남구·강동구·광진구, 인천 남동구·부평구·중구, 경기 의정부시의 7곳. 시범사는 직접 설정한 영업 지역이 0곳이다(2026-10-27 운영 DB 조회). 시범 측정 지역은 **서울특별시 강남구** 1곳이다.
- `shared_business_places`는 0행, 운영 DB 크기는 **109,620,371바이트(109.6 MB)**다. 400 MB 안전 상한까지 **290.4 MB** 남았다. 이 값은 실제 DB 조회이며 향후 인덱스·WAL 증가량을 예측한 값은 아니다.
- 기존 강남구 미병합 리드는 본사 830건, 시범사 240건이다. 이 숫자는 기존 리드 기준이며 새 원천과의 중복 건수가 아니다. 새 원천의 관리번호·상호·주소를 받아야 중복을 계산할 수 있다.

공식 포털의 공개 HTML은 각 API의 존재·이용 조건을 확인시켜 주지만, 동적으로 제공되는 요청 변수 명세를 노출하지 않는다. 따라서 `cond`로 지역·상태·수정일을 서버에서 거를 수 있는지는 **검증되지 않았다**. 키가 정상인 서버에서 각 `/info`의 명세와 조건 호출 결과를 먼저 확인해야 한다. 조건이 없는 것으로 가정해 수집 코드를 전환해서는 안 된다.

## 용량 경계

기존 설계의 구조화 행+인덱스 추정치인 **0.7~1.0 KB/행**을 잠정 적용한다. 강남구 정확 행 수가 없으므로 수용량은 확정할 수 없다. 400 MB 상한까지 남은 290.4 MB를 1.0 KB/행으로 나누면 약 **29만 행**이 절대 상한이다. 수도권 4종 영업 중 약 27.4만 행 전부를 담는 극단적 가정도 약 274 MB로 상한에 근접한다. 강남구 1곳은 그 부분집합이지만, 실측 행 수와 샘플 INSERT 후 `pg_total_relation_size`를 보기 전까지 안전 판정은 보류한다. 일반음식점은 이 4종 계산에 포함하지 않았다.

## API 호출량과 Hobby 60초

지역·상태 조건을 서버에서 걸 수 없고 `numOfRows=1000`이면 전국 원본 전체 한 바퀴에 휴게 652 + 제과 71 + 집단급식 84 + 위탁 38 = **845개 페이지**가 필요하다. 인증키 첫 페이지 중복 호출과 재시도는 별도다. 개발계정 10,000회/일 대비 전체 한 바퀴는 8.45%지만, 60초 함수 안에 넣을 수 있다는 뜻은 아니다.

| 하루 처리 가능한 페이지/데이터셋 | 휴게 | 제과 | 집단급식 | 위탁 | 1개 데이터셋/일 순환 시 한 바퀴 |
|---:|---:|---:|---:|---:|---:|
| 150(현재 일반음식점 코드 상한, **실속도 아님**) | 5일 | 1일 | 1일 | 1일 | 최소 8일 |
| 50(가정) | 14일 | 2일 | 2일 | 1일 | 19일 |
| 30(가정) | 22일 | 3일 | 3일 | 2일 | 30일 |

기존 정부 일반음식점 크론은 최근 40~46초 소요됐으나 페이지 수가 기록되지 않아 성공 페이지/초를 계산할 수 없다. 4종을 각 35초 예산으로 순차 실행하면 140초여서 Hobby 60초를 넘는다. 병렬 실행은 순간 호출량과 시간 초과 위험을 새로 만든다. 수정일 조건이 없다면 위 회전 방식은 신선한 리드를 매일 모두 포착하지 못한다. **최초 CSV 적재와 이후 회전 API만으로 매일 최신이라는 약속은 할 수 없다.** 일일 전체 파일의 지역 단위 다운로드 가능 여부 또는 날짜 조건을 먼저 확인해야 한다.

## 다음 읽기 전용 측정

1. A1 관리자 진단에서 Vercel 서버 실행(`executedOn`)·상류 상태·`resultCode/resultMsg`를 확인한 뒤, 4개 데이터셋 각 1페이지를 호출해 응답 칸과 시간을 기록한다. 키와 원문 응답 전체는 로그에 남기지 않는다.
2. 공식 명세의 지역·영업상태·원천수정일 `cond` 변수 이름과 허용값을 확인하고, 조건 유무를 각 데이터셋별로 구분한다.
3. 조건이 없으면 공식 CSV를 임시 로컬 디렉터리에서만 읽어 강남구 영업 중 건수, 관리번호 유무, 기존 리드와의 관리번호→사업자번호→엄격 상호·주소 중복 건수를 계산한다. 다운로드 파일은 저장소·운영 DB에 넣지 않는다.
4. 각 데이터셋 응답 시간의 중앙값·95백분위와 30초/35초 예산 안에서 완료한 페이지 수를 기록해 실제 한 바퀴 소요일을 다시 계산한다. `cond` 또는 CSV 접근이 막히면 이 항목은 미측정으로 보고한다.

대표 확인 전에는 `shared_business_places`에 쓰거나, 회사별 수집을 공용 원장으로 전환하거나, 진단 경로를 제거하지 않는다.
