# 08 WO-8 구독 결제 기반 1차

## 결정

- 요금제 추천 기준은 영업 지역 안 최근 3개월의 월 신규 리드 평균이다. 임시 영업과 제외 리드는 세지 않는다.
- 추천은 상한을 충족하는 활성 요금제 중 가장 작은 요금제이며, 상한 초과 시 리드를 숨기거나 추가 청구하지 않는다.
- 요금제 변경은 `scheduled_plan_code`로 예약하고 다음 청구 경계에서 적용한다.
- 결제 실패는 예정일 기준 1·3·5일에 재시도하고 7일까지 유예한 뒤 읽기 전용으로 전환한다. 데이터는 삭제하지 않는다.
- 회사·청구월 결제 주기 키를 재시도와 무관하게 고정하고 Toss orderId에도 같은 키를 사용한다. 월 성공 결제는 1건만 허용한다.

## 이번 PR 범위

- 순수 도메인 정책과 회귀 테스트
- `plans`, 구독 보완 칼럼, 월 사용량, 결제 시도 멱등 키 SQL 초안
- 운영 DB 실행, Toss 실결제, 크론 분리, 화면/API 연결은 하지 않는다.

## 적용 전 확인

- 대표가 요금제 이름·월 리드 상한·금액·직원 상한을 확정하고 관리자 화면에서 입력한다.
- `TOSS_SECRET_KEY`, `NEXT_PUBLIC_TOSS_CLIENT_KEY`는 값이 아니라 환경별 설정 여부만 확인한다. 라이브 키 전환과 실결제는 대표 승인 후 진행한다.
- 세금계산서는 Toss 카드 영수증과 별개다. MAJU의 과세 유형과 발행 주체를 세무 전문가에게 확인한 뒤 전자세금계산서 발행 또는 수동 발행 절차를 확정한다.
- 정기결제 고지 초안: “매월 다음 결제일에 등록한 카드로 요금제 이용료가 자동 결제됩니다. 요금제 변경은 다음 결제일부터 적용되며, 결제 실패 시 1·3·5일 뒤 재시도하고 7일 동안 결제 정보를 수정할 수 있습니다.”

## 후속 순서

1. SQL 대표 승인·운영 적용
2. 관리자 요금제 CRUD 및 고객사별 예약 변경
3. 최근 3개월 신규 리드 사용량 집계와 추천 표시
4. 전용 청구 크론·1/3/5일 재시도·7일 유예·읽기 전용 집행
5. 고객 화면 사용량·변경·이력·영수증·해지 안내
