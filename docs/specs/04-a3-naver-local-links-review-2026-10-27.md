# A3 네이버 지역검색 링크 활용 — 코드·저장 경계 검토

## 결론

- 네이버 지역검색 API의 `link`는 지도 상세 주소만이 아니라 인스타그램·네이버 블로그·업체 홈페이지일 수 있다.
- 이번 변경은 응답 링크 분류와 상호명·주소 일치 판정, 기존 인스타 보존 결정을 **쓰기 없는 순수 함수**로만 추가한다.
- 비공식 크롤링, 네이버 지도 페이지 접근, 운영 외부 API 호출, DB 쓰기는 하지 않았다.

## 현재 저장 구조와 차이

| 채널 | 현재 저장 칸 | 이번 결정 |
|---|---|---|
| 인스타그램 | `business_permit_leads.instagram_url` 있음 | 기존 값이 있으면 반드시 유지. 빈 경우도 자동 저장 전 사람 확인 필요 |
| 네이버 블로그 | 전용 칸 없음 | 드라이런에서 후보·확보율만 집계. 저장 연결 금지 |
| 홈페이지 | `shared_business_places.homepage_url`만 있음 | 공용 원장 쓰기 승인 전 후보·확보율만 집계 |
| 네이버 지도 | 기존 `naver_place_url` | 현재 동작 유지. A3 채널 보강 대상으로 세지 않음 |

블로그 URL을 실제 저장하려면 새 컬럼 또는 채널 테이블 설계가 필요하다. 이는 DB 스키마 변경이므로 이번 PR에서
초안도 추가하지 않고, 강남구 200곳 드라이런 결과와 함께 별도 승인을 받는다.

## 안전한 후보 판정

1. 네이버 지역검색의 `title`에서 HTML 강조 태그를 제거하고 기존 상호명과 정규화 포함 관계를 확인한다.
2. `roadAddress` 또는 `address` 중 하나가 기존 주소와 정규화 포함 관계여야 한다. 시·군·구만 같은 후보는 허용하지 않는다.
3. `http`/`https` 링크만 허용한다.
4. `instagram.com`은 인스타 후보, `blog.naver.com`은 블로그 후보, 네이버 지도 도메인은 지도 링크,
   그 밖의 웹 도메인은 홈페이지 후보로 분류한다.
5. 기존 인스타가 있으면 새 인스타 후보는 덮어쓰지 않는다. 모든 결과는 `writeEnabled=false`다.

주소 표기가 도로명/지번으로 서로 다르면 안전을 위해 불일치로 처리될 수 있다. 강남구 200곳 보고에서 이 거짓 음성
비율을 따로 세고, 자동 저장을 넓히기 전에 주소 정규화 정책을 승인받는다.

## 강남구 200곳 읽기 전용 드라이런 출력

대표 브라우저/Claude가 공식 네이버 지역검색 API로 확인할 때 원문 전체나 자격증명을 저장하지 않고 아래 집계만 남긴다.

- 표본 200곳 중 상호명+주소 일치 건수와 불일치 사유(상호/주소/링크 없음)
- 일치 후보 중 인스타·네이버 블로그·홈페이지·네이버 지도 건수와 비율
- 기존 인스타 보존 건수, 신규 인스타 후보 건수
- 도로명/지번 차이로 보수적으로 제외된 건수
- API 호출 수와 오류 수

## 승인 후 선택지

- 인스타: 기존 사람 확인 흐름에 후보만 전달하고 자동 저장하지 않는다.
- 블로그: 전용 URL 칸 또는 일반 채널 테이블 중 하나를 설계한다.
- 홈페이지: 공용 원장 `homepage_url` 쓰기 승인 후에만 연결한다.
- 이름·주소 불일치 후보는 어떤 채널도 저장하지 않는다.
