# ARC-03 리드 → 거래처 전환 계약

## 소유권

- 영업 모듈은 `business_permit_leads`, `lead_actions`의 원본과 전환 상태를 소유한다.
- 고객 모듈은 `normalized_customers` 생성·갱신을 소유한다.
- 두 모듈의 공통 계약은 고객 모듈이 반환한 `customerId`를 같은 회사의 리드에 연결하는 것뿐이다.
- 영업 이력은 고객 테이블로 복사하지 않는다. `matched_customer_id`로 연결해 원본을 읽는다.

## 전환 순서와 재시도

1. 사용자가 남긴 연락·방문·후속 일정은 `lead_actions`에 먼저 저장한다.
2. 고객 모듈이 기존 거래처를 반환하거나 새 거래처를 생성하면 영업 모듈이 리드를 그 `customerId`에 연결한다.
3. 영업 모듈은 회사와 리드로 기존 `convert` 이력을 확인하고, 없을 때만 전환 이력을 추가한다.
4. 전환 이력 확인에 실패하면 성공으로 숨기지 않는다. 사용자가 재시도하면 기존 거래처 연결 경로에서 누락 이력을 복구한다.
5. 재시도는 최초 연락·방문 이력을 다시 만들거나 수정·삭제하지 않는다.
6. 고객 생성과 lead 연결 뒤 전환 이력 저장이 실패한 재시도는 `matched_customer_method='conversion'`인 `lead.matched_customer_id`를 같은 회사에서 먼저 검증해 그대로 재사용한다. 자동 중복 연결을 재시도로 오인하지 않으며, 전체 고객 중복 탐색이나 고객 upsert를 다시 하지 않는다.
7. 이 복구 경로도 누락 전환 이력과 수락 견적 단가 후처리를 같은 완료 절차로 다시 실행한다.

## 회사 격리

- 리드 조회, 고객 중복 검사, 리드 연결, 전환 이력 확인·추가는 모두 서버 인증에서 얻은 동일한 `companyId`를 사용한다.
- 다른 회사의 `leadId` 또는 `customerId`를 연결하는 것은 허용하지 않는다.
- DB 연속성 초안의 `(company_id, matched_customer_id)` 외래 키가 승인·적용되기 전까지 애플리케이션의 회사 필터를 유지한다.

## 남은 원자성 경계

현재 고객 생성, 리드 연결, 전환 이력 추가는 여러 요청이다. 이번 코드 단계는 정상 재시도를 멱등하게 만들고, 기존 전환 이력의 `metadata.customer_id`가 새 연결 대상과 다르면 성공으로 숨기지 않는다.

동시 요청이 서로 다른 기존 거래처 후보를 선택하면 다음 순서로 분리가 재현된다.

1. A와 B가 모두 아직 `convert` 이력이 없다고 읽는다.
2. A가 lead를 customer A에 연결하고 B가 같은 lead를 customer B에 연결한다.
3. A가 customer A를 담은 전환 이력을 먼저 추가한다.
4. 최종 lead는 customer B지만 전환 이력은 customer A를 가리킨다.

코드 단계는 이 불일치를 탐지해 재검토를 요구한다. `20261101-lead-customer-conversion-atomicity.sql` 초안은 고객 생성·갱신을 포함하지 않고, 고객 모듈이 반환한 ID를 받은 뒤 영업 소유 lead 행을 잠가 연결과 전환 이력만 한 transaction에서 확정한다. 운영 적용 전에는 기존 중복 이력 대사, partial unique index 검토, 격리 PostgreSQL 동시성 검증, 기능 플래그 승인이 필요하다.

운영 DB 변경, 기능 플래그 활성화, 기존 연속성 SQL 초안 적용은 이 작업 범위에 포함하지 않는다.
