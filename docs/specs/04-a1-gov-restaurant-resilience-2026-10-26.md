# 04-A1 정부 음식점 수집 안정화

## 10행 probe

2026-10-26 KST에 Vercel Production 환경의 `GOV_RESTAURANT_API_KEY`로 `numOfRows=10`, 1페이지를 읽기 전용 호출했다. 키 값은 출력하지 않았다.

| 데이터셋 | HTTP | 응답 시간 | 결과 |
|---|---:|---:|---|
| 일반음식점 `general_restaurants` | 403 | 350ms | 인증 거부, 정상 데이터 응답 시간 측정 불가 |
| 휴게음식점 `rest_cafes` | 403 | 70ms | 인증 거부, 정상 데이터 응답 시간 측정 불가 |

두 요청 모두 빠르게 403을 반환했으므로 데이터셋 자체의 지연 비교 자료로 사용할 수 없다. 공공데이터포털 활용 신청 상태·서비스키 등록 범위를 먼저 확인한 뒤 같은 probe를 다시 실행해야 한다.

## 페이지 장애 처리

- 동시 요청 묶음 안에서 실패한 페이지만 1회 재시도한다.
- 재시도도 실패하면 해당 페이지만 건너뛰고 나머지 페이지의 적재를 계속한다.
- `lead_sync_runs.metadata`에 `scannedPages`, `skippedPageCount`, `skippedPages`를 기록한다.
- 다음 커서는 실패 페이지에서 멈추지 않도록 시도한 페이지 수만큼 전진한다. 건너뛴 페이지 번호는 운영 이력으로 남으므로 후속 진단이 가능하다.
- 전체 페이지 수를 알아야 하는 첫 페이지가 두 번 모두 실패하면 실행 전체를 오류로 기록한다.

## CSV 대체안

API 인증 또는 지연 장애가 지속되면 공공데이터포털에서 공식 제공하는 최신 원본 CSV를 운영자가 내려받아 비공개 임시 저장소에 올리고, 서버 작업이 스트리밍으로 읽어 기존 `ingestPermitLeadRows`에 같은 행 구조로 전달한다. 원본은 재배포하지 않고 처리 후 삭제하며 파일 해시·기준일·행 수·오류 행 수만 수집 이력에 남긴다. 다음 정상 API 실행부터 `sourceRecordKey`와 최종수정일 기준 증분 갱신을 재개한다. CSV 자동 다운로드 URL과 이용 조건을 확인하기 전에는 자동화를 시작하지 않는다.
