# A2 강남구 전체 매장 DB 드라이런 준비

## 결론과 안전 경계

- 이번 변경은 **계획 계산과 순수 테스트만** 추가한다. 운영 공공 API 호출, `shared_business_places` 쓰기,
  회사 리드 fan-out, 운영 배포는 하지 않는다.
- 일반음식점은 기존 기준선이 있으므로 A2의 “4개 데이터셋”은 추가 4종인 휴게음식점·제과점영업·
  집단급식소·위탁급식영업으로 고정한다.
- 모든 요청 범위는 `서울특별시 강남구` / 개방자치단체코드 `3220000` / 영업 상태 `01` / 페이지당
  `100`행이다. 드라이런 결과에는 원문 행이나 API 키를 남기지 않고 건수·페이지·응답 시간·필드 존재 여부만 남긴다.

## 실행 전 검증표

| 항목 | 고정값 또는 판정 |
|---|---|
| 대상 지역 | 서울특별시 강남구 |
| 개방자치단체코드 | `3220000` |
| 상태 조건 | `SALS_STTS_CD=01`(영업 중) |
| 데이터셋 | `rest_cafes`, `bakeries`, `group_meal_facilities`, `contract_catering` |
| 페이지 크기 | 100 |
| 쓰기 | 0건, `writeEnabled=false` |
| 커서 | `(dataset, page)`, 마지막 페이지 뒤 다음 데이터셋 1페이지 |
| 중단선 | 예상 DB 400MB 또는 일 호출 10,000회에 닿기 전 중단 |

대표 브라우저/Claude가 운영 키로 확인할 때 각 데이터셋 첫 페이지의 `totalCount`가 영업 중 조건을 반영하는지,
모든 행의 `OPN_ATMY_GRP_CD=3220000` 및 `SALS_STTS_CD=01`이 일치하는지 먼저 확인한다. 조건이 무시되거나
필드가 다르면 다음 페이지로 진행하지 않는다.

## 커서·호출량 계산

- 데이터셋별 호출 수는 `max(1, ceil(activeTotalCount / 100))`이다. 0건도 첫 페이지 확인 1회가 필요하다.
- 첫 페이지가 전체 건수와 함께 데이터도 반환하므로 별도의 “건수 조회 1회”를 더하지 않는다.
- 실패한 페이지에서는 커서를 전진시키지 않는다. 데이터셋 마지막 페이지 뒤에만 다음 데이터셋 1페이지로 이동한다.
- 기존 일반음식점 강남구 전체 17,451건은 상태 조건 전 기준이므로 영업 중 적재 예상치로 사용하지 않는다.
  단순 상한은 175페이지지만, A2 추가 4종 호출량에는 포함하지 않는다.

## 용량 계산

- 읽기 전용 자료의 현재 DB 사용량 `104MB`, 안전 중단선 `400MB`, 구조화 행+인덱스 추정 `870B/행`을 사용한다.
- 안전 가용량은 `296MB`, 계산상 최대 추가 행은 `floor(296,000,000 / 870) = 340,229행`이다.
- 실제 적재 승인 전에는 4종의 영업 중 건수 합계에 870B를 곱해 예상 증가량을 다시 계산한다.
- 예상치가 296MB를 넘거나 전체 DB가 400MB를 넘을 가능성이 있으면 적재 승인을 요청하지 않고 범위를 축소한다.

## 시·도 전체 선택 후속 설계

현재 코드표는 기존 수집 자료 기반이라 시·도 전체의 하위 시군구 완전성을 보장하지 않는다. PR #37의 fail-fast는
유지한다. 설정 UI 후속에서는 시·도만 선택된 경우 “정부 공공데이터 수집은 시·군·구 선택이 필요합니다”를 표시하고,
정부 수집 저장/실행을 비활성화한다. 공인된 완전 코드표를 도입하기 전까지 일부 하위 지역만 성공처럼 수집하지 않는다.

## 운영 확인 후에만 가능한 다음 단계

1. 대표 브라우저/Claude가 추가 4종의 첫 페이지를 쓰기 없이 확인한다.
2. `activeTotalCount`, 호출 페이지, 응답 시간, 공통 필드 일치 여부를 이 문서에 기록한다.
3. 예상 용량과 일 호출량이 중단선 아래인지 검토받는다.
4. 별도 승인 뒤에만 공유 원장 쓰기와 회사별 fan-out을 구현한다.
