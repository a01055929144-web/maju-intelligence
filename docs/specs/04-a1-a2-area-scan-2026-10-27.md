# A1·A2 지역 조건 수집 1차

## 확인된 기준

- 대표의 운영 서버 실측: `cond[OPN_ATMY_GRP_CD::EQ]=3220000`은 강남구 17,451건을 최신순으로 반환했다.
- 기존 정부 리드의 `administrative_area`·`jurisdiction` 최빈값에서 225개 시군구 코드를 만들었다. 원문 `MNG_NO` 앞 7자리가 보존된 121건과 `jurisdiction`의 불일치는 0건이었다.
- 운영 DB의 영업 지역은 본사 7곳, 시범사 0곳이다. 본사 7곳 중 인천광역시 중구는 기존 리드에서 코드를 확인할 수 없어 수집을 건너뛰고 동기화 이력에 누락 지역으로 남긴다. 포털 코드표를 받으면 검증 후 추가한다.

## 배포 범위

- 일반음식점 크론은 전국 회전을 중단하고 회사 영업 지역 코드별 `/info` 1페이지부터 조회한다. 마지막 완료된 스캔 시작 시각에서 하루를 겹쳐 보며 최대 14일 전까지만 읽는다.
- 한 실행에서 최대 14페이지를 읽고, 남은 지역·페이지·기준 시각을 `lead_sync_runs.metadata.areaCursor`에 기록해 다음 실행에서 이어간다. 이전 실행 두 건이 실패해도 마지막 성공 기록의 커서를 사용한다.
- I/U/D와 영업 상태 코드를 읽으며, D 및 폐업 코드는 신규 리드로 만들지 않고 기존 리드 상태 처리 경로로 전달한다.
- 동일한 지역 조건 조회 함수는 일반·휴게·제과·집단급식·위탁급식 데이터셋을 지원한다. 현재 크론 연결은 일반음식점만이다.
- 전체 매장 DB 최초 적재는 `activeOnly` 조건과 페이지 커서 함수까지만 준비했다. 공유 테이블에 쓰는 수집 전환은 별도 승인 전까지 연결하지 않는다.

## 호출량과 첫 적재

- 현재 본사 기준 매핑 가능한 시군구 6곳은 한 실행 최소 6회, 최대 14페이지이며 재시도까지 최대 28회다. 일일 1만 회 한도의 최대 0.28%다. 시범사는 영업 지역이 없어 0회다.
- 강남구 일반음식점 전체 17,451건은 페이지당 200건이면 최대 88페이지다. 영업 중만의 정확한 건수와 나머지 데이터셋·지역 건수는 운영 서버 `mode=cond` 진단으로 확인해야 한다. 첫 적재는 여러 크론 실행에 나누어 이어받는 설계다.
- 진단 경로는 `mode=cond&dataset=general_restaurants&areaCode=3220000&statusCode=01` 형식으로 10건만 조회하고 코드·응답 시간·조건 일치 여부만 반환한다. API 키나 원문 행은 응답하지 않는다.
