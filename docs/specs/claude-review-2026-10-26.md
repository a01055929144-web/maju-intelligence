- 실행 조건: 크롬이 켜진 PC에서 동작(크롬 "백그라운드 앱 계속 실행" 켬, 절전 해제). 주문 시간대 30분마다 + 마감 시각 1회, 마지막 성공 시각을 관리자 화면에 표시.
- 배송 코스 일원화: 동선·오늘 코스·권역/호차를 "코스" 하나로 — 배송 코스(거래처·호차)와 영업 방문 코스(리드·담당자)가 같은 순서 계산 엔진 사용, 순서는 자동·사람은 예외만 수정. 정기 코스(호차별 요일 거래처) → 매일 아침 오늘 코스 자동 생성 + 업로드/확장으로 들어온 주문 반영.
- 보고(설계 문서): ERP별(대표가 알려줄 ERP) API 유무·엑셀 형식·자동 조작 가능 여부·이용약관, 크롬 확장 구조(MV3, alarms, 권한 최소화), 배포 방법(크롬 웹스토어 비공개 등록).
- **ERP 계정 보관(대표 결정 10-26: 고객사 ERP 아이디·비밀번호를 받음)**:
  - 받는 경로는 MAJU 화면 한 곳(관리자 대행 설정 또는 고객사 설정 > ERP 연결)만. 채팅·카톡·메일·문서로 주고받지 않음. 고객사에 **조회·엑셀 내려받기만 되는 전용 하위 계정**을 만들어 달라고 안내(권한 최소화).
  - 저장: 서버에서 암호화(앱 비밀키는 환경변수, DB에는 암호문만), 저장 후 화면·API·로그·감사 기록 어디에도 다시 표시 금지(쓰기 전용, "등록됨·마지막 성공 시각"만). 회사 해지 시 즉시 삭제. 고객사 동의 기록(누가·언제·문구 버전).
  - 사용 위치 결정(설계 문서에서 비교 후 대표 선택): (a) 크롬 확장이 로그인 풀렸을 때 자동 재로그인 — PC 필요, 비밀번호가 PC에 전달됨 (b) 서버 작업기(Playwright, Vercel 밖의 별도 실행 환경)가 직접 로그인·다운로드 — PC 불필요·진짜 24시간, 운영비 추가. 
  - 캡차·2단계 인증은 자동 통과 금지 → 알림. ERP 이용약관의 자동 로그인 허용 여부 확인. 실패 3회 연속이면 자동 중지(계정 잠김 방지).
  - SQL(ERP 연결 테이블: 회사·ERP 종류·암호문·상태·마지막 성공·동의) 초안 → 승인.
