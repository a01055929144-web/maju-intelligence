- 원인: lib/store.ts 고객사 목록 조회에서 `customerPassword: credentials?.customer_password` 를 그대로 반환.
- 수정: 목록·상세 응답에서 customerPassword 제거 → `hasPassword: boolean`. 칸은 "새 비밀번호(바꿀 때만)", 빈 값이면 유지(필수 표시 제거).
  계정 완료 배지·준비율도 hasPassword 기준. 테스트: 관리자 고객사 API 응답 JSON에 해시·비밀번호 문자열 없음.

### C2 고객사 구분 = 사업자등록번호 (상호명 중복 허용)
- 기준: companies.business_registration_number (기존 부분 유니크 인덱스 유지). 같은 사업자번호는 저장 차단.
- 상호명은 중복 허용. 생성·이름 변경 시 같은 이름이 있으면 경고 + 기존 회사(대표자·지역·사업자번호 끝 4자리) 보여 주고 확인 후 저장.
- 같은 이름이 둘 이상이면 목록·결제·관리자 지표·알림에서 "이름 · 대표자 · 지역 (…끝4자리)"로 자동 구분 표시.
- 상세 맨 위에서 이름·대표자·업종·사업자번호 바로 수정(연필 → 저장), 비밀번호와 분리 저장. 사업자번호는 국세청 상태조회로 확인(실패해도 저장, "미확인" 표시).

- 이준형 회사(898d85fc…)가 "마주식자재"가 된 경로 조사(가입·생성 기본값, app/page.tsx `companyName: "마주식자재"` 하드코딩 등) → 하드코딩 제거, 원인 보고.
