# 집중 개선 Task 0 결과 (2026-10-19)

## 정부·서울 리드 영업 지역 제한

- 기존 `company_lead_search_regions`를 회사가 직접 지정하는 영업 시·군·구 저장소로 재사용했다. 신규 테이블은 만들지 않았다.
- 직접 지정값이 없으면 `companies.origin_address`와 `delivery_territory_areas.administrative_area`의 시·군·구 합집합을 기본값으로 계산한다.
- 정부·서울 자동 적재, 적재 직후 보강, 일일 보강, 기본 리드 목록은 이 지역 안만 처리한다.
- 기존 권역 밖 데이터는 변경·삭제하지 않고 `영업 지역 밖 보기`에서만 표시한다.
- 설정 위치: `/dashboard/settings/company`의 `영업 지역` 카드.

운영 읽기 전용 집계 시점 기준:

| 회사 | 전체 기존 리드 | 현재 유효 시·군·구 | 기본 표시/후속 자동 처리 | 지역 밖 |
| --- | ---: | --- | ---: | ---: |
| 마주식자재 `04ebb7bb…` | 17,239 | 없음 (`인천`은 광역 단위라 제외) | 0 | 17,239 |
| 마주식자재 `898d85fc…` | 4,764 | 없음 | 0 | 4,764 |

두 회사 모두 출발지와 배송 권역 시·군·구가 비어 있으므로, 회사 정보에서 영업 지역을 지정하기 전 신규 자동 적재는 0건이다. 운영 데이터는 수정하지 않았다.

## 거래 시작과 거래처 연결

- 방문 결과 `거래 시작`은 `전환 진행`까지만 저장한다.
- 신규 거래처 생성 또는 기존 거래처 연결 성공 후에만 `거래처 전환`으로 변경한다.
- 기존 거래처와 일치할 때 `제외`로 바꾸지 않고 `matched_customer_id`, 매칭 방법·신뢰도와 함께 연결한다.
- 거래처 연결 실패 후 PC·모바일에서 `거래처 연결 다시 시도`를 제공한다.
- 신규 거래처 자동 매칭은 `거래처 전환` 상태라도 `matched_customer_id`가 없는 과거 행을 다시 포함한다.

## KST 후속일

`getDefaultVisitFollowUpDate`는 UTC 문자열이 아니라 Asia/Seoul 날짜를 기준으로 +3일을 계산한다. KST 08:00 경계 테스트를 추가했다.

## 영업시간·브레이크타임

- 승인된 `lead_business_hour_intervals` 마이그레이션을 운영에 적용하고 저장 API를 연결했다.
- PC 리드 상세와 모바일 영업에서 `매일 15:00~17:00 브레이크`, `월 휴무` 형태로 직접 입력한다.
- 리드 목록에서 `지금 방문 가능`, `오늘 브레이크 있음` 필터를 제공한다.
- 외부 Google API 호출은 추가하지 않았다.
- 마이그레이션 검증: 테이블·복합 FK·선행 UNIQUE 존재, anon/authenticated SELECT 거부.
