# 매입가 업로드 · 이력 화면 계약

상태: CX-86 코드 근거 검토 완료. 이 문서는 현재 동작을 설명하며 기능·DB 변경을 승인하지 않는다.

Owner Domain: `pricing`(매입가·매입 이력)
Related Domain: `catalog`(상품명·규격·단위·과세 구분), `pricing-document`(매입가를 쓰는 문서 영향)

## 목적과 사용자

- 대표·관리자가 엑셀 원문을 상품에 연결하고, 원문 거래 이력을 보존하며, 선택한 경우에만 현재 매입가와 마진 기반 판매가를 바꾼다.
- 매입 이력은 날짜·품목·매입처별 원문 거래를 확인하고 사유를 남겨 정정하는 화면이다.
- 파일을 올린 것만으로 저장하지 않는다. `① 엑셀 올리기 → ② 열 정렬 → ③ 저장`을 모두 거쳐야 한다.

현재 구현 근거:

- 화면·후보·저장 흐름: `components/purchase-cost-workspace.tsx`
- 원문 열 판독: `domains/pricing/purchase-import.ts`
- 날짜별 저장 행과 원문 보존: `domains/pricing/purchase-cost-date.ts`
- 이력 집계: `domains/pricing/purchase-receipt.ts`
- 이력 화면: `components/purchase-history-panel.tsx`
- 이력 API: `app/api/price-sheets/receipts/route.ts`

## CX-86 질문 답변

### 1. `변경 후 매입가`가 이력만 저장에서도 보이는 이유

상품 표의 열 목록이 저장 방식과 무관하게 동일하기 때문이다. 이력만 저장으로 열 정렬하면 해당 상품의 후보를 제거하지만, 열 렌더러는 후보가 없을 때 현재 매입가와 `수정` 버튼을 표시한다. 그래서 실제 현재가 변경이 0건이어도 `변경 후 매입가`에 현재가가 다시 보인다.

판정: 데이터가 바뀌는 버그는 아니지만 의미가 잘못 전달된다. CX-87에서는 이력만 저장일 때 이 열을 숨기거나 셀을 `변경 없음`으로 표시한다. 최소 변경은 열을 유지하고 셀을 `변경 없음`으로 바꾸는 것이다. 사용자가 직접 수정하면 저장 방식이 현재가 변경으로 바뀐다는 별도 동작이 없으므로, 이력만 저장 상태에서 `수정` 버튼도 노출하지 않는다.

### 2. `변동 확인 필요`의 실제 뜻

현재 코드의 `확인 필요`는 직전값이 없다는 뜻이 아니다. 서버 후보의 `direction`이 `review`일 때 `reviewOnly`가 되고, 이 경우 선택을 막고 변동 셀에 `확인 필요`를 표시한다. 구체 사유는 `바꾼 방법·근거` 열의 매입처 검토 사유에 들어간다. 직전 이력이 없거나 차이가 0인 일반 행은 `-`다.

판정: 직전값 부재와 검토 필요를 섞어 빈칸으로 바꾸면 실제 경고를 숨긴다. CX-87에서는 다음처럼 분리한다.

- 비교할 직전값 없음: 빈칸
- 차이 없음: `변경 없음`
- 서버가 검토 대상으로 준 후보: `확인 필요` 유지 + 사유를 같은 셀 또는 도움말에 표시

### 3. `바꾼 방법·근거` 열의 목적

저장 전 후보가 직접 입력인지, 엑셀 파일인지, 확정 매입처 최신 단가인지 구분하고 파일명 또는 검토 사유를 보여 주는 추적 열이다. 그러나 상세 값은 후보 상태에만 있어 새로고침 뒤에는 `매입 이력`만 남고 파일명·방법이 복원되지 않는다. 영구 감사 근거 열로 볼 수 없다.

판정: 저장 전 검토에는 유용하지만 상시 핵심 열은 아니다. CX-87에서는 공통 표 열 설정에서 기본 숨김으로 두고, 후보의 `확인 필요` 사유는 변동 셀에서도 볼 수 있게 한다. 영구 근거가 필요하면 별도 DB 계약·승인이 선행돼야 하며 CX-87 범위가 아니다.

### 4. `단가 기준`의 포함·별도·빈칸

이 열은 상품의 과세 구분이 아니라 이번 후보 단가가 부가세 포함으로 읽혔는지를 뜻한다. `포함`을 누르면 원문 단가를 보존한 채 저장 원가를 부가세 제외 금액으로 환산하고, `별도`는 원문 단가를 그대로 저장 원가로 쓴다. 후보가 없으면 현재는 `-`다.

판정: 현재 코드에는 회사별 부가세 기본 설정을 읽는 동작이 없다. 따라서 빈칸을 “회사 기본값”이라고 설명하면 사실과 다르다. CX-87에서는 후보가 없을 때 `별도(저장 기준)`으로 표시하고 도움말 `저장되는 매입가는 부가세 별도 기준`을 제공한다. `과세` 열은 상품 세금 종류이므로 유지하고 두 열을 합치지 않는다.

## CX-87 최소 구현 범위

   - `바꾼 방법·근거` 기본 숨김과 `단가 기준` 도움말을 적용한다.

   - 1440·390에서 고정 단계 바, 저장 확인 접근, 가로 넘침 0을 검증한다.

- 원문 파서와 단가 계산식

## 보존 조건

- 원문 거래행은 가격 후보 선택과 별도로 모두 이력에 보존한다.
- 소수 수량은 단가를 다시 계산하지 않고 원문 단가를 유지한다.
- 이력만 저장은 현재 매입가·판매가를 바꾸지 않는다.
- 현재가 변경은 최신 적용일의 명시적으로 선택된 후보만 반영한다.
- 직접 정한 판매가는 유지하고 마진 기반 판매가만 재계산한다.
- 새로고침 전 후보와 서버에 저장된 이력을 같은 것으로 오인하지 않는다.
- 운영 데이터 자동 수정·DB 적용·기능 ON·배포를 하지 않는다.
