## 0. 목표 (이번 차수 하나)

**홍곱창 신촌점이 대표 카카오로 첫 실주문을 넣고, 고객사 주문 목록·금액이 맞는 것까지.** 나머지는 이 목표를 막지 않는 범위에서 병렬.

전략 기준(11/25 대표): 소형 유통사 틈새 — 매입가 → 공격적 단가표 → 신규 매장 영업 → 매장 원가·마케팅 → 주문. ERP 만들지 않음.

## 1. 공통 규칙 (R2 0-2절 + 아래)

- 브랜치 `codex/<ID>-<요약>`, PR 제목 `[<ID>]`, 본문 첫 줄 `Ponytail: 사용함`. 한 PR = 한 고객 행동.
- 작업 전·PR 전 `git fetch && git rebase origin/main`. 열린 PR(`gh pr list`)과 파일이 겹치면 먼저 병합된 쪽 기준.
- 운영 DB 쓰기는 `docs/sql-drafts/` 초안 + down + PG17 → 대표 승인 문구 → 적용 → 읽기 검증 → `docs/work-orders/db-approval/` 기록.
- 매장 화면에 매입가 노출 금지. 휴대폰 원문 출력 금지(끝 4자리만). 비밀값 출력 금지. 테스트를 약하게 만들어 CI 통과시키지 않기.
- 가격은 화면에서 계산하지 않는다(서버 `self_order_price_v2` 결과만). 배송일·마감 문구는 `domains/order/order-rules.ts`(`deliveryDayState`, `deliveryGuide`) 하나에서만 만든다.
- 문서·항목 삭제 금지(대표 11/25: "삭제는 하지마 추후에 필요할 수도 있음"). 안 쓰는 것은 `보류`로 표시.

## 3. 이번에 새로 쓰는 작업지시

### 3-1. CX-145 P1-6 마감 문구 통일 (작은 PR)

- 바꿀 것: "전날 23:59", "주문 마감 · 전날 HH:MM" 등 → **"오늘 주문하면 내일 배송 (밤 11:59 마감)"**. 마감이 2일 전이면 "오늘 주문하면 모레 배송", 3일 이상이면 "오늘 주문하면 11/29(토) 배송"처럼 날짜.
- 대상: 단가표 하단(인쇄물·공개 화면·매장 앱), 매장 주문 화면 안내, 고객사 주문 설정 화면(설정값은 그대로, "매장에는 이렇게 보입니다" 미리보기 추가).
- 문구는 `deliveryGuide` 하나에서. 화면마다 따로 쓰지 않음.
- 완료 기준: `grep -rn "전날" app components lib domains` 결과 0건(테스트·문서 제외)을 PR 본문에 첨부. PC 1440·모바일 390 e2e.

### 3-2. CX-151 영업 지역 = 기본 배송권역

- 배경: 11/26 관제탑이 운영에 수동으로 "기본 배송 권역(영업 지역)" 권역 1개 + 18개 지역 + 요일 {월~토}를 넣었다(기록 `docs/work-orders/db-approval/2026-11-26-default-delivery-territory.md`). 이를 자동으로 유지하게 만든다.
- 할 것: `company_lead_search_regions` 추가·삭제 시 기본 배송권역 지역 동기화. 지역별 "배송 안 함" 옵션. 영업 지역과 배송권역이 어긋나면 설정 화면에 경고 한 줄.
- 다른 권역(예: "서울 송파구")에 이미 있는 지역은 기본 권역에 넣지 않는다(중복 매칭 → `ambiguous_area` 방지).
- 범위: SQL 초안 + down + PG17 테스트 + 설정 화면. **운영 적용은 대표 승인 후.** 플래그 기본 OFF.
- Files: `docs/sql-drafts/2026-11-26-CX-151-*.sql`, 배송 권역 설정 화면·API, 테스트. `lib/store.ts` 손대지 않음.

### 3-3. CX-148c 단가표 > 마진

- 대표 결정(11/25): 받은 단가표 가격 = 주문 가격. **기본 단가표에 있는 품목은 카테고리 마진 가격보다 단가표 가격 우선.**
- 할 것: `self_order_price_v2`의 "매장별 후보"와 `received_document_products_v1`이 같은 후보 규칙을 쓰도록 공통 내부 함수 하나로 합치기. 우선순위: 매장별 후보 → **회사 기본 단가표** → 카탈로그 마진 → 기본가. (현재는 마진이 기본 단가표보다 앞)
- 검증: 운영 읽기 dry-run(트랜잭션 안 적용 → 계산 → `raise exception 'DRYRUN_RESULT: %'`로 되돌림)으로 홍곱창 신촌점 품목 전부 "받은 단가표 표시가 = 주문가" 일치 건수를 PR에 첨부. 래퍼가 security invoker이므로 내부 함수에 `service_role` grant 확인(11/25 장애 재발 방지).
- 범위: SQL 초안 + down + PG17. 운영 적용은 대표 승인 후.
