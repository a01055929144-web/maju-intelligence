# R18 현장 영업·매장 주문 우선순위 (11/24 14:02 대표 결정)

원칙: **새로 만들지 말고 있는 기능을 묶어 쓴다.** 개발 리소스를 최소로.

## 대표 결정
1. 진행 중인 일은 지금 단계까지만 정리하고, 끝나지 않은 건 이 문서로 팔로업한다.
2. 직원·알바 위치: 가입하면 계속 보이게(웹/앱 화면을 연 동안 전송되는 구조). 문제 생기면 그때 고친다.
3. 알바 운영: 매장 브레이크 타임 **14:00~18:00**, 하루 2~4시간, 매일 또는 주 2~3회. 배정된 매장에 전단지·단가표·견적서·카탈로그를 **전달만**(상담 없음 — 상담은 전단지 연락처 또는 QR로 매장이 직접). **놓고 온 사진이 있어야 방문 인정.** 방문 1건당 지급 방식 예상. 성과 기준(가입·주문 연결)은 추후.

## 흐름 (대표안)
발행(온/오프라인) → 현장 전달(기사·영업·알바, 사진+GPS) → 매장 QR → 카카오 가입·매장 등록 → 단가표·전체 상품 보고 주문 → MAJU 주문관리에 쌓임 → 매장·고객사 화면에 상태 → 배송완료·방문 사진/영상 기록. ERP 연동은 나중.

## CX-135 현장 기록 통일
- 기사·영업·알바가 같은 **[현장 기록]**: 사진/영상 + 자동 GPS·시각 + 종류(배송완료 / 방문 / 단가표·견적서·카탈로그 비치 / 전단지) + 대상 매장(배정 매장 또는 지도 위치).
- 재사용: `components/mobile-delivery-proof-panel.tsx`, `app/api/orders/delivery-photos`, `app/api/visits`, `app/api/customer-attachments`, `components/mobile-location-reporter.tsx`, 지도 `components/map/use-live-vehicle-feed.ts`·`vehicle-layer.tsx`.
- 지도에 영업·알바 위치도 차량처럼 표시(역할 색 구분). 관리자·고객사 관리자만.
- "비치" 기록은 사진 1장 이상 필수. 사진 없는 기록은 방문 인정 안 됨 표시.
- 먼저 기존 배송완료 사진·방문 기록 저장 구조를 읽고 **표 하나로 합칠지/종류 칸만 추가할지** 설계 3~5줄 보고 후 구현.

## CX-136 대신 주문 입력 + 새 주문 알림
- 종이 단가표 보고 전화·카톡으로 온 주문을 직원이 주문관리에서 매장 대신 입력 → 매장 주문과 같은 목록·상태·매장 화면에 보임(입력자·경로 "직원 입력" 표시).
- 재사용: 주문함 `components/order-inbox-workspace.tsx`, 매장 주문 생성 경로(스토어프론트 주문 함수)를 그대로 호출. 가격은 매장 가격 함수(`self_order_price_v2`)로.
- 새 주문 알림: 우선 브라우저 알림 + 주문함 배지. 카카오 알림톡은 비용·발신 프로필 필요 → 별도 결정.
- 묶음 2 운영 적용 전에는 기능 플래그 OFF.

## CX-137 알바 초대 · QR 출처 · 조회수
- 알바: 초대 링크 + 휴대폰 인증으로 가입, 권한 "현장 기록 전용"(오늘 배정 매장·현장 기록만, 가격·거래처 정보 안 보임).
- 배정: 관리자가 날짜별 매장 목록 배정(지도 영역 선택 재사용). 근무 14:00~18:00 안내.
- QR 출처 코드: 알바/동선별 짧은 주소(`pricing_document_share_links.short_code` 재사용) → 가입·주문에 출처 남김. 정산은 "사진 있는 비치 기록 건수"로 집계 화면만(지급 계산은 추후).
- 조회수: 긴 주소(`/pricing-document#토큰`)로 열어도 1회 세기. 지금은 `resolve_pricing_document_short_link_v1`에서만 올라가 3매장 링크(f9c076c7)가 0으로 보임.
