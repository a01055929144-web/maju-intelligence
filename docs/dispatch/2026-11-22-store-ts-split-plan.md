# `lib/store.ts` 분리 계획 지시서 (2026-11-22 · 다음 차수 Codex 배정용)

작성: Claude Code(컨트롤타워) · 상태: **계획만. 이 문서로는 코드를 바꾸지 않는다.** 구현은 다음 차수에 Codex 방이 한 조각씩 맡는다.

## 왜
- `lib/store.ts` 16,100줄 · `export function` 226개(전체 export 374개). `app/page.tsx` 4,556줄, 지도 `components/sales-route-map-workspace.tsx` 5,670줄.
- 약 300개 파일이 `lib/store`를 직접 가져다 쓴다. 새 기능을 얹을 때마다 파일 소유 충돌(여러 작업방이 같은 파일 수정)과 리뷰 부담이 커진다. CLAUDE.md 6절이 말하는 God Component · Direct DB Dependency에 해당한다.

## 원칙 (Strangler · 한 번에 한 조각)
1. **동작을 바꾸지 않는다.** 함수 본문을 새 파일로 옮기고, `lib/store.ts`는 그 자리에서 `export { … } from "…"`로 다시 내보낸다. 기존 import 경로는 한 줄도 바꾸지 않는다(호출부 수정은 별도 PR).
2. **한 PR = 한 조각 = 한 도메인.** 조각이 끝나 CI가 초록이 되기 전에는 다음 조각을 시작하지 않는다.
3. 새 파일 위치는 기존 `domains/<도메인>/`(예: `domains/product/order-cutoff.ts`) 규칙을 따른다. 도메인 사이 직접 import 금지(공용은 0번 조각).
4. 매 조각마다 Ponytail, 전체 CI, Stage A 실제 API 시험, 파일 잠금(2시간, 현황판) 필수. DB·운영 설정 변경 없음.
5. 조각 PR 본문에 "옮긴 함수 N개 · 줄 범위 · 호출부 변경 0 · 테스트 변화 0"을 적는다.

- `lib/store.ts` 줄 수가 줄고(PR 본문에 전후 줄 수), 새 파일에서 옮긴 함수가 `export`된다.
