| ⑤ | **전달 못 함** | 작은 링크 → 이유 하나: 문이 닫혀 있음(상태 그대로, 다음 배송 때 다시) · 폐업·이전함(→ `제외`, 사유 "폐업") · 받지 않음(→ `거절`, 사유 "기존 거래처 유지" 등 CC-50 사유) · 시간이 없어 못 들름(→ 내일 경로에 다시). 고르면 바로 다음 배송지 |
| ⑥ | 메시지 | 완료를 밀 때 카톡 공유창이 같이 열림(보내기는 기사가 고름, 자동 발송 없음) — 3절 템플릿 그대로 |

**연결 검토 (11/16 20:2x)** — 0절을 하려면 먼저 필요한 것:
- **P1 정류장 테이블이 없음**: 지금 경로 = `route_plan_confirmations.customer_ids`(거래처 id 배열) + 거래처별 하루 상태 `delivery_route_follow_ups`. 정류장 순서 · 종류(배송/영업) · 도착/완료 시각 · 사진 · 리드 연결을 둘 곳이 없고, **리드는 거래처가 아니라 경로에 못 넣음**. → **CX-46c SQL 초안에 `delivery_route_stops`**(회사 · 날짜 · 기사/차량 · 순서 · 종류 `delivery`/`sales` · `customer_id` 또는 `lead_id` · 상태 · 도착/완료 시각 · 위치 · 사진 경로 · 전달 못 함 이유, 회사 범위 RLS)를 넣고, 기존 `customer_ids` 경로는 읽어서 정류장으로 펼침(이전 화면 계속 동작). 48-7ⓑ(사진 ↔ 배송 연결) · CX-46e(가는 길 영업)가 모두 이 테이블 위에.
- **배송 주소 우선(11/16 21:2x S-2b 검토)**: 지금 지도 · 경로 마커 · 기사 경로는 거래처 `address`(사업장 주소)를 쓰고 주문 판정만 `delivery_base_address`(배송 주소)를 쓴다. CX-46a부터 기사 화면 · 길 안내 · 지도 마커는 **배송 주소가 있으면 배송 주소, 없으면 `address`**. 좌표도 같은 규칙으로(48-5 `usableStoredPoint`가 주소가 바뀌면 옛 좌표를 쓰지 않는 것은 유지).
- 기사 화면이 읽는 배송 정보(받는 분 · 출입 · 놓는 곳)는 **거래처 칸**(S 2-5 Ⓐ) — 매장이 바꾼 값은 유통사가 반영한 뒤에 기사에게 보임.

## 1. 기사의 하루 (화면 흐름)

| # | 단계 | 화면 |
| --- | --- | --- |
| 1 | 출근 | `/mobile/today` 첫 화면: 오늘 날짜 · 내 호차 · 배송지 n곳 · 예상 끝 시각 · **[운행 시작]**(화면 꺼짐 방지 켬) |
| 2 | 상차 확인 | (선택) 차량별 명세서 묶음 출력 목록(E 2-2)을 휴대폰에서 보기 · 상차 사진(기존 `mobile-loading-attachment-panel`) |
| 3 | 배송지마다 | **포커스 카드**(지금 배송지 하나만 크게): 상호 · 주소 · 출입 메모 · 품목 n개 · [길 안내] [전화] → **[도착]**(그 순간 위치 새로 측정·저장) |
| 4 | 처리 | 사진(여러 장, 최대 5) → 결과 고르기 **[완료 · 일부 · 문제]** → 일부·문제면 품목·수량·사유 → 매장에 보낼 **메시지 확인**(템플릿) → **[보내고 다음]** |
| 5 | 수령 확인 | 매장이 온라인 수령 확인(E 2-3)을 했으면 카드에 "수령 확인됨" · 안 했고 종이 명세서에 서명 받았으면 **[서명 사진 찍기]**(그 전표에 붙음) |
| 6 | 다음 | 자동으로 다음 배송지가 포커스 카드로 · 위쪽 진행 막대(완료/남음) |
| 7 | 퇴근 | **[운행 종료]** · 오늘 요약(완료·일부·문제·사진 없는 곳) · 못 한 곳은 사유 필수 |

- 전체 목록은 **아래에서 올라오는 창**(공용 `BottomSheet`): 대기 배송지는 길게 눌러 순서 바꾸기, 탭하면 길 안내·전화. 진행 중인 곳은 "닫고 지금 처리하기".
- 화면 아래는 **고정 주 버튼 1개**(지금 단계의 다음 동작: 도착 → 보내고 다음 …), 하단 메뉴는 `오늘 코스 · 배송 기록 · 더보기` 3개(공용 `BottomNav` 기사용).

## 2. 처리 결과 → 다른 단계와 연결

| 기사 입력 | 연결 |
| --- | --- |
| 완료 + 사진 | 배송 완료 사진이 **그 배송 건(정류장·주문·전표)에 연결**(CC-48-7ⓑ — DB 칸 필요, 승인) → 매장·고객사 화면·지도 상세에서 보임 |
| 일부(품목·수량) | 유통사 주문 확인 화면에 "일부 배송" 알림 → 유통사가 확인하면 **전표 수정 차액**(E 2-1) — 기사가 직접 금액을 바꾸지 않음 |
| 문제(파손·부재·반품) | 사유 코드 + 사진 → 유통사 할 일 목록(반품이면 E 반품 전표로 이어짐) |
| 서명 사진 | 그 전표의 수령 확인 "오프라인 서명 사진"(E 2-3) |
| 도착·완료 위치 | 정류장 기록에 시각·위치(D-3 기존 설계) — GPS 끊긴 구간은 "기록 없음"(지어내지 않음) |

## 3. 매장에 보내는 메시지 (목업 확정안 그대로)

- 템플릿 7종(완료 안내 · 부재 · 수량 확인 · 회수 · 반품 · 보충 · 특이사항), `{매장명}` 자리 채움.
- **회사 기본(PC 관리) + 기사별 수정본** 2단 — 기사별 수정본은 **서버 저장**(기기 바꿔도 유지, 브라우저 저장 아님 — 새 테이블, 승인 필요).
- 보내기는 **휴대폰 공유창**(Web Share — 사진+문구를 카톡으로, 기본 카톡 · 문자 선택). **자동 발송 아님**(단체 문자·카톡 매크로 금지 원칙).

## 4. 화면 기준 (M 공통 + 기사 특화)

- 한 손 조작: 주 버튼은 화면 아래 엄지 닿는 곳, 48px, 장갑 낀 손 고려해 버튼 사이 12px.
- 햇빛 아래: 글자 대비 강하게(회색 글자도 진하게), 본문 16px.
- 느린 연결: 누르면 바로 "보내는 중", 실패하면 입력·사진 그대로 두고 [다시 보내기]. 사진은 올리기 전 줄임(긴 변 1600px).
- 확인 창 최소화: 되돌릴 수 있는 동작은 확인 없이 바로 + "되돌리기" 알림 5초. 되돌릴 수 없는 것(운행 종료·문제 보고)만 확인.
- 분위기: 담백하게(CX-44·M 기준). 이모지·축하 애니메이션 없음.
