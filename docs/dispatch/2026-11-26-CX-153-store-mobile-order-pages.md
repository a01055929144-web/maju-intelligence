# CX-153 — 매장 모바일: 주문 흐름 페이지 분리 · 화면 틀 통일 (2026-11-26 13:15 대표 피드백)

## 대표 피드백 (원문 요지)

1. 모바일 UX/UI 틀에 통일성이 없다.
2. 단가표 카테고리 확인: 스크롤이 너무 길어 어렵다.
3. 장바구니를 하단에 배치할 게 아니라 **페이지를 나눠서 들어가야 한다**: **주문 > 장바구니 > 주문 확인 > 접수 > 배송 확인** (일반적인 배송 현황).

## 결정

- **CX-145 P1-5(하단 고정 장바구니 시트)는 중단한다.** 브랜치 `claude/cx145-p1-5-bottom-cart`는 지우지 않고 보류. 재사용할 부분(수량 조절·합계 계산 표시)만 가져온다.
- 매장 주문은 아래 5단계 화면으로 나눈다. 단계마다 상단에 "← 뒤로 · 단계 이름", 화면 하나는 한 가지 일만.

| 단계 | 화면 | 하는 일 | 다음 |
|---|---|---|---|
| 1 | 주문(상품) | [받은 단가표 \| 전체 상품] 탭(#1435 유지) + **카테고리 칩 상단 고정**(가로 스크롤). 한 번에 **한 카테고리만** 보여 스크롤을 짧게. 검색. 행: 이름·단위·가격·행사 배지·[− 수량 +] | 하단 얇은 바 "장바구니 3품목 · 45,000원 [장바구니 보기]" → 2 |
| 2 | 장바구니 | 담은 품목·수량 수정·삭제, 소계 | [주문 확인으로] → 3 |
| 3 | 주문 확인 | 배송일(월 달력, #1432 재사용), 배송지·적치 위치(#1439 카드, 빠졌으면 여기서 입력), 요청사항, 공급가·세액·합계(서버 값), "오늘 주문하면 내일 배송" 안내 | [주문 접수] → 4 |
| 4 | 접수 완료 | 주문번호·배송일·합계, [배송 현황 보기] [계속 주문] | → 5 |
| 5 | 배송 확인 | 주문 상태 단계 표시: **접수(submitted) → 확인(confirmed) → 배송 완료(delivered)**. 지금 DB에 있는 상태만 쓴다(새 상태 만들지 않음). 주문 내역 목록에서도 들어감 | — |

- 하단 얇은 바는 장바구니 **내용**이 아니라 2단계로 가는 **입구**다(대표 요청과 충돌 없음 — 다르게 보이면 바 없이 상단 장바구니 아이콘+개수로 대체 가능, PR 본문에 캡처로 비교).
- **화면 틀 통일**: `/store` 아래 모든 화면(홈·주문·장바구니·주문 확인·접수·배송 확인·주문 내역·매장 정보·구성원)이 같은 매장 셸을 쓴다 — 상단 바(뒤로·제목·매장 이름), 하단 탭 4개(홈 · 주문 · 주문 내역 · 내 매장), 같은 카드·버튼·여백 토큰. 새 디자인 시스템을 만들지 말고 기존 공통 컴포넌트 재사용. 화면별 차이 목록을 PR 본문에 표로.

## 구현 범위 (PR 나누기)

1. **PR1 셸 통일**: 매장 공통 셸(상단 바·하단 탭) 적용, 기존 화면 기능 변경 없음.
2. **PR2 주문 → 장바구니 → 주문 확인 → 접수**: 장바구니 상태는 같은 매장·같은 회사 범위에서만 유지(새로 고침해도 남게 — 브라우저 저장은 try/catch, 실패하면 메모리). 가격·합계는 서버 값만, 화면 계산 금지. 기존 주문 API 그대로 사용.
3. **PR3 배송 확인**: 접수 완료 화면 + 주문 상세 상태 단계. 주문 내역에서 진입.

라우트는 `/store?view=...` 확장이든 하위 경로든 기존 구조에 맞게 고르되, 기존 링크(`view=order`, `received=1`, 공개 단가표 → 주문)는 그대로 동작해야 한다.
