# CX-146 — 점주 휴대폰으로 매장 자동 연결 (2026-11-25 대표 결정)

## 대표 요구 (17:51)
매장별 링크를 보낼 필요가 없어야 한다. 고객사가 거래처(홍곱창 신촌점·강남점·의정부점)에 점주 휴대폰 010-…을 미리 넣어 두면, 점주가 **카카오로 로그인하는 순간 그 번호가 등록된 매장 전부에 연결**된다. 링크는 회사 공통 링크(기본 단가표·고객사 링크) 하나면 충분.

## 대표 결정
1. 첫 로그인 때 **한 번 확인 후 연결**: "홍곱창 신촌점·강남점·의정부점이 내 매장이 맞습니다" 한 번 → 모두 연결. 번호 오타로 남의 매장 가격이 보이는 것 방지. 아니라고 하면 연결하지 않고 고객사에 알림.
2. 미리 등록된 매장은 **국세청 확인 없이 바로 가격·주문**(고객사 보증). 사업자번호가 있으면 뒤에서 상태 조회만.
3. 거래처에 **'점주 휴대폰' 칸을 따로** 둔다(기존 연락처는 유선전화가 많음). 같은 번호를 여러 매장에 넣으면 한 번에 연결.

## 설계 요점 (구현 전 보고 후 진행)
- Owner Domain: organization(store account) / Related: customer(거래처 칸), lead(CX-142 연결)
- 카카오 휴대폰: 로그인 콜백에서 받은 번호(운영에서 카카오 사용자 3명 중 2명 번호 수신 확인)를 정규화(010xxxxxxxx). 지금은 app_users.phone을 **처음 생성 때만** 저장하므로 로그인마다 갱신 필요. 번호를 못 받으면(동의 안 함) 기존 초대 흐름으로 안내.
- 거래처 칸: normalized_customers에 owner_mobile(정규화·인덱스) 추가. 입력 화면은 거래처 원장 기본정보. 바꾸면 기존 연결은 그대로, 새 번호는 다음 로그인 때 매칭.
- 매칭: 같은 회사 여러 매장 + **여러 회사**도 가능(점주가 거래하는 고객사가 둘이면 둘 다). 연결 대상 = 같은 번호 · 활성 거래처 · 아직 그 사용자가 구성원이 아닌 매장.
- 연결 시: store_accounts 없으면 생성(business_status는 사업자번호 정상이면 active, 없으면 고객사 보증 상태 — 가격·주문 허용), 점주(owner)로 추가. 이미 다른 활성 점주가 있으면 자동 연결하지 않고 고객사에 "점주 확인 필요" 알림. 가격 공개는 system 확인(CX-142 finalize 재사용, source 구분 'phone_match'). 리드 연결도 finalize 재사용.
- 확인 화면: 매장 목록(상호·주소 일부) + [모두 맞음] / [아님]. 일부만 맞는 경우 체크 해제 가능.
- 여러 매장 전환: 매장 홈 상단 매장 선택(이미 storeAccountId 파라미터 구조 있음).
- 기록: store_account_member_events 'join' actor 'phone-match:<customer_id>', 확인 시각.
- 플래그: FEATURE_STORE_PHONE_LINK(기본 OFF, 대표 회사 allowlist).
- SQL 초안·down·PG17(service_role 호출 시나리오 포함). 번호 대조는 서버 전용 함수, 번호 원문은 로그·응답에 출력 금지(뒤 4자리만).

## 이것으로 대체되는 것
- CX-144 U2(사업자번호 없이 초대 가입), CX-145 C3(직원 초대 방식 매장 초대)는 이 기능으로 대체. 개별 초대 링크는 번호가 없는 매장용 예비 경로로만 남김.

## 완료 기준
고객사가 매장 2곳에 대표 휴대폰을 넣음 → 대표가 회사 링크로 카카오 로그인 → 확인 한 번 → 두 매장 홈에서 가격 보고 주문 1건.
