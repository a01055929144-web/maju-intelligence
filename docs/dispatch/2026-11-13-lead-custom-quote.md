## 2. 보내는 방식 · 통화 방식 (20:43 대표 결정)

- **보내는 곳: 카카오톡 1:1**(대표·영업 휴대폰에서 직접). 보낼 것 = **견적 링크 + 견적서 이미지(또는 PDF)**.
- **통화 방식**: 따로 "괜찮냐"고 허락을 받는 단계 없이, 인사하면서 **"견적서 카톡으로 보내드릴 테니 한번 보시고 연락 주세요"**라고 안내하고 보냄. 거절하면 안 보냄.
- 시스템 반영:
  - 통화 결과 버튼을 **`안내하고 보냄 예정`(기본) · `거절` · `안 받음` · `수신거부`** 4개로 단순화. `안내하고 보냄 예정`이면 바로 견적 서랍으로.
  - 기록은 `lead_actions`(`action_type='call'`, `result='quote_notice'`, `metadata={source_disclosed, notified_at}`) — 통화 때 안내했다는 기록이 남음.
  - **보내기 버튼이 잠기는 경우는 `거절`·`수신거부`·밤(21:00~08:00)뿐.**
- 컨트롤타워 참고(법률 자문 아님): 정보통신망법 제50조는 문자·메신저로 영리 광고를 보낼 때 **명시적 사전 동의**를 요구하고, 예외로 "연락처 출처를 육성으로 알리고 전화로 권유"하는 경우를 둠. 그래서 ① 통화 대본에 **연락처 출처 고지 줄**을 고정으로 넣고 ② 안내 문장을 **"…카톡으로 보내드려도 될까요? / 보내드릴게요, 괜찮으시죠?"처럼 대답을 듣는 말투**로 끝내 두면 기록상 안전함(대부분 "네"로 끝남 — 대표가 실제 쓰는 방식과 거의 같음). 카톡 메시지 끝에 **회사명·연락처·수신거부 방법** 한 줄은 고정. 최종 문구는 대표 확인.

## 4. 화면별 상세

### 4-1. 리드 목록 — "맞춤 견적" 대기열

- 리드 화면 대기열 카드에 **`맞춤 견적 N`**(010 있음 · 제외/폐업 아님 · 수신거부 아님).
- 표 열: 상호 · 업종 · 지역 · 개업일 · **통화**(안 함 / 안내함 날짜 / 거절) · 최근 연락 · 견적(없음/보냄/열람/수락).
- 정렬 기본: 6개월 내 개업 → 배송 가능 지역 → 업종(바구니 있는 업종 먼저).
- 배송 불가 지역(배송 권역 밖)은 회색 + "배송 권역 밖" — 견적 버튼 숨김.

### 4-2. ① 전화 — 리드 상세 오른쪽 패널

- `전화 걸기`(휴대폰 `tel:`, PC는 번호 크게 표시 + 복사).
- **통화 스크립트**(회사가 수정 가능, 출처 고지 줄은 고정):
  > 안녕하세요, ○○유통 △△입니다. 사장님 연락처는 [인허가 공개정보/카카오맵]에서 확인했습니다. 근처 매장에 식자재 배송하고 있는데, 사장님 매장에 맞춘 견적서를 카톡으로 보내드릴게요. 한번 보시고 편하실 때 연락 주세요. 괜찮으시죠?
  - 출처는 리드 원천(`gov_restaurant_api`·`seoul_opendata_api` → "인허가 공개정보", `kakao_keyword_search` → "카카오맵")에서 자동.
- 통화 후 **결과 기록**(한 번 누르기): **`안내하고 보냄 예정`(기본)** · `거절` · `안 받음`(2일 뒤 재시도 할 일) · `수신거부`(→ `company_do_not_contact` 등록, 이후 전화·보내기 숨김).
- `안내하고 보냄 예정`이면 바로 ③ 견적 서랍.

### 4-3. ② 통화 기록 (DB 변경 없음 — `lead_actions`)

- `action_type='call'`, `result='quote_notice'|'declined'|'no_answer'|'opt_out'`, `metadata={source_disclosed: true, notified_at, phone_last4}`, `actor_name`.
- 출처 고지 체크는 대본에 이미 들어 있으므로 기본 켜짐(끄면 저장 시 확인창 한 번).
- `거절`·`수신거부`는 이후 보내기 잠금. 나중에 매장이 먼저 연락하면 `다시 열기`(사유 입력).

### 4-4. ③ 맞춤 견적 서랍 (3단계, 휴대폰 우선)

**1단계 매장 정보**
- 업종(자동 `industry_primary`, 바꿀 수 있음) · 메뉴/주력(통화에서 들은 것, 짧게: "짬뽕·탕수육") · 규모(면적 있으면 자동, 없으면 `작음/보통/큼`) · 주문 횟수(주 1·2·3회+) · 배송 가능 요일(배송 판정에서 자동 표시).

**2단계 품목** (목표 15~30개)
- 자동 담기 순서: ① 업종 바구니(43b) ② 메뉴 키워드 → 상품 매칭(예: 짬뽕 → 오징어·홍합·양파·배추·고춧가루; 규칙은 `domains/pricing/quote-suggest.ts` 한 곳, 키워드→분류/상품명) ③ 같은 업종 거래처가 많이 산 품목(거래처가 쌓이면, 개별 매장 정보 노출 없이 집계만).
- 표(공용 표): 체크 · 품목 · 규격 · 기본 수량(주문 횟수·규모로 조절) · 판매가 · **주력** 별표(견적서 맨 위로).
- `+ 품목 추가`는 견적서 품목 고르기 그대로. 시세 품목은 "시세 · 오늘 기준 6,200원".
- 회사에게만 보이는 경고: 이익 낮음·손해 품목(CC-40 기준) 빨강.

**3단계 가격·조건**
- 가격 기준: 카탈로그 선택(기본 / "신규 매장" 등) → **서버 계산 결과만**. 화면 계산 없음.
- 첫 거래 혜택(선택): 없음 / 첫 주문 n% / 첫 주문 배송비 무료 — **행사(CC-34) 대상 = 이 리드가 거래처가 되면**으로 연결하지 않고, 1단계는 견적서 문구로만 표시(실제 할인은 첫 주문 때 수동 — 돈이 오가는 자동 혜택은 별도 승인).
- 유효기간 기본 **3일**(농·수산 시세), 공산품만이면 7일.
- 미리보기: 품목 수 · 예상 1회 주문 금액(수량×단가, 시세 제외) · 배송 요일·마감.

### 4-5. ④ 견적서 (지금 편집기 그대로 + 맞춤 머리말)

- 제목 "○○ 사장님 매장 맞춤 견적" · 받는 곳 = 리드 상호(거래처 아님 표시).
- 맨 위 3줄: 업종·주력 메뉴 맞춤 문구, 배송 요일·마감, "링크에서 바로 주문(카카오 로그인)".
- 주력 품목 → 나머지(분류순). 시세 품목 안내 줄. 회사 소개·연락처는 인쇄 기본값.
- 발행 = 그때 가격 고정(지금 규칙).

### 4-6. ⑤ 카톡 1:1 보내기 (이미지/PDF + 링크)

- 잠기는 경우만: **`거절`·`수신거부` 기록 · 21:00~08:00**. 그 외엔 켜짐(통화 기록이 없으면 "통화 기록 없이 보냄" 확인창 한 번).
- **휴대폰**: `카톡으로 보내기` → 휴대폰 공유 창(`navigator.share`, 파일 공유 지원 시)에 **견적서 이미지 + 문구(링크 포함)** → 카카오톡 선택 → 매장 사장님 대화방.
  - 이미지: 지금 견적서 "이미지 저장"(`html-to-image`, `pricing-document-preview.tsx` 247줄) 재사용. 품목이 많으면 **20줄씩 여러 장**(1/2, 2/2)으로 나눔.
  - 파일 공유가 안 되는 휴대폰: 이미지 저장 + 문구 복사 → 카톡에서 붙이기 안내.
  - 카톡 친구가 아닐 수 있음 → 버튼 아래 작은 안내 "번호 저장 후 카톡 친구 목록에서 찾기" + `번호 복사`.
- **PC**: `이미지 내려받기`·`PDF 저장`(지금 인쇄 → PDF) + `문구 복사` → PC 카톡에 붙이기.
- 문구 템플릿 3개(회사 수정 가능, 끝 줄 고정):
  1. 짧게: "{상호} 사장님, 방금 통화드린 {회사명}입니다. 매장에 맞춘 견적서 보내드립니다. 한번 보시고 편하실 때 연락 주세요. {링크}"
  2. 첫 거래 혜택: "… 첫 주문은 {혜택}입니다. {링크}"
  3. 주력 메뉴: "… {주력} 위주로 {N}개 품목 구성했습니다(가격 {유효기간}까지). {링크}"
  - 고정 끝줄: "{회사명} {대표전화} · 받지 않으시려면 '수신거부'라고 답장 주세요"(회사 설정에서 방법 변경 가능).
- 링크 = 리드 공유 링크(열람 기록됨). 이미지에는 링크 QR 작게(휴대폰 사진으로 저장해 둬도 주문으로 연결).
- 보내기 누르면 `lead_actions`에 `action_type='quote'`, `metadata={document_id, version_id, share_link_id, channel:'kakao_share'|'copy'|'pdf', template, image_pages}` + 리드 상태 `견적 발송`. (실제로 카톡에서 보냈는지는 앱이 알 수 없음 → "보냈어요" 확인 한 번.)

### 4-7. ⑥ 후속 (있는 리마인드 재사용)

- 링크 첫 열람 → 담당자 알림(기존 열람 이벤트) + 타임라인 "열람".
- 보낸 뒤 2일 미열람 → 할 일 "견적 열람 확인 전화" · 열람 후 3일 미수락 → "견적 후속 전화".
- 유효기간 지나면 견적서에 "가격 다시 확인" 표시, `새 가격으로 다시 보내기`(새 버전, 거절 기록 없으면 바로).

### 4-8. ⑦ 수락 → 거래 시작 (있는 흐름)

- 수락 = 첫 거래 확인 대기(CX-13) → 확인하면 거래처 생성 + **견적에 쓴 카탈로그를 매장 카탈로그로 지정** + 매장 카카오 개통 초대 링크.
- 리드 상태 `거래 시작`, 퍼널에 반영.

## 5. 업종 바구니 (43b, DB)

- 설정 › 판매 › **업종별 기본 품목**: 업종 9개(한식·중식·일식·양식·분식·카페/디저트·주점·치킨/고깃집·기타) × 품목·기본 수량·주력 여부.
- **처음 채우기 도우미**: 분류·상품명 규칙으로 업종별 후보 40개 제안 → 대표가 체크 저장(자동 확정 없음). 예: 중식 = 양파·대파·배추·춘장·식용유·밀가루·전분·오징어·홍합·고춧가루…
- 견적을 보낼수록 "자주 넣은 품목" 위로(집계만).
- 테이블 `company_industry_baskets(company_id, industry_key, product_catalog_id, default_qty, is_core, sort_order, updated_by, updated_at)` PK(company_id, industry_key, product_catalog_id), 숨김 상품 FK 유지·화면 제외, service_role만, 감사 기록.

## 6. 지표 (43c)

리드 화면 위 한 줄: **대상 100 → 통화 N → 안내 N → 발송 N → 열람 N → 수락 N → 첫 주문 N**(이번 주/이번 달). 업종별 수락률.

## 7. 권한·개인정보

- 전화·통화 기록·보내기: 대표·관리자·리드 담당 영업. 전체 번호 표시도 같은 범위(지금 리드 권한).
- 통화 기록은 리드 삭제 시 함께 보관 기간(1년) 뒤 정리 — 개인정보 처리 방침 문구는 대표 확인.
- 견적서 링크·이미지에 매장 전화번호를 넣지 않음.
