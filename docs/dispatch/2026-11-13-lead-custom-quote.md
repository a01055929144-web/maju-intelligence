### 4-4. ① 맞춤 견적 서랍 (3단계, 휴대폰 우선)

**1단계 매장 정보**
- 업종(자동 `industry_primary`, 바꿀 수 있음) · 메뉴/주력(선택 — 카카오맵·간판·리뷰에서 본 것, 짧게: "짬뽕·탕수육". 비우면 업종 바구니만) · 규모(면적 있으면 자동, 없으면 `작음/보통/큼`) · 주문 횟수(주 1·2·3회+) · 배송 가능 요일(배송 판정에서 자동 표시).

**2단계 품목** (목표 15~30개)
- 자동 담기 순서: ① 업종 바구니(43b) ② 메뉴 키워드 → 상품 매칭(예: 짬뽕 → 오징어·홍합·양파·배추·고춧가루; 규칙은 `domains/pricing/quote-suggest.ts` 한 곳, 키워드→분류/상품명) ③ 같은 업종 거래처가 많이 산 품목(거래처가 쌓이면, 개별 매장 정보 노출 없이 집계만).
- 표(공용 표): 체크 · 품목 · 규격 · 기본 수량(주문 횟수·규모로 조절) · 판매가 · **주력** 별표(견적서 맨 위로).
- `+ 품목 추가`는 견적서 품목 고르기 그대로. 시세 품목은 "시세 · 오늘 기준 6,200원".
- 회사에게만 보이는 경고: 이익 낮음·손해 품목(CC-40 기준) 빨강.

**3단계 가격·조건**
- 가격 기준: 카탈로그 선택(기본 / "신규 매장" 등) → **서버 계산 결과만**. 화면 계산 없음.
- 첫 거래 혜택(선택): 없음 / 첫 주문 n% / 첫 주문 배송비 무료 — **행사(CC-34) 대상 = 이 리드가 거래처가 되면**으로 연결하지 않고, 1단계는 견적서 문구로만 표시(실제 할인은 첫 주문 때 수동 — 돈이 오가는 자동 혜택은 별도 승인).
- 유효기간 기본 **3일**(농·수산 시세), 공산품만이면 7일.
- 미리보기: 품목 수 · 예상 1회 주문 금액(수량×단가, 시세 제외) · 배송 요일·마감.

### 4-5. ② 견적서 (지금 편집기 그대로 + 맞춤 머리말)

- 제목 "○○ 사장님 매장 맞춤 견적" · 받는 곳 = 리드 상호(거래처 아님 표시).
- 맨 위 3줄: 업종·주력 메뉴 맞춤 문구, 배송 요일·마감, "링크에서 바로 주문(카카오 로그인)".
- 주력 품목 → 나머지(분류순). 시세 품목 안내 줄. 회사 소개·연락처는 인쇄 기본값.
- 발행 = 그때 가격 고정(지금 규칙).

### 4-6. ③ 카톡 1:1 보내기 (링크 + 이미지/PDF)

- 잠기는 경우만: **`거절`·`수신거부` 기록 · 21:00~08:00**. 오늘 보낸 수가 20건을 넘으면 경고(계정 제한 위험 안내, 막지는 않음).
- **핵심은 진짜 링크**(20:48 대표): 카톡방에서 바로 눌러 들어가게 **링크를 문구 맨 위 줄에** 넣음. QR은 이미지 안에 보조로만.
- **휴대폰**: 두 번에 나눠 보냄(카카오톡은 공유 창에 이미지와 글을 함께 넘기면 글을 버리는 경우가 있음 — 링크가 빠지면 안 되므로).
  1. `① 링크·문구 보내기` → 공유 창(`navigator.share({text})`) → 카카오톡 → 사장님 대화방. **링크 미리보기 카드**가 뜸(아래).
  2. `② 견적서 이미지 보내기` → 공유 창(`navigator.share({files})`) → 같은 대화방. 이미지는 지금 "이미지 저장"(`html-to-image`, `pricing-document-preview.tsx` 247줄) 재사용, 품목 많으면 **20줄씩 여러 장**.
  - 파일 공유가 안 되는 휴대폰: 이미지 저장 → 카톡에서 사진 보내기 안내.
  - 카톡 친구가 아닐 수 있음 → 버튼 아래 "번호 저장 후 카톡 친구 목록에서 찾기" + `번호 복사`.
- **PC**: `문구 복사`(링크 포함) · `이미지 내려받기` · `PDF 저장`(지금 인쇄 → PDF) → PC 카톡에 붙이기.
- **링크 미리보기 카드**(카톡에서 링크 아래 뜨는 제목·설명·그림): 지금 공유 링크는 `/pricing-document#토큰`이라 서버가 어느 문서인지 몰라 **"공유 문서"로만 보임**. 맞춤 견적 링크는 `/q/{미리보기ID}#{토큰}` 형식으로:
  - `미리보기ID`(무작위 128비트, 접근 권한 없음)로 서버가 **제목 "○○ 사장님 맞춤 견적 · {회사명}"·설명 "{N}개 품목 · {유효기간}까지"·그림(회사 로고 또는 견적서 첫 장 축소)**만 만들어 줌. 가격·품목 내용·번호는 미리보기에 넣지 않음.
  - 실제 열람·주문 권한은 지금처럼 `#토큰`(서버 로그·리퍼러에 안 남음). 미리보기ID만으로는 문서를 못 봄.
  - 미리보기 정보 저장: 공유 링크 행에 `preview_id`·`preview_title`·`preview_description` 열 추가 → **43b SQL 초안에 포함**(43a는 지금 링크 형식으로 먼저, 카드 제목만 일반 "견적서가 도착했습니다 · {회사명}"은 불가하므로 "공유 문서" 그대로).
- 문구 템플릿 3개(회사 수정 가능, 끝 줄 고정):
  1. 기본(인사): "{링크}\n안녕하세요 {상호} 사장님, {지역}에서 식자재 배송하는 {회사명} {담당자}입니다. 사장님 매장에 맞춰 견적서 만들어 보내드립니다. 한번 보시고 편하실 때 연락 주세요."
  2. 첫 거래 혜택: "{링크}\n… 첫 주문은 {혜택}입니다."
  3. 주력 메뉴: "{링크}\n… {주력} 위주로 {N}개 품목 구성했습니다(가격 {유효기간}까지)."
  - 고정 끝줄: "{회사명} {대표전화} · 받지 않으시려면 '수신거부'라고 답장 주세요"(회사 설정에서 방법 변경 가능).
- 링크 = 리드 공유 링크(열람 기록됨). 이미지에는 같은 링크 QR을 작게(보조).
- 보내기 누르면 `lead_actions`에 `action_type='quote'`, `metadata={document_id, version_id, share_link_id, channel:'kakao_share'|'copy'|'pdf', template, image_pages}` + 리드 상태 `견적 발송`. (실제로 카톡에서 보냈는지는 앱이 알 수 없음 → "보냈어요" 확인 한 번.)

### 4-7. ④ 반응 기록 · ⑤ 후속 (있는 리마인드 재사용)

- 리드 상세에 버튼: `답장 옴`(메모) · `관심 없음`(=거절, 보내기 잠금) · `수신거부`(→ `company_do_not_contact`, 영구 잠금). 기록은 `lead_actions`(`action_type='kakao_reply'`, `result`).
- 매장이 링크를 열면 자동으로 "열람"(답장 없어도 반응 확인 가능).

- 링크 첫 열람 → 담당자 알림(기존 열람 이벤트) + 타임라인 "열람".
- 보낸 뒤 2일 미열람 → 할 일 "견적 다시 보내기(짧은 안부)" · 열람 후 3일 미수락 → "후속 메시지"(템플릿: 궁금한 품목·첫 주문 안내). 후속도 같은 잠금 규칙.
- 유효기간 지나면 견적서에 "가격 다시 확인" 표시, `새 가격으로 다시 보내기`(새 버전, 거절 기록 없으면 바로).

### 4-8. ⑥ 수락 → 거래 시작 (있는 흐름)

- 수락 = 첫 거래 확인 대기(CX-13) → 확인하면 거래처 생성 + **견적에 쓴 카탈로그를 매장 카탈로그로 지정** + 매장 카카오 개통 초대 링크.
- 리드 상태 `거래 시작`, 퍼널에 반영.

## 5. 업종 바구니 (43b, DB)

- 설정 › 판매 › **업종별 기본 품목**: 업종 9개(한식·중식·일식·양식·분식·카페/디저트·주점·치킨/고깃집·기타) × 품목·기본 수량·주력 여부.
- **처음 채우기 도우미**: 분류·상품명 규칙으로 업종별 후보 40개 제안 → 대표가 체크 저장(자동 확정 없음). 예: 중식 = 양파·대파·배추·춘장·식용유·밀가루·전분·오징어·홍합·고춧가루…
- 견적을 보낼수록 "자주 넣은 품목" 위로(집계만).
- 테이블 `company_industry_baskets(company_id, industry_key, product_catalog_id, default_qty, is_core, sort_order, updated_by, updated_at)` PK(company_id, industry_key, product_catalog_id), 숨김 상품 FK 유지·화면 제외, service_role만, 감사 기록.

## 6. 지표 (43c)
