## 2. ⚠️ 먼저 지킬 것 — 문자 견적은 "동의 받은 곳"에만

- 정보통신망법 제50조: 문자 같은 전자적 전송매체로 **영리 목적 광고성 정보**를 보내려면 **수신자의 명시적 사전 동의**가 필요. 예외는 ① 거래하면서 직접 연락처를 받은 경우(같은 종류 재화) ② 전화권유판매자가 **개인정보 수집 출처를 육성으로 알리고 전화로 권유**하는 경우. 오후 9시~오전 8시는 별도 동의 필요. 보낼 때 **보낸 사람 이름·연락처, 수신거부 방법** 표시.
- 처음 연락하는 리드에게 견적서를 문자로 먼저 보내는 것은 광고성 정보로 볼 수 있음 → **(11/13 20:29 지시서의 "(광고) 표기만 하고 보내기"는 부족 — 이 설계로 바꿈.)**
- 그래서 흐름은 **① 전화(출처 알림) → ② "견적 문자로 받아보시겠어요?" 동의 → ③ 동의 기록 → ④ 문자 보내기**. 동의 기록이 없으면 보내기 버튼이 잠김.
- 동의가 있어도 문자 끝에 보낸 회사·연락처·수신거부 방법은 넣음. 21:00~08:00 보내기 잠금(야간 동의 따로 받은 경우만 예외 — 1단계에서는 그냥 잠금).
- 컨트롤타워는 법률 자문이 아님 — 통화 문구·문자 문구 최종본은 대표 확인(필요하면 전문가 확인).

## 4. 화면별 상세

### 4-1. 리드 목록 — "맞춤 견적" 대기열

- 리드 화면 대기열 카드에 **`맞춤 견적 N`**(010 있음 · 제외/폐업 아님 · 수신거부 아님).
- 표 열: 상호 · 업종 · 지역 · 개업일 · **동의**(없음 / 동의함 날짜 / 거부) · 최근 연락 · 견적(없음/보냄/열람/수락).
- 정렬 기본: 6개월 내 개업 → 배송 가능 지역 → 업종(바구니 있는 업종 먼저).
- 배송 불가 지역(배송 권역 밖)은 회색 + "배송 권역 밖" — 견적 버튼 숨김.

### 4-2. ① 전화 — 리드 상세 오른쪽 패널

- `전화 걸기`(휴대폰 `tel:`, PC는 번호 크게 표시 + 복사).
- **통화 스크립트**(회사가 수정 가능, 출처 고지 줄은 고정):
  > 안녕하세요, ○○유통 △△입니다. 사장님 연락처는 [인허가 공개정보/카카오맵]에서 확인했습니다. 근처 매장에 식자재 배송하고 있는데, 사장님 매장에 맞춰 견적서를 문자로 한 번 보내드려도 될까요?
  - 출처는 리드 원천(`gov_restaurant_api`·`seoul_opendata_api` → "인허가 공개정보", `kakao_keyword_search` → "카카오맵")에서 자동.
- 통화 후 **결과 기록**(한 번 누르기): `안 받음`(2일 뒤 재시도 할 일) · `관심 없음` · `수신거부`(→ `company_do_not_contact` 등록, 이후 전화·문자 버튼 숨김) · **`견적 원함`**.
- `견적 원함`이면 같은 창에서 ②로.

### 4-3. ② 동의 기록 (DB 변경 없음 — `lead_actions`)

- `action_type='consent'`, `result='granted'`, `metadata = {method: 'call'|'visit'|'store_request'|'sms_reply', scope: 'quote', phone_last4, source_disclosed: true, night_consent: false}`, `actor_name`, `created_at`.
- 화면: 방법(기본 전화) · 받을 번호 확인(뒤 4자리 표시, 다르면 새 번호 입력 → 리드 연락처에 추가) · "통화에서 출처를 알렸습니다" 체크(전화일 때 필수).
- 철회: `수신 동의 철회` → 같은 행 `voided_at`·`void_reason` + 수신거부 등록.
- 동의는 **같은 리드·같은 번호·범위 quote**에만 유효. 1년 지나면 다시 받기(표시만).

### 4-4. ③ 맞춤 견적 서랍 (3단계, 휴대폰 우선)

**1단계 매장 정보**
- 업종(자동 `industry_primary`, 바꿀 수 있음) · 메뉴/주력(통화에서 들은 것, 짧게: "짬뽕·탕수육") · 규모(면적 있으면 자동, 없으면 `작음/보통/큼`) · 주문 횟수(주 1·2·3회+) · 배송 가능 요일(배송 판정에서 자동 표시).

**2단계 품목** (목표 15~30개)
- 자동 담기 순서: ① 업종 바구니(43b) ② 메뉴 키워드 → 상품 매칭(예: 짬뽕 → 오징어·홍합·양파·배추·고춧가루; 규칙은 `domains/pricing/quote-suggest.ts` 한 곳, 키워드→분류/상품명) ③ 같은 업종 거래처가 많이 산 품목(거래처가 쌓이면, 개별 매장 정보 노출 없이 집계만).
- 표(공용 표): 체크 · 품목 · 규격 · 기본 수량(주문 횟수·규모로 조절) · 판매가 · **주력** 별표(견적서 맨 위로).
- `+ 품목 추가`는 견적서 품목 고르기 그대로. 시세 품목은 "시세 · 오늘 기준 6,200원".
- 회사에게만 보이는 경고: 이익 낮음·손해 품목(CC-40 기준) 빨강.

**3단계 가격·조건**
- 가격 기준: 카탈로그 선택(기본 / "신규 매장" 등) → **서버 계산 결과만**. 화면 계산 없음.
- 첫 거래 혜택(선택): 없음 / 첫 주문 n% / 첫 주문 배송비 무료 — **행사(CC-34) 대상 = 이 리드가 거래처가 되면**으로 연결하지 않고, 1단계는 견적서 문구로만 표시(실제 할인은 첫 주문 때 수동 — 돈이 오가는 자동 혜택은 별도 승인).
- 유효기간 기본 **3일**(농·수산 시세), 공산품만이면 7일.
- 미리보기: 품목 수 · 예상 1회 주문 금액(수량×단가, 시세 제외) · 배송 요일·마감.

### 4-5. ④ 견적서 (지금 편집기 그대로 + 맞춤 머리말)

- 제목 "○○ 사장님 매장 맞춤 견적" · 받는 곳 = 리드 상호(거래처 아님 표시).
- 맨 위 3줄: 업종·주력 메뉴 맞춤 문구, 배송 요일·마감, "링크에서 바로 주문(카카오 로그인)".
- 주력 품목 → 나머지(분류순). 시세 품목 안내 줄. 회사 소개·연락처는 인쇄 기본값.
- 발행 = 그때 가격 고정(지금 규칙).

### 4-6. ⑤ 1:1 보내기

- 조건 3개 모두 맞아야 버튼 켜짐: **동의 기록 있음 · 수신거부 아님 · 08:00~21:00**. 아니면 이유를 버튼 아래에 표시.
- `문자 앱으로 열기`(휴대폰: `sms:번호?body=…`) · `문구 복사`(카카오톡 등). 단체·자동 발송 없음.
- 문구 템플릿 3개(회사 수정 가능, 끝 두 줄 고정):
  1. 짧게: "{상호} 사장님, 통화드린 {회사명}입니다. 매장에 맞춘 견적서 보내드립니다(3일 유효). {링크}"
  2. 첫 거래 혜택: "… 첫 주문은 {혜택}. {링크}"
  3. 정중: "… 주력 메뉴({주력})에 맞춰 {N}개 품목으로 구성했습니다. 편하실 때 확인 부탁드립니다. {링크}"
  - 고정 끝줄: "{회사명} {대표전화}" · "수신거부: {수신거부 방법}" (회사 설정의 수신거부 번호/링크).
- 보내기 누르면 `lead_actions`에 `action_type='quote'`(이미 있는 유형), `metadata={document_id, version_id, share_link_id, channel:'sms'|'copy', template}` + 리드 상태 `견적 발송`.

### 4-7. ⑥ 후속 (있는 리마인드 재사용)

- 링크 첫 열람 → 담당자 알림(기존 열람 이벤트) + 타임라인 "열람".
- 보낸 뒤 2일 미열람 → 할 일 "견적 열람 확인 전화" · 열람 후 3일 미수락 → "견적 후속 전화".
- 유효기간 지나면 견적서에 "가격 다시 확인" 표시, `새 가격으로 다시 보내기`(새 버전, 동의 그대로면 바로).

### 4-8. ⑦ 수락 → 거래 시작 (있는 흐름)

- 수락 = 첫 거래 확인 대기(CX-13) → 확인하면 거래처 생성 + **견적에 쓴 카탈로그를 매장 카탈로그로 지정** + 매장 카카오 개통 초대 링크.
- 리드 상태 `거래 시작`, 퍼널에 반영.

## 5. 업종 바구니 (43b, DB)

- 설정 › 판매 › **업종별 기본 품목**: 업종 9개(한식·중식·일식·양식·분식·카페/디저트·주점·치킨/고깃집·기타) × 품목·기본 수량·주력 여부.
