# CX-150 — 고객사 PC 자동 업로드 에이전트 (매입가 · 오늘 갈 곳) — 설계 먼저 (2026-11-25 대표 결정)

## 대표 결정
- 매입가(⑤)와 오늘 갈 곳(⑥ TMS)을 **고객사 PC에서 자동으로** 올린다. 이카운트처럼 브라우저형 ERP는 아이디·비밀번호만 있으면 고객사 PC가 접속해 내려받아 MAJU에 업로드.
- 매입가 활용은 기존 결정대로(동의 절차 없음, **매장 노출 절대 금지**).

## 설계 원칙 (변경 불가)
1. **비밀번호는 고객사 PC 밖으로 나가지 않는다.** OS 보안 저장소(Windows 자격 증명 관리자 / macOS 키체인)에만. MAJU 서버·로그·PR·화면 어디에도 저장·전송 금지.
2. 업로드는 **회사별 업로드 키**(MAJU에서 발급·회수·만료, 해시 저장)로만. 키로는 "업로드"만 가능, 읽기 불가.
3. 서버 입구는 **기존 매입 업로드(CX-138)와 같은 파이프라인**: 에이전트는 ERP에서 내려받은 엑셀/CSV를 그대로 올리고, 열 인식·단위 정규화(대문자)·품목 매칭은 서버가 한다. 오늘 갈 곳도 같은 입구(파일 종류만 다름).
4. 실패해도 조용히 틀리지 않는다: 업로드마다 원본 파일 보관, 결과(행 수·매칭률·오류)를 고객사 화면에 표시, 연속 실패 시 알림.
5. ERP 화면이 바뀌면 깨질 수 있음 → ERP별 "수집 스크립트"를 분리하고 버전 관리, 깨지면 수동 업로드 안내로 자동 전환.

## 1차 범위 (시범: 대표 회사 · 이카운트)
- 에이전트: Windows 우선. 형태 비교 후 제안(① 작은 데스크톱 앱(Electron/Tauri) + 브라우저 자동화(Playwright) ② 스케줄러로 도는 스크립트 + 설치 도우미). 설치·업데이트·로그 보기·지금 실행·예약(예: 매일 06:00 매입가, 05:30 오늘 갈 곳).
- 수집: 이카운트 로그인 → 매입 현황(기간) 엑셀 내려받기 / 출고·배송 목록 내려받기 → 업로드.
- 서버: `/api/agent/uploads` (업로드 키 인증, 파일 크기 제한, 서명 업로드 4.5MB 우회 방식 재사용), 업로드 이력 표.
- 고객사 화면: [자동 업로드] 설정 — 키 발급·회수, 마지막 성공 시각, 최근 결과.
- 기사 화면: 오늘 갈 곳 업로드 결과가 오늘 코스 목록으로 바로 보이게(기존 오늘 코스 재사용).

## 먼저 보고할 것 (구현 전)
- 에이전트 형태 비교(설치·자동 업데이트·코드 서명 인증서 비용·백신 오탐·유지보수), 1인 유지보수 관점 추천.
- 이카운트 약관상 자동 접속 제한 여부와 공식 OpenAPI로 대체 가능한 범위(가능하면 API가 우선, 안 되는 부분만 화면 자동화).
- 서버 쪽 DB 변경(업로드 키·업로드 이력) 초안 목록.

## Do Not Touch
가격 계산(self_order_price_v2), 매장 화면에 매입가 노출 경로, 기존 수동 업로드 동작(그대로 유지).

## 순서
