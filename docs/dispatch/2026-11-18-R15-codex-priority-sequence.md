## 공통 파일 잠금과 병합 규칙

- **총괄방 전용**: `docs/dispatch/*` 현황판·새 지시서·중앙 체크리스트. 기능 PR에 섞지 않는다. 기존 #1085의 `docs/dispatch/2026-11-18-R13-decisions.md` 변경은 03 PR에서 제외하고 총괄방 기록으로 이관한다.
- **03 전용**: `lib/store.ts` 및 메뉴 파일. 다른 방은 필요한 호출 한 줄과 이유를 03방에 요청한다.
- **09 전용**: `components/storefront-workspace.tsx`, 공개 문서→주문 화면. #1054·CX-74·CX-101 주문 완료 연결은 **09가 차례로**.
- **공유 순차**: `.github/workflows/ci.yml`은 기존 실행 줄을 보존하고 줄 추가만. `lib/feature-flags.ts`, `docs/backend/01_SCHEMA.md`는 먼저 병합한 PR 기준으로 다음 PR을 다시 맞춘다. #1073·#1086·#1077·#1063·#1090과 #1065·#1066은 이 순차 규칙 대상이다.
- 지도 파일의 Claude Code 소유 여부는 R2 지시서·현황판에서 재확인. 소유 해제 전 CX-111 코드 금지.
- PR 제목 `[CX-NN]`, 본문 첫 줄 `Ponytail: 사용함`(코드). 바뀐 화면, 와이어프레임 차이, 확인 못 한 점, 기존 기능 유지 표, 기본 플래그, 돈 안전 표(주문·전표·입금)를 적는다.
- PR 전 `git fetch`·최신 main 재배치, CI(build·tsc·vitest·auth-boundary·관련 PG17) 초록. 화면 PR은 1440/390 Playwright·가로 스크롤 0. 실패는 원인을 먼저 PR에 남기고 수정한다.
- 운영 DB는 SQL 초안·down·PG17·승인표까지만. 대표의 **프로젝트를 명시한 승인** 뒤 현황판 적용 잠금 → 적용 → 단계별 읽기 검증. 기능 ON·운영 배포도 별도 지시가 있어야 한다. 실데이터 자동 보정, 단체 발송, 스크래핑 금지.
