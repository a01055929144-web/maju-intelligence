# CC-36 매장 링크 "전체 상품" (카탈로그 가격) + 시세 품목 오늘 기준가·지난 출고가 (2026-11-13 16:46 대표)

> 컨트롤타워 설계 · 담당 Claude Code. Owner `pricing`(가격) · `store`(주문 화면). **원칙: 새 화면을 만들지 않고 있는 틀을 재사용, 구조(무엇을 어떤 순서로 보여 줄지)만 새로.** 선행: CC-32b(카탈로그 가격 계산).

## 대표 요청

- "링크 주문에서 단가표·견적서도 있지만 **전체 상품 매출가**도 있어야 할 것 같아."
- "당일 매입해서 출고한 판매가도 있으면 매장 입장에서 확인하기 좋을 것 같다."
- "공통 틀을 재사용하고 구조화만 보여 주게끔 만들면 빠른 개발이 되겠지?" → 예.

## 지금 (11/13 운영·코드 확인)

- 매장 링크(`storefront_links`)는 **발행한 문서 버전 1개**(`document_version_id` NOT NULL)에 묶임. 매장이 보는 품목 = 그 문서 줄뿐 (`lib/pricing/storefront.ts` `readStorefront`).
- 주문 RPC `place_store_order`·`place_store_member_order`도 그 버전의 `showPrice`·`validUntil`·줄 기준으로 검증 → **전체 상품 주문은 DB 함수 변경이 필요**(승인 건).
- 시세 품목(`order_pricing_mode='market'`)은 "가격 미정 · 싯가·경매가에 따라 달라질 수 있습니다"만 표시.
- 매장 화면 PC(1440·1920)·모바일(390) 틀, 카드/표 전환, 장바구니·배송일·내역은 이미 있음(e2e `store-shell`, `store-member-journey`).

## 화면 구조 (바뀌는 것은 이것뿐)

1. 매장 주문 탭 맨 위 전환: **`받은 단가표 | 전체 상품`** (전체 상품 링크가 있는 매장만 보임). 기본은 마지막에 쓴 쪽.
2. 전체 상품: 왼쪽 분류(PC) / 위 분류 칩(모바일) · 검색 · 즐겨찾기 먼저 · 카드/표 전환. 가격 옆 출처 작은 글씨는 **매장에는 안 보임**(내부 용어 노출 금지), 행사만 배지.
3. **시세 품목 줄**(market):
   - `오늘 기준가 6,200원` — 오늘 날짜 매입가가 있을 때만(`purchase_price_date = 오늘`) 그 매장 카탈로그 가격. 없으면 표시 안 함.
   - `지난 출고 11/12 · 5,800원` — **이 매장**의 최근 확정 주문 줄 단가(`store_order_lines`, 이 매장 것만). 다른 매장 가격은 절대 안 보임.
   - 아래 작은 글씨: 지금 문구 "싯가·경매가에 따라 달라질 수 있습니다" 유지. 주문 금액 합계는 지금처럼 "+ 시세 품목 가격 미정".
4. 회사 쪽 링크 관리: 발급할 때 `문서 링크 | 전체 상품 링크` 선택. 전체 상품 링크는 문서·버전 선택 없음, 유효기간만(기본 1년). 목록에 종류 열.
5. 같은 화면 틀이라 PC 왼쪽 메뉴·모바일 아래 메뉴 변경 없음.

## DB (SQL 초안 → 컨트롤타워 검토 → 대표 승인)

- `storefront_links`: `source text not null default 'document' check (source in ('document','catalog'))`, `document_version_id`는 `source='document'`일 때만 필수(체크로).
- 주문: 기존 문서 경로는 **한 줄도 바꾸지 않음**. 전체 상품용 `place_store_catalog_order_v1`(+ member 판)을 새로 두되, 배송일·마감·최소금액·멱등·수정(revision) 검증은 **기존 함수에서 공용 내부 함수로 뽑아 둘 다 호출**(복사 금지). 줄 가격은 서버에서 `margin_template_price_v1` 재계산(요청 단가 무시, CC-29b 교훈), 판매 중 상품만, 행사 한도 동일.
- 감사: 링크 발급 `admin_audit_logs`(지금 문서 링크와 같은 action에 `source` 메타).
- down: catalog 링크나 그 주문이 있으면 거부.
- PG17: 문서 링크 기존 테스트 전부 통과 · catalog 링크 주문 가격 = 서버 계산 · 다른 회사 상품 거부 · 판매 중지 상품 거부 · 시세 품목 단가 null.

## 스위치

`STORE_CATALOG_LINK` 기본 OFF, 회사 allowlist(첫 대상 제이에스리테일). 다른 회사 켜기는 대표 승인.

## 순서

1. **CC-36a** 읽기 화면: 링크 없이도 시험할 수 있게 "받은 단가표 | 전체 상품" 전환 + 전체 상품 목록(가격 = 서버 함수, 주문 버튼은 '준비 중') + 시세 품목 오늘 기준가·지난 출고가. DB 없음.
2. **CC-36b** SQL 초안(링크 source + catalog 주문 RPC + 공용 검증 함수) → 컨트롤타워 검토 → 대표 승인 → 적용.
3. **CC-36c** 링크 관리 "전체 상품 링크" 발급 + 주문 연결 + e2e.
