## CX-65 기사 빈 화면 (01) — 와이어 "기사" 캔버스
1. **문제 품목**(⑯-2): 배송지 카드에서 품목별 [정상 / 파손 / 누락 / 오배송] 템플릿을 고르고 사진(선택) · 메모를 남깁니다.
   - 고객사 주문 확인 · 매장 주문 내역에 "문제 n건"으로 보입니다.
   - **금액 차감(전표 수정)은 하지 않습니다.** 고객사가 주문 상세(CX-67)에서 처리합니다.
2. CC-66에서 남은 것
   - 운행 시작 때 **화면 꺼짐 방지**(`navigator.wakeLock`, 안 되는 기기는 안내만)
   - 완료 · 전달 못 함 뒤 **5초 되돌리기** 알림
   - 대기 배송지 **길게 눌러 순서 바꾸기**(경로 확정 전에만)
   - 사진 "필수 1장" 여부는 회사 설정값으로 둡니다(기본: 선택)
   - 운행 종료 뒤 **오늘 요약**(완료 · 전달 못 함 · 영업 · 사진 수)
3. "+n분"(가는 길 영업 칸의 추가 시간)은 저장할 칸이 없습니다. SQL 초안을 따로 내고 운영 적용은 승인 뒤 합니다.
- 시험: 390 e2e(밀기 · 일반 버튼 · 키보드), 되돌리기 시간 경계, 순서 바꾸기 뒤 정류장 순서 저장.

## CX-66 출고 준비 · 선주문 집계 · 인쇄 3종 (06) — 와이어 "주문 · 출고" 캔버스(⑨-2 · ⑩ · ⑩-0 · ⑩-1~3)
1. **선주문 집계**(⑨-2): 배송일 · 권역 · 호차별로 접수된 주문 품목 수량을 합칩니다(공용 표 · 합계 줄).
2. **출고 준비**(⑩): 주문 → 발주 → 입고 → 출고 단계를 한 화면에서 봅니다.
   - 상품의 재고 방식(재고 / 사입 / 시세 — 와이어 5절 메모)에 따라 줄을 나눕니다. 사입 · 시세는 발주 대상입니다.
   - **읽기 · 인쇄 먼저.** "출고 확정" 버튼은 대표 결정 1 이후에 붙입니다. 화면에는 자리만 두고 꺼 둡니다.
3. **인쇄 3종**(A4, 흑백 인쇄 가능, 기존 인쇄 부품 사용)
   - 사입표: 매입처별 · 품목별 수량
   - 피킹표: 창고 동선 순 · 보관 위치 열
   - 상차표: 호차 · 정류장 순 · 보관 열 · 메모 2칸 · 체크칸
4. **발주서 이미지**(⑩-0): 매입처별 발주 품목을 이미지 · PDF로 만듭니다. **보내기는 사람이 직접**(카톡 첨부 · 공유)이고 자동 발송은 하지 않습니다.
5. 출고 상태가 DB에 필요하면(예: 주문 줄 `picked` · `loaded`) SQL 초안 + down + PG17을 따로 냅니다. 운영 적용은 승인 뒤입니다.
- 스위치: 새 `ORDER_FULFILLMENT`(기본 OFF, 제이에스리테일 allowlist는 대표 승인 뒤).

## CX-67 주문서 상세: 품절 · 대체 · 부분 취소 (09) — 와이어 ⑨-1
- 고객사 주문 확인에서 주문을 열면 매장 정보 · 배송지 · 줄별 [품절 / 대체 품목 / 수량 줄이기 / 줄 취소]를 고릅니다.
- 매장에 바뀐 내용을 알립니다(회사 알림 · 매장 주문 내역에 "바뀜" 표시 · 전후 비교).
- **금액 · 전표**
  - 바뀐 주문은 revision을 올리고, 서버가 금액을 다시 계산합니다.
  - 전표가 이미 있으면 `revise_order_sale_document`(원자 접수 RPC와 같은 계약)를 씁니다.
  - 대표 결정 1이 "출고 때 확정"이면, 접수 뒤에는 작성중 전표만 고치게 됩니다. **결정 전까지는 화면과 서버 계산까지만 하고, 전표 연결은 결정 뒤에 합니다.**
