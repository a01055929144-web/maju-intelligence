# CC-32 카탈로그(가격 묶음) + 매장 등급(직접 만든 분류) — 2026-11-13 대표

> 컨트롤타워 설계 · 담당 Claude Code. Owner Domain `pricing`(카탈로그) · `customer`(매장 등급). 와이어프레임: Design 캔버스 "카탈로그(등급) 단가 와이어프레임" ①~⑤ (대표 계정).

## 대표 요청·결정 (원문 요지)

- (11:00) "기본 카탈로그 = 전체 단가표, 공산품과 야채가 각각 % 나눠서 그 카탈로그 안에서 반영된 마진율로 매출가가 보여지는 거야. 그 단가를 보고 매장 쪽에서 주문을 하는 거지. 그동안 만들어 놓은 기능들을 다 사용해서 마진율 반영이 더 쉽도록." (참고: 카드형 카탈로그 목록 — 이름·품목 수·매장 수)
- (11:07) "내가 말한 등급은 **매장의 등급**을 뜻하는 거였어."
- (11:08) 매장 등급과 카탈로그는 **따로 관리**(카탈로그는 매장마다 직접 지정, 등급은 매장 분류) · 매장 등급은 **회사가 직접 만든 등급**(VIP·일반·신규 등).

## 화면 (와이어프레임 ①~⑤)

1. **가격 관리 탭 = `카탈로그 | 행사·임박 | 매장 가격`** — 지금 "판매가" 탭은 **기본 카탈로그 상세**로 들어감(옛 주소 이동).
2. ① **카탈로그 목록**: 카드(이름 · 분류 마진 칩 · 품목 수 · 매장 수 · 기본 대비 평균 %) + `기본` 배지 + `+ 새 카탈로그`(주 버튼). 카드/표 전환, 정렬(매장 많은 순).
3. ② **카탈로그 상세**: 위 **분류 마진 칸**(대분류 + 채소류처럼 자주 쓰는 중분류, 비우면 기본 따라감, "기본 18% → +2%p") → 저장 즉시 반영 + "N개 바뀜 [되돌리기]". 아래 분류 트리 + 표(매입가·기본가·마진·이 카탈로그 가격·차이·출처 배지). 칩: 기본과 다른 것만 / 이익 낮음 / 이 카탈로그에서 제외. 주 버튼 "이 카탈로그로 단가표 만들기", 보조 "매장 지정 N", ⋯(이름·복제·보관).
4. ③ **새 카탈로그 서랍**: 시작점(기본/다른 카탈로그 복제) → 바꿀 분류만 % → **미리보기**(바뀌는 품목 수·평균 %·예시 3개) → 이름 자동 제안("공산품18 · 채소20", 수정 가능) → 매장 지정(선택).
5. ④ **매장 가격 탭(매장 목록)**: 열 = 매장 · **매장 등급 칩** · 카탈로그(고르기) · 이 매장만 가격 수 · 받은 단가표 · 최근 주문. 필터 매장 등급/카탈로그/기본/첫 거래. **여러 매장 선택 → 카탈로그 바꾸기** 확인창(다음 주문부터 · 보낸 문서는 고정 · 새 단가표 링크 보내기 선택 · 매장 개별 가격 우선). `매장 등급 관리` 서랍(이름·색·순서, 삭제는 쓰는 매장 0일 때만).
6. ⑤ **매장 화면**: 자기 카탈로그 가격(+약정가·행사 배지)으로 주문 — 이미 CC-29b/c·CC-30d 서버 계산 그대로, 표시 문구만.

## 11:30 대표 보강 (이 절이 위 "화면"보다 우선)

- 카탈로그 마진은 **대분류 단위만**: 농산 · 축산 · 수산 · 공산품 · 비식품 · 기타(분류 체계 순서). 중분류 칸 없음(상품·고정 예외는 품목·가격 탭에서 지금처럼).
- **카탈로그 이름 수정 가능**: 카드 ⋯ 이름 바꾸기 + 상세 제목 칸에서 바로 수정(Enter 저장).
- **새 카탈로그 서랍 없음**: "+ 카탈로그 추가" = 이름 한 줄 입력 → 기본 카탈로그 마진으로 생성(분류 폴더 추가와 같은 조작). 카드 ⋯ = 이름 바꾸기 · 복제 · 삭제(연결 매장 0일 때) · 카드 끌어 순서 바꾸기. 상품관리 분류 트리의 추가·이름·삭제·끌기 컴포넌트를 재사용.
- **카드를 누르면 매장 목록이 먼저**: 위 대분류 마진 칸, 아래 탭 `매장 연결 N | 품목·가격`. 매장 연결 = 공용 표 + **전체 선택(헤더 체크) · 일부 선택 · 검색(이름·주소·전화) · 매장 등급 필터** + "연결된 매장만"·"다른 카탈로그 매장" 칩 → 선택 줄 툴바 [이 카탈로그에 연결] [연결 해제(기본으로)]. 다른 카탈로그 매장을 고르면 옮겨짐(확인창 "N곳 옮김").
- 카탈로그를 상품관리 트리 안에 넣지 않는 이유(컨트롤타워): 카탈로그는 상품 묶음이 아니라 **전체 상품에 거는 가격 묶음**이라, 분류 폴더와 섞이면 "이 상품이 어느 폴더냐"와 "어느 가격이냐"가 한 트리에서 헷갈림. 조작 방식만 폴더와 같게 함.
- 순서 수정: 32a 이름 정리 → **32b 카탈로그 카드(추가·이름·삭제·순서) + 상세(대분류 마진 + 매장 연결 표)** → 32c 매장 등급 SQL(매장 등급 필터는 32c 적용 전엔 숨김) → 32d 매장 가격 탭 일괄 바꾸기.

## DB (SQL 초안 → 컨트롤타워 검토 → 대표 승인)

- `company_store_grades(id, company_id, name, color, sort_order, archived_at, created_at, updated_at)` — (company_id, lower(name)) 유일, service_role만.
- `normalized_customers.store_grade_id uuid null` FK (company_id, id) → 같은 회사 등급만.
- `pricing_promotion_targets.target_kind` 허용값에 `'store_grade'` 추가 + `promotion_applies_to`에 매장 등급 판정 추가(매장 → 매장 등급 → 카탈로그 순, 기존 동작 유지).
- down: 등급을 쓰는 거래처·행사 대상이 있으면 거부.
- 카탈로그는 DB 변경 없음(`margin_templates` 재사용). "기본 대비 %"·품목 수는 서버 계산(캐시 가능).
