- **배경(컨트롤타워 확인)**: `normalized_customers`에 좌표 칸이 없다. 리드(`business_permit_leads`)는 `latitude`·`longitude`가 있는데, **리드 → 거래처 전환(`convertPermitLeadToCustomer`, `lib/store.ts`)은 주소 글자만 옮기고 좌표는 버린다.** 지도(`kakao-address-map.tsx`)는 거래처마다 브라우저에서 주소로 다시 찾고 결과를 브라우저 저장소에만 둔다.
- **Owner Domain**: customer. Related: route(지도 표시), lead(전환).
- **Files**: `docs/sql-drafts/2026-11-15-customer-coordinates.sql` + `…-down.sql` · PG17 시험(기존 sql-drafts 시험 방식) · `docs/work-orders/db-approval/2026-11-15-customer-coordinates.md` 승인표.
- **Required**:
  1. `normalized_customers`에 `latitude double precision` · `longitude double precision` · `geocode_accuracy text check (in ('exact','approx','manual','lead'))` · `geocoded_at timestamptz` · `geocoded_address text`(좌표를 구한 주소 — 주소가 바뀌면 다시 찾을지 판단용). 모두 null 허용, 기존 행 영향 0.
  2. 좌표 범위 check(위도 33~39, 경도 124~132 — 한국 밖 값 차단).
  3. RLS·회사 범위는 기존 정책 그대로(새 칸은 같은 행 권한). 쓰기 경로가 RPC면 그 함수 범위만.
  4. 승인표에: 영향 행 수 읽기 쿼리, 적용 SQL(한 트랜잭션, `set local lock_timeout='3s'`, `admin_audit_logs` 기록), down, 읽기 검증 쿼리.
  5. (선택, 같은 초안) 기존 거래처 중 전환된 리드와 연결된 행은 리드 좌표로 채우는 **별도** 백필 SQL — 적용 여부는 승인표에서 따로 묻는다.
- **Do Not Touch**: 앱 코드 전부(지도·`lib/store.ts`는 승인·적용 뒤 Claude Code CC-48-5).
- **Completion Criteria**: 초안·down·PG17 통과·승인표 병합 → 컨트롤타워가 대표에게 승인 문구 요청.

### 적용 뒤 (Claude Code CC-48-5, 참고)
- 지도: 저장된 좌표가 있으면 그대로 그림(주소 다시 찾기 생략), 없을 때만 찾고 찾은 결과를 저장(정확/추정 구분). 주소를 바꾸면 좌표 다시 구함.
- 48-2 주소 검색으로 고르면 그 결과 좌표를 `exact`로 저장. 지도에서 위치 직접 지정 = `manual`.
- 리드 → 거래처 전환 때 리드 좌표를 `lead`로 복사(`lib/store.ts` 한 함수만 — 그때 다른 작업과 겹침 확인).
