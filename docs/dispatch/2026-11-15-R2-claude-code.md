# R2 작업지시 — Claude Code (2026-11-15 18:3x, Codex와 동시 작업)

대표가 Claude Code에 **"이어서 작업해"**(또는 "이어서", "다음 진행해")라고만 보내면, Claude Code는 **묻지 않고** 이 문서대로 다음 일을 골라 끝까지 한다.

## 1. "이어서 작업해"를 받으면 (순서대로, 한 번에 한 PR)

1. `git fetch` → 내 열린 PR 확인(`gh api repos/{owner}/{repo}/pulls?state=open`).
2. **열린 PR이 있으면 그것부터** 끝낸다.
   - CI 실패 → main에서 같은 시험이 통과하는지 먼저 확인. 통과하면 내 PR이 깬 것 = 고친다. main도 실패면 "막힘(main 실패)".
   - main보다 뒤처졌으면 `update-branch` 후 CI 다시.
   - Ponytail(ponytail-review) 지적 남았으면 보완.
   - CI 전부 초록 + Ponytail 끝 → **병합 직전 배포 잠금 확인**(현황판 [배포 기록](2026-11-10-R1-board.md)에 `진행 중` 줄이 있으면 병합하지 않고 기다림) → squash 병합.
3. 열린 PR이 없으면 **아래 2절 대기열의 다음 칸**을 시작한다: 지시서 읽기 → 7절 영향 분석(짧게, PR 본문에) → 구현 → 검증 → PR → 2번.
4. 한 칸 병합이 끝나면 **멈추지 않고 다음 칸**으로 간다. 아래 3절 "멈출 때"에만 멈춘다.
5. 대기열이 끝나면 새 일을 만들지 않고 "대기열 끝 — 컨트롤타워 다음 칸 대기"로 보고하고 멈춘다.

검증(매 PR): `npm ci` → `npx tsc --noEmit` → `npm run lint` → `npm test` → `npm run build` → `npm run check:auth-boundaries`, 화면이 바뀌면 `npm run test:e2e:layout`(1440·390). PR 첫 줄 `Ponytail: 사용함 (Claude Code ponytail-review)`. 화면 동작이 바뀌는 PR은 본문에 "바뀌는 화면" + "실제 화면 확인 못 함(배포 후 대표 확인)".

## 3. 멈출 때 (이때만 멈추고 보고)

- 운영 DB 스키마·데이터 변경이 필요할 때 → 초안(`docs/sql-drafts/` + down + PG17 테스트)까지만, 적용은 대표 승인 문구 뒤 컨트롤타워.
- 0절 소유 밖 파일이 필요할 때 / Codex 열린 PR과 파일이 겹칠 때.
- main에서도 같은 시험이 실패할 때.
- 지시서와 실제 코드가 달라 지시서대로 하면 기능이 깨질 때(차이를 적고 선택지 2개 제시).
- 대표 확인이 필요한 화면 결정(색·문구·배치가 지시서에 없음)일 때 → 가장 무난한 안으로 PR을 올리고 본문에 "대표 확인 필요"로 적는다(멈추지 않음). 되돌리기 어려운 결정만 멈춤.
- 배포 잠금 중 → 병합만 기다리고 다음 칸 구현은 계속.
- **문맥(context)이 20% 아래로 내려가면** 새 칸을 시작하지 않는다: 진행 중 PR을 정리(커밋·푸시·본문에 남은 일)한 뒤 "문맥 부족 — 새 대화에서 '이어서 작업해'" 보고. 새 대화는 이 문서 1절부터 다시 하면 이어진다.
