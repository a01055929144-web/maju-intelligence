## CX-58 상세 — `docs/sql-drafts/2026-11-17-CX-58-customer-business-identity.sql` (+ down · PG17 테스트 · CI 단계)
- `normalized_customers`에 추가합니다(모두 nullable, 기존 행은 그대로).
  - `business_name text`: 사업자 상호(법인명). 비면 `customer_name`과 같다고 봅니다.
  - `sub_business_number text`: **`company_profiles.sub_business_number`와 같은 이름**. 체크 `sub_business_number is null or sub_business_number ~ '^[0-9]{4}$'`
  - `business_entity_type text`: 체크 `in ('individual','corporation')`, null 허용
  - `corporate_registration_number text`: 법인등록번호. 체크 숫자 13자리 또는 null
- `company_profiles.sub_business_number`에도 같은 4자리 체크를 겁니다. 운영 값이 규칙에 맞는지 먼저 읽어 보고, 맞지 않는 값이 있으면 NOT VALID로 겁니다.
- 인덱스: `(company_id, business_registration_number, coalesce(sub_business_number,''))` 일반 인덱스. **unique는 만들지 않습니다**(중복 허용 목록 때문).
- PG17 테스트
  - 같은 사업자번호 + 다른 종사업장 2행 저장
  - 4자리가 아니면 거부
  - down으로 원복
- 선행 조건 표: 운영 읽기로 칸 없음 · `company_profiles.sub_business_number` 값 형식 · 사업자번호가 겹치는 매출처 수를 적습니다.
