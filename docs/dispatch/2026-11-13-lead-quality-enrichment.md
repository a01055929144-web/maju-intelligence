# CC-46 리드 품질 · 카카오/네이버 연동 · 규모 — **0순위, 군더더기 뺀 판** (2026-11-13 22:50 대표)

> 대표: "비용 발생하는 건 보류. 정말 필요한 것만, 효율적으로." → **새 표·새 화면·유료 API 없이**, 이미 있는 보강 함수를 **빨리·넓게·싸게** 돌리는 게 핵심. CC-42c는 46-3으로 흡수.

## 왜 비어 있나 (코드 확인)

1. **하루 30곳**: `/api/cron/recommend-refresh`(하루 1번)가 회사당 30곳만 보강(`LEAD_CONTACT_BACKFILL_BATCH_SIZE = 30`, `lib/store.ts` 12075) → 1만 1천 곳 한 바퀴 ≈ 390일.
2. **대상이 좁음**: 전화나 주소가 **없는** 리드만 고름(`or=(phone.is.null,address.is.null)`) → 전화는 있는데 카카오·네이버 링크가 없는 리드는 영원히 안 채워짐. 영업 지역 밖도 제외.
3. **구글 유료 호출이 섞여 있음**: 리드 1곳 보강마다 `syncGoogleReviewsForCustomer`(구글 Places, 유료)도 부르고 평점·리뷰 수를 저장(`performPermitLeadExternalInfoEnrichment`). 키가 운영에 있으면 **이미 돈이 나가는 구조** + 구글 약관상 장기 저장 문제.
4. 면적은 정부 인허가 원천 기록이 있는 리드(약 1,500곳)만 받을 수 있음 — 나머지 1만여 곳(옛 CSV)은 원천 키가 없음.

## 할 것 (4단계, 새 표·새 화면 없음)

### 46-1 진단 — 반나절, 코드·DB 변경 없음
운영 읽기 조회 한 번으로 회사별 표(PR 본문에 그대로):
- 칸별 채움률: 전화(010/유선) · 주소·좌표 · `kakao_place_url` · `naver_place_url` · `kakao_category_name` · 업종 '기타' · 면적 · 상태(신규/영업/제외/폐업)
- 원천별(인허가 API·서울·카카오·옛 CSV) 수, 최근 30일 보강 시도·성공 수(`lead_enrichment_events`)
- **운영에 `GOOGLE_PLACES_API_KEY`가 있는지(있음/없음만)**, 리드에 `rating`·`review_count`가 채워진 수
- 카카오 로컬·네이버 검색 하루 한도(콘솔 확인, 수치만)

### 46-2 보강 빠르고 넓게 — 핵심
1. **구글 단계 끄기**: 리드 보강에서 구글 호출 제거(스위치 `LEAD_ENRICH_GOOGLE` 기본 OFF). 비용 0.
2. **대상 넓히기**: 전화·주소 없음 **또는 카카오 링크 없음 또는 업종 '기타'**, 최근 시도한 곳은 기존 재시도 간격 규칙 그대로.
3. **크론 처리량**: 30 → 60초 안에 끝나는 만큼(동시 처리 그대로, 예상 100~200). 남은 시간 보고 멈춤.
4. **첫 일괄 보강(밀린 1만 곳)**: 새 화면 없이 Claude Code가 **같은 함수**를 스크립트로 묶어 실행 — ① dry-run(대상 수·예상 API 호출 수·하루 한도 대비 며칠) → ② 컨트롤타워 검토 → ③ **대표 승인** → ④ 한도 안에서 1~3일 나눠 실행 → ⑤ 46-1 표로 전후 비교 기록. 06:00~07:30 피함.
5. 같은 패스에서 **업종 보정**: 카카오 카테고리로 '기타'·빈 업종만 채움(기존 `industry-classification` 규칙, 이미 정해진 업종은 안 건드림).
6. 매칭이 애매하면(상호·주소가 확실히 안 맞으면) **비워 둠** — 지금 후보 판정 함수 그대로, 틀린 연결보다 빈칸이 낫다.

### 46-3 규모(면적) — 무료 공공 API
- 인허가 원천 키가 있는 리드만 정부 API로 면적 채움(dry-run → 승인 → 실행). **옛 CSV 리드는 이번에 안 함**(원천 키가 없어 매칭 비용 대비 효과 낮음).
- 결과 비율을 보고 규모 필터를 켤지 대표 결정(켜면 "규모 모름" 따로 선택, 평 단위).

### 46-4 폐업 정리 — 작은 수정
- 인허가 상태가 폐업인 리드: 목록·지도·맞춤 견적 대상에서 **기본 제외**, `폐업` 칩. (지금 '폐업(날짜)' 상태값이 섞여 있음 — 판정 한 곳으로.)
