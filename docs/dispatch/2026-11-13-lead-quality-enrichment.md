> 대표: "비용 발생하는 건 보류. 정말 필요한 것만, 효율적으로." → **새 표·새 화면·유료 API 없이**, 이미 있는 보강 함수를 **빨리·넓게·싸게** 돌리는 게 핵심. CC-42c는 46-3으로 흡수.

## 왜 비어 있나 (코드 확인)

1. **하루 30곳**: `/api/cron/recommend-refresh`(하루 1번)가 회사당 30곳만 보강(`LEAD_CONTACT_BACKFILL_BATCH_SIZE = 30`, `lib/store.ts` 12075) → 1만 1천 곳 한 바퀴 ≈ 390일.
2. **대상이 좁음**: 전화나 주소가 **없는** 리드만 고름(`or=(phone.is.null,address.is.null)`) → 전화는 있는데 카카오·네이버 링크가 없는 리드는 영원히 안 채워짐. 영업 지역 밖도 제외.
3. **구글 유료 호출이 섞여 있음**: 리드 1곳 보강마다 `syncGoogleReviewsForCustomer`(구글 Places, 유료)도 부르고 평점·리뷰 수를 저장(`performPermitLeadExternalInfoEnrichment`). 키가 운영에 있으면 **이미 돈이 나가는 구조** + 구글 약관상 장기 저장 문제.
4. **면적은 인허가 데이터에 있다 — 저장을 꺼 둔 것뿐**(22:54 확인): 행정안전부 API `LCTN_AREA`·서울 열린데이터 `SITEAREA`를 이미 ㎡로 읽고 있음(`lib/gov-restaurant.ts` 98, `lib/seoul-restaurant.ts` 106). 그런데 저장은 서버 스위치 `LEAD_STORE_AREA_ENABLED`가 켜져야만 함(`lib/store.ts` 9516·9523) — **꺼져 있어서 매일 동기화 때마다 면적을 받아 놓고 버림.** 10/29 설계에서 "새 수집분 분포 확인 후 백필"로 미뤄 둔 상태 그대로. DB 칸(`store_area_sqm`)은 운영에 이미 있음.
   - 옛 CSV 리드(약 1만 곳): 행정안전부 인허가 **파일 데이터(일반음식점 전체, 무료)**에도 `시설총규모`가 있음 → 리드에 인허가 관리번호가 남아 있으면 그 번호로, 없으면 상호+주소로 매칭 가능. 46-1에서 관리번호 보유 수 확인.


## ★ 기본 구조 — 공통 리드 (23:23 대표)

> 대표: "제이에스리테일의 리드들은 **공통의 리드**. 고객사가 여러 곳 들어오면 리드 정보를 **같이 공유**해야 한다. 고객사마다 **거래처와 영업 지역**을 입력하고 **그 지역에 맞춰 리드를 업데이트**."

**이미 설계·테이블은 있음 — 연결이 안 됐을 뿐**: [WO-1 전체 매장 DB 설계](../specs/wo-1-shared-ledger-design-2026-10-25.md)(10/25), 운영 테이블 `shared_business_places`(10/26 적용, **0행**, `area_m2`·`public_phone`·`homepage_url`·인허가 상태 칸 있음, company_id 없음·service_role만). 수집 전환은 "미승인"으로 멈춰 있음. 지금 리드는 회사마다 **따로 복사본**(`business_permit_leads.company_id`)이라 같은 매장을 회사마다 따로 받고·따로 보강함.

| 층 | 무엇 | 누가 보나 |
| --- | --- | --- |
| **전체 매장 DB**(`shared_business_places`) | 공공 인허가 사실만: 상호·주소·좌표·업종·개업/폐업·**면적**·공개 전화·홈페이지·원천 키 | 모든 고객사가 **같은 값**을 받음(한 번 수집·한 번 보강) |
| **회사 리드**(`business_permit_leads`, `shared_place_id`로 연결) | 그 회사 것만: 상태·담당·메모·영업 기록·견적·직원이 알아낸 연락처·메뉴 메모·수신거부·카카오/네이버 링크(약관 확인 전까지 회사 쪽) | 그 회사만 |

- **회사가 영업 지역·거래처를 저장하면** → 그 지역의 영업 중 매장으로 회사 리드를 만들거나 갱신, **자기 거래처와 같은 매장은 리드에서 제외**(설계: 설정 저장 직후 바로 fan-out).
- 다른 회사의 상태·메모·거래처 관계는 **절대 공유하지 않음**(WO-1 안전·격리 규칙 그대로).
- **용량**: Supabase 무료 500MB 중 약 110MB 사용 → **고객사 영업 지역이 있는 시·도만** 적재, 400MB 넘을 것 같으면 멈춤(요금제 올리기는 비용 → 보류).
- 카카오 결과는 약관상 전체 매장 DB에 넣어 재배포하지 않음(WO-1 결정) → 회사 리드에만.

### 공통 리드 단계 (46-A~C)

| 단계 | 내용 | 승인 |
| --- | --- | --- |
| **46-A 적재** | 제이에스리테일 영업 지역(서울 강남·강동·광진, 인천 남동·부평·중구, 경기 의정부 — 46-1에서 최신 확인) **영업 중 매장만** 전체 매장 DB로. 일반음식점부터, 휴게·제과·급식은 용량 보고 다음. dry-run(행 수·예상 MB) 먼저 | **dry-run → 대표 승인**(WO-1 미승인분) |
| **46-B 연결** | 기존 회사 리드 → `shared_place_id` 연결(인허가 관리번호 → 상호+주소 정확 일치, 애매하면 연결 안 함). 연결된 리드는 면적·폐업·개업일을 전체 매장 DB 값으로 | dry-run → 승인(칸 추가 SQL 필요하면 초안) |
| **46-C 지역 맞춤 갱신** | 영업 지역 저장 시 즉시 fan-out + 매일 변경분만 갱신 + 자기 거래처 제외. 새 고객사도 같은 길 | SQL 초안 필요 시 승인 |

## 품질 단계 (위 공통 구조 위에서, 새 표·새 화면 없음)

### 46-1 진단 — 반나절, 코드·DB 변경 없음
운영 읽기 조회 한 번으로 회사별 표(PR 본문에 그대로):
- 칸별 채움률: 전화(010/유선) · 주소·좌표 · `kakao_place_url` · `naver_place_url` · `kakao_category_name` · 업종 '기타' · 면적 · 상태(신규/영업/제외/폐업)
- 원천별(인허가 API·서울·카카오·옛 CSV) 수, 최근 30일 보강 시도·성공 수(`lead_enrichment_events`)
- **운영에 `GOOGLE_PLACES_API_KEY`가 있는지(있음/없음만)**, 리드에 `rating`·`review_count`가 채워진 수
- 카카오 로컬·네이버 검색 하루 한도(콘솔 확인, 수치만)

### 46-2 보강 빠르고 넓게 — 핵심
1. **구글 단계 끄기**: 리드 보강에서 구글 호출 제거(스위치 `LEAD_ENRICH_GOOGLE` 기본 OFF). 비용 0.
2. **대상 넓히기**: 전화·주소 없음 **또는 카카오 링크 없음 또는 업종 '기타'**, 최근 시도한 곳은 기존 재시도 간격 규칙 그대로.
3. **크론 처리량**: 30 → 60초 안에 끝나는 만큼(동시 처리 그대로, 예상 100~200). 남은 시간 보고 멈춤.
4. **첫 일괄 보강(밀린 1만 곳)**: 새 화면 없이 Claude Code가 **같은 함수**를 스크립트로 묶어 실행 — ① dry-run(대상 수·예상 API 호출 수·하루 한도 대비 며칠) → ② 컨트롤타워 검토 → ③ **대표 승인** → ④ 한도 안에서 1~3일 나눠 실행 → ⑤ 46-1 표로 전후 비교 기록. 06:00~07:30 피함.
5. 같은 패스에서 **업종 보정**: 카카오 카테고리로 '기타'·빈 업종만 채움(기존 `industry-classification` 규칙, 이미 정해진 업종은 안 건드림).
6. 매칭이 애매하면(상호·주소가 확실히 안 맞으면) **비워 둠** — 지금 후보 판정 함수 그대로, 틀린 연결보다 빈칸이 낫다.

### 46-3 규모(면적) — 무료 (46-A가 들어오면 전체 매장 DB `area_m2`가 기준, 그 전까지는 아래로 회사 리드에 바로)

1. **저장 스위치 켜기**: `LEAD_STORE_AREA_ENABLED=true`(서버, 저장만 — 화면 표시 스위치 `NEXT_PUBLIC_…`는 그대로 OFF). **대표 승인 필요(기능 플래그 규칙)**. 켜면 그날부터 동기화되는 리드는 면적이 저장됨.
2. **원천 키 있는 리드 다시 받기**: 인허가 API·서울 API 원천 기록(`business_permit_lead_source_records`)의 `raw_payload`에 이미 면적이 들어 있는 것은 **API 호출 없이** 그 값으로 채움 → 없는 것만 API 재조회. dry-run(채울 수·이상치 0/음수/10만㎡ 초과 제외) → 승인 → 실행.
3. **옛 CSV 리드**: 행정안전부 인허가 파일 데이터(일반음식점, 무료 다운로드)의 `시설총규모`로 — 리드에 관리번호가 있으면 번호로, 없으면 상호+주소 정확 일치만(애매하면 비움). 파일은 대표가 화면에서 올리거나 공공데이터 API로 받음(저장소에 커밋 금지). dry-run → 승인.
4. 채움률 보고 **화면 규모 필터 켜기**는 대표 결정(평 단위, "규모 모름" 따로).

### 46-4 폐업 정리 — 작은 수정
- 인허가 상태가 폐업인 리드: 목록·지도·맞춤 견적 대상에서 **기본 제외**, `폐업` 칩. (지금 '폐업(날짜)' 상태값이 섞여 있음 — 판정 한 곳으로.)
