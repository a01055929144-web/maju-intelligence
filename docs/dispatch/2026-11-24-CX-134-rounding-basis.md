# CX-134 끝자리 올림 기준 선택: 공급가 / 부가세 포함가 (11/24 대표 결정)

**고객 행동:** 회사 설정에서 "끝자리 기준"을 고르면, 매장이 보는 최종 가격(과세 품목 부가세 포함)이 50원 단위로 떨어진다.
**Owner Domain:** pricing · 담당: Claude Code (Codex 11/27 11:00까지 중지)

## 현재 (11/24 13:30 운영 확인)
- 회사 50원 올림 적용됨(755개). 올림은 **공급가** 기준: `pricing_p0_price = ceil(매입가×(1+마진)/단위)×단위`.
- 문서 표시는 과세 품목만 `Math.round(공급가×1.1)` (`domains/pricing/document.ts` `documentDisplayPrice`). 그래서 공급가 2,200·6,850 → 화면 2,420·7,535.
- 행사가는 `priceIncludesTax`(부가세 포함 고정가) 저장 경로가 이미 있다.

## 해야 할 것
1. 회사 설정에 `끝자리 기준` 추가: `공급가`(기본, 지금 동작) / `부가세 포함가`.
2. `부가세 포함가`일 때 과세 품목은 **화면·인쇄·공개 링크·주문에 보이는 부가세 포함 가격이 정확히 단위의 배수**여야 한다. 면세는 지금과 같다.
3. **먼저 설계 보고, 그다음 구현.** 공급가를 역산(`round(T/1.1)`)하면 `round(s×1.1)=T`인 정수 s가 없는 T가 있다(T=50k에서 5k mod 11 = 6인 경우, 예 T=300·850…). 아래 두 안 중 하나를 근거와 함께 고르고 보고:
   - 안 A: 공급가 역산 + 표시 계산을 "기준이 부가세 포함가면 저장된 포함가를 그대로" 쓰도록(행사가 고정가 경로 재사용).
   - 안 B: 판매가를 부가세 포함으로 저장하는 플래그를 품목 가격에 추가.
   - 어느 쪽이든 주문 합계·세금계산서·공급가액/부가세 분리 계산이 1원도 어긋나지 않음을 시험으로 증명.
4. SQL 초안 + down + PG17(경계값 T=50·300·850·2,450·7,550 포함). 운영 적용은 대표 승인 후 컨트롤타워.
5. 기준을 바꿔도 확정가·게시본·약속가는 그대로, 기존 "변경 대기 → 지금 반영" 흐름을 탄다.

## 하지 않음
행사가 계산 변경, 반올림·내림 옵션, 마진 그룹·템플릿별 기준(회사 하나만).
