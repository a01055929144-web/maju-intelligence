## 1. 저장 실패 (P1 — 지금 행사를 하나도 못 만듦)

- 운영 로그(11/13 12:08): `POST /api/pricing-documents` → `Pricing P1 request failed Error: 필수 항목과 입력 길이를 확인해 주세요.` (라벨 없는 `field()` 검증 실패).
- 화면에는 이 이유 대신 일반 문구 **"저장하지 못했습니다. 입력값과 최신 버전을 확인하고…"**가 나감(`app/api/pricing-documents/route.ts` catch가 검증 오류도 503 일반 문구로 바꿈) → **원인이 안 보임**.
- 유력 원인: 행사 서랍 저장 내용의 `name: promo?.name || product?.name || ""` — 상품을 검색 목록(`catalog-index`)에서 골랐을 때 그 항목의 이름 필드가 `name`이 아니면 빈 문자열 → 필수 검증 실패. (`displayName`은 더보기 안이라 비어도 됨인지 서버 규칙 확인.) 재현해서 확정할 것.
- 고칠 것: ① 검증 오류(`Error` 메시지가 사용자 문구인 것)는 **400 + 그 메시지 그대로**, 버전 충돌만 409 "다른 곳에서 바뀌었습니다", 그 외 503 ② 모든 `field()` 호출에 라벨(행사 이름·날짜 등) ③ 이름이 비면 상품 이름으로 채움 ④ 회귀 테스트(검색 목록에서 고른 상품으로 행사 저장 성공).
- **이 1번은 2번과 별도 PR로 먼저**(작은 수정, 바로 배포 대상).

## 2. 등록 흐름 — 견적서·단가표 품목 추가와 같게

지금: 서랍에서 상품 하나 검색 → 고르기 → 행사 매입가·마진(%)·시작일·종료일·재고 입력 → 저장. 하나씩만, 매입가·마진으로 행사가를 역산해야 해서 어색함.

바뀐 흐름(문서 편집기의 품목 고르기 부품 재사용):

1. 행사·임박 탭 주 버튼 **`+ 행사 상품 담기`** (임박 탭은 `+ 임박 상품 담기`) → 오른쪽 넓은 서랍.
2. 서랍 위: **기간 한 번에** `시작 [오늘] ~ 종료 [이번 주 일요일]` (빠른 칩: 이번 주 · 다음 주 · 이번 달 · 직접), 임박은 `유통기한`.
3. 서랍 왼쪽: 문서와 **같은 상품 고르기** — 검색 · 분류 폴더(상품관리 순서) · 폴더 통째 담기 · 여러 개 체크 → [담기].
4. 서랍 오른쪽: **담은 품목 표**(칸에서 바로 입력) — 상품 · 정상가(지금 판매가, 자동) · **행사가** 또는 **할인 %**(둘 중 하나 입력하면 다른 쪽 자동) · 이익(매입가 대비, 손해면 빨강) · 재고(선택) · 매장당 한도(선택) · 빼기. 위에 일괄: "선택 줄 할인 10% / 행사가 반올림 10원".
5. 아래: 대상 `전체 매장 | 특정 매장만 [고르기]`(CC-29, 스위치 따름) · [취소] **[N개 행사 등록]**(주 버튼 하나).
6. 저장은 품목마다 행사 1건(지금 테이블 그대로), 한 번 요청으로 묶어 저장 — 실패한 줄만 빨강 + 이유, 나머지는 저장.
7. 목록의 행사 줄 클릭 → 같은 서랍에 그 1건만 담긴 채 수정. "끝내기"는 ⋯ 안.
8. 행사 매입가가 정상 매입가와 다를 때만 쓰는 "행사 매입가" 칸은 **더보기**로(기본은 지금 매입가 자동).
