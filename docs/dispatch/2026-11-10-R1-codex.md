# R1 작업지시 — Codex (2026-11-10)

운영 방식: [README](README.md). 진행 상황은 [R1 현황판](2026-11-10-R1-board.md)에 한 줄씩 적는다. 모든 코드 PR은 **Ponytail 사용 → `Ponytail: 사용함`** 이 첫 줄이어야 병합한다. 운영 DB 쓰기·플래그 변경은 하지 않는다(승인 패킷 작성까지만). **배포는 Codex 총괄방만, 컨트롤타워가 멈췄을 때 대신**([README "배포 담당"](README.md)) — 작업방은 배포하지 않는다.

**Codex 총괄방이 이 문서를 받아 아래 CX 작업을 작업방에 나눠 준다**(CX-00 검토방은 전용 작업방 하나를 지정). 브랜치: `codex/<ID>-<요약>`. 기존 작업방 번호(01~09)와 파일 소유는 [단계 완료 기준](../work-orders/2026-11-07-stage-completion-gates.md) "병렬 작업 충돌 방지"를 따른다.

## CX-00 Ponytail 검토방 — Claude Code PR 점검 (상시 · 최우선 응답)

- **대상**: 제목이 `[CC-*]`이고 본문에 `Ponytail: 검토 요청`인 Draft PR.
- **할 일**: 해당 브랜치를 받아 Ponytail로 점검 → 최소 변경·재사용·중복 제거·죽은 코드 제거를 **같은 브랜치에 보완 커밋**(기능 범위·화면 구성은 바꾸지 않음) → 로컬 검증(tsc·lint·test·build·auth-boundaries) → PR 본문 첫 줄을 `Ponytail: 사용함 (Codex 검토)`로 바꾸고 점검 요약(바꾼 것 / 그대로 둔 이유) 코멘트.
- **범위 밖 발견**: 고치지 말고 PR 코멘트 + 현황판 "막힘/후속"에 적는다.
- **추가(여유 시)**: Claude가 11/03~11/05 직접 만든 PR #223~#246 중 `docs/qa/20261106-ponytail-category-pricing-review.md`에 포함되지 않은 범위를 표로 정리하고, 필요한 정리 PR을 `codex/CX-00b-*`로 작게 나눠 올린다.

## CX-07 (09·07) 매장 홈에 "가입한 문서" 연결 (#471 검토 결과 · P0)

- **Objective**: 매장 홈은 `storefront_links`만 문서로 보여 준다. 공개 문서 링크로 가입한 매장은 매장별 링크가 자동 발급되지 않아 홈에서 문서가 보이지 않는다(운영 DB에서 `storefront_links`를 만드는 함수는 `issue_storefront_links`·`record_pricing_document_acceptance` 두 개뿐, 가입 함수는 만들지 않음).
- **Required**: 가입(또는 첫 수락) 시 해당 게시 버전으로 매장 링크를 1건 발급하거나, 홈이 가입 출처 문서를 함께 보여 주는 방법 중 하나를 선택해 근거와 함께 구현. 같은 문서 중복 발급 없음(멱등), 회사·매장 격리, 만료·회수 존중. DB 함수 변경이 필요하면 SQL 초안+down+PG17 → 승인 패킷까지.
- **추가(작게)**: 홈의 「배송지 주소」 버튼이 원가관리와 같은 주소로만 이동한다 → 주소 영역으로 바로 이동. 매장 측 "전체 주문 내역"(문서별이 아닌 매장 단위)은 R2 후보로 현황판에 적기.
- **Done**: 공개 문서 가입→홈에 그 문서 표시 테스트(PC/390), CI 초록, Ponytail.

## CX-08 (09) 행사 수량 계산을 "취소 아닌 주문 전부"로 — CC-02 병합 선행 (P0 · SQL)

- **배경**: Claude Code가 CC-02(#480 고객사 주문함) 구현 중 발견. 주문 함수(`place_store_order`, `place_store_member_order`)가 행사 수량(재고)을 셀 때 `status = 'submitted'`만 센다(운영 함수 동일, 읽기 확인). 주문함에서 확인(received)되면 그 수량이 빠져 행사 재고보다 많이 팔릴 수 있다.
- **소유**: 주문 함수는 09 소유. 함수를 고치는 사람이 한 명이어야 덮어쓰기가 없으므로 **09가 작성**한다(Claude Code는 SQL을 쓰지 않음).
- **Required**: ① 두 함수의 행사 수량 집계 조건을 `status <> 'cancelled'`로 바꾸는 **작은 단독 SQL 초안**(+down+PG17: submitted·received·in_delivery·delivered는 차감, cancelled는 제외, 동시 주문 경쟁) ② 아직 미적용인 `20261110-09-pending-delivery-order.sql`이 같은 함수를 다시 정의하면 같은 조건으로 맞추거나, 대표 정정(권역 없이 접수 금지)으로 쓰지 않을 초안이면 폐기 표시 ③ `docs/work-orders/db-approval/`에 승인표(적용 순서: 이 SQL → #480 병합).
- **Done**: SQL 초안·PG17 CI 초록·승인표 병합. 운영 적용은 대표 승인 문구 후.
