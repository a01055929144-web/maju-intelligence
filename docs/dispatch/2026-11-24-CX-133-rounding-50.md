# CX-133 매출가 끝자리 50원 단위 옵션 (11/24 대표 요청)

**고객 행동:** 기본 마진율(현재 회사 10%)로 계산한 매출가를 50원 단위로 올려 맞춘다.
**Owner Domain:** pricing · Related: catalog

## 현재 (11/24 10:30 운영 읽기)
- 계산식 `pricing_p0_price`: `ceil(매입가 × (1+마진) / 단위) × 단위` — 끝자리 **올림**. 단위는 1·10·100원만 허용.
- 회사 설정 `pricing_settings`: 마진 10%(1000bp), 단위 10원. 마진 그룹 2개·마진 템플릿 2개도 각자 단위를 가진다.
- 50원을 막는 곳 8곳:
  - DB CHECK 3개: `pricing_settings_rounding_check`, `margin_groups_rounding_check`, `margin_templates_rounding_check` (`in (1,10,100)`)
  - DB 함수 `pricing_p0_price` 입력 검사 `rounding not in (1,10,100)`
  - 코드: `domains/pricing/price-rules.ts:39`, `app/api/margin-templates/route.ts:52`, `components/price-sheets-workspace.tsx:158`, `components/pricing-margin-groups.tsx:152`, `components/pricing-margin-templates.tsx:122`

## 할 일
1. 허용 단위를 `1, 10, 50, 100`으로. 목록은 `domains/pricing`에 상수 하나(`PRICE_ROUNDING_UNITS`)로 두고 위 코드 5곳이 모두 그 상수를 쓴다(중복 배열 제거).
2. 방식은 기존과 같은 **올림**. 예: 매입가 1,833 × 1.10 = 2,016.3 → 10원 2,020 / 50원 2,050 / 100원 2,100.
3. 선택 문구: "1원 · 10원 · 50원 · 100원 단위 올림". 설정 화면에 위 예시처럼 "매입가 1,833원 → 2,050원" 미리보기 한 줄.
4. SQL 초안 `docs/sql-drafts/2026-11-24-CX-133-rounding-50.sql` + `.down.sql` + PG17 시험:
   - CHECK 3개를 `(1,10,50,100)`으로 교체, `pricing_p0_price` 검사만 같은 목록으로 교체(계산식 변경 없음).
   - down: 50원 쓰는 행이 있으면 실패하도록 가드 후 원복.
5. 단위를 바꿔도 **이미 확정된 판매가·게시된 단가표는 바뀌지 않는다.** 기존 "변경 대기 n건 → 적용" 흐름(`applied_rounding` 비교)을 그대로 탄다. 시험으로 확인.
