# R20 — 리드 표·지도 건수와 외부정보 전체 선택 복구 (11/27 대표 제보)

현황판: [board/2026-11-27-R20.md](board/2026-11-27-R20.md). 기존 [R10 CX-81](2026-11-17-R10-leads.md)의 일괄 작업과 [R19](2026-11-26-R19-codex.md)의 진행 중 주문 작업을 중복 구현하지 않는다. 이 차수는 대표가 실제 화면에서 제보한 두 버그만 다룬다. 새 운영 데이터 작성·외부 API 실호출·배포는 총괄방 확인 전 금지한다.

## 공통 원칙

- 코드 작성은 Ponytail 필수. Owner Domain은 `lead`; 필터·선택·진행 상태를 순수 계산과 서버 Use Case에 두고 UI는 연결만 한다.
- 원인을 먼저 PR 본문에 3줄로 기록한다. 가짜 리드로 회귀 시험을 만들고 1440·390에서 같은 필터·선택·진행 상태를 확인한다.
- 필터가 다른 두 화면의 숫자를 억지로 같게 만들지 않는다. **같은 회사·상태·지역·인허가/개업일·업종 조건**에서 모집단을 대조하고, 주소가 없어 지도에 표시 못 하는 리드는 `표 N / 지도 표시 M / 위치 미확인 N-M`처럼 이유를 드러낸다. 실제 날짜는 `openDate || permitDate` 공통 규칙을 유지한다.
- 외부 API는 합성 응답만 시험한다. 회사별 일일·초당 제한, 권한, 중단·실패 다시 시도, idempotency를 유지한다. 고객사 간 리드 ID 혼합 금지.
- main CI 빨강·배포 잠금 중에는 병합하지 않는다. 완료 전까지 기능 OFF + 회사 allowlist.

## CX-155 — 리드 표·지도 건수 일치 (01방)

**증상:** 같은 인허가일 등 조건인데 표의 리드 수와 지도 수가 다르게 보인다.

**먼저 확인:** 표는 필터를 통과한 `leads` 전체, 지도 상단은 주소가 있는 `leadRadiusMapMarkers + allLeadsMapMarkers`를 세는 코드다. 날짜 함수는 양쪽 모두 `getPermitLeadOpenDate`를 쓴다. 이 코드상 차이가 실제 제보의 원인인지, 같은 가짜 데이터로 재현한다. 지도는 상태·업종·지역·등급 필터와 반경·레이어 표시도 거치므로 각각의 누락 건수를 분리해 보고한다.

**수정 범위:** `components/sales-route-map-workspace.tsx`, `domains/lead/map-filters.ts`, 관련 lead 순수 계산 시험·1440/390 e2e. 표 `components/permit-leads-view.tsx`는 읽기 대조만; 수정 필요 시 03방 소유와 겹침을 먼저 정리한다. 지도 마커·필터의 기존 동작을 깨지 않고 동일 조건의 *결과 건수*와 실제 *지도 표시 건수*를 명확히 구분한다. 인허가일 미확인과 주소 미확인 리드도 누락 이유를 보여 준다.

**완료:** 같은 가짜 리드 집합의 날짜(인허가일만 있는 경우·개업일만 있는 경우·둘 다 있는 경우·날짜 없음)와 주소 유무를 바꿔 표·지도 결과 및 표시 건수를 대조한 시험 통과. 필터 해제/재적용 뒤 카운트 일치, 1440·390 가로 넘침 0.

## CX-156 — 전체 선택 외부정보 불러오기 (03방)

**증상:** 왼쪽 목록에서 전체 선택 후 외부정보 불러오기가 끝까지 작동하지 않는다.

**먼저 확인:** 현재 버튼은 선택 건수가 50을 넘으면 *첫 50건만* 시작한다. UI는 다음 50건을 자동으로 이어가지 않으며, 서버는 `LEAD_BULK_ENRICHMENT_ENABLED`와 회사 allowlist가 꺼져 있으면 404를 돌린다. 이 둘 중 무엇이 실제 제보를 설명하는지 가짜 API·읽기 로그와 설정 이름으로 확인한다. 실제 키 값이나 고객사 리드 목록은 출력하지 않는다.

**수정 범위:** `components/map/map-side-panel.tsx`, `components/permit-leads-view.tsx`(표와 지도 선택 동작 일치가 필요한 경우), `domains/lead/bulk-enrichment.ts`, `application/lead/run-bulk-enrichment.ts`, `app/api/leads/bulk-enrichment/route.ts`, `lib/lead-bulk-enrichment.ts`, `lib/lead-bulk-enrichment-feature.ts`, 관련 시험. CX-155의 지도 작업 파일은 수정하지 않는다.

**완료:** 51·120건 전체 선택을 한 번 누르면 50건 단위 작업이 안전하게 이어져 선택 건수·처리/성공/실패/남은 건수가 일치한다. 회사 일일 한도·중단·실패·탭 복귀에서 남은 건수와 다음 행동을 표시한다. 404/403/429는 원인별 안내로 보여 준다. 표에서도 일괄 버튼을 제공하는 기존 CX-81 계약을 확인하고 빠졌다면 같은 동작에 연결한다. 합성 API·PG17(기존 DB 계약 변경 시에만)·1440/390을 검증한다. 운영 DB 변경은 초안+down+PG17·대표 승인 전 금지.
