## 대표 보강 (2026-11-11 02:45) — PC에서도, 링크·QR 없이도

- 매장은 **PC에서도** 가입·로그인·사용한다. 단가표·견적서 QR/링크는 여러 입구 중 하나일 뿐, 기본 입구는 **`/store` 직접 가입**이다.
- PC 카카오 로그인: 카카오 계정 로그인 화면(아이디·비밀번호 또는 휴대폰 카카오톡 QR 인증)을 그대로 쓴다. 모바일 전용 분기(앱 전환·`intent:`)에 의존하지 않는다.
- `/store` 첫 화면 문구 "첫 가입은 받은 견적서·단가표 링크에서 진행합니다"를 "카카오로 시작 → 처음이면 매장 정보 입력"으로 바꾼다(플래그 ON일 때만, OFF면 지금 문구 유지).
- 모든 R2 화면 Done에 **PC 1440·1920 + 모바일 390** e2e를 넣는다.
- **PC 화면 틀 = 지금 MAJU 운영 화면과 같게, 코드 재사용(02:46 대표)**: 왼쪽 사이드바(접기 포함)·상단 제목줄·본문 카드 구성. 새로 그리지 않고 `components/app-sidebar.tsx`의 `AppSidebar`(groups·brand·footer를 받는 공용 부품)를 그대로 쓰고, `customer-app-shell.tsx`와 같은 구조의 얇은 `store-app-shell.tsx`(매장 메뉴 그룹만 다름)를 만든다. 매장 메뉴 정의는 `lib/store-navigation.ts`(신규, `lib/customer-navigation.ts`와 같은 형식). 버튼·입력·표·카드는 기존 `components/ui/*`·`maju-*` 클래스만 쓴다.
  - 매장 사이드바 메뉴(초안): 홈 · 거래 유통사(유통사별 공개 단가표·내 견적서) · 주문 · 주문 내역 · 원가관리 · 매장 정보(주소·구성원)
  - 휴대폰(≤640px)은 지금 `/store`의 하단 탭 화면을 유지한다. 같은 페이지 부품을 PC는 셸 안에, 휴대폰은 하단 탭 안에 넣는다(화면 내용 중복 구현 금지).
  - 이 셸 작업은 **CX-11의 첫 PR**로 먼저 낸다(가입 플래그와 무관하게 기존 링크 가입 매장도 PC에서 이 틀로 보이게). 고객사 메뉴·권한 코드(`customer-navigation.ts`)는 수정하지 않는다.
- 우선순위: CX-10 SQL 승인·적용 → **CX-11(직접 가입, PC 포함)을 R2 최우선** → CC-07·CX-12 → CX-13 → CC-08.

## Claude Code 단독 진행 (2026-11-11 대표 지시 — Codex 사용량 소진 기간)

- CX-10~CX-13도 Claude Code가 지시서 ID 그대로 진행한다(브랜치 `claude/CX-10-…`, PR 제목 `[CX-10]`). Codex가 돌아오면 남은 것만 다시 나눈다.
- Claude Code가 **SQL 초안**도 쓴다: `docs/sql-drafts/` 초안 + down + PG17 테스트 + `docs/work-orders/db-approval/` 승인표까지. **운영 적용은 하지 않는다**(대표 승인 문구 → 컨트롤타워 적용).
- 한 번에 한 작업 PR. 진행 순서: CX-10(SQL 초안) → [대표 승인·적용] → CC-07 → CX-11 → CX-12 → CX-13 → CC-08. SQL 승인을 기다리는 동안은 R1 남은 일(CC-10·CC-09) 먼저.
- Ponytail은 ponytail-review로 직접.
