# 07 C6 잔여 점검 · N3 준비 기록

## C6 코드/읽기 점검

- `STAFF_ACCESS_V2_ENABLED=true`일 때 `getCustomerSession()`은 매 요청마다 활성 `company_members`와 임시 권한 만료를 다시 확인한다. 비활성·만료 계정은 다음 요청부터 세션이 없는 것으로 처리된다.
- 알바는 기본 30일 만료일, 설정·결제·직원 관리·회사 전체 운영·보고서 제외가 코드와 단위 테스트에 반영돼 있다.
- 카카오/네이버/구글 초대 수락은 같은 회사의 활성 멤버십을 중복 생성하지 않고 1인 1계정을 유지한다.
- 플래그 OFF 동안에는 기존 배송 흐름을 유지한다. 대표 실제 계정으로 권한/업무/만료/차량 저장 및 재로그인 검증 전에는 켜지 않는다.
- 남은 실제 확인: 대표 계정에서 알바 초대 → 실제 소셜 계정 수락 → 담당 거래처 노출 → 만료 직후 다음 API 401 → 동시 2기기 알림. 이번 작업에서는 운영 DB 쓰기와 플래그 변경을 하지 않았다.

## N3 승인 경계

- 현재 상태는 대표 전용 기록 화면과 출입 비밀번호 서버 reveal/API까지 같은 PR에 구현됐지만 **운영 기능은 미완료**다. 기존 화면의 원문 응답 제거·호출 전환과 운영 SQL 검증 전에는 N3 완료로 표시하지 않는다.
- SQL은 `docs/sql-drafts/20261027-07-N3-sensitive-access-logs.sql`에만 있으며 운영 적용되지 않았다.
- `SENSITIVE_ACCESS_LOGS_ENABLED` 기본 OFF. OFF 상태에서 화면은 승인 대기를 표시하고 API는 N3 테이블을 조회·수정하지 않는다.
- 조회·숨김은 활성 고객사 대표만 가능하다. MAJU 관리자 단독 세션은 401, manager는 403, 비활성 멤버는 기존 세션 재검증에서 401이다.
- 값·마스킹값·토큰 저장을 막기 위해 자유형 payload/metadata 컬럼과 입력을 두지 않았다.
- `POST /api/customers/[id]/sensitive/access-password/reveal`은 플래그 OFF를 DB 접근 전에 확인하고, ON일 때도 최신 활성 멤버십·만료·역할·담당 거래처를 다시 확인한다. 원문은 감사 INSERT 성공 뒤에만 `no-store` 응답으로 반환하며, 실패 시 503으로 닫힌다.

## 02 의존관계

- 02의 출입 비밀번호 비마스킹 표시는 이 SQL 승인·적용, 대표 계정 조회 확인, `SENSITIVE_ACCESS_LOGS_ENABLED=true` 이후에만 켠다.
- 그 전에 일반 응답/RSC에서 원문 제거, 서버의 최신 멤버십·담당 범위 재검증, 감사 INSERT 성공 후에만 원문 반환하는 fail-closed reveal API, `Cache-Control: no-store`를 같은 배포 단위로 검증해야 한다.
- 카카오 공유 문구·엑셀·공유 링크에는 출입 비밀번호를 포함하지 않는다.
