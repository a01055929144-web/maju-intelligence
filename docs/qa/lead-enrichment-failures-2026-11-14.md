## 3. 46-2⓪에서 고칠 것 (DB 변경 없음)

1. **성공 기준 바꾸기**: 결과를 `filled`(칸 채움) · `linked`(장소 연결) · `already_complete`(이미 있음) · `not_found`(0건) · `rejected`(후보 버림) · `error`로 기록. 성공률 = filled + linked + already_complete. 진단 화면·보고는 이 기준.
2. **버린 이유 기록**: rejected일 때 `reject_reason`(거리 초과·상호 불일치·주소 불일치·업종 불일치)과 거리·상호 점수를 metadata에.
3. **새 가게 다시 시도**: not_found·rejected이고 개업 90일 이내면 **개업 +30일·+60일·+90일**에 다시 시도(그 뒤는 매월 1회, 최대 6회). 지금처럼 한 번 실패로 끝내지 않음.
4. **상호 정리 검색어 추가**(애매하면 비움 원칙 유지): 괄호 안 지우기 · 법인 표기 지우기 · 끝 `점`/지점명 뗀 이름 · 띄어쓰기 없앤 이름 — 순서대로 시도하고 어떤 변형으로 찾았는지 `kakao_query_variant`에 기록(지금 전부 `none`).
5. **폐업 리드는 보강 대상에서 제외**(46-4 `isClosedLead` 재사용).
6. 단위 테스트는 가짜 상호·가짜 응답으로. 실제 상호·전화 금지.
