## 2. P1 — 즉시 조치 필요

### 2-1. CI 보안 게이트가 실제로 실패 중 (`check:auth-boundaries`)

- **증상**: `node scripts/check-api-auth-boundaries.mjs` 로컬 실행 시 `API authentication boundary missing: - app/api/public/quotes/[token]/route.ts` 로 실패.
- **원인**: 신규 라우트 `app/api/public/quotes/[token]/route.ts`가 `scripts/check-api-auth-boundaries.mjs`의 `publicRoutes` 허용목록(Map, 14개 항목)에 등록되지 않음.
- **실제 보안 상태는 정상**: `lib/store.ts`의 `getPublicSalesQuote()`를 직접 읽어 확인 — UUID 토큰 형식 검증, `public_enabled=true` + `valid_until` 만료 체크, 원가/마진 컬럼은 SELECT 자체에서 제외(주석: "고객 공개 응답에서는 내부 원가와 마진 컬럼을 SELECT 자체에서 제외합니다"). 즉 **코드는 안전하지만 CI 게이트 등록만 빠진 상태**이고, 현재 이 게이트가 빨간불이면 이후 다른 라우트의 실제 인증 누락도 묻힐 수 있어 선조치가 필요합니다.
- **권장 수정**: `scripts/check-api-auth-boundaries.mjs`의 `publicRoutes` Map에 한 줄 추가:
  ```js
  ["public/quotes/[token]/route.ts", "토큰 기반 공개 견적 조회 — UUID 토큰 검증 + 만료 체크 + 원가/마진 컬럼 제외로 보호됨"],
  ```
- **Codex Task**: 위 한 줄 추가 후 `node scripts/check-api-auth-boundaries.mjs` 재실행해 통과 확인. Owner Domain: 없음(툴링). Related Domain: quote.

### 2-2. "리드" 탭 재진입 시 렌더러 먹통 (신규, 라이브 감사에서 발견)

- **증상**: `/dashboard`(지도 홈)에서 지도→거래처→코스→리드→히스토리 탭을 한 바퀴 돈 뒤 **리드 탭에 다시 진입**하면 화면이 멈춥니다. 재현 중 CDP 스크린샷 캡처가 30초씩 반복 타임아웃(누적 100초+)되었고, 같은 탭 안에서 `/dashboard`로 재이동을 시도해도 복구되지 않아 **브라우저 탭을 닫고 새로 여는 것 외에는 복구 방법이 없었습니다.** 콘솔에는 에러 없음, 네트워크 요청도 추가로 발생하지 않음 — 즉 네트워크 실패가 아니라 **메인 스레드가 점유된 상태**로 보입니다.
- **중요한 단서**: 새 탭에서 **처음** `/dashboard?view=leads`에 진입하면 정상 동작(로딩 메시지 후 정상 렌더: 전체 신규 개업 64곳 등). 즉 **첫 마운트에서는 재현되지 않고, 같은 세션에서 해당 뷰를 다시 마운트할 때만 재현**됩니다 — 단순 "데이터가 많아서 느리다"가 아니라 **상태 누적/재구독 문제**를 시사합니다.
- **코드 레벨 1차 소견 (확정 아님 — 이 샌드박스에는 브라우저 프로파일러가 없어 추정 수준)**: 아래 두 지점이 재마운트 시 위험 패턴을 보여 조사 우선순위로 제안합니다.
  1. `components/sales-route-map-workspace.tsx:1009-1060` — 차량 실시간 위치를 **4초 간격 `setInterval`**로 폴링(2026-09-07 피드백 대응으로 15초→8초→4초로 단축). 이 컴포넌트는 지도/거래처/코스/리드/히스토리 5개 탭을 모두 감싸는 상위 컴포넌트라서, **탭을 바꿔도 언마운트되지 않고 계속 폴링**이 돌고 있습니다. cleanup(`clearInterval`)은 있지만, 리드 탭 재진입 시 이 컴포넌트가 또 다른 무거운 연산(아래 2번)과 동시에 같은 4초 윈도우에서 경합할 가능성이 있습니다.
  2. `components/permit-leads-view.tsx:246-326` — 필터 상태를 `sessionStorage`에 저장/복원하는 두 개의 `useEffect` 쌍(불러오기 `246` / 저장 `293`)과, `filteredLeads`(515)→`tableSortedLeads`(592)→`sortedLeads`(612)→`pagedLeads`(619)로 이어지는 연쇄 `useMemo` 체인이 있습니다. 재마운트 시 `sessionStorage`에 **이전 세션의 필터가 이미 저장되어 있어 첫 마운트와 다른 코드 경로(필터 적용 상태)**를 타게 되는데, 바로 이 조건에서만 문제가 재현되는 점과 일치합니다. 리드 데이터 규모(라이브 확인: 개시일 미확인 포함 전체 약 1,000건)에서 이 체인 중 하나가 매 렌더마다 새 배열을 만들어 하위 `useMemo`의 의존성이 매번 바뀌는 패턴(memoization 무효화 연쇄)이 있다면, 탭 재진입 직후 폴링 틱과 겹쳐 렌더가 꼬리를 물고 반복될 수 있습니다.
- **권장 조치**: 코드 정적 분석만으로는 100% 확정이 어려우므로, Codex가 Chrome DevTools Performance 탭 또는 React Profiler로 "지도→리드 2회 진입" 시나리오를 실제로 프로파일링해 어느 `useMemo`/`useEffect`가 반복 실행되는지 확인 후 수정해야 합니다. **이 항목이 이번 라이브 감사에서 나온 가장 심각한 사용성 문제이며, 사용자가 실제로 겪을 가능성이 높아(지도 홈에서 탭을 오가는 것은 자연스러운 사용 패턴) 최우선으로 올립니다.**
- **Codex Task**: Owner Domain: route(지도 워크스페이스) / Related Domain: lead. 재현 시나리오를 문서화한 뒤 프로파일링 → 원인 확정 → 수정 → "지도→리드 3회 이상 왕복" 수동 회귀 테스트로 완료 기준 확인.

## 6. UX/사용성 개선 제안 (라이브 감사 기반)

사용자가 요청한 "UX를 다듬어야 사용성이 좋아질 것 같다"에 대한 구체적 제안입니다. 실제 배포된 화면을 직접 조작하며 확인한 내용 기준입니다.

1. **출발지 주소 미설정 경고를 온보딩 체크리스트로 통합** — 지금은 지도/거래처/코스 탭 전체에 같은 경고 배너("⚠ 물류 출발지 주소가 아직 설정되지 않아...")가 반복 노출되는데, 정작 그 원인은 `회사 설정` 페이지의 "적용 현황: 1/2 완료" 체크리스트 한 곳에 있습니다. 이 체크리스트 패턴 자체는 UX적으로 훌륭합니다 — 다만 **지금은 설정 페이지에만 있고 나머지 화면은 흩어진 배너로 땜질**하는 구조입니다. 신규 회사 가입 직후 1회성 온보딩 위저드(회사명 → 출발지 주소 → 완료)로 승격시키고, 완료 전에는 관련 화면 상단에 "설정 마치기" 단일 CTA만 보여주는 쪽을 제안합니다.
2. **사이드바와 탭 구조의 불일치 해소** — 위 3번 항목과 동일 문제의 UX 관점 제안입니다. "영업 관리/상품 매칭/영업 성과" 등 9개의 사이드바 메뉴가 실제로는 1개 화면의 탭일 뿐이라면, 사이드바에서도 그 사실이 드러나도록(예: 하나의 상위 메뉴 아래 하위 탭으로 들여쓰기, 또는 사이드바 클릭 시 같은 화면 안에서 탭만 전환되는 것을 시각적으로 알 수 있는 전환 효과) 바꾸는 것이 "메뉴 = 별도 페이지"라는 사용자의 기대와 실제 동작을 일치시킵니다.
3. **"다음 액션 요약" 패턴을 더 넓게 적용** — `/revenue/pipeline`의 "미처리 우선 0건 / 견적 요청 0건 / 관심 있음 0건"처럼 각 카드가 "무엇을 해야 하는지"와 "작업 열기" 링크를 함께 제공하는 패턴은 사용성이 좋습니다. 리드 탭, 거래처 탭 등 다른 목록형 화면에도 같은 "다음 행동 제안" 카드를 확장하면 전체 제품의 일관성과 사용성이 함께 올라갈 것으로 보입니다.
4. **빈 상태(empty state) 메시지 품질 유지** — 히스토리 탭의 "이 날짜에는 저장된 완료·운행 기록이 없습니다. 달력에서 완료 건수가 표시된 날짜를 선택하세요.", 상품 매칭의 "📦 조건에 맞는 품목이 없습니다" 등은 원인과 다음 행동을 함께 알려주는 좋은 사례입니다 — 새 화면을 만들 때 이 수준을 기본 가이드라인으로 삼을 것을 제안합니다.
5. **코스 탭의 제약 투명성 문구 유지/확산** — "티맵 경유지 제한 때문에 실제 도로 계산은 최대 15곳씩 나눠 처리합니다"처럼 시스템 제약을 사용자에게 솔직하게 설명하는 문구는 신뢰도를 높입니다. 비슷한 제약(예: 배치 작업 상한, 동시 처리 한도)이 있는 다른 화면에도 같은 방식의 설명을 추가 검토.
6. **리드 탭 프리즈(2-2)는 UX 문제이기도 함** — 버그 섹션에 있지만 본질적으로는 "탭을 자유롭게 오갈 수 있어야 한다"는 가장 기본적인 사용성 기대를 깨뜨리는 문제라, 체감 우선순위로는 이 목록의 다른 어떤 UX 제안보다 높습니다.
7. **모바일/기사용 화면 검증 필요** — 이번 감사에서 기사(드라이버)용 모바일 UI를 열지 못했습니다. TMS 제품에서 기사 화면은 핵심 사용자 접점이므로, 실제 모바일 기기 또는 브라우저 디바이스 모드로 한 번 더 점검해 데스크톱 전용으로 설계된 화면이 모바일에서 깨지지 않는지 별도 확인을 권장합니다.
8. **견적 패널 입력 경험 개선 (PM 피드백 반영, 신규)** — PM 김은아님이 실제 사용 중 남긴 코멘트를 그대로 반영합니다.
   > "가로스크롤과 세로스크롤이 한곳에 있으면 UX가 좀 불편하거든요. 지도를 보면서 입력해야되는게 아니라면 새창에서 열기 버튼을 넣거나 확장하기 등이 있어야 될 것 같고요. 그리고 값을 입력하고 이탈하려고 하면 얼럿창이 뜨는게 좋아보여요. 입력한거 다 날리네요."

   세 가지를 구체적인 개선안으로 정리하면: (a) 드로어 안에 또 다른 가로 스크롤 테이블을 넣는 대신, 품목 테이블은 패널 폭에 맞춰 줄바꿈되거나 카드형으로 쌓이는 레이아웃으로 바꿔 스크롤축을 하나로 줄이기. (b) 지도를 동시에 볼 필요가 없는 작업(가격 입력, 품목 연결)은 드로어가 아니라 전체화면 모달 또는 별도 탭("새 창에서 열기")으로 빼서 넓은 화면에서 입력하게 하기. (c) 품목 입력값이 하나라도 바뀐 상태에서 패널을 닫거나 다른 화면으로 이동하려 하면 "저장하지 않은 변경사항이 있습니다" 확인창을 띄워 실수로 입력을 날리는 일을 막기. PM이 "기능은 코멘트 못하지만 디테일을 살리면 좋겠다"고 명시했듯, 이 항목들은 계산 로직이 아니라 **입력 중 사용자를 보호하는 장치**가 핵심입니다.
9. **(전체 재검토) 미저장 입력값 이탈 보호 — 실제로 앱 전반에 비일관적으로 적용되어 있음.** "견적 패널과 똑같은 상황이 다른 화면에도 있을 것"이라는 가정을 코드베이스 전체에서 검증했습니다. 결과를 있는 그대로 보고합니다 — 과장도, 축소도 하지 않습니다.
   - **중첩 스크롤(①)은 전체 코드베이스에서 재확인되지 않았습니다.** `overflow-y-auto`로 스크롤되는 드로어/모달 패턴 전체(약 6개 파일)를 확인했고, 그 안에 또 `overflow-x-auto` 테이블이 중첩된 사례는 견적 드로어(`sales-route-map-workspace.tsx:7250/7352`) 한 곳뿐이었습니다. `excel-mapping-preview.tsx`의 매핑 테이블도 `overflow-x-auto`를 쓰지만 바깥 패널이 `overflow-hidden` 전체화면 모달이라 중첩이 아닙니다. **이 항목은 8번 한 건으로 한정해도 됩니다.**
   - **"확장/새 창 보기"(②)도 지도에 묶인 좁은 드로어라는 견적 패널의 특수성이 큽니다.** 나머지 폼들은 애초에 전체 페이지라 이 요청이 그대로 적용되지는 않습니다. 다만 §3-2에서 지적한 "사이드바 vs 탭" 문제와 맞물려, 긴 입력 작업(아래 목록)을 좁은 패널/드로어에 가두지 않는다는 원칙 자체는 재사용할 수 있습니다.
