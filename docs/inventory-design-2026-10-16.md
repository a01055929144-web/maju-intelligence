# 재고관리 · 매장 주문 단가 규칙 설계 (2026-10-16)

> 상태: 설계 검토용. 구현 및 운영 DB 적용 금지.
> Owner: `inventory` / Related: `product`, `purchasing`, `sales`

## 1. 목표와 1단계 범위

재고의 단일 원장은 `inventory_movements`다. 전표 확정·수정·이동·취소와 실사는 원장을 직접 수정하지 않고 새 이동 행을 추가한다. 현재고는 원장 합계와 항상 재구성 가능해야 한다.

1단계 구현 범위는 다음으로 제한한다.

- 회사 마스터 상품 기준 재고 원장
- 전표 확정·발행 전표 수정·취소·라인 이동 연동
- 매입처 상품의 확정 매핑과 단위 환산
- 현재고 및 마이너스 재고 목록
- 상품별 실사와 조정 이동

안전재고 기반 발주 추천과 매장 주문·예약은 1단계 후속이다. 여러 창고, 소비기한·로트, 바코드 스캔은 2단계로 미룬다.

## 2. 수량과 상품 기준

- 재고 상품은 `product_catalog` 기준이다. 공급사 원본 상품은 재고의 최종 키가 아니다.
- 수량은 상품별 가장 작은 `base_unit`으로 `numeric(14,3)`을 저장한다.
- `product_unit_conversions.base_quantity`는 해당 단위 1개가 기본 단위 몇 개인지 뜻한다. 예: 기본 단위가 `개`이고 `박스=20개`면 `박스`의 값은 `20`이다.
- 기존 `purchase_to_sales_ratio`는 “매입 단위 1개에 판매 단위 N개” 의미를 유지한다. 신규 계산은 단위별 기본 수량으로 통일하며, 레거시 값은 확인된 경우에만 변환 제안값으로 쓴다.

매입 라인은 `supplier_product_id`에서 활성 `confirmed` 매핑을 따라 `product_catalog_id`를 찾는다. 확정 매핑이 없거나 단위 환산이 확인되지 않으면 재고 이동을 만들지 않고 `재고 미연결` 목록에 표시한다. 전표 자체의 확정은 막지 않는다.

## 3. 데이터 모델

### 3.1 단위와 상품 설정

- `product_unit_conversions`: 상품별 단위, 기본 수량, 기본 단위 여부, 확인 여부를 보관한다. 상품당 기본 단위는 하나다.
- `product_inventory_settings`: 추적 여부, 안전재고, 기본 매입처 상품을 보관한다. 안전재고 발주 초안 기능은 후속에서 사용한다.
- `companies.inventory_negative_policy`: 기본 `warn`. 후속 승인 시 `block`을 사용할 수 있도록 설계하되 1단계에서는 경고만 한다.

### 3.2 원장과 현재 상태

`inventory_movements`는 append-only다.

- 입고 계열 `purchase_in`, `sale_return_in`은 양수다.
- 출고 계열 `sale_out`, `purchase_return_out`은 음수다.
- `adjustment`, `revision`은 0이 아닌 차이다.
- 전표·라인·상품·단위·원수량·환산율·상품명은 스냅샷으로 남긴다.
- `(company_id, idempotency_key)` 유니크로 재호출 중복을 막는다.
- UPDATE/DELETE는 DB 트리거로 차단한다.

`inventory_document_positions`는 전표별·상품별 “현재 반영된 기본 단위 수량”을 보관하는 재생성 가능한 기술 투영이다. 발행 전표가 수정되면 새 목표 수량과 이 값의 차이만 `revision`으로 기록한다. 라인 교체나 거래처 이동에도 기존 라인 ID에 의존하지 않는다.

`inventory_balances`는 원장이 아니라 동기식 투영이다. 현재고·마이너스·실시간 주문 검증에서 수십만 건을 매번 합산하는 비용을 피하기 위해 중앙 재고 RPC가 원장 INSERT와 같은 트랜잭션에서 갱신한다. 장애 시 원장 합계로 재구축하고 정기 대조할 수 있어야 한다. 1단계에는 창고 축을 넣지 않는다.

## 4. 전표 연동

중앙 내부 함수 `apply_inventory_for_document(company_id, document_id, reason, actor)` 하나만 재고를 반영한다. 문서와 대상 balance 행을 고정 순서로 잠근다.

| 전표 유형 | 목표 이동 |
| --- | ---: |
| `purchase` | `+기본단위수량` |
| `sale` | `-기본단위수량` |
| `sale_return` | `+기본단위수량` |
| `purchase_return` | `-기본단위수량` |
| `cancelled` 또는 삭제 | `0` |

연동 위치는 다음과 같다.

1. `confirm_business_document`: 원장 전표 반영과 함께 최초 유형 이동을 기록한다.
2. `save_business_document`: confirmed 전표의 품목·수량·단위가 바뀌면 목표와 현재 position의 차이를 `revision`으로 기록한다. 거래처만 이동하면 수량 차가 0이므로 재고 이동은 없다.
3. `cancel_business_document`: 목표를 0으로 맞추는 역방향 `revision`을 기록한다.
4. `move_business_document_lines`: 원본과 대상 문서를 UUID 정렬 순으로 잠그고 두 문서의 차이를 한 트랜잭션에서 반영한다. 복사는 draft에만 추가되므로 확정 전에는 재고 영향이 없다.

ERP 1-B v2 RPC 최종본이 저장소에 기록된 뒤 그 함수 본문에 위 호출을 합쳐야 한다. 별도 API에서 재고를 후처리하면 전표와 재고가 갈라질 수 있으므로 금지한다.

### 미연결과 실패 처리

- 확정 매핑 없음, 변환 미확인, 원가 미확정 라인은 재고 미반영 사유를 반환한다.
- 전표 UI는 `재고 반영 n / 미연결 n / 환산 미확인 n`을 보여준다.
- 미연결을 나중에 해결하면 명시적 재처리 RPC가 현재 position과 목표의 차이를 기록한다.
- 동일 idempotency key 재호출은 성공으로 취급한다.

## 5. 원가와 마진

- 매입 입고 단가는 매입 단가를 기본 단위 수량으로 나눈 값이다.
- balance에는 `inventory_value`와 `average_unit_cost`를 함께 둔다. 입고·반품·revision의 금액 차이를 같은 트랜잭션에서 반영한다.
- 매출 출고 시 출고 직전 이동평균 단가를 movement와 매출 라인의 원가 스냅샷에 기록한다.
- 마이너스 재고에서는 평균원가를 임의로 0으로 만들지 않고 마지막 유효 평균원가를 사용하며 `negative_cost_estimate=true`로 표시한다. 입고 후 원가 재평가 정책은 후속 승인 사항이다.
- 전표/품목/거래처별 마진은 매출 스냅샷에서 파생한다. 매장·공개 견적·공개 문서에는 원가, 평균원가, 마진, 매입처를 절대 반환하지 않는다.

## 6. 실사, 부족, 발주 추천

실사는 draft 헤더와 상품별 counted 수량을 저장한 뒤 `post_inventory_stocktake`가 당시 시스템 수량과 차이를 `adjustment`로 기록한다. 게시 후 실사 내용은 수정하지 않고 새 실사를 만든다. 사유와 담당자 표시명은 필수다.

1단계에서 음수 출고는 허용하고 경고한다. `inventory_balances.on_hand_quantity < 0` 목록을 운영 화면에 제공한다. `block` 정책은 주문 예약과 동시성 시나리오를 함께 검증한 뒤 활성화한다.

후속 안전재고 기능은 `가용재고 = 현재고 - 예약수량`이 안전재고보다 작은 상품을 기본 매입처별로 묶어 `purchase` draft 전표를 만든다. 자동 확정·자동 발주는 금지한다.

## 7. 매장 주문 가격과 예약 (설계만)

매장이 보는 단가는 주문일 기준으로 다음 순서다.

1. 유효한 `customer_price_agreements`
2. `product_catalog.default_sales_price`
3. 최근 확정 매입 원가를 주문 판매 단위로 환산한 계산가

3번은 단순히 기존 `purchase_to_sales_ratio`를 곱하지 않는다. 예를 들어 박스 원가 20,000원, 1박스=20개라면 개당 원가는 `20,000 / 20 = 1,000원`이다. 표준식은 `매입단가 × (판매단위 기본수량 / 매입단위 기본수량)`이다.

일반 상품은 매입가가 변해도 판매가를 자동 변경하지 않고 `가격 조정 필요` 알림만 만든다. 명시적으로 `cost_multiplier` 가격 모드를 선택한 상품만 승인된 배율로 계산가를 갱신하며 회사 마진 하한을 지킨다.

주문 접수 시 `inventory_reservations`에 기본 단위 예약을 잡고, 출고 확정 시 소비, 주문 취소 시 해제한다. 가용재고는 현재고에서 활성 예약을 뺀 값이다. 이 테이블과 주문 연동은 1단계 SQL 범위 밖이다.

## 8. 화면

- 운영 관리 > 재고관리: 현재고, 가용재고(후속), 평균원가, 안전재고, 음수/미연결 필터
- 상품관리 > 단위 환산: 기본 단위와 매입·판매 단위 변환 확인
- 전표 작성: 각 라인의 재고 연결·환산 상태 표시
- 재고 미연결: 전표/매입처 상품/미연결 사유, 매핑 후 재처리
- 재고 실사: 실사 입력, 차이 미리보기, 게시
- 발주 추천(후속): 안전재고 부족을 기본 매입처별 draft로 생성

## 9. 권한·테넌트·검증

- 모든 FK는 `(company_id, id)` 복합 참조를 사용한다.
- public 스키마 테이블은 RLS를 활성화하고 `anon`, `authenticated`, `PUBLIC` 권한을 회수한다. 서버의 service role과 `manage_sales` 또는 향후 `manage_inventory` 권한만 사용한다.
- 원장 조회 API는 회사 조건을 필수로 하고 매장 포털 DTO에는 민감 필드를 포함하지 않는다.
- 중앙 RPC는 `security invoker`, service role 전용이며 함수 실행 권한을 명시적으로 회수한다.

필수 회귀 테스트:

- 전표 확정 재호출 시 이동 중복 없음
- 발행 전표 수량 수정 시 차이만 기록
- 거래처 이동만으로 재고 수량 변화 없음
- 라인 이동 시 두 전표 이동 합계가 보존됨
- 취소 시 현재 반영분만 정확히 역반영
- 매핑/환산 없는 매입 라인은 전표 확정되지만 재고 미연결로 남음
- 같은 상품 동시 입출고에서 balance와 원장 합계 일치
- 실사 재호출 중복 없음
- 다른 회사 상품·전표 ID 거부
- 매장·공개 응답에 원가·마진·매입처 없음

## 10. 단계별 구현 순서

1. SQL 최종 검증 및 적용: 단위, 원장, position, balance, 실사, append-only 보호.
2. 중앙 재고 도메인 함수와 순수 수량/원가 계산 테스트.
3. ERP RPC 네 곳에 같은 트랜잭션으로 연동.
4. 현재고·마이너스·미연결·실사 화면.
5. 안전재고와 발주 draft 추천.
6. 매장 주문 가격 규칙과 예약.
7. 2단계: 다중 창고, 소비기한/로트, 바코드 스캔.
